阻塞 IO 与等待队列：poll / select / epoll 的驱动侧

read(fd, buf, n) 卡住的那几百毫秒里，进程并不是「在忙等」，而是从运行队列里消失了。把它叫醒的，是另一个上下文里的 wake_up。

这一篇讲清三件事：等待队列的结构、阻塞 read 的完整路径、以及 poll/select/epoll 在驱动侧到底要求你实现什么。

先玩一下：一次阻塞 read 的全过程

点「自动播放」。注意第 4 步之后进程状态变成 S（可中断睡眠），它不再占 CPU；第 6 步数据到达后，中断上下文只做「唤醒」，不做拷贝。

这就是「条件 + 队列」的标准范式。所有阻塞型驱动都长这样，区别只在「条件」是什么（有数据？有空间？有事件？）。

一、等待队列的三个角色

wait_queue_head_t队列头，驱动里一个静态或动态成员。它保护一张链表和一个自旋锁。
wait_queue_entry每个等待者一项，内含「当前进程」与唤醒函数。wait_event 系列宏在栈上建它。
条件一个由驱动维护的布尔/计数。等待队列本身不存状态，醒来必须重新判断条件——这是防「虚假唤醒」的关键。

wait_event_interruptible(wq, cond) 展开后就是这张表上的循环：

for (;;) {
    prepare_to_wait(&wq, &__wait, TASK_INTERRUPTIBLE);
    if (cond) break;                 // 条件已满足：不睡
    if (signal_pending(current)) { ret = -ERESTARTSYS; break; }
    schedule();                      // 真正让出 CPU
}
finish_wait(&wq, &__wait);

三个细节值得记住：先挂队列再判条件（否则可能丢唤醒）；醒来必须重判（可能被别的等待者抢走）；区分可中断/不可中断（前者能被 Ctrl-C 打断，返回 -ERESTARTSYS，VFS 会自动重启系统调用）。

二、poll / select / epoll 要驱动提供什么

用户态问「这个 fd 现在可读吗」，内核最终会调用驱动 file_operations.poll（或 poll 成员）。驱动要做的事只有两件：

  1. 用 poll_wait(file, &wq, wait) 把「调用者的等待项」挂到你的等待队列上；
  2. 返回一个位掩码：EPOLLIN | EPOLLRDNORM 表示可读，EPOLLOUT 表示可写。

poll_wait 本身不睡，它只是登记。睡与醒来由 do_poll/epoll_wait 负责。这个分工是理解 epoll 的关键：epoll 把「登记」这件事做成了一张常驻的表（红黑树 + 就绪链表），于是每次等待不需要把上万个 fd 从头扫一遍。

机制复杂度适用触发方式
selectO(n)，且有 1024 fd 上限老代码、少量 fd水平触发（每次都要重新扫）
pollO(n)，无上限中等数量、跨平台水平触发
epollO(1) 取就绪，注册 O(log n)大量连接、长期存活水平或边沿触发

三、边沿触发（ET）为什么必须读干净

水平触发（LT）的语义是「只要还有数据，每次 wait 都通知你」。边沿触发（ET）只在状态发生变化时通知一次。于是 ET 模式下，如果你只读了一半就回去等，剩下的数据不会再触发通知——程序看起来「卡住」了。

正确做法是：ET 模式下 read 一直读到返回 EAGAIN 为止，并且 fd 必须是非阻塞的。这也是几乎所有高性能网络库的固定套路。

误解：阻塞驱动里可以随便 msleep 等硬件中断上下文不能睡，持有自旋锁时不能睡，原子上下文不能睡。判断标准是「当前上下文允许调度吗」——不确定就用 in_interrupt()、in_atomic() 自查，或者干脆把耗时工作丢到工作队列/线程里。
一个立刻能用的观察进程卡在 read 时，cat /proc/<pid>/stack（需 root 与内核配置）或 ps -o stat,wchan 能看到它睡在哪个内核函数上。wchan 显示的符号名，通常就是你驱动里的那个 wait_event 所在函数。

动手（可选）：把「等」做出来

只在 🔧 实作模式展开需要板子；纯读可跳过。
  1. 在字符设备里加一个 wait_queue_head_t 与 int have_data；read 用 wait_event_interruptible。
  2. 用一个定时器或按键中断把 have_data=1 后 wake_up_interruptible。
  3. 用户态先 read（会阻塞），再触发按键，观察 read 返回。
  4. 把 O_NONBLOCK 打开，read 立刻返回 EAGAIN；再用 poll() 等，验证 poll_wait 生效。
