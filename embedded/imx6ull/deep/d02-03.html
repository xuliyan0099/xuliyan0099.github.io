程序加载与内存布局：段、栈、堆、core dump

可执行文件在磁盘上是一堆段，在内存里是另一套地址。谁把它们搬过去、栈和堆为什么相向生长、core 文件为什么能还原现场。

磁盘上的可执行文件和内存里的进程，不是同一件东西。文件里是「段 + 偏移」，内存里是「页 + 地址」。把这两者对上，你就同时理解了启动、崩溃和 core dump。

先玩一下：一个程序在内存里长什么样

把鼠标在条上移动，看每一段装的是什么、地址往哪边长。注意堆和栈是相向生长的，中间那块空白就是它们共用的余地。

四个静态段（.text/.rodata/.data/.bss）的地址在链接时就定了（PIE 除外，那是「相对固定」）；堆和栈是运行时长出来的。.bss 是最容易被误解的一段：它在文件里几乎不占空间，但在内存里占满——这后面的机制叫「零页」。先记住结论，卷 03 讲 MMU 时会再回来。

一、加载是内核干的，不是 ld.so 干的

很多人以为「加载」是动态链接器做的。准确地说，execve 进内核后，内核里的 load_elf_binary（在 fs/binfmt_elf.c）才是主角。它做四件事：

  1. 读 ELF 头，找到程序头表（Program Header，PT_LOAD 项），而不是段表。段表是给链接器和调试器看的。
  2. 对每个 PT_LOAD，按 p_offset 把文件内容 mmap 到 p_vaddr；p_memsz > p_filesz 的部分（.bss）补零。
  3. 建立用户栈：把 argc/argv/envp 和 auxv（含 AT_ENTRY、AT_PHDR、AT_SYSINFO_EHDR）压进去。这就是 main() 能拿到参数的原因。
  4. 若存在 PT_INTERP（即动态链接的程序），把控制权交给 ld.so 的入口；否则直接跳到 ELF 头的 e_entry。

注意第三站的措辞：映射建立时并没有真的读磁盘。第一次访问那一页会触发缺页异常，内核这时才去页缓存取。这套「懒加载」让一个只用到 10% 代码的程序只付 10% 的 IO。

二、地址是谁定的：VMA 与 LMA

链接脚本里有两个词值得记住：

  • VMA（Virtual Memory Address）：运行时它在这个虚拟地址上。
  • LMA（Load Memory Address）：烧录/加载时它被放在哪个物理位置。

在 PC 上两者通常相同，所以感觉不到。在板子上它们经常不同：镜像烧在 Flash 的 0x8000_0000（LMA），运行时却要在 DDR 的 0x8000_0000 或 0x4000_0000（VMA），于是启动代码里必须有一段「把 .data 从 LMA 搬到 VMA」的循环。U-Boot 的 relocate_code、内核的 __relocate_dtb 都是干这个的。

一个立刻能用的判断程序里出现「函数能跑，但全局变量初值全是 0」——九成是 .data 的搬运段没执行。这不是编译器问题，是启动代码少了一段拷贝。

三、对齐的代价：页是最小单位

内存按 4 KB 页管理，而链接器按字节排段。于是「段有多大」和「实际占多少物理内存」不是一回事。

四、core dump：把地址空间拍成一张快照

进程崩了，内核可以把它当时的地址空间写成一个 ELF 文件——注意，core 文件本身就是 ELF 格式，只是类型是 ET_CORE，段表里放的是内存映射而不是磁盘内容。

部分内容gdb 用它做什么
PT_NOTENT_PRSTATUS（各线程寄存器）、NT_PRPSINFO（命令行、信号）、NT_FILE（映射的文件与偏移）还原调用栈、还原信号与线程状态
PT_LOAD各段内存内容（可按映射裁剪）读变量、看堆上的数据
PT_AUXV辅助向量定位 vDSO、页大小

常用命令：ulimit -c unlimited 打开；/proc/sys/kernel/core_pattern 决定文件名与落点；gdb ./app core 直接进现场。没有二进制就没有 core——所以产品里要保留带符号的镜像，或用 build-id 找到对应版本。

误解：core 文件里什么都有，随便就能还原core 只含当时映射进来的页，被换出或从未触及的页不在其中；而且没有 vmlinux/app 的符号，你只能看到一串地址。core 的价值一半在快照，一半在你手上的符号文件。

动手（可选）：看一次真实的加载

只在 🔧 实作模式展开PC 上即可，不需要板子。
  1. readelf -l ./app 看程序头：每个 PT_LOAD 的 VirtAddr、FileSiz、MemSiz、Flg（R/W/X）。
  2. 启动后在 /proc/<pid>/maps 里对照：文件段、[heap]、[stack]、[vvar]/[vdso] 都在。
  3. 往 .bss 里放一个 100 MB 的数组，看 ls -l 的文件大小几乎没变，而 maps 里 .bss 的区间变大了——这就是零页。
  4. 制造一次段错误（解引用空指针），用 ulimit -c unlimited 后再跑，拿到 core，gdb ./app core 里 bt。

离开这一篇，你应该能

  • 区分程序头表与段表：谁给加载器看，谁给链接器看。
  • 解释 .bss 为什么「文件里不占空间、内存里占满」。
  • 说出 core 文件为什么是 ELF，以及没有符号文件时它有多大价值。
