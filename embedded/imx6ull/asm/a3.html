寻址与栈：地址是怎么算出来的

第 03 章约 25 分钟★ 必读

一条指令，四件事要交代

ldr / str 只有三个问题要答：从哪个寄存器取基址、偏移多少、取完基址要不要改。所有寻址模式都是这三者的组合。

写法名字r1 变不变用在哪
ldr r0, [r1]零偏移不变取指针指向的第一个字段
ldr r0, [r1, #4]偏移不变取结构体第 2 个字段；外设寄存器组
ldr r0, [r1, #4]!前索引写回（pre-index）变（r1 += 4）顺序扫寄存器组、链表
ldr r0, [r1], #4后索引（post-index）变（r1 += 4）数组遍历，取完就走

偏移量可以是立即数（#imm，注意 ±4095 范围），也可以是寄存器（[r1, r2]），还能带移位（[r1, r2, lsl #2]——这个形态在 C 里对应「按 4 字节元素访问数组」，反汇编里一眼能认出 arr[i]）。

@ 同一件事，四种写法
    ldr  r0, [r1]            @ r0 = *r1
    ldr  r0, [r1, #4]        @ r0 = *(r1 + 1)     ← 结构体第二个字段
    ldr  r0, [r1, #4]!       @ 先 r1 += 4, 再 r0 = *r1
    ldr  r0, [r1], #4        @ 先 r0 = *r1, 再 r1 += 4

写回（!）在前还是在后，只有一处差别：地址加在读取之前还是之后。做指针遍历时这个差别决定「第一个元素取到的是 r1 还是 r1+4」。手写时写错一次就会整体偏移，而且不会崩，只是数据差一格——比崩更难查。

宽度：不只是 32 位

指令宽度符号典型场景
ldr / str32 位无寄存器、指针、int
ldrh / strh16 位零扩展半字外设寄存器（不少 SoC 是 16 位宽）
ldrb / strb8 位零扩展字符串、字节寄存器、协议字段
ldrsb / ldrsh8/16 位符号扩展C 里的 char / short（有符号）

这里有个必须知道的坑：C 的 char 是否有符号，取决于工具链。ARM 上 char 默认无符号（-funsigned-char 是 ARM EABI 的约定），所以取字节常用 ldrb；但如果你显式写了 signed char，编译器会给 ldrsb。反汇编里看到 ldrsb，说明这个字节是有符号语义的。

对齐：两条不能破的规矩

  • ldrd / strd（64 位访问）地址必须 8 字节对齐。不对齐在 Cortex-A7 上会触发 alignment fault（或者被内核修一次再警告你）。
  • sp 在公开接口处必须 8 字节对齐。push 奇数个寄存器就破了它；后面接 NEON/VFP 指令或 64 位参数时会出问题。

至于「非对齐的 32 位访存」，A7 上 ldr 一般允许（内部会拆两次总线访问，代价是性能），但别依赖它：写 DMA 缓冲、结构体、协议头时该对齐就要对齐。

批量搬运：ldm / stm

一次搬多个寄存器，一条指令完成，比循环快得多。后缀表示「地址增长方式」：

后缀全称起始地址
IAIncrement Afterr1 之后开始，向上长
IBIncrement Beforer1 处开始，向上长
DADecrement After向下长
DBDecrement Before向下长

日常只需要认识两个别名：

    push {r4, r5, lr}       @ 完全等价于 stmdb sp!, {r4, r5, lr}
    pop  {r4, r5, pc}       @ 完全等价于 ldmia sp!, {r4, r5, pc}

pop 到 pc 是「函数返回」的另一种写法，比 bx lr 少一条指令，内核里大量使用。

一个容易困惑的点：push 里寄存器的书写顺序不代表地址顺序。ARM 规定：编号小的寄存器落在低地址。所以 push {r4, r5, lr} 之后，栈里从低到高是 r4、r5、lr。pop 时按相反方向恢复。这个规则在手工算栈偏移（比如取第 5 个参数）时极其重要。

栈：满递减，只有一条规则

ARM 的栈是 FD（Full Descending，满递减）：

  • 递减：栈向低地址生长。
  • 满：sp 始终指向最后一个有效数据（不是下一个空位）。

所以 push 的语义是「sp 先减 4，再存」：

    @ 初始 sp = 0x2000
    push {r4}               @ sp = 0x1FFC, [0x1FFC] = r4
    push {r5}               @ sp = 0x1FF8, [0x1FF8] = r5
    pop  {r5}               @ r5 = [0x1FF8], sp = 0x1FFC
    pop  {r4}               @ r4 = [0x1FFC], sp = 0x2000

必须成对：push 几个就 pop 几个，顺序相反。漏一个，sp 就永久偏了 4 字节；函数返回后调用者的栈帧全错，表现出来是「莫名其妙跑飞」。

一个典型函数栈帧张什么样

非叶子函数的标准栈帧（push {r4-r6, lr}）：

地址内容谁写
sp + 12lr（返回地址）被调函数 push
sp + 8r6被调函数 push
sp + 4r5被调函数 push
sp + 0r4被调函数 push
sp + 16第 5 个参数（调用者放的）调用者
sp + 20第 6 个参数调用者

注意第 5 个参数在调用者的栈上，被调函数用 [sp, #16] 取（因为自己 push 了 4 个字，sp 已经下移了 16）。这就是 04 篇要讲的「超过 4 个参数怎么取」。

字节序：小端，但网络是大端

i.MX6ULL 是小端：一个 32 位字 0x12345678 在内存里是 78 56 34 12。

网络协议、文件头、某些传感器寄存器是大端。C 里用 htonl/ntohl，汇编里就是一条 rev：

    ldr  r0, [r1]
    rev  r0, r0              @ 字节翻转：0x12345678 → 0x78563412

rev16、revsh 处理 16 位和半字带符号的情况。顺手记：rbit 是按位翻转（不是按字节），用在位运算技巧里。

三大常见错误（都很难查）

  1. 写回用错方向：[r1, #4]! 和 [r1], #4 混用，整体偏移一格，数据全错但不崩。
  2. push/pop 不对称：漏 pop 一个，sp 永久偏移；多个函数叠加后栈溢出或踩到别的变量。
  3. 对齐被破坏：push 三个寄存器（12 字节）以后调用带 64 位参数或 NEON 的函数，直接触发 fault。

本篇验收

  • 能说出四种寻址在什么场景用，特别是写回写在 ! 前与写在 , 后的区别。
  • 能写出「用 ldm/stm 一次搬 4 个字」的代码，并说清 IA/IB/DA/DB 的差别。
  • 能画出 push {r4, r5, lr} 之后栈里三格的顺序（提示：编号小的在低地址）。
  • 能解释「为什么 sp 必须 8 字节对齐」，以及破坏它会在哪种场景炸。
  • 能说清 rev 与 rbit 的区别。
