最小可跑：工具链与第一条指令

第 01 章约 22 分钟★ 必读含互动工具

目标：把「写出来的字」和「跑起来的字节」对上

学汇编最怕悬空：看懂了助记符，但不知道它长什么样、放在哪里、怎么跑起来。这一篇只干一件事——建立完整闭环：写一个 .s → 汇编 → 链接 → 反汇编 → 看到自己写的 32 位机器码。

闭环通了，后面所有知识都能自己验证；闭环没通，你只能信我。

工具链：装哪几个，各自管什么

交叉工具链有两条常用路线，选一条即可：

工具用途装哪个包
arm-none-eabi-gcc裸机 / 无操作系统，-nostdlib 直接用gcc-arm-none-eabi
arm-linux-gnueabihf-gcc给 Linux 用户态、内核模块用（armhf，硬浮点）gcc-arm-linux-gnueabihf
arm-none-eabi-as / ld汇编器与链接器（通常随 gcc 一起来）同上
arm-none-eabi-objdump反汇编、看段布局、看机器码binutils-arm-none-eabi
gdb-multiarch连 qemu 或板子，看寄存器/内存/单步gdb-multiarch
qemu-arm / qemu-arm-static在电脑上跑 ARM 用户态程序，不用板子qemu-user

装完先验一件事：arm-none-eabi-gcc --version 与 arm-none-eabi-objdump --version 都能出来。出不来就是路径问题，先解决这个，别往下走。

第一条指令：只做一件事

新建 start.s：

@ start.s —— 最小可跑的最小
.syntax unified
.arm
.global _start
_start:
    mov  r0, #1
    b    .              @ 死循环，相当于 while(1);

三行伪指令的含义必须清楚：

  • .syntax unified：让 ARM 态和 Thumb 态共用一套写法（push、ldr r0, =x、movw 这些统一语法才可用）。写在文件头，别省，否则老式分列语法会让你怀疑人生。
  • .arm：这一段按 32 位 ARM 指令集汇编。对应 .thumb / .thumb_func（后者还要告诉链接器这是 Thumb 函数，否则 bl 会跳错模式）。
  • .global _start：把 _start 导出成全局符号，链接器才看得见。

编译、链接、反汇编：

arm-none-eabi-gcc -c -march=armv7-a -marm start.s -o start.o
arm-none-eabi-ld -Ttext=0x80000000 -e _start start.o -o start.elf
arm-none-eabi-objdump -d start.elf
注意 -Ttext=0x80000000：这是 DDR 的起始地址，它隐含一个前提——DDR 已经被初始化好了。纯指令练习不必上板（objdump 就够验收），但真要在板子上跑，得先回答「谁把代码搬到这里、DDR 是谁配的」。

真上板：DDR 在什么时候才需要初始化

mov r0,#1; b . 这两条指令本身没有任何问题，能跑；跑起来就是原地死循环。决定它「能不能跑」的是三件事：链接地址有没有对上、谁把镜像搬过去、DDR 有没有起来。

运行方式代码被放到哪DDR 谁初始化需要自带 IVT/DCD 吗
u-boot 命令行 goDDR（你 load 进去的）u-boot 早就配好了不需要
uuu / MFG Tool 下载默认 OCRAM，也可选 DDR工具按自带的 DCD 配工具会处理
SD/eMMC 冷启动DDRBoot ROM 按你镜像头里的 DCD 配必须，否则 Boot ROM 根本不理你的镜像

所以：

  • 只想验指令：链接到片内 OCRAM，完全不碰 DDR。

    • ``bash arm-none-eabi-ld -Ttext=0x00900000 -e _start start.o -o start.elf arm-none-eabi-objcopy -O binary start.elf start.bin ` i.MX6ULL 的 OCRAM 在 0x00900000（容量以 RM 的 Memory Map 为准），用 uuu` 直接下进去就能跑。这条路不需要 DCD、不需要 DDR。

  • 要从卡上冷启动：必须有 IVT + DCD。DCD 就是那张「先把 IOMUX、时钟、DDR 参数写进寄存器」的表，Boot ROM 读完它、DDR 通了，才跳到你的入口。这也是为什么裸机镜像要用 mkimage/MFG Tool 生成头部，而不是把 .bin 直接 dd 到卡首。
  • 两条路的共同坑：POR 后看门狗可能已经使能，代码跑不到几秒就被复位，看起来像「跑飞了」。开头先清 WDOG1（0x020BC000）的使能位再干活。

反汇编输出长这样：

80000000 <_start>:
80000000:   e3a00001    mov  r0, #1
80000004:   eafffffe    b    80000000 <_start>

逐列读，这是本篇最重要的一件事：

  1. 第一列是地址（0x80000000、0x80000004），差值 4 —— ARM 态指令定长 32 位。
  2. 第二列是机器码（e3a00001），也就是真正写进 flash 的四个字节。小端存放，实际字节序列是 01 00 a0 e3。
  3. 第三列是助记符，第四列是操作数。
  4. b .（跳到自己）被编成 eafffffe：0xEA 是 B 的操作码，低 24 位 0xFFFFFE 是「相对 pc 的偏移 -8」——因为 pc 在读指令时已经指向下一条（+8 流水线偏移），所以「跳到自己」的偏移是 -2 条指令。
想验证「pc 指向下一条」这件事：把 b . 改成 b .+8，机器码的偏移会变成 0。这个练习比背十遍「ARM 流水线」都有效。

ARM 态与 Thumb-2：为什么你在板子上看到的反汇编长得不一样

同一段代码，用 -mthumb 编译：

arm-none-eabi-gcc -c -march=armv7-a -mthumb start.s -o start_t.o
arm-none-eabi-objdump -d start_t.o

输出会变成 2 字节一条（或 2+2 组成 32 位）：

0:   b580        push   {r7, lr}
2:   466f        mov    r7, sp
...

差别不只是「短」。ARMv7-A 的 Thumb-2 是混合编码：常用指令压到 16 位，需要立即数大、寄存器号高的指令仍是 32 位。带来的后果：

  • 代码体积小约 30%，i-cache 压力小，所以 Linux 内核、armhf 用户态默认都是 Thumb-2。
  • 条件执行受限：ARM 态可以随便给指令加 eq/ne/lt 后缀；Thumb 态只有 b 系列能带条件，其余条件指令必须包在 IT 块里（05 篇细讲）。
  • 反汇编里会出现「地址 +2 不 +4」的情况，看起来像错位，其实是 16/32 位混排，正常。

你在板子上 objdump -d 内核模块，看到的大多是这种混排。别以为是工具坏了。

常量池：ldr r0, =0x12345678 的真身

手写时最常用的一条伪指令是 ldr r0, =值。它不是一条指令，而是汇编器的约定：

    ldr  r0, =0x12345678     @ 汇编器处理：把常数塞进常量池，再生成一条 PC 相对的 ldr

编译后变成：

   4:  e59f0008    ldr  r0, [pc, #8]     @ 去 pc+8 的地方取数
   8:  ...
   c:  12345678                          @ 常量池里躺着这个字

这一步很关键，因为它解释了两个日常现象：

  1. 为什么反汇编里会突然出现一堆看着不像代码的「数据」——那是常量池，被夹在函数之间。
  2. 为什么 ldr r0, =x 是「取内存」而不是「取立即数」——它真的在访存，而且 PC 相对，所以位置无关代码里也能用。

跑起来：不用板子也能验

裸机二进制没法直接在本机跑，但你有两条退路：

退路一：qemu 用户态（验 C 和简单汇编逻辑）

arm-linux-gnueabihf-gcc -static -o hello hello.s
qemu-arm ./hello

退路二：qemu 系统态（验裸机、验向量表）

qemu-system-arm -M vexpress-a9 -kernel start.elf -nographic

vexpress-a9 是 Cortex-A9，不是 A7，但指令集与异常模型同族，用来验「关狗/设栈/向量表」这类骨架足够。真正的外设地址只有板子有。

退路三（推荐）：直接看反汇编，不上板。 90% 的练习（立即数、条件码、栈、位域）用 objdump -d 就能验收，这是最快的学习回路。

工具：把这些指令一条条走一遍

下面这个单步台内置六段程序（算术、循环、函数调用、内存、位域、有符号比较）。每点一次「单步执行」，它会告诉你：这条指令动了哪个寄存器、标志位怎么变、栈上多了什么。先在这里把 04 篇要讲的 push/pop 和 bl/bx lr 看明白，再看文字，效率高得多。

单步台 · 看每条指令到底改了哪个寄存器（先选一段，再点单步）

选一段程序，然后一步一步走。橙色框是这一步改动的寄存器，绿色标志位是这一步置起来的。

建议按这个顺序玩：

  1. 选 A · 算术与标志位，单步走完。重点看 cmp r2, #0 之后 Z 变 1，然后 addeq 真的执行了（r3 从 0 变 1）。
  2. 选 B · 循环，走两轮就明白 cmp + blt 怎么把控制权拉回去。
  3. 选 C · 函数调用，盯住 lr：bl 把它写成返回地址，push {lr} 把它存进栈，bx lr 又把 pc 拉回去。这就是 04 篇的全部内容。

本篇验收

  • 能说出 mov r0,#1 的机器码里哪几位是操作码、哪几位是立即数（e3a00001：e3a 是「mov 立即数」的编码头，低 12 位是立即数 1）。
  • 能解释 b . 为什么编成偏移 -8。
  • 能说出「内核为什么用 Thumb-2」，以及 Thumb 态下条件执行受限在哪。
  • 能解释 ldr r0, =0x12345678 为什么会变成「PC 相对访存 + 常量池」。
  • 单步台里 C 程序走完后，r0 是 7，sp 回到起始值（栈必须平衡）。
