C 与汇编互调：四条约束和两个别省

第 07 章约 24 分钟◆ 可选读

日常真正用到的，只有两种

  1. 内联汇编（asm volatile("...")）：在 C 里插几条指令，用来做屏障、读特殊寄存器、执行协处理器指令。
  2. 外部汇编函数（.S 文件 + extern 声明）：整个函数用汇编写，比如上下文切换、启动 stub、极短的热路径。

这两种都受同一套规则约束：AAPCS。C 侧不知道你在里面干了什么，只相信你守约。

内联汇编的四种约束

asm volatile ("指令模板" : 输出 : 输入 : 破坏列表);
约束含义例子
"r"输入：放进任意通用寄存器asm("mov %0, %1" : "=r"(a) : "r"(b))
"=r"输出：只写、任意通用寄存器asm("mov %0, #1" : "=r"(a))
"+r"输入兼输出（读写）asm("add %0, %0, #1" : "+r"(a))
"m"内存操作数asm("str %0, %1" :: "r"(v), "m"(buf))
"I"立即数（编译期常量）asm("mov %0, %1" : "=r"(a) : "I"(3))

模板里的 %0、%1 是占位符，按「输出在前、输入在后」编号。修饰符：%0 可以加 w（16 位视图）、b（8 位视图）、=（只写）、+（读写）。

static inline unsigned read_cpsr(void)
{
    unsigned v;
    asm volatile ("mrs %0, cpsr" : "=r"(v));
    return v;
}

static inline void write_sctlr(unsigned v)
{
    asm volatile ("mcr p15, 0, %0, c1, c0, 0" :: "r"(v) : "memory");
}

两个「别省」：volatile 与 "memory"

省掉 volatile：编译器认为这段代码没有副作用、输出也没人用，直接删掉，或者提到循环外。

/* 反例：这条会被优化掉 */
asm("mov r0, r0");

/* 正确：空转也要留着 */
asm volatile ("mov r0, r0");

省掉 "memory" clobber：编译器不知道你改了内存，会继续用寄存器里缓存的旧值。

int flag = 0;
asm volatile ("str %0, [%1]" :: "r"(1), "r"(&flag));   /* 没写 : "memory" */
while (!flag) { }                                       /* 编译器把 flag 缓存进寄存器 → 死循环 */

加上 : "memory" 后，编译器每次都会重新从内存读。这就是「为什么延迟循环、写寄存器后要加 memory」的全部原因，不是玄学。

同样，编译器可能把相邻的两次 str 重排（因为它看不出顺序有意义），加 "memory" 也能拦住。

屏障指令：四种，别混用

指令保证典型场景
dmb数据访存顺序（读写不越界）环形缓冲区、DMA 描述符
dsb访存完成（等到真正落地）改页表后、写外设配置后
isb指令流水线冲刷（后续指令按新状态取）改 CPSR/SCTLR、跳转后
sev/wfe事件唤醒多核、低功耗等待

写外设寄存器的标准组合：

writel(v, base + REG);
dsb();          /* 等写真正到达外设，再继续 */

改系统控制寄存器（MMU、cache、异常向量基址）的标准组合：

asm volatile ("mcr p15, 0, %0, c1, c0, 0" :: "r"(v));
isb();          /* 必须：否则后面的指令可能仍按旧状态执行 */

dsb 与 isb 不能互换：dsb 等的是数据访问，isb 冲的是流水线。启用 MMU 那段代码里两个都要，顺序是 dsb → isb。

.S 文件里写函数：三条纪律

纪律一：符号名与 C 一致，不需要修饰（C++ 才需要 extern "C"）

    .global my_delay
    .type   my_delay, %function
my_delay:
    subs r0, r0, #1
    bne  my_delay
    bx   lr
    .size   my_delay, . - my_delay

.type 与 .size 不是必须，但加上以后链接器/调试器能正确识别函数边界，objdump 的分节也更好看。

纪律二：遵守 AAPCS，尤其是「被调用者保存」

改过 r4–r11 必须恢复：

    push {r4-r7, lr}
    ...
    pop  {r4-r7, lr}
    bx   lr

纪律三：Thumb 函数要标 .thumb_func

    .thumb
    .global my_func
    .thumb_func
my_func:
    ...

不标的话，链接器按 ARM 态生成 bl，跳过去发现是 Thumb 代码，立刻异常。

反过来：汇编调 C

    .global _start
_start:
    ldr  sp, =stack_top
    bl   c_main          @ 参数在 r0-r3 里给，返回值在 r0
    b    .

三条注意：

  1. 调用前 sp 必须 8 字节对齐。
  2. 被调函数返回后 r0–r3 里是垃圾，别指望。
  3. 如果 C 函数可能抛异常/用栈很多，栈空间要留足（裸机上通常几百字节起步）。

性能对比：一段 C 与它的 -O0 / -O2

unsigned sum_arr(const unsigned *p, int n)
{
    unsigned s = 0;
    for (int i = 0; i < n; i++) s += p[i];
    return s;
}

-O0 会在栈上给 i 和 s 各开一格，每轮都 ldr/str 一次栈——慢，但你能看懂每一行。

-O2 会用寄存器 + 后索引的 ldr：

    mov  r2, #0
    cmp  r1, #0
    bxle lr
1:  ldr  r3, [r0], #4
    add  r2, r2, r3
    subs r1, r1, #1
    bne  1b
    mov  r0, r2
    bx   lr

七条指令搞定循环。手写要追平这个，需要你自己想到后索引 + subs 融合。这也是为什么说「手写不一定更快」——但你能看懂它快在哪。

本篇验收

  • 能写出读 CPSR 的内联汇编，并说明为什么用 "=r"。
  • 能解释「不加 "memory" 为什么会死循环」，并能说出编译器到底缓存了什么。
  • 能区分 dsb 与 isb，并说出启用 MMU 时的顺序。
  • 能在 .S 文件里写一个守 AAPCS 的函数（push/pop 对称、bx lr 收尾）。
  • 能解释 .thumb_func 不加会发生什么。
