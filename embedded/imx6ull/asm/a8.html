裸机第一条：在这块板子上点灯

第 08 章约 30 分钟🔌 需板子

先摆地址（用之前请按 RM 的 Memory Map 复核一遍）

模块基地址要碰的寄存器
WDOG10x020BC000控制寄存器（偏移 0x00），清看门狗使能位
CCM0x020C4000CCGR1（偏移 0x6C）里的 GPIO1 门控两位
IOMUXC0x020E0000SW_MUX_CTL_PAD_GPIO1_IO03（0x68）、SW_PAD_CTL_PAD_GPIO1_IO03（0x2F4）
GPIO10x0209C000DR 0x00、GDIR 0x04、PSR 0x08

不同开发板（正点原子 MINI/ALPHA、野火、米尔）的 LED 挂在不同 GPIO 上，先看原理图确认「哪个脚、串了多大电阻、是高电平亮还是低电平亮」。下面按「GPIO1_IO03 上的 LED」写，逻辑与脚号无关。

顺序为什么不能乱

关看门狗 → 开模块时钟 → 配引脚复用与电气属性 → 定方向 → 输出
  • 不关狗：上电后看门狗默认可能已使能，代码跑不到几秒就被复位，表现是「灯闪一下就重来」。
  • 不开时钟：模块时钟没开，写它的寄存器不会报错，只是静默无效（读回全 0）。i.MX6 上访问未开时钟的模块还可能触发总线 abort。
  • 不配 MUX：脚上的信号还连着别的功能（UART、I2C…），你写的 GPIO 寄存器根本影响不到它。
  • 不配 PAD_CTL：驱动能力/上拉没设，可能推不动 LED 或读不到按键。

这四步的顺序，跟你在 u-boot 里看到的 board_init_f 一模一样——外设初始化永远是「先电后钟再引脚」。

完整代码：纯汇编点灯

.text
.global _start
_start:
/* ① 关看门狗：清控制寄存器里的使能位 */
    ldr  r0, =0x020BC000
    ldr  r1, [r0]
    bic  r1, r1, #0x4                  @ 使能位（位 2）清 0
    str  r1, [r0]

/* ② 开 GPIO1 时钟：CCGR1 里对应两位写 11 */
    ldr  r0, =0x020C406C
    ldr  r1, [r0]
    mov  r2, #3
    lsl  r2, r2, #26                   @ 3 → bit[27:26]
    bic  r1, r1, r2
    orr  r1, r1, r2
    str  r1, [r0]

/* ③ 配引脚：MUX 与 PAD 两组都要写 */
    ldr  r0, =0x020E0068               @ SW_MUX_CTL_PAD_GPIO1_IO03
    mov  r1, #5                        @ ALT5 = GPIO
    str  r1, [r0]

    ldr  r0, =0x020E02F4               @ SW_PAD_CTL_PAD_GPIO1_IO03
    ldr  r1, =0x10B0                   @ 驱动强度/速率/上下拉组合，按参考板取值
    str  r1, [r0]

/* ④ 方向：GDIR 的 bit3 置 1 → 输出 */
    ldr  r0, =0x0209C004
    ldr  r1, [r0]
    orr  r1, r1, #0x8
    str  r1, [r0]

/* ⑤ 翻转：异或就是翻转 */
    ldr  r0, =0x0209C000               @ GPIO1_DR
loop:
    ldr  r1, [r0]
    eor  r1, r1, #0x8
    str  r1, [r0]
    bl   delay
    b    loop

/* 一个粗延时：r0 从 0x400000 往下数 */
delay:
    ldr  r0, =0x400000
1:  subs r0, r0, #1
    bne  1b
    bx   lr

几个刻意的细节：

  • ① 用读改写而不是直接 mov r1,#0; str，因为那个寄存器里除了使能位还有其它字段（超时值）。手写时也不要图省事整写。
  • ② 里 bic 与 orr 用同一个 r2，写成「先清后置」——顺序反了就变成全 0。
  • ⑤ 用 eor r1, r1, #8 而不是 str #8 / str #0 两条，一条指令完成翻转，也能顺便看见「异或=翻转」这个用法。
  • delay 里的 subs 必须带 s，否则 bne 用的还是上次的标志——循环次数会错到离谱。

加一段真正的启动骨架

纯裸机还要有向量表和栈。i.MX6ULL 从上电到你的代码，中间是 Boot ROM：

上电 → Boot ROM 读启动设备 → 找 IVT（镜像头，含入口地址与 DCD）
     → 按 DCD 初始化 DDR → 跳到你的入口

所以你的镜像头部需要 IVT + DCD（这是 u-boot 里的 imx6ull_ivt/dcd 段），它不是代码，是一张「告诉 Boot ROM 怎么初始化 DDR」的表。用小工具（mkimage、MFG Tool、uuu）生成通常最省事。

_start 里第一段代码应该做：

_start:
    cpsid  if                  @ 先关中断，别让异常打断初始化
    ldr    sp, =stack_top      @ 栈必须先有，否则任何 C 调用都会踩空
    bl     clear_bss
    bl     c_main              @ 进 C
1:  b      1b
    .ltorg                     @ 常量池就近放，避免超出 ldr 范围

cpsid if 是 CPSR 的写操作伪指令：关 IRQ 与 FIQ。ldr sp, =stack_top 用的是前面讲的常量池——栈必须先有，不然 bl clear_bss 一系列 push 会写到随机地址。

上板验证的三种路径

路径做法适用
烧到 SD/TF 卡生成 .img（带 IVT/DCD）放卡首，拨码选 SD 启动最常见的裸机验证
uuu / MFG ToolUSB OTG 连电脑，直接下载到 DDR 运行不擦卡，改动快
u-boot 下 go先停在 u-boot，用 mw 写寄存器、go addr 跑只想验几行指令

第三种最灵活：在 u-boot 命令行里

=> mw 0x0209C004 0x00000008      # 直接置 GDIR
=> mw 0x0209C000 0x00000008      # 置 DR

灯就亮了——这相当于用 u-boot 帮你做完前面所有准备，只验最后两步。反过来说，如果 mw 能让灯亮而你的汇编不能，问题一定在前面三步（狗/时钟/复用）。

失败对照表

现象最可能的原因
灯完全不亮，串口也没输出没关看门狗（几秒复位）；或栈没设，bl 就飞了
灯偶尔闪一下然后重来看门狗复位循环
mw 能让灯亮，烧的镜像不行MUX/PAD 没配，或时钟没开
灯常亮但翻转不了方向寄存器没设成输出（GDIR 还是输入）
烧进去完全没反应镜像头（IVT/DCD）不对，Boot ROM 没认；或启动拨码不对

本篇验收

  • 能默写五步顺序，并解释每一步「不做会怎样」。
  • 能说清为什么 delay 里必须 subs 而不是 sub。
  • 能解释 IVT/DCD 是什么、为什么它不是代码。
  • 能说清 _start 里「先关中断、再设栈」的理由。
  • 在板子上跑通一次，并故意注释掉「开时钟」那一行，观察现象（这是最有价值的一次对照实验）。
