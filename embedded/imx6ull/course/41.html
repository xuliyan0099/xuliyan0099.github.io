第 41 课 · 根文件系统：让系统「能用」的那一堆文件

内核起来了，但它只会「管理资源」，不会「做事」。要有一个 shell、能执行命令、能挂载、能登录，需要一份最小的用户态集合——根文件系统。这一课讲清它最少要有什么、怎么构出来、以及为什么嵌入式常用「只读 + overlay」。

这一课要回答的问题

① 最小 rcS 长什么样？② busybox 为什么这么小？③ 静态与动态链接怎么选？④ 为什么嵌入式常用只读根 + overlay？⑤ 怎么在 PC 上先把 rootfs 搭好？

1. 一个真实的启动脚本

# /etc/inittab（busybox 格式）
::sysinit:/etc/init.d/rcS
::askfirst:-/bin/sh
::ctrlaltdel:/sbin/reboot

# /etc/init.d/rcS
#!/bin/sh
mount -t proc  none /proc
mount -t sysfs none /sys
mount -t devtmpfs none /dev 2>/dev/null || mdev -s
ifconfig eth0 192.168.1.10 up
# 启动你的应用
/usr/bin/myapp &

整个系统的「开机流程」就这么几行。这也是嵌入式调试的入口：应用起不来时，先看 rcS 有没有执行到那一行。

2. busybox：一个二进制，几百个命令

busybox 把所有常用命令编进一个可执行文件，靠「看自己被叫什么名字」分派功能。所以 /bin/ls 其实只是一个指向 busybox 的符号链接。

# 静态编译（推荐给嵌入式）
make ARCH=arm CROSS_COMPILE=arm-linux-gnueabihf- defconfig
make menuconfig     # 选 static、选需要的命令
make && make install

# 结果
file _install/bin/busybox     # 应为 statically linked
ldd  _install/bin/busybox     # 静态时为 "not a dynamic executable"

静态版的好处是「零依赖」——把整个 rootfs 拷到任何 ARM 板子都能跑。代价是体积大一点（约 1MB），但对根文件系统来说完全值得。

4. 三种构建方式

方式做法适用
手工busybox + 手写 rcS + 手拷库学习、极简系统
Buildroot配置菜单 → 自动生成完整 rootfs + 交叉工具链大多数嵌入式项目
Yocto配方化、可复现、支持多层定制产品化、长期维护

学习阶段用「手工」最有价值——你会踩到「忘了拷 ld.so 导致所有命令都不能执行」这种经典坑，从而真正理解动态链接。做产品时用 Buildroot 或 Yocto。

6. 自测与动手

1

最小 rootfs 至少要哪几样？

看答案

可执行的 init（或 shell）、/dev 与 /proc 挂载、必要的库（动态时）、基本配置。

2

busybox 怎么能用一个文件提供几百个命令？

看答案

靠 argv[0]（自己被调用的名字）分派到对应功能，其余名字都是符号链接。

3

为什么会报「文件不存在」但文件明明存在？

看答案

缺动态链接器 ld-linux.so，内核找不到解释器，报 ENOENT。

4

只读根 + overlay 解决什么问题？

看答案

避免断电损坏与 Flash 磨损，同时保留「可改」的使用体验。

5

Buildroot 与手工搭建的核心差别？

看答案

Buildroot 自动处理依赖、库、工具链并生成镜像；手工要自己盯每一件。

  1. 在 PC 上用静态 busybox 搭一个 rootfs 目录。
  2. 用 chroot 进去跑几个命令，验证能工作。
  3. 故意删掉 ld.so，观察「文件不存在」的报错。
  4. 把它打成 ext4 或 squashfs 镜像，挂到板子上启动。
