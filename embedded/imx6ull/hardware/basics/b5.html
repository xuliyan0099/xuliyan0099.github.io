时间：时钟、建立保持、抖动、消抖

第 05 章约 24 分钟★★ 核心含互动工具

数字电路有一个隐含前提：等一等

所有「时钟沿采样」的动作，都默认两件事成立：

  1. 数据在沿之前已经稳定（建立时间 setup）。
  2. 数据在沿之后还能保持（保持时间 hold）。

这两条来自电路的真实物理：门有延迟，走线有延迟，负载有电容。「等一会儿」不是保守，是硬性要求。

时钟：不是方波就行

理想时钟是完美方波，实际时钟有四个指标：

指标含义坏了会怎样
频率每秒多少个周期太快 → 来不及建立
占空比高电平占的比例偏了 → 半周期不够用
上升/下降时间边沿斜率太慢 → 噪声窗口变长、易误触发
抖动（jitter）边沿位置在抖有效时间窗缩短，高速时致命

i.MX6ULL 的主时钟从 24MHz 晶振进来，经 PLL 倍频再分频给各模块。每个模块的频率都不是随便设的——它受「模块自身上限」与「外部器件时序」双重限制（这就是为什么 Datasheet 的 AC 表与驱动的 max-frequency 是同一个来源）。

建立/保持：一张图就够了

        ┌───────┐
CLK ────┘       └───────
        │←setup→│←hold→│
DATA ───╳═══════╳═══════╳──
        数据必须在 沿 前后 这段时间内保持不变

违反的后果：

  • 违反 setup：数据来得太晚，被采到的是上一次的值。表现为「偶尔少一位」「数据总是慢一拍」。
  • 违反 hold：数据变得太早，被采到的是新值。表现为「偶尔提前」「错位」。

两者都不是每次必现，因为延迟随温度、电压、批次漂移。这就是「实验室好的，量产坏了」的经典成因。

抖动的两个来源与软件的对策

机械抖动（按键）：金属弹片在接触瞬间弹跳几毫秒，产生一串边沿。软件对策有两种：

  • 延时消抖：检测到变化后等 10–20ms 再读一次。
  • 定时采样：每 5ms 采一次，连续 N 次一致才认。

电气噪声（开关电源、电机、长线）：高频尖峰。硬件对策：

  • RC 低通（串电阻 + 对地电容）。
  • 施密特触发器输入（带滞回，抗噪声）。
  • TVS 钳位。

RC 充放电：硬件消抖的数学

电容电压按指数上升：

U(t) = U0 · (1 − e−t/τ)　　τ = R·C

三个经验值（必记）：

  • 1τ → 63.2% 满幅
  • 2τ → 86.5%
  • 5τ → 99.3%（工程上认为「充满」）

「到达某个阈值需要多久」由反解得到：

t = −τ · ln(1 − Uth / U0)

这就是「为什么 10kΩ + 100nF = 1ms 量级」：τ = 10k × 100n = 1ms，2τ 就是 2ms，正好覆盖按键的抖动窗口。

RC 充放电曲线 · 改 R、C、阈值看时间

输入单位：R 用 kΩ、C 用 µF、阈值用「满幅比例」（0–1）。绿线标出「到达阈值的时间点」。

三组值得试的：

  • 10k / 0.1µF / 0.5 → τ=1ms，到 50% 约 0.69ms（按键消抖的量级）。
  • 10k / 0.1µF / 0.9 → 约 2.3ms（更保守的阈值）。
  • 1k / 0.1µF / 0.5 → τ=0.1ms，太快，消抖不够。

复位电路也是 RC

板子上的复位按键旁边通常有「R + C」：按下拉低，松开后电容慢慢充电，让复位信号延迟释放。这是同一个公式的另一个用途：把「瞬间动作」变成「持续一段时间的信号」。

同理，上电复位（POR）电路也是 RC：电源上升后，复位保持一段时间，等电源稳定再放开 CPU。这段时间不够，CPU 会在电源还没稳时启动，表现为「有时能启动、有时不能」。

本篇验收

  • 能说出 setup/hold 违反各自的现象。
  • 能解释「为什么违反时序是偶发的」，以及温度/电压/批次的影响。
  • 能默写 τ=RC 与 1τ/2τ/5τ 三个经验值。
  • 能用公式算出「到达 50% 需要多久」。
  • 能解释「复位电路本质上是一个 RC 延时」。
  • 能用工具把 τ 调成 1ms 与 0.1ms，并说出哪个适合消抖。
