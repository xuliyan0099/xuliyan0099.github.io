拿到手册，先做四件事

第 01 章约 18 分钟★ 必读

这四件事，顺序不能反

① 建索引（知道词在哪） → ② 画内存图（知道东西在哪）
     → ③ 找时钟树（知道它靠谁活） → ④ 贴引脚表（知道它接到哪个脚）

四件事做完，你手上就有了一张「自己版的手册摘要」，之后查任何外设都是查自己这张纸。

① 建索引：只做三件事

第一件：确认书签全不全。 从官网下的 PDF 通常带书签，但有人给的是「扫描合并版」，书签全丢。丢了的补救办法不是手工加，而是——用寄存器名直接全文搜。搜寄存器名比搜模块名准得多：搜 UART_URXD 会直接落到寄存器表，搜 UART 会命中几百处。

第二件：抄一张缩写表。 RM 前几页有一张 "Table of acronyms"，把你不认识的十个缩写抄下来。i.MX 的手册大量使用缩写，且同一个缩写在不同章节含义可能不同（比如 SRC 是 System Reset Controller，不是 source）。

第三件：把「三张总表」的页码写下来。

总表在哪用来干什么
Memory MapIntroduction 章 / System Memory Map查基地址
Signal Multiplexing（引脚复用总表）IOMUXC 章末尾查脚能复用成什么
Clock Tree（时钟树图）CCM 章查某模块的时钟从哪来

页码写在一张便签上，比每次翻目录快十倍。

② 画内存图：先画「三个圈」

i.MX6ULL 的地址空间不是平的，按访问路径分成几段。你不需要背所有地址，只需要知道「我要找的东西在哪一段」：

0x0000_0000 ───────── 片上 ROM / Boot ROM（只读，固化代码）
0x0001_0000 ───────── 片内 OCRAM（小容量高速 SRAM）
0x0090_0000 附近 ──── 部分外设（视具体型号映射）
0x0200_0000 起 ────── AIPS 段：绝大多数外设寄存器（UART/I2C/GPIO/CCM/IOMUXC…）
0x8000_0000 起 ────── DDR 段：外部内存（容量看板子）
0xFFFF_0000 附近 ──── 私有外设（GIC、SCU、定时器等，属 Cortex-A7 核）

画这张图的目的：判断「这个模块的寄存器是读一次要几十周期的慢速外设，还是核内的快速外设」。 前者访问要经过总线桥，后者不用。这个差别在后面写延迟敏感的代码时会出现（比如中断里读 GIC 和读 UART 的代价不同）。

具体每段的边界与每个模块的基地址，一律以 RM 的 Memory Map 为准；这张图只用来「定方位」，不用来「背数值」。

③ 找时钟树：三问

外设不工作，八成是时钟没开。查时钟，只问三句：

  1. 这个模块的时钟从哪个 PLL 来？ CCM 章的时钟树图会画出来（PLL1/PLL2/PLL3/PLL528/PLL_ENET 等）。
  2. 它有没有分频器 / 门控？ 门控就是 CCGRx 寄存器里的两位；分频在 CACRR、CSCDRx 等寄存器里。
  3. 开它的顺序有要求吗？ 有些模块要求「先停时钟，改配置，再开时钟」，有些要求「设置 PLL 后等锁定」。这些写在模块章的 "Initialization" 小节，不在寄存器表里。

一个实用的对照方法：内核里这个外设的驱动是怎么开时钟的——clk_prepare_enable() 后面跟的名字（比如 uart1_ipg）就是时钟树里的节点名。用节点名回到 CCM 章找，比从模块名倒推快。

④ 贴引脚表：一根线四个名字

同一个物理脚，在不同语境下叫四个名字：

语境叫法例子
原理图网络名设计者起的LED_RED
封装球号BGA 上的坐标A15
数据手册引脚名引脚的功能名GPIO1_IO03
IOMUXC 寄存器名可写的那个SW_MUX_CTL_PAD_GPIO1_IO03

做法：拿一张纸（或一个表格文件），四列——网络名 / 球号 / 引脚名 / 复用寄存器名。每用到一根线就填一行。 十行之内你会发现规律：引脚名与寄存器名只差一个 SW_MUX_CTL_PAD_ 前缀，但不是所有脚都遵循这个前缀（有的叫 SW_MUX_CTL_PAD_，有的叫 SW_MUX_CTL_GRP_ 用于整组，还有 SELECT_INPUT 用于输入选择）。

这张表填满三十行左右，你查引脚就不需要再翻手册了。

一张「自己的摘要」长什么样

== UART1 ==
基址      0x02020000            （Memory Map）
时钟      uart1_ipg / uart1_uart（CCM 时钟树 + dts）
门控      CCGR5 里某两位         （CCM 寄存器表）
关键位    UCR1.UARTEN(bit0) / UCR2.SRST(bit0)
坑        先写 UCR2 的 SRST 清 FIFO，再置 UARTEN

每一行右边括号里写「这个结论从哪来」。这是最有价值的部分：下次结论不对时，你知道该回去翻哪份材料，而不是重头再猜。

本篇验收

  • 能说出为什么「搜寄存器名」比「搜模块名」快。
  • 能画出 i.MX6ULL 地址空间的「三个圈」，并说出画它的用处。
  • 能对一个陌生外设问出时钟的三个问题。
  • 能写出一个引脚的四种名字，并指出你的板子上哪根线对应哪个脚。
