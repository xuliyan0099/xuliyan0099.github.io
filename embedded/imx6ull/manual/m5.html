四个真实例子：从手册到代码

第 05 章约 32 分钟★★ 核心

四个例子，四个层次

CCM     → 模块「有没有电」        （时钟门控）
IOMUXC  → 引脚「通向哪里」        （复用 + 电气）
UART    → 模块「怎么工作」        （模式、FIFO、状态）
GPIO    → 最简单的位操作          （方向、数据、中断）

每个例子都写清三件事：手册哪一行 → 代码哪一句 → 写错会怎样。地址一律以 RM 的 Memory Map 为准，下面给的是常见取值，换板子/换实例要重查。

例一：CCM —— 给 GPIO1 开时钟

手册：CCM 章的 CCGR1 寄存器，每 2 位管一个模块时钟，00 关、11 开（01/10 通常也视为开，但别用中间值偷懒，语义不明确）。

代码：

#define CCM_CCGR1  (0x020C4000 + 0x6C)

/* 模块 13 对应 bit[27:26]（以 RM 表为准） */
u32 v = readl(CCM_CCGR1);
v &= ~(3u << 26);
v |=  (3u << 26);
writel(v, CCM_CCGR1);

写错会怎样：不报错，静默失效。写这个 GPIO 的寄存器读回全 0，且往往「有时又能用」——因为别的驱动已经替这个模块开了时钟。这类 bug 最难查，因为它取决于初始化顺序。

一句话总结：先清后置，别整写，别用中间值。

例二：IOMUXC —— 把引脚交给 GPIO

手册：IOMUXC 章有两张关键表——

  • SW_MUX_CTL_PAD_*：选功能（MUX_MODE，3 位）。
  • SW_PAD_CTL_PAD_*：定电气属性（驱动强度、速率、上下拉、开漏等）。

代码：

#define MUX_GPIO1_IO03   (0x020E0068)   /* SW_MUX_CTL_PAD_GPIO1_IO03 */
#define PAD_GPIO1_IO03   (0x020E02F4)   /* SW_PAD_CTL_PAD_GPIO1_IO03 */

writel(5, MUX_GPIO1_IO03);      /* ALT5 = GPIO（ALT 号按复用总表） */
writel(0x10B0, PAD_GPIO1_IO03); /* 电气配置，参考板上实测/官方取值 */

写错会怎样：

  • MUX_MODE 写错 → 引脚还连着 UART/I2C，你改 GPIO 寄存器完全无效。
  • PAD_CTL 不配 → 可能推不动负载（驱动太弱），或输入悬空（没上拉）。
  • 整写 MUX 寄存器 → 顺手把 SION 等位清掉，输入回读路径失效。

注意 PAD_CTL 的值不是「随便一个数」：它是有位域语义的组合（驱动强度档位、 slew rate 档位、pull 类型）。官方 BSP 与参考板给的 0x10B0 是「已知能跑」的组合，先用它，再按需调。

例三：UART —— 从「模块端口」到「能收发」

手册：UART 章的顺序是 Overview → Block Diagram → Signal Descriptions → Functional（含 FIFO 与错误处理）→ Register → Initialization。

关键寄存器（偏移以 RM 为准）：URXD（收）、UTXD（发）、UCR1（含 UARTEN）、UCR2（含 SRST、RXEN、TXEN）、USR1/USR2（状态）、UBIR/UBMR（波特率分子分母）。

正确的初始化顺序（照 Initialization 小节）：

/* 1. 关模块 */
v = readl(UART1 + UCR1); v &= ~1u; writel(v, UART1 + UCR1);

/* 2. 软复位：写 SRST=1，等它自己清 0 */
writel(1u, UART1 + UCR2);
while (readl(UART1 + UCR2) & 1u) { }

/* 3. 配波特率（分子/分母） */
writel(bir, UART1 + UBIR);
writel(bmr, UART1 + UBMR);

/* 4. 配帧格式、使能收发 */
v = readl(UART1 + UCR2);
v |= (1u << 1) | (1u << 2);        /* RXEN | TXEN */
v &= ~(1u << 8);                   /* 8 位数据、无校验之类，看表 */
writel(v, UART1 + UCR2);

/* 5. 最后才使能模块 */
v = readl(UART1 + UCR1); v |= 1u; writel(v, UART1 + UCR1);

写错会怎样：

  • 先使能再复位 → 带着旧 FIFO 数据启动，第一帧全是垃圾。
  • 波特率算错 → 收到的全是乱码（不是收不到，是收错）。
  • 没配 MUX → UART 模块里 USR1 显示发送完成，但引脚上什么也没有。

例四：GPIO —— 最小闭环

手册：GPIO 章的寄存器很少，DR（数据）、GDIR（方向）、PSR（引脚状态）、ICR1/2（中断配置）、IMR（中断屏蔽）、ISR（中断状态，多为 W1C）。

完整闭环：

writel(readl(GPIO1 + GDIR) | (1u << 3), GPIO1 + GDIR);  /* 输出 */
writel(readl(GPIO1 + DR)  ^ (1u << 3), GPIO1 + DR);     /* 翻转 */

/* 读引脚真实电平：读 PSR，不是读 DR */
v = readl(GPIO1 + PSR) & (1u << 3);

DR 与 PSR 的区别是这块最容易错的地方：DR 是你「想输出什么」，PSR 是「引脚上实际是什么」。输出模式下两者一般一致；输入模式下 DR 无意义，必须读 PSR。用 DR 判断按键，会出现「按键永远读不到」。

中断部分：ICR1 每两位管一个脚，配「上升沿/下降沿/双边/低电平」；IMR 是屏蔽位；ISR 是 W1C——清中断必须写 1。

手册里的一行代码里的一行错一个的后果

本篇验收

  • 能解释为什么 CCM 写错是「静默失效」，而 UART 写错是「有状态但乱码」。
  • 能说出 MUX_MODE 与 PAD_CTL 各自解决什么问题。
  • 能默写 UART 的五步初始化，并说出每一步跳过的后果。
  • 能解释 DR 与 PSR 的差别，并说明为什么按键必须读 PSR。
  • 能说出 GPIO 中断里 ICR/IMR/ISR 各管什么，以及 ISR 的 W1C 特性。
