Datasheet 怎么读：只读五处

第 02 章约 22 分钟★ 必读

Datasheet 只值得读五处

它比 RM 短得多（几十页到一百多页），但里面真正对「写代码的人」有用的只有五处。其余（封装尺寸、回流焊曲线、卷带包装）是给生产和画板用的。

#章节对写代码的人有什么用
①Ordering Information确认手上这颗是什么料号，主频/温度/封装
②Absolute Maximum Ratings知道「超了会烧」，用来判断硬件是否被误接
③Electrical Characteristics（DC/AC）电平门限、驱动电流、时序参数
④Signal Multiplexing / Pin Descriptions引脚有哪些功能（完整表在 RM）
⑤Package / Ball Map定位球号，与原理图对照

① Ordering Information：先确认「你手上是哪颗」

料号后缀通常编码三件事：温度等级、封装、最高主频。比如同一家族里，「工业级 + BGA + 528MHz」与「消费级 + BGA + 528MHz」是两个不同料号，Datasheet 的电气参数也可能略有差别（主要是温度范围）。

为什么这对写代码重要：主频不同，你在裸机里算的延时循环次数就不同；温度等级不同，某些模块的最高频率限制也不同（DDR 时钟尤其明显）。写死一个循环次数然后换板子，现象就是「延时长了 20%」。

② Absolute Maximum Ratings：只读，不设计

这一节给的是「超过就可能永久损坏」的极限值，不是工作范围。典型项目：每路电源的极限电压、IO 的极限输入电压、存储温度、ESD 等级。

它是排查硬件损伤的第一依据：一个脚被误接 5V（而它的绝对最大是 3.6V），即使当时还能用，也可能已经击穿了 ESD 结构——表现是「这个脚读出来一直是 1」或「驱动能力明显变弱」。这类故障软件层面无法修，只能换片子。

③ Electrical Characteristics：三个必看参数

（a）输入电平门限 VIH / VIL

这是判断「什么算高电平」的唯一依据。i.MX6ULL 的 IO 多为 3.3V 域，典型 VIH 约为 0.7×VDD_IO、VIL 约为 0.3×VDD_IO（具体数值以 Datasheet 表格为准，不同 IO 域可能不同）。它的直接后果：

  • 你用 1.8V 的器件去驱动 3.3V 域的输入，可能永远读不到 1（达不到 VIH）。
  • 反过来 3.3V 输出驱动 1.8V 器件，可能超过对方的绝对最大。

所以做电平转换不是「加个电阻就行」，得看两边门限。

（b）输出驱动能力 / VOH / VOL

VOH 是「输出高电平时至少能到多少伏」，且是在某个负载电流下标定的。含义：驱动电流越大，输出电压越往下掉。这就是为什么 LED 要串限流电阻、为什么长排线要加缓冲器——不是「信号不够强」，是「电压被拉下来了」。

（c）AC 时序参数

总线（I2C、SPI、SD/eMMC）都有一张时序表：上升沿到采样沿要多久、数据保持多久。这份表决定了你在驱动里能把时钟设多快。 内核里那些 max-frequency 属性就是从这里推出来的。

④ Signal Multiplexing：只看「这个脚有没有我要的功能」

Datasheet 里的引脚表通常只给「球号 → 引脚名 → 默认功能」，完整的复用列表在 RM 的 IOMUXC 章。读法：

  1. 先在原理图找到网络名 → 对应球号。
  2. 用球号在 Datasheet 的 ball map 找到引脚名（如 GPIO1_IO03）。
  3. 回 RM 的 Signal Multiplexing 表，看这一行的 ALT0–ALT7 各是什么，选你要的那个 ALT 号。
  4. 那个 ALT 号就是要写进 MUX_MODE 的值。

一个常见误区：以为 ALT 号越小越好。不是，ALT0 通常是最「普通」的功能（比如 GPIO 往往在 ALT5），没有优先级，只看你要哪个。

⑤ Ball Map：唯一的作用是对号

画板的人用它布线上；你用它做一件事：确认「原理图上标的球号，和你以为的那个脚是同一个」。

这一步经常救命。板子上标 GPIO1_IO03，但实际连的是球 A15，而 A15 在封装上对应的引脚名可能是另一个——如果厂商的原理图符号标错了（这种情况真实存在），你写的代码会打在空处。

一个完整的「Datasheet 五处」查法示例

场景：板子上一个按键，按下去没反应。

  1. Ordering：确认板子是 i.MX6ULL 哪个料号（不影响本次，但先确认）。
  2. Ball map：按键网络名 → 球号 → 引脚名，比如 GPIO1_IO05。
  3. Signal Multiplexing（在 RM）：确认这个脚的 ALT 里有 GPIO 功能，记下 ALT 号。
  4. Electrical：确认按键那一路有上拉（否则悬空读到的值是随机的，表现为「有时好有时坏」）。
  5. Absolute max：确认按键直接接 3.3V 而没有串电阻时，是否还在极限内（短接到地时是靠内部上拉限流，不是靠电阻）。

这五步里有四步都在 Datasheet/RM 之间来回，这就是为什么 01 篇要求先把「引脚四名字表」建好。

本篇验收

  • 能说出 Datasheet 里哪五处对写代码有用，其余为什么可以跳过。
  • 能解释 VIH/VIL 为什么会让「1.8V 驱动 3.3V」失败。
  • 能解释 VOH 是在什么条件下标定的，以及它和「串限流电阻」的关系。
  • 能给一个具体场景（比如按键无反应），走完五处查法。
