虚拟地址是什么

每个 32 位进程都以为自己拥有整个 4GB 空间，起始地址是 0x00400000，栈在 0xBFFF_xxxx。但板上只有 512MB DDR，还同时跑着几十个进程。这中间的魔法叫 MMU：CPU 发出的每个地址都先被翻译一次，才落到物理内存上。

★ 一读 纯读约 1 小时 左侧是本卷目录 理论为主 · 实作可跳

这一课要回答的问题

① 为什么要虚拟地址？② MMU 怎么翻译？③ 页是多大？④ 内核空间在虚拟地址的哪里？⑤ 没有 MMU 的 MCU 怎么办？

1. 三个好处

好处没有 MMU 会怎样有了 MMU
隔离一个程序写错地址就改到别人数据，甚至改内核页权限挡住，越界直接 SIGSEGV
简化链接每份程序必须知道自己的物理地址，加载到别处就得重定位统一链接到固定虚拟地址，随便放
共享与节省libc 在每个进程占一份物理内存同一份物理页映射到多个进程

再加一条：按需分配。malloc 100MB 不会立刻占 100MB 物理内存，只有第一次写才真分配（第 26 课）。

2. 翻译过程：一次查表

32 位 ARM 常用两级页表，页大小 4KB：

MMU 里有个小表叫 TLB（Translation Lookaside Buffer），缓存最近翻译过的页。TLB 未命中比 Cache 未命中更贵——因为它要读页表，而页表本身可能又不在 Cache 里，形成「两次内存访问」。

3. Linux 的地址空间划分

# 典型的 32 位 Linux 划分（3G/1G）
0x0000_0000 - 0xBFFF_FFFF   用户空间（3GB）
0xC000_0000 - 0xFFFF_FFFF   内核空间（1GB，所有进程共享）

# 内核空间里：
#   0xC000_0000  直接映射物理内存（线性映射，phys = virt - 0xC0000000）
#   0xE000_0000  vmalloc 区
#   0xF000_0000  外设寄存器（ioremap 之后映射到这里）

# 查看当前布局：
cat /proc/self/maps      # 用户态进程的映射
cat /proc/vmallocinfo    # 内核 vmalloc 使用情况

「内核空间所有进程共享」这一点很重要：进入内核态时不需要换页表（只改 ASID/权限），所以系统调用比进程切换便宜得多。

4. 一个具体的映射例子

// 用户态进程里，代码虚拟地址 0x0040_0000
// 实际可能落在物理 0x80A0_0000
// 你完全无法从用户态知道（也不需要知道）

// 而访问外设要「绕过」这套映射：
void __iomem *base = ioremap(0x0209C000, 4096);   // 内核里
writel(1 < 26, base + 0x04);

ioremap 做的事就是在虚拟空间里新建一段映射，指向那段物理设备地址，并标记为「不可缓存、不允许乱序」。

5. 没有 MMU 的 MCU

STM32 这类 Cortex-M 通常没有 MMU（有 MPU，只能做区域保护，不能翻译）。所以：

  • 所有地址就是物理地址，程序必须链接到它真正要运行的地址。
  • 没有进程隔离，只有「一个程序 + 中断」。
  • 不能用 Linux（Linux 需要 MMU；有 uClinux 但限制很多）。

i.MX6ULL 有 MMU，所以能跑完整 Linux——这正是一块 SoC 能不能上 Linux 的第一道门槛。

7. 自测与动手

1

虚拟地址的主要好处有哪三个？

看答案

进程隔离（权限）、链接简化（统一地址）、共享与按需分配（同一物理页多映射）。

2

4KB 页的虚拟地址，页内偏移占几位？

看答案

12 位（2^12 = 4096），剩下的 20 位用于页表索引。

3

TLB 是干什么的？为什么重要？

看答案

缓存虚拟页到物理页的翻译。命中只多几周期；未命中要读页表（可能再未命中），代价可达几十到上百周期。

4

为什么系统调用比进程切换便宜？

看答案

内核空间在所有进程间共享，进入内核不需要换页表；进程切换要换页表、刷 TLB、清流水线。

5

用户态能直接写 0x0209C000 吗？为什么？

看答案

不能。该地址在用户进程页表里没有映射，访问会触发缺页异常并被内核以 SIGSEGV 终止。

  1. 在 Ubuntu 上 cat /proc/self/maps，找出代码段、堆、栈、共享库各在哪个虚拟区间。
  2. 用 pmap <pid> 看一个进程的物理占用，对比虚拟大小。
  3. 写一段 C 故意访问 0x0209C000，观察 SIGSEGV。
  4. 在驱动里用 ioremap 映射 GPIO，再读写验证。
