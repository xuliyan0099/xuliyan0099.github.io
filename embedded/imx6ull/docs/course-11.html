ALU 与标志位

ALU 是 CPU 里唯一「真的在算数」的部件。但它不是一堆独立电路，而是一组电路 + 一个多路选择器：opcode 决定选哪一路输出。这一课讲 ALU 的内部结构，讲五个标志位怎么被算术「顺手」产出，再讲 ARM 最漂亮的特性——条件执行：不跳转也能分支。

★ 一读 纯读约 1 小时 左侧是本卷目录 理论为主 · 实作可跳

这一课要回答的问题

① ALU 为什么能一个周期做多种运算？② 五个标志位分别从哪来？③ 条件执行怎么做到「不跳转就分支」？④ 为什么 ARM 的移位器是「免费」的？⑤ 一条 adds 和一条 add 差了什么？

1. 直觉：一排计算器，一个开关

想象五台计算器并排放在桌上：一台只做加法、一台只做减法、一台做与、一台做或、一台移位。你把同样的两个数同时喂给五台，然后按一个开关只让其中一台的结果登上屏幕。这就是 ALU。

失效处：五台同时算，功耗是五份（虽然翻转少时耗电也少）。所以现代 ALU 会做「功能分组复用」——比如加法器同时兼做减法、比较、加一、减一，靠控制位切换。

2. 硬件上：ALU 的输入输出

端口内容来源
A32 位被操作数寄存器 Rn
B32 位操作数寄存器 Rm（可先经移位器）
op4~5 位功能码译码器
Cin进位输入减法/带进位加
Y32 位结果→ 寄存器堆 / 地址 / 分支
N Z C V4 个标志→ CPSR

ARM 的移位器接在 B 端口前：add r0, r1, r2, lsl #3 的意思是 r0 = r1 + (r2 << 3)，移位不占额外指令、不占额外周期。这就是「免费移位」的由来，也是 ARM 代码密度高的一个重要原因。

3. 标志位是被「顺手」产生的

N、Z、C、V 在第 06 课已经讲过来源。这里要强调的是它们的使用方式：它们只在下一条指令执行前有效，是「一次性」的。所以代码里常见的模式是紧挨着写的：

cmp  r0, #0        ; 做 r0 - 0，只更新标志，不写结果
beq  zero_label    ; 若 Z=1（相等）则跳
addne r1, r1, #1   ; 若不相等才执行这条加法

注意第三条：addne 是「条件执行的加法」——条件不满足时它不写结果、不更新标志，但也不跳转，流水线不打断。

4. 为什么 adds 和 add 不同

ARM 的数据处理指令有一个 S 位：置 1 时才更新标志。这个位不是「小细节」，而是性能设计：循环里大部分加法不需要标志（省下写 CPSR 的动作，也避免标志依赖串行化）。编译器会聪明地只在真正需要时加 S。

反过来说，标志位写回是流水线里一个讨厌的依赖点：如果每条指令都写 CPSR，下一条读 CPSR 就得等，形成长依赖链。这是「为什么不要滥用条件执行」的原因之一——现代 CPU 里条件执行过多反而会因为依赖链变慢。

5. 实验：用 Python 造一个 8 位 ALU

def alu(a, b, op, cin=0, bits=8):
    mask = (1 << bits) - 1
    if   op == "add": r = a + b + cin
    elif op == "sub": r = a + (~b & mask) + 1
    elif op == "and": r = a & b
    elif op == "or":  r = a | b
    elif op == "xor": r = a ^ b
    elif op == "lsl": r = a << b
    else: raise ValueError(op)
    res = r & mask
    c = 1 if r > mask else 0                # 无符号进位
    n = (res >> (bits-1)) & 1               # 符号位
    z = 1 if res == 0 else 0
    # 溢出：两操作数同号且结果异号
    sa, sb = (a >> (bits-1)) & 1, (b >> (bits-1)) & 1
    v = 1 if (sa == sb and ((res >> (bits-1)) & 1) != sa) else 0
    return res, {"N":n, "Z":z, "C":c, "V":v}

for op in ("add","sub","and","or","xor"):
    print(op, alu(0b0111_1000, 0b0000_1001, op))
print("有符号溢出案例:", alu(127, 1, "add"))

最后一条会给出 res=128, V=1。这一行就是「为什么 CPU 需要 V 标志」的代码级证明。

7. 自测与动手

1

ALU 为什么能「一个周期做多种运算」？

看答案

各功能电路并行工作，多路选择器按 opcode 只输出一路——不是「依次尝试」，而是「同时算、选一个」。

2

为什么 ARM 的移位「免费」？

看答案

移位器串接在操作数 B 的路径上，与 ALU 同一周期完成，不需要额外指令或周期。

3

无符号比较用哪几个标志？有符号呢？

看答案

无符号看 C 与 Z（hi / ls）；有符号看 N、V、Z（ge / lt / gt / le）。

4

cmp 为什么不写结果？

看答案

它的目标是「产生标志位」而不是保存差值；硬件上 Rd 设为 PC 之外的无效目标，只更新 CPSR。

5

条件执行不满足时，指令做了什么？

看答案

什么也不做：不写目标寄存器、不更新标志，但已占用了一个指令槽——所以它「不改变状态」但「占时间」。

  1. 跑 Python ALU 脚本，验证 127+1 的 V=1。
  2. 用 objdump 找一条 adds 和一条 add，对比机器码里的 S 位（第 20 位）。
  3. 写两个版本的绝对值函数，一个用分支，一个用条件执行，比较周期数（用 perf stat）。
  4. 把 add r0,r1,r2,lsl #3 写成三条普通指令，看代码长了多少。
