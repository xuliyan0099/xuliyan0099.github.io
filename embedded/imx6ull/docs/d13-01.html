AArch64 / RISC-V / x86：三套体系横向对照

i.MX6ULL 是 ARMv7。往上看 AArch64，往旁边看 RISC-V 与 x86，三套体系的差异其实只有五个维度。

● 一读 纯读约 4 小时 左侧是本卷目录 理论为主 · 实作可跳

i.MX6ULL 是 ARMv7-A、32 位、单核。它的天花板不在主频，而在地址空间、异常等级与页表层数。往上看 AArch64，往旁边看 RISC-V 与 x86，差异其实只有五个维度。

先玩一下：同一个函数，三套汇编

点「单步」。看参数怎么传、返回值放哪、栈怎么动——这是三套体系最日常的差异。

一、五个维度对照

维度ARMv7（i.MX6ULL）AArch64RISC-Vx86-64
通用寄存器16 × 32 位31 × 64 位 + SP32 × XLEN16 × 64 位
特权级7 种 mode（USR/SVC/IRQ/FIQ/ABT/UND/SYS）EL0–EL3U/S/M（可选 H）ring 0–3
页表两级，4 KB 页，32 位 VA4 级（39 位 VA），4 KB 页Sv39 三级4 级（48 位 VA）
指令长度固定 4 字节（Thumb 2 字节）固定 4 字节4 字节（C 扩展可 2 字节）变长 1–15 字节
传参r0–r3x0–x7a0–a7rdi, rsi, rdx, rcx, r8, r9

这五条决定了很多「上层看不着」的事：为什么 32 位进程只能寻址 4 GB；为什么 AArch64 的内核要四级页表；为什么 RISC-V 的汇编看起来最规整；为什么 x86 的反汇编最难读。

二、特权级：从 mode 到 EL

ARMv7 的 7 种 mode 与 AArch64 的 4 个 EL 是同一件事的两种表达。差异在于 AArch64 把「安全世界」与「虚拟化」做成了独立的异常等级，而不是靠协处理器与 mode 组合。

三、页表：为什么 32 位只有两级

32 位虚拟地址 + 4 KB 页 → 页内偏移 12 位，剩 20 位要分给页表。ARMv7 拆成 12 + 8：一级表 4096 项（覆盖 1 GB），二级表 256 项（覆盖 1 MB）。一级表本身 16 KB，常驻。

AArch64 用 39 位 VA（可扩到 48），拆成 9 + 9 + 9 + 12，四级表每级 512 项。多一级的好处是「稀疏地址空间不必为空洞建表」——64 位世界里空洞是常态。

误解：64 位就是「地址空间无限」当前实现通常只用 39 或 48 位 VA（用户态 256 TB 左右）。真正的限制来自页表层数与物理地址位宽，不是「64 位」这三个字。
怎么快速看懂一套新架构按这五问：几个通用寄存器？几个特权级？几级页表、页多大？指令定长吗？前几个参数放哪？五分钟就能把「陌生架构」变成「熟悉架构的变体」。

动手（可选）：同一段 C 编三遍

只在 🔧 实作模式展开PC 上装交叉编译器即可。
  1. 写一个带 4 个参数的函数，分别用 arm-linux-gnueabihf-gcc -S、aarch64-linux-gnu-gcc -S、riscv64-linux-gnu-gcc -S 生成汇编。
  2. 对比参数寄存器、返回值、栈帧建立方式。
  3. 把参数加到 10 个，看哪些开始走栈——这就是 ABI 的边界。
  4. 用 objdump -d 看指令编码长度差异（x86 最明显）。

离开这一篇，你应该能

  • 用五个维度对比 ARMv7 / AArch64 / RISC-V / x86。
  • 解释 32 位两级页表与 AArch64 四级页表的算术来源。
  • 说出 ARMv7 mode 与 AArch64 EL 的对应关系。
