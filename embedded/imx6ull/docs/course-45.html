卷 09·驱动体系·第 02 篇

写一个字符设备

前面四十四课都在讲「为什么」。从这一课起动手：写一个能 echo 进去、能 cat 出来的驱动，看清「用户进程的一次 read」到底落到你写的哪个函数上。这是所有驱动的最小原型——把这个跑通，LED、按键、I2C 传感器只是换里面的寄存器操作。

★ 一读 纯读约 1 小时 左侧是本卷目录 理论为主 · 实作可跳

这一课要回答的问题

① 主次设备号各自决定什么？② /dev 下的一个节点是怎么和内核里的驱动对上号的？③ file_operations 这张函数表是谁在什么时候调用？④ 为什么必须用 copy_to_user 而不是直接 memcpy？⑤ 没有 mknod 的现代系统怎么自动生成设备节点？

1. 直觉：设备是一扇窗，窗口后面挂着一张函数表

用户进程打开 /dev/mychr 那一刻，内核手里拿到的是一个 struct file，里面有一个指针 f_op，指向你注册的那张表。之后进程每次 read，VFS 只是查表：f->f_op->read(...)。所以「驱动开发」本质是「填表」，不是「写主函数」。

类比失效处：窗口这个比喻会让人以为数据是「流过去的」。实际是：用户缓冲区在内核眼里是另一个地址空间，必须用专门的拷贝函数跨过去，跨不过就返回 -EFAULT。

2. 软件路径：注册的三步

不管字符设备还是别的，注册都绕不开三步：拿号（alloc_chrdev_region 或 register_chrdev_region）→ 绑表（cdev_init 把 file_operations 挂到 cdev 上）→ 入册（cdev_add 告诉内核「这个号段归我」）。卸载时逆序 cdev_del、unregister_chrdev_region。

老教材里的 register_chrdev(0, name, &fops) 是这三步的语法糖，一次占掉 256 个次设备号，现代内核不推荐——它没法只精确登记一个次设备号。

3. 最小可编译驱动

#include <linux/module.h>
#include <linux/fs.h>
#include <linux/cdev.h>
#include <linux/uaccess.h>

#define NAME "mychr"
#define SZ   256

static dev_t dev;
static struct cdev cdev;
static char kbuf[SZ];
static int  klen;

static int my_open(struct inode *i, struct file *f) { return 0; }

static ssize_t my_read(struct file *f, char __user *ub, size_t n, loff_t *off)
{
    int cnt = min((size_t)(klen - *off), n);
    if (cnt <= 0) return 0;
    if (copy_to_user(ub, kbuf + *off, cnt)) return -EFAULT;
    *off += cnt;
    return cnt;
}

static ssize_t my_write(struct file *f, const char __user *ub, size_t n, loff_t *off)
{
    if (n > SZ) n = SZ;
    if (copy_from_user(kbuf, ub, n)) return -EFAULT;
    klen = n; *off = 0;
    return n;
}

static struct file_operations fops = {
    .owner = THIS_MODULE,
    .open  = my_open,
    .read  = my_read,
    .write = my_write,
};

static int __init my_init(void)
{
    int ret = alloc_chrdev_region(&dev, 0, 1, NAME);
    if (ret) return ret;
    cdev_init(&cdev, &fops);
    cdev.owner = THIS_MODULE;
    ret = cdev_add(&cdev, dev, 1);
    if (ret) { unregister_chrdev_region(dev, 1); return ret; }
    pr_info("mychr: major=%d minor=%d\n", MAJOR(dev), MINOR(dev));
    return 0;
}

static void __exit my_exit(void)
{
    cdev_del(&cdev);
    unregister_chrdev_region(dev, 1);
}

module_init(my_init);
module_exit(my_exit);
MODULE_LICENSE("GPL");

4. 编译、加载、验证

# Makefile（交叉编译到 i.MX6ULL，内核源码树按自己的路径改）
obj-m := mychr.o
KDIR  := /home/you/imx6ull/linux-imx
PWD   := $(shell pwd)
all:
	$(MAKE) -C $(KDIR) M=$(PWD) ARCH=arm CROSS_COMPILE=arm-linux-gnueabihf- modules
clean:
	$(MAKE) -C $(KDIR) M=$(PWD) clean
# 板上
insmod mychr.ko
dmesg | tail -1          # 应看到 major=xxx
cat /proc/devices        # 找 mychr 这一行，确认号段被占用
mknod /dev/mychr c <major> 0
chmod 666 /dev/mychr

echo hello-kernel > /dev/mychr
cat /dev/mychr           # 输出 hello-kernel
rmmod mychr
ls /dev/mychr            # 节点还在，但驱动已撤走：此时 open 会返回 ENODEV

这四个现象必须全部对上，否则说明中间某一步没做：dmesg 有号、/proc/devices 有名字、echo 成功、rmmod 后 open 失败。最后一条最容易忽略，它证明「节点只是文件，真正干活的是驱动」。

5. 三条误解

  • 「设备节点是驱动创建的」：老式 register_chrdev 时代确实靠手写 mknod；现代内核是 udev/mdev 按 /sys/class 里的信息自动建（见下一条）。节点是文件系统对象，驱动只负责把自己的号登记进内核。
  • 「class_create 只是建个目录」：class_create + device_create 会生成 /sys/class/mychr/mychr0/dev，里面写着 主:次；mdev/udev 读到它就自动 mknod。这才是「插上就能用」的来源。
  • 「read 返回长度随便写」：返回大于实际拷贝的字节数，用户态会读到未初始化内存；返回负数是错误码，返回 0 表示「读完了」。这三个约定是所有 VFS 接口的共同语言。

6. 五题自测

1

同一个驱动要管 4 路串口，主设备号和次设备号各怎么用？

看答案

同一个主设备号（一个驱动一个 major），4 个次设备号 0–3。alloc_chrdev_region(&dev, 0, 4, NAME) 一次登记 4 个，然后在 open 里用 iminor(inode) 区分是哪一路。

2

copy_to_user 失败通常返回什么？为什么不能直接 memcpy？

看答案

返回 -EFAULT。memcpy 用的是内核页表视角，用户缓冲区可能不在当前页表里（甚至被换出），直接解引用会触发 oops；copy_to_user 会做地址合法性检查并可休眠换页。

3

没有 mknod，节点为什么也会自己出现？

看答案

驱动调用 class_create 与 device_create 后，/sys/class/<class>/<dev>/dev 里出现 major:minor；mdev/udev 监听 uevent，读到这行就建节点。

4

两次 cat 同一个设备，第二次为什么可能读到空？

看答案

因为 loff_t *off 是按「打开的文件」维护的。同一个进程里 cat 两次是新的一次 open，偏移归零，能读到；但如果你的 read 忘了用 *off 或忘了推进，就会出现「越读越怪」的现象。

5

模块卸载时忘了 cdev_del 会怎样？

看答案

号段仍被占着，下次 alloc_chrdev_region 拿不到同一段；更糟的是代码段已卸载而内核还留着指向它的函数表，一旦有人 open 就是野指针 oops。

7. 动手（30 分钟）

1. 按上面的代码与 Makefile 编出 mychr.ko，insmod 后从 dmesg 抄下主设备号。

2. 手写 mknod 建节点，跑通 echo / cat，贴出两条输出。

3. 给驱动补上 class_create 与 device_create，删掉 mknod，验证节点自动出现。

4. 故意把 copy_to_user 换成 memcpy，在板上 cat 一次，看 dmesg 里那条 oops——这比你读十页文档更能记住为什么不能这么写。
