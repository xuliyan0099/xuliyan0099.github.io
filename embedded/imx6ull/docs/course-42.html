卷 08·启动链·第 09 篇

做出一块能跑的系统

前面 41 课都是零件。这一课把它们拼起来：分区怎么划、镜像怎么烧、上电看到什么才算成功。整个过程只有六步，但每一步都有明确的「验证点」——按顺序验证，出问题时你就知道卡在哪一步。

★ 一读 纯读约 1 小时 左侧是本卷目录 理论为主 · 实作可跳

这一课要回答的问题

① 分区怎么划？② u-boot 写到哪？③ root= 该怎么填？④ 上电看不到输出怎么查？⑤ 怎么快速迭代（不改卡也能换内核）？

1. 分区与烧写

# 在 Linux PC 上对 SD 卡操作（/dev/sdX 一定要确认对！）
sudo dd if=u-boot.imx of=/dev/sdX bs=1k seek=1 conv=fsync

# 分区（举例）
# p1: FAT32, 64MB   → zImage + dtb
# p2: ext4, 剩余     → rootfs

sudo mkfs.vfat /dev/sdX1
sudo mkfs.ext4 /dev/sdX2
sudo mount /dev/sdX1 /mnt/boot
cp zImage imx6ull-xxx.dtb /mnt/boot/
sudo tar xf rootfs.tar.gz -C /mnt/root   # 或 dd 镜像

seek=1 的含义是「跳过 1KB」，这正是 i.MX 的要求。conv=fsync 保证写完真的落盘——不加它，拔卡时数据可能还在缓存里，导致「明明烧了却启动不了」。

2. bootargs 与分区名的对应

# eMMC/SD 的设备名规则
/dev/mmcblk0      # 整卡
/dev/mmcblk0p1    # 第 1 分区
/dev/mmcblk1p2    # 第 2 张卡的第 2 分区

# 板子上常见是 mmcblk1（因为 mmcblk0 是 eMMC）
bootargs=console=ttymxc0,115200 root=/dev/mmcblk1p2 rootwait rw

写错一位就是 Waiting for root device。不确定时，先进 u-boot 的 shell，用 mmc list 与 mmc part 查真实编号。

3. 快速迭代的两个技巧

# u-boot 里配网络启动（示例）
setenv ipaddr 192.168.1.20
setenv serverip 192.168.1.10
setenv bootcmd 'tftp 0x80800000 zImage; tftp 0x83000000 dtb; bootz 0x80800000 - 0x83000000'
setenv bootargs 'console=ttymxc0,115200 root=/dev/nfs rw nfsroot=192.168.1.10:/nfs/rootfs ip=192.168.1.20'
saveenv

4. 上电验证清单

现象下一步查
串口无任何字符电源、晶振、启动引脚、串口接线
只有乱码波特率、晶振频率、PLL 配置
停在 =>bootcmd 是否被改坏；printenv
Waiting for root deviceroot= 分区名、存储驱动、卡是否识别
Kernel panic - not syncing前面的日志才是原因，往上翻
有日志但没有 shellinit 是否存在/可执行、inittab

这张表值得打印出来。「往上翻日志」是最重要的一条经验：panic 的那一行几乎从不是根因。

6. 自测与动手

1

i.MX6ULL 的 u-boot.imx 写到卡的什么位置？

看答案

偏移 1KB（1024 字节）处，即 dd ... seek=1 bs=1k。

2

为什么 dd 要加 conv=fsync？

看答案

强制把缓存刷到设备，避免拔卡时数据丢失。

3

怎么确认分区名对不对？

看答案

在 u-boot 里 mmc list / mmc part，或在内核启动后用 ls /dev/mmcblk*。

4

为什么 panic 那一行不是根因？

看答案

panic 是「已经无法继续」时的最后反应，真正原因在前面的警告或错误日志里。

5

网络启动需要哪几个环境变量？

看答案

ipaddr、serverip、bootcmd（tftp 加载）、bootargs（nfsroot 与 ip）。

  1. 按六步做一次完整烧写，每步记录验证结果。
  2. 故意把 u-boot 写到分区里（不 seek），观察「无输出」。
  3. 配一次 tftp + NFS 启动，测一次迭代时间。
  4. 把上电验证清单抄下来，下次排障直接对照。
