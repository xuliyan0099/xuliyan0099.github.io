卷 08·启动链·第 03 篇

i.MX6ULL 与启动链路

板子按下电源到出现 shell 提示符，中间只跑了一件事：把四个镜像依次搬到内存里，最后交棒给内核。这一章把这条链拆开。

★ 一读 纯读约 10 小时 左侧是本卷目录 理论为主 · 实作可跳

本章目标

① 认识 i.MX6ULL 的关键资源；② 记住主要外设的地址；③ 画出五级启动流程并标出加载地址；④ 能读懂串口启动日志的每一段；⑤ 知道启动介质是怎么选的。

8.1 这颗芯片有什么

资源参数对学习的意义
CPU单核 ARM Cortex-A7，最高 528MHz，带 NEON有 MMU，能跑完整 Linux
片内 SRAMOCRAM 128KB启动第一阶段只能用它，装不下 U-Boot
外部内存DDR3 / LPDDR2，常见 256MB 或 512MB内核、根文件系统都跑在这
存储eMMC、SD 卡、NAND、NOR四件套就存在这
网络ENET1 / ENET2，10/100MNFS/TFTP 调试
串口多路 UART，UART1 常作调试口你唯一的生命线
其他2×CAN、I2C、SPI、LCD、ADC、GPIO 5 组第 12 章的实验对象

8.2 地址空间：程序眼里的世界

ARM 的地址空间是统一编址的，读一个地址就是读某个外设寄存器。写驱动时你操作的 ioremap 地址，就来自这张表。

区域起始地址用途
DDR0x80000000256/512MB 内存，内核与程序在这
OCRAM0x00900000128KB 片内 SRAM，启动第一阶段用
GPT / EPIT0x02098000 附近定时器
UART10x02020000调试串口
GPIO10x0209C000通用 IO
IOMUXC0x020E0000引脚复用配置（pinctrl 就是配它）
CCM0x020C4000时钟控制
ENET1 / ENET20x02188000 / 0x020B4000网卡
uSDHC10x02190000SD/eMMC 控制器
地址以芯片手册为准 上表是常见值，用之前必须对照《i.MX6ULL Reference Manual》对应章节。板卡不同、芯片型号后缀不同，个别外设可能不在同一位置。背地址没有意义，会查手册才有意义。

8.3 五级启动，一级都不能少

① BootROM芯片内部固化
上电先跑它
→
② IVT + DCD镜像头 + 初始化数据
配 DDR 时钟与参数
→
③ SPL / U-Boot 前半在 OCRAM 里跑
把 U-Boot 搬进 DDR
→
④ U-BootDDR 里运行
加载内核与设备树
→
⑤ 内核解压、初始化、
挂载根文件系统、起 init

每一级到底在干什么

  1. BootROM：芯片出厂就烧死的代码，改不了。它只做一件事——按 BOOT_MODE 引脚/熔丝决定从哪个介质（SD、eMMC、USB、NAND）读镜像，然后把镜像头部搬到 OCRAM 的固定位置。它只认特定格式的镜像，这是后面所有烧写工具的基础。
  2. IVT 与 DCD：镜像开头有一张「中断向量表」(IVT) 和一段「设备配置数据」(DCD)。DCD 是一串「往某地址写某值」的指令，专门用来初始化 DDR——因为此时 DDR 还不能用，只能靠片内 SRAM 干活。
  3. SPL / U-Boot 前半段：DDR 配好后，把完整的 U-Boot 从存储介质搬进 DDR。之所以要分两段，是因为 OCRAM 只有 128KB，装不下完整 U-Boot（通常几百 KB）。这就是「两级引导」的根本原因。
  4. U-Boot：跑到 DDR 后，初始化串口、网卡、MMC，读环境变量 bootcmd，把 zImage 和设备树搬到指定地址，最后 bootz 跳进内核。
  5. 内核：自解压、建立页表、初始化各子系统、解析设备树、挂载根文件系统，最后执行 /sbin/init（或 systemd），这才出现登录提示符。

常见加载地址（示例，非通用）

镜像地址谁放的
U-Boot 链接地址0x87800000编译时 CONFIG_SYS_TEXT_BASE 决定
zImage0x80800000U-Boot 的 bootcmd 里 fatload 指定
设备树 .dtb0x83000000同上
这些数字是会变的 DDR 大小改了、U-Boot 配置改了、设备树里 memory 节点改了，地址就得跟着调。判断方法：看 U-Boot 的 printenv 输出，那是这块板子真正在用的值，不是抄来的。

8.4 启动介质是怎么选的

i.MX6ULL 有一组 BOOT_MODE[1:0] 引脚（板上通常是拨码开关）：

模式行为用途
内部 Boot从 eMMC / SD / NAND 启动正常使用
Serial Download从 USB OTG 接收镜像（UUU / mfgtool）系统刷死后的救援通道

板子变砖的第一反应不是拆芯片，而是把拨码拨到 Serial Download，用 USB 线和工具重新烧。这个开关的位置现在就去找，记在笔记里，以后会救你很多次。

从这段日志能读出四件事：U-Boot 版本与编译时间、DDR 容量、有几个 MMC 设备、内核是否成功挂载根文件系统。起不来时，日志停在哪一行，问题就在哪一级：

卡住位置大概率原因
完全无输出串口线/波特率错，或板子根本没启动（供电、拨码）
停在 U-Boot 之前镜像没烧对，DDR 参数（DCD）不匹配
反复打印 Hit any key 后无动作bootcmd 路径错、镜像文件不存在
Starting kernel ... 后死住加载地址错、dtb 不对、内核与硬件不匹配
Kernel panic - No working init found根文件系统没挂上，或里面没有 init

8.6 动手任务

  • 不看本章，白纸画出五级启动流程，并写出每级运行在哪个存储/内存区域。
  • 找到你板子上的 BOOT 拨码开关，查厂商文档确认两种模式怎么拨。
  • 板子上电，把串口日志从头到尾存成文本，逐段标注「这是哪一级在打印」。
  • 进 U-Boot 执行 bdinfo、printenv，抄下 DRAM 大小、bootcmd、bootargs，和你手上的文档对比，找不同。
  • 回答：为什么 U-Boot 不能直接在 OCRAM 里跑完？

8.7 验收标准

  • 能画出五级启动链，标出每一级的位置与作用
  • 能解释 IVT 和 DCD 各是什么，为什么需要 DCD
  • 能说出「为什么要两级引导」，并算出 OCRAM 与 U-Boot 体积的矛盾
  • 能找到 UART1、GPIO1、IOMUXC、CCM 的地址，并知道去哪查
  • 看到串口日志停住时，能判断问题在哪一级
  • 知道 Serial Download 模式怎么进，能用来救砖
