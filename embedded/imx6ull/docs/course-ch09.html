卷 08·启动链·第 05 篇

U-Boot 与烧写

U-Boot 是板子的「BIOS + GRUB」。它只做四件事：初始化硬件、读环境变量、搬运镜像、跳进内核。学会它，你就不再依赖烧写工具。

★ 一读 纯读约 12 小时 左侧是本卷目录 理论为主 · 实作可跳

本章目标

① 会用 U-Boot 的查看/设置/保存环境变量；② 会从 MMC、TFTP 加载镜像；③ 看懂 bootcmd 与 bootargs 每一段；④ 能独立烧写一套系统；⑤ 知道板子刷死后怎么救。

9.1 U-Boot 的位置

U-Boot 全称 Universal Boot Loader，是开源的引导程序。它运行在内核之前，负责把代码从存储介质搬进 DDR，并把控制权交给内核。在 i.MX6ULL 上，它是启动链的第 3–4 级。

u-boot/
├── arch/arm/cpu/armv7/mx6/    # i.MX6 系列芯片初始化代码（时钟、DDR）
├── board/freescale/mx6ull.../ # 板级代码（对应你的板子）
├── drivers/mmc/               # SD/eMMC 驱动
├── drivers/net/               # 网卡驱动
├── include/configs/mx6ull...h # 板级配置头文件
├── common/                    # 命令实现，main.c 是入口
└── .config                    # 编译配置

9.2 环境变量：U-Boot 的大脑

环境变量存在存储介质的一个固定区域里，U-Boot 每次启动先读它，按里面的脚本执行。板子「启动不了」很多时候不是镜像坏了，是环境变量被改坏了。

=> printenv                    # 打印全部（内容很多，按空格翻页）
=> printenv bootcmd
=> printenv bootargs
=> setenv ipaddr 192.168.1.101
=> setenv serverip 192.168.1.100
=> saveenv                     # 写入存储，不执行就只在本次生效
=> setenv foo bar; printenv foo
=> setenv foo                  # 不赋值 = 删除
变量作用
bootcmd倒计时结束自动执行的命令序列
bootargs传给内核的启动参数，决定根文件系统从哪挂、控制台用哪个串口
ipaddr / serverip板子自己的 IP / PC（TFTP 服务器）的 IP
ethaddrMAC 地址
baudrate串口波特率，默认 115200
filesize最近一次下载的文件大小（只读，脚本里常用）
改坏 bootcmd 的后果 板子会一直重启或停在 U-Boot。改之前先 printenv bootcmd 抄到记事本里，改坏了还能贴回去。这个习惯值一整个晚上。

9.3 常用命令速查

类别命令说明
查看version bdinfo mmc list mmc info mmc part版本、内存信息、设备与分区
存储fatls mmc 1:1列 FAT 分区文件（SD 卡常用）
存储ext4ls mmc 0:2 /列 ext4 分区文件（eMMC 常用）
加载fatload mmc 1:1 80800000 zImage从 FAT 分区读到 DDR
加载ext4load mmc 0:1 80800000 zImage从 ext4 分区读
网络ping tftp 80800000 zImage dhcpTFTP 下载（U-Boot 只支持 TFTP）
启动bootz 80800000 - 83000000启动 zImage，中间 - 表示无 initrd
启动bootm / gouImage / 裸机程序
其他reset help mmc dev 1重启、帮助、切换当前 mmc 设备
mmc dev 与 mmc 1:1 的关系 mmc dev 1 选设备，mmc 1:1 表示「1 号设备第 1 个分区」。设备编号是 eMMC 还是 SD 卡，取决于板子连线与 U-Boot 配置，用 mmc list 看，别抄教程。

9.4 bootcmd 与 bootargs：一行命令决定能不能起

=> printenv bootcmd
mmc dev 1; fatload mmc 1:1 80800000 zImage;
fatload mmc 1:1 83000000 imx6ull-14x14-evk.dtb;
bootz 80800000 - 83000000

=> printenv bootargs
console=ttymxc0,115200 root=/dev/mmcblk1p2 rootwait rw

分解看：

片段含义
mmc dev 1切换到 1 号 MMC 设备（这里假设是 SD 卡）
fatload ... 80800000 zImage把内核读到 0x80800000
fatload ... 83000000 xxx.dtb把设备树读到 0x83000000
bootz 内核地址 - dtb地址启动；中间的 - 是 initrd 位置，没有就写短横
console=ttymxc0,115200内核控制台用 UART1、115200
root=/dev/mmcblk1p2根文件系统在第 1 个 mmc 设备的第 2 分区
rootwait等存储设备就绪再挂根（eMMC 上必备）
rw根文件系统以读写方式挂载
从 NFS 启动（开发期最常用） 
setenv bootargs console=ttymxc0,115200 root=/dev/nfs rw \
nfsroot=192.168.1.100:/home/ubuntu/nfsroot,nfsvers=3 \
ip=192.168.1.101:192.168.1.100:192.168.1.1:255.255.255.0::eth0:off
saveenv
改一个程序只要在 PC 上重新编，板子重启就生效，不用烧写。这是后面第 11、12 章的主要调试方式。

9.5 三种烧写方式

方式一：厂商工具（mfgtool / UUU）

把板子拨到 Serial Download 模式，USB 连接 PC，双击工具里的脚本，整套镜像（U-Boot、内核、dtb、rootfs）一次写进去。这是最快、最不容易错的方式，适合第一次和救砖。

方式二：U-Boot 里直接写

已经能进 U-Boot 时，可以用命令把镜像写到 eMMC：

# 通过 TFTP 下载到 DDR，再写入 eMMC 的某个分区
=> tftp 80800000 zImage
=> mmc dev 0
=> mmc write 80800000 0x800 0x4000    # 地址与长度以块(512B)为单位，慎用

# 更安全的做法：文件系统分区用 fatwrite / ext4write
=> fatwrite mmc 0:1 80800000 zImage 0x600000
mmc write 写错偏移会覆盖 U-Boot 自己，板子立刻变砖。第一次别碰裸写，用工具烧，或者用 fatwrite 写进文件系统分区。

方式三：量产 / 自动化

产线用 UUU 脚本批量烧，或用 dd 把整卡镜像写到 SD 卡。自己学习阶段用不上，知道有这回事即可。

9.6 分区：为什么有 FAT 和 ext4

典型的分区布局（以厂商镜像为例，具体以你的板子为准）：

分区格式放什么
裸区（无分区表项）rawU-Boot 镜像（BootROM 直接读，不能放进文件系统）
分区 1FAT32zImage、dtb（U-Boot 用 fatload 读，简单可靠）
分区 2ext4根文件系统

为什么 U-Boot 那部分必须是裸的？因为 BootROM 只认固定偏移的原始数据，它不懂文件系统。这也是为什么「U-Boot 只能用工具烧，不能简单拖进 SD 卡」。

9.7 板子刷死了怎么救

  1. 断电，把 BOOT 拨码拨到 Serial Download。
  2. USB OTG 接 PC，上电，PC 应识别到一个 USB 设备（可能显示为 HID 或串口）。
  3. 打开厂商烧写工具，加载配置，执行烧写，串口应能看到进度。
  4. 烧完断电，拨码拨回内部 Boot，重新上电。
  5. 串口能看到 U-Boot 日志 = 救回来了。

9.8 动手任务

  • 进 U-Boot，printenv 全部抄进笔记（这是你板子的「出厂配置」）。
  • 用 mmc list、mmc info、mmc part 搞清每个设备是什么、几个分区。
  • 先 setenv 改 bootargs 加一个无害参数（如 loglevel=7），saveenv，重启验证；再改回原样。
  • 用 TFTP 在 U-Boot 里下载一次 zImage，bootz 启动成功。
  • 把 bootargs 改成 NFS 根文件系统，启动成功后在板子上 df -h 确认根是 NFS。
  • 查厂商文档，找到 BOOT 拨码位置和烧写工具的下载链接，写进笔记。

9.9 验收标准

  • 会 printenv / setenv / saveenv，知道不 save 只在本次生效
  • 能读懂 bootcmd 的每一段，并能自己改加载地址
  • 能说出 bootargs 里 console、root、rootwait、rw 各是什么
  • 能从 eMMC 和从 NFS 各启动一次
  • 能用厂商工具完整烧写一套系统
  • 知道 Serial Download 模式怎么进，能独立救砖
