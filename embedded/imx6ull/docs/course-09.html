卷 01·机器与指令·第 10 篇

冯诺依曼五件事

1945 年那份草稿里写的结构，今天的手机、服务器、你的 i.MX6ULL 开发板，一模一样的五个部件。这一课把这五件事讲清楚，再讲它带来的唯一一个根本缺陷——指令和数据挤在同一条路上。这个瓶颈至今没被解决，只是被层层缓存掩盖。

★ 一读 纯读约 1 小时 左侧是本卷目录 理论为主 · 实作可跳

这一课要回答的问题

① 五件事分别是什么？②「存储程序」为什么是革命性的？③ 冯诺依曼瓶颈到底是什么？④ 哈佛结构怎么绕开它，为什么现代 CPU 用「改良哈佛」？⑤ 为什么「读写一个地址」就能控制硬件？

1. 五个部件，各司其职

部件职责本课程里的位置
运算器 ALU算术与逻辑运算第 06–07 课造，第 11 课用
控制器取指、译码、发出控制信号第 10、12 课核心
存储器按地址存/取指令与数据第 20–26 课
输入把外部世界变成比特第 03 课按键，第 40 课外设
输出把比特变成外部动作第 03 课屏幕，第 40 课 PWM / LCD

注意：控制器 + 运算器通常合称 CPU；存储器、输入、输出在嵌入式里往往「长在一起」——SoC 内部有 SRAM、DDR 控制器、几十个外设控制器。五件事是一个逻辑划分，不是物理划分。

2. 存储程序：把程序也变成数据

在冯诺依曼之前，计算机（如 ENIAC）的「程序」是接线板和开关：换一个任务，要重新插一堆线、拨一堆开关，耗时几小时到几天。

冯诺依曼的关键一步：把指令也用二进制编码，存在同一片存储器里。于是换程序只需要「换一段数据」，机器本身不用改。CPU 需要的只有一件事：能从内存读 32 位、能解释这 32 位。

3. 冯诺依曼瓶颈：一条路，两个用途

既然指令和数据在同一个存储器里，那就只有一条总线。取指令要占用它，取数据也要占用它。CPU 运算一次只要 1 纳秒，但从 DDR 取一次数据要几十纳秒——于是 CPU 大部分时间在等内存。

这就是冯诺依曼瓶颈。所有现代计算机的复杂结构，都可以理解为「围绕这个瓶颈做的缓解措施」：

  • Cache：把常用数据搬到离 CPU 最近的 SRAM（第 20–23 课）。
  • 流水线：让取指与执行重叠进行（第 13 课）。
  • 多级存储：寄存器 → L1 → L2 → DDR → Flash，越远越大越慢（第 20 课）。
  • 预取：提前把即将用到的指令/数据搬进来。

4. 读写一个地址，就是控制硬件

这一点对写驱动的人至关重要。看这段 C 代码：

#define GPIO1_DR   (*(volatile unsigned long *)0x0209C000)
#define GPIO1_GDIR (*(volatile unsigned long *)0x0209C004)

void led_on(void) {
    GPIO1_GDIR |= (1 << 26);   // 把 GPIO1_26 设为输出
    GPIO1_DR   |= (1 << 26);   // 输出高电平，点亮
}

这段代码没有调用任何「驱动函数」，只是在写内存。但 0x0209C000 不在 DDR 上，它在 SoC 内部的一个寄存器上。写这个地址，总线就会把值送到那个寄存器，硬件立刻响应。

三个细节必须注意：

  • volatile：告诉编译器「别优化掉、每次都真去读」，否则循环里可能只读一次。
  • 位操作读-改-写不是原子的：中断或另一个核同时改同一寄存器会丢位。内核里要用 setbits/clrbits 或自旋锁。
  • 写后要屏障：某些外设要求写入顺序严格，需要 wmb() 或读回一次做 flush。

5. 实验：摸到冯诺依曼结构的边界

# 在 Ubuntu 上，看看 CPU 眼里的地址空间长什么样
cat /proc/iomem        # 物理地址映射（需要 root）
cat /proc/cpuinfo      # 核数、型号、频率
ls /sys/devices/system/cpu/   # 每个核的目录
cat /sys/devices/system/cpu/cpu0/cpufreq/scaling_cur_freq

# 用 dd 测一下内存带宽，感受「瓶颈」的量级
dd if=/dev/zero of=/dev/null bs=1M count=1000

# 在板子上：看外设寄存器地址
cat /proc/iomem | head -40

在 i.MX6ULL 上你会看到 0x02000000-0x0202ffff : ocram、0x0209c000-0x0209cfff : gpio1 之类的条目。这就是「五件事」在真实硬件上的物理地址快照。

6. 三条常见误解

7. 自测与动手

1

「存储程序」相比接线板编程，解决了什么问题？

看答案

换任务不用改硬件，只换内存里的指令序列；程序可以被读、被改、被生成——这是编译器、操作系统存在的前提。

2

冯诺依曼瓶颈的物理原因是什么？

看答案

指令与数据共用同一存储器与总线，取指与取数争抢带宽；且内存访问延迟远大于运算延迟。

3

为什么说 Cortex-A7 是「改良哈佛」？

看答案

L1 的指令缓存与数据缓存分离（可并行取指取数），但 L2 与主存统一，兼顾吞吐与成本。

4

为什么访问外设寄存器必须加 volatile？

看答案

否则编译器会认为值不变而缓存到寄存器，或删掉「无用」写入；实际硬件状态可能随时改变，必须每次真读。

5

GPIO1_DR |= (1<<26) 有什么隐患？

看答案

读-改-写三步非原子：若中断在中间改了其它位，会丢更新。应使用内核提供的原子位操作或加锁。

  1. 在 Ubuntu 上跑 cat /proc/iomem，找出三块不同性质的区域。
  2. 在板子上跑同样命令，找到 gpio1 的地址范围。
  3. 写一个最小内核模块，用指针写 GPIO 寄存器点亮 LED。
  4. 用 dd 测带宽，算出「一次 DDR 访问 = 多少条指令的时间」。
