设备树

2000 年代的 ARM Linux 有个灾难：每块开发板都要在内核源码里写一份板级文件，改一个 GPIO 就要重编内核。解法是把「硬件描述」抽成一份文本——设备树。现在同一个内核能跑几十块不同的板子，靠的就是它。

★ 一读 纯读约 1 小时 左侧是本卷目录 理论为主 · 实作可跳

这一课要回答的问题

① dts / dtsi / dtb 三者关系？② compatible 怎么匹配驱动？③ reg 的格式？④ 改硬件怎么改设备树？⑤ 运行时怎么看设备树？

1. 真实片段

/ {
    model = "i.MX6ULL 14x14 EVK";
    compatible = "fsl,imx6ull-14x14-evk", "fsl,imx6ull";

    memory@80000000 {
        device_type = "memory";
        reg = <0x80000000 0x20000000>;   /* 起始与长度：512MB */
    };

    chosen { bootargs = "console=ttymxc0,115200 root=/dev/mmcblk1p2 rw"; };
};

&uart1 {
    pinctrl-names = "default";
    pinctrl-0 = <&pinctrl_uart1>;
    status = "okay";
};

&uart1 表示「引用已有节点并追加/覆盖」——这正是 .dtsi（芯片公共描述）+ .dts（板级差异）能组合的原因。

2. compatible 与驱动匹配

static const struct of_device_id my_ids[] = {
    { .compatible = "fsl,imx6ull-uart" },
    { .compatible = "myvendor,mychip" },
    { }
};

// 内核为每个节点找 compatible 列表有交集的驱动
// 匹配上就调用 probe()，并把节点指针传进去

所以「驱动不 probe」的第一排查点：设备树里的 compatible 与驱动表里的字符串是否完全一致（含大小写与逗号）。差一个字符就不匹配，日志还很隐晦。

3. 编译与查看

# dts + dtsi  --dtc-->  dtb（二进制）
make ARCH=arm CROSS_COMPILE=arm-linux-gnueabihf- imx6ull_xxx.dtb

# 反编译回文本（读别人的 dtb 必备）
dtc -I dtb -O dts -o out.dts xxx.dtb

# 运行时直接看内核解析后的结果
ls /proc/device-tree/
cat /proc/device-tree/model
hexdump -C /proc/device-tree/memory@80000000/reg

/proc/device-tree 是「运行时的设备树快照」。如果驱动读到的资源不对，先来这里核对：它显示的是内核实际拿到的值，不是你源码里写的值。

4. 改硬件时的标准动作

  1. 确认引脚复用（pinctrl）配置：哪个引脚做 UART、哪个做 GPIO。
  2. 确认 reg 地址与手册一致（别抄错一位）。
  3. 确认 interrupts 用的是 GIC 中断号（不是引脚号）。
  4. status = "okay" 打开节点（默认常是 disabled）。
  5. 重编 dtb、替换、重启，看 dmesg 是否 probe 成功。

这五步是嵌入式里改硬件配置的日常。第 3 条最容易错：引脚号与中断号是两套编号。

6. 自测与动手

1

dtsi 与 dts 的分工？

看答案

dtsi 描述芯片级公共部分（可被多板复用），dts 描述板级差异并通过 &引用覆盖。

2

驱动 probe 的前提有哪些？

看答案

compatible 匹配、status=okay、所依赖的时钟/引脚/中断资源可用、驱动已编进内核。

3

reg 属性的两个数是什么？

看答案

寄存器基地址与长度（address-cells / size-cells 决定各占几个 32 位字）。

4

怎么读一个别人给的 dtb？

看答案

dtc -I dtb -O dts 反编译成文本。

5

为什么设备树能避免「一板一内核」？

看答案

硬件差异全在 dtb 里，内核只按节点找驱动，同一镜像可配不同 dtb 跑不同板。

  1. 找到你板子的 dts，标出 uart1、gpio1、memory 三个节点。
  2. 改一个 LED 的 GPIO 编号，重编 dtb 并验证。
  3. 用 cat /proc/device-tree/model 确认加载的是哪份 dtb。
  4. 故意把 compatible 改错一个字符，观察 probe 失败。
