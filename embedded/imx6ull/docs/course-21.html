Cache 三参数

Cache 只有三件事要定：装多少（容量）、一次搬多少（行大小）、放哪都行还是只能放固定位置（相联度）。这三个数字决定了命中率，也决定了「什么样的代码会莫名其妙变慢」。这一课把物理地址拆成三段，讲清「冲突未命中」是怎么发生的——那是性能优化里最阴的一类问题。

★ 一读 纯读约 1 小时 左侧是本卷目录 理论为主 · 实作可跳

这一课要回答的问题

① 三个参数分别影响什么？② 直接映射、组相联、全相联的区别？③ 「冲突未命中」怎么产生？④ 写回与写穿差在哪？⑤ 为什么结构体成员顺序会影响性能？

1. 三种映射方式

方式规则优点缺点
直接映射每个块只能放唯一一组硬件最省、查找最快两个地址「同组」就互相踢，冲突高
组相联（N 路）每组 N 个位置，可放任意一路冲突大幅下降要比 N 个标签、替换策略
全相联任意块可放任意位置冲突几乎为零比较器太多，只在小 Cache 用

i.MX6ULL 用 4 路（L1）/ 8 路（L2），这是「命中率 vs 硬件成本」的典型折中。真实芯片几乎不用纯直接映射，也不用全相联。

2. 三类未命中

  • 冷未命中（compulsory）：第一次访问，本来就没在 Cache 里。无法避免。
  • 容量未命中（capacity）：Cache 太小，装不下工作集。换更大 Cache 或改分块（tiling）。
  • 冲突未命中（conflict）：明明总数据量不大，但都撞到同一组。改数据布局或加填充即可解决。
// 经典冲突案例：二维数组按列访问
int a[1024][1024];
for (int i = 0; i < 1024; i++)
    for (int j = 0; j < 1024; j++)
        sum += a[j][i];        // 每次跳 4KB —— 撞同一组

// 改成按行访问，性能可能提升 5~10 倍
for (int i = 0; i < 1024; i++)
    for (int j = 0; j < 1024; j++)
        sum += a[i][j];

代码一行没变逻辑，只是换了访问顺序。这类优化不需要改算法，只需要懂 Cache 的几何。

4. 结构体顺序为什么影响性能

struct bad {  char flag;  int value;  };   // 8 字节（有 3 字节填充）
struct good { int value;  char flag;  };    // 8 字节，但访问 value 不需跨行

// 更极端：热字段与冷字段混在一起
struct mixed {
    int hot;        // 每次循环都读
    char cold[60];  // 很少用
};
// 一行 32 字节只能装 1 个这样的结构体 → 缓存浪费

// 拆分：把热的放一起（结构体拆分 / SoA）
struct hot_only { int hot; };

这不是「内存对齐」那点小事：它决定了同一行 Cache 里能装几个有用的对象。链表节点尤其明显——每个节点 64 字节，遍历时每个节点都是一次潜在未命中。

5. 实验：造一个冲突未命中

# 用 Python 演示「按列 vs 按行」的耗时差（数量级示意）
import time, random
N = 512
a = [[random.randint(0,9) for _ in range(N)] for _ in range(N)]

t = time.time(); s = 0
for i in range(N):
    for j in range(N): s += a[i][j]     # 行优先，局部性好
print("row-major  %.3fs" % (time.time()-t))

t = time.time(); s = 0
for i in range(N):
    for j in range(N): s += a[j][i]     # 列优先，跳步访问
print("col-major  %.3fs" % (time.time()-t))

Python 的解释器开销会掩盖一部分差异，但在 C 里这个差距通常是 5~10 倍。想看得更清楚，就在板子上用 C 跑，配 perf stat -e cache-misses。

6. 三条常见误解

7. 自测与动手

1

32KB、2 路、32 字节行：多少组？index 几位？

看答案

32KB / (2 × 32B) = 512 组，index 9 位，offset 5 位。

2

为什么二维数组按列遍历会变慢？

看答案

跨步等于行宽（常为 4KB 的倍数），大量地址映射到同一组，造成冲突未命中；且每次只用 4 字节却搬进 32 字节。

3

写回与写穿各适合什么场景？

看答案

写回适合普通内存（写密集快）；写穿适合外设寄存器与需强一致的共享内存。

4

DMA 与 Cache 为什么会打架？怎么解决？

看答案

CPU 写了数据还在 Cache 里，DMA 直接读 DDR 得到旧值。解决：DMA 前刷 Cache（clean），读回前失效（invalidate），用 dma_sync_* API。

5

为什么链表遍历通常比数组慢？

看答案

节点分散在内存里，几乎没有空间局部性，每次跳转都可能未命中；数组是连续访问，一次搬一整行。

  1. 用 C 写行优先与列优先遍历，比较耗时与 cache-misses。
  2. 算出你自己 L1 的组数、index 位数，标在纸上。
  3. 写一个结构体，调整字段顺序，用 pahole 或手算对齐看差异。
  4. 在一个驱动里做 DMA，故意不刷 Cache，观察数据错乱。
