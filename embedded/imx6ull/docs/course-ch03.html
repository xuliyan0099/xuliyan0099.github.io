命令行与文件系统

这一章是全书最长的一章，也是最不能跳的一章。板子上没有鼠标，所有操作都是命令；命令不熟，第 8 章以后你连「把文件从 PC 拷到板子」都要卡半天。

★ 一读 纯读约 16 小时 左侧是本卷目录 理论为主 · 实作可跳

本章目标

① 记住 /bin、/etc、/dev、/proc、/sys 各放什么；② 20 个核心命令不查文档能敲；③ 会用管道和重定向把命令串起来；④ 彻底理解权限位；⑤ 说清软硬链接差别。

3.1 根目录下每个文件夹是干什么的

Linux 不按「C 盘 D 盘」分，只有一棵树，根是 /。所有设备都挂在树上的某个位置——这就是「挂载」。

目录放什么你会在哪章用到
/bin /sbin最基础的命令程序（ls、cp、shutdown）全程
/usr用户程序与库，/usr/bin 是绝大多数命令住的地方全程
/etc所有配置文件：网络、SSH、NFS、启动脚本02 / 06 / 09
/dev设备文件，每个硬件一个节点，如 /dev/ttyUSB0、/dev/mmcblk003 / 12
/proc内核运行时状态，虚拟文件，如 /proc/cpuinfo、/proc/meminfo03 / 13
/sys内核设备模型，能直接读写硬件属性，如 /sys/class/leds10 / 12
/home普通用户的家目录，你的代码都在这全程
/rootroot 用户的家目录04
/var会变的数据：/var/log 日志、/var/lib 数据库04 / 13
/tmp临时文件，重启清空全程
/lib共享库，相当于 Windows 的 dll07
/mnt /media手动挂载点 / 自动挂载（U 盘、SD 卡）06 / 09
/opt第三方大软件（如交叉工具链常装在这）07
/boot内核镜像、启动配置（板子上很关键）09 / 10

3.2 「一切皆文件」到底什么意思

这是 Linux 最核心的设计思想：硬件、内核状态、甚至网络连接，都被抽象成文件，你能用同一套 cat / echo / read / write 去操作。

# 1. 硬件是文件：串口设备就是 /dev 下的一个节点
$ ls -l /dev/ttyUSB0

# 2. 内核状态是文件：读 CPU 信息
$ cat /proc/cpuinfo | head -20
$ cat /proc/meminfo | head -5

# 3. 硬件属性是文件：直接 echo 就能改
$ ls /sys/class/leds/
$ echo 1 > /sys/class/leds/sys-led/brightness   # 点亮
$ echo 0 > /sys/class/leds/sys-led/brightness   # 熄灭

# 4. 网络连接也是文件
$ cat /proc/net/tcp
这条思想为什么重要 第 12 章写驱动时，你要做的事本质上就是「在 /dev 下造一个文件，让用户程序通过 read/write 控制硬件」。理解了这一层，驱动开发就不再神秘。

3.3 路径、通配符、Tab 补全

  • 绝对路径：从 / 开始，如 /home/ubuntu/work。
  • 相对路径：从当前位置算，如 ../work；. 是当前目录，.. 是上一级。
  • 家目录简写：~ 等于 /home/你的用户名。
  • 通配符：* 任意字符，? 一个字符，[abc] 集合，{a,b} 展开。
$ ls *.c                # 所有 .c 文件
$ ls file[1-3].txt      # file1~file3
$ cp img.{jpg,bak} /tmp # 展开成 img.jpg img.bak
两个救命键 Tab 补全路径（敲一半按 Tab，按两次列出所有候选）；Ctrl+C 中断当前命令。新手 80% 的输错路径，Tab 都能避免。

3.4 核心命令（按用途分组，必须练到盲打）

① 我在哪 / 我去哪

命令作用常用写法
pwd打印当前路径pwd
cd切换目录cd /etc、cd ..、cd ~、cd -（回上一个目录）
ls列目录ls -l（详细）、ls -lh（人读大小）、ls -a（含隐藏）、ls -lt（按时间）
tree树形展示tree -L 2（只看两层）

② 建 / 删 / 改 / 移

命令作用注意
mkdir建目录mkdir -p a/b/c 一次建多层
touch建空文件 / 更新时间戳touch a.c b.c
cp复制cp -r dir1 dir2 复制目录必须 -r
mv移动 / 改名mv a.c b.c 就是改名
rm删除rm -rf 极危险，删前先用 ls 看一下
ln建链接ln -s 源 目标 建软链接
关于 rm -rf Linux 没有回收站。一条 rm -rf /* 能让系统在几秒内变成空壳。养成三个习惯：① 删之前先 ls 确认 ② 路径用 Tab 补全而不是手打 ③ 不确定时先用 -i 逐个确认。本书所有实验都别用 root 执行 rm。

③ 看内容

命令作用场景
cat整个文件打印出来小文件、拼接 cat a b > c
less分页浏览，可搜索大文件、日志（/关键字 搜索）
head tail头 / 尾 N 行tail -f log 实时看日志，调试必备
wc统计行数/字数wc -l file 数行数
grep按内容搜索grep -rn "keyword" . 递归搜代码

④ 找文件

命令按什么找示例
find按名称/大小/时间/权限find . -name "*.c"、find / -size +10M
which命令的可执行文件在哪which gcc
whereis命令 + 手册 + 源码位置whereis ls
locate数据库查找（快，可能过期）sudo updatedb 后 locate stdio.h

⑤ 压缩打包（传文件必用）

# 打包 + gzip 压缩（最常用）
$ tar -zcvf work.tar.gz work/
# 解压到指定目录
$ tar -zxvf work.tar.gz -C /tmp/
# 只看内容不接压
$ tar -ztvf work.tar.gz
# zip
$ zip -r work.zip work/ && unzip work.zip

参数记忆法：z 用 gzip、c 创建、x 解压、v 显示过程、f 指定文件名（必须放最后）。

3.5 管道与重定向：把命令串起来

单个命令能力有限。管道 | 把前一个命令的输出交给后一个命令当输入，这才是 Linux 的真正威力。

ps aux列出所有进程
|
grep nginx筛出含 nginx 的行
|
wc -l数一数有几个
# 找出占用 CPU 最高的 5 个进程
$ ps aux --sort=-%cpu | head -6

# 统计当前目录下 .c 文件有多少行代码
$ find . -name "*.c" | xargs wc -l | tail -1

# 看谁在占用 22 端口
$ ss -lntp | grep :22

重定向则是把输出写进文件，而不是打印到屏幕：

写法含义
> file覆盖写入（清空原内容）
>> file追加写入
2> err.log只把错误输出写进文件
&> all.log正确 + 错误都写进去
2>&1把错误重定向到标准输出（常配合管道用）
< file把文件当标准输入
 
# 编译并把所有输出存日志，屏幕只看结尾
$ make > build.log 2>&1 && tail -5 build.log

# 丢弃输出（不想看又不想存）
$ command > /dev/null 2>&1
/dev/null 是什么 一个黑洞设备文件，写进去的东西全部消失。第 5 章写脚本时天天用。

3.6 find + grep：定位问题的第一把刀

后面调试时，你会反复用这两个命令。记住四种组合就够：

# 1. 按名字找
$ find /home -name "*.c" -type f

# 2. 按大小找（找占空间的大文件）
$ find / -type f -size +100M 2>/dev/null

# 3. 找到后对每个文件执行命令
$ find . -name "*.log" -exec rm -f {} \;

# 4. 在文件内容里搜（写驱动时找某个宏定义）
$ grep -rn "CONFIG_LEDS_GPIO" drivers/leds/

# 5. 组合：找出所有 .dts 里含 gpio 的文件
$ grep -rl "gpio" --include="*.dts" arch/arm/boot/dts/

3.7 权限：Linux 最重要的一道门

看这一行，每个字符都有含义：

$ ls -l hello.c
-rwxr-xr-x 1 ubuntu ubuntu 1024 Nov 20 10:00 hello.c
 ↑↑↑↑↑↑↑↑↑  ↑      ↑
 │└┬┘└┬┘└┬┘  │      └── 所属组
 │ │  │  │   └───────── 属主
 │ │  │  └───────────── 其他人 rwx
 │ │  └──────────────── 同组用户 rwx
 │ └─────────────────── 属主 rwx
 └───────────────────── 类型：- 普通文件, d 目录, l 链接, c/b 设备
字母对文件对目录
r读内容能列出里面有什么（ls）
w改内容能新建/删除里面的文件
x执行（可执行文件）能进入（cd）

数字表示法：r=4、w=2、x=1，三位相加。所以 755 = rwx r-x r-x，644 = rw- r-- r--。

$ chmod 755 hello.c        # 属主全权，其他人读+执行
$ chmod u+x script.sh      # 给属主加执行权
$ chmod -R 755 dir/        # 递归改整目录
$ chown ubuntu:ubuntu file # 改属主与属组
$ chgrp dialout /dev/ttyUSB0
为什么板子上老报 Permission denied ① 文件没有 w 或 x；② 你不是属主也不是同组；③ 串口/设备需要 dialout 组；④ 目录没有 x 你连 cd 都进不去。按这四条查，基本必中。

umask：新文件的默认权限从哪来

$ umask
0002          # 普通用户默认
# 新建目录 = 777 - 002 = 775；新建文件 = 666 - 002 = 664
$ umask 022    # 临时改：新文件变成 644

3.8 软链接和硬链接

软链接 ln -s硬链接 ln
本质一个存着目标路径的「快捷方式」文件同一个 inode 的另一个名字
跨分区可以不行（必须同一文件系统）
指向目录可以不行
目标删了链接变红/失效文件还在，数据不丢
典型用途换版本（/usr/bin/gcc -> gcc-11）、跨目录共享备份、省空间
 
$ ln -s /opt/gcc-linaro/bin/arm-linux-gnueabihf-gcc ~/bin/arm-gcc
$ ln data.txt data_hard.txt
$ ls -l      # 软链接显示 ->，硬链接看不出差别
$ stat data.txt data_hard.txt   # 看 inode 是否相同

3.9 动手任务

  • 只用终端，在家目录建 ~/lab/ch03/{src,log,backup} 三层目录。
  • 在 src 下建 5 个 .c 文件、3 个 .h 文件，每个随意写几行。
  • 用 find 找出 ~/lab 下所有 .c 文件，用 xargs wc -l 统计总行数。
  • 把整个 lab 打包成 lab.tar.gz 放进 backup，再解压到 /tmp 验证。
  • 给 src 下一个脚本加执行权限，然后 ./ 运行它；再故意 chmod 000，感受 Permission denied。
  • 给 src 建一个软链接到 ~/lab/link_src，删掉 src 看链接怎么变；再建硬链接重复一次，对比 stat 输出。
  • 读 /proc/cpuinfo，找出你的 CPU 型号和核数；读 /proc/meminfo 找总内存。
