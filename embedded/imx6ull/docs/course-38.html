卷 07·芯片与硬件底座·第 09 篇

总线

CPU 与 DDR、外设之间不是「直连」，而是一条共享的公路——总线。总线有宽度、有频率、有仲裁，所以带宽是有限的。当你觉得「CPU 明明很快，为什么处理数据还是慢」，答案常常在总线上。

★ 一读 纯读约 1 小时 左侧是本卷目录 理论为主 · 实作可跳

这一课要回答的问题

① AXI / AHB / APB 各服务谁？② 带宽怎么算？③ 地址译码怎么找到目标设备？④ 为什么多个主设备会「抢总线」？⑤ DMA 为什么比 CPU 拷贝快？

1. 带宽怎么算

带宽 = 位宽 × 频率（单边）
# 例：64 位 AXI @ 132MHz
64 bit = 8 字节 × 132M = 1056 MB/s ≈ 1 GB/s

# 但真实可用带宽远低于理论值：
#   - 读写切换开销
#   - 非连续访问（每次都要发新地址）
#   - 仲裁与等待
# 实际能到 50%~70% 就已不错

这条算式很实用：算清「你的应用需要多少带宽」与「总线能给多少」，就能预判是否会卡。比如 800×480 RGB565、60fps 的屏幕，需要约 46MB/s——占 AXI 带宽的 5% 左右，没问题；但若同时做摄像头采集 + 存储写入，就可能挤爆。

2. 地址译码：谁来接这一单

每个外设在总线上有一个地址范围。CPU 发出地址，译码器比较高位，决定由哪个从设备响应：

0x8000_0000 - 0x9FFF_FFFF  → DDR 控制器
0x0209_C000 - 0x0209_CFFF  → GPIO1
0x0219_0000 - 0x0219_3FFF  → UART1
0x0000_0000 - 0x0001_FFFF  → Boot ROM / OCRAM

# 地址空间就这么被切开了
cat /proc/iomem

这也解释了「访问一个不存在的地址会怎样」：总线会返回一个 abort（第 29 课的 data abort），内核据此判定「非法访问」。

4. 时钟域与异步

不同总线段可能跑不同频率（AXI 132M、IPG 66M）。跨时钟域传输必须同步（第 08 课的亚稳态问题），硬件上用异步 FIFO 或握手协议解决。

软件侧能感知的现象：访问慢速外设时，一次读写要等好几个周期。所以驱动里连续读同一个寄存器要谨慎，能批量读就批量读（burst）。

6. 自测与动手

1

64 位 @132MHz 的 AXI 理论带宽？

看答案

8 字节 × 132M ≈ 1056 MB/s，约 1 GB/s。

2

为什么要把总线分三层？

看答案

隔离慢速外设与高速内存，避免低速访问拖累整体带宽。

3

地址译码的依据是什么？

看答案

比较地址高位与各设备分配的范围，决定由哪个从设备响应。

4

DMA 为什么快？

看答案

由专用控制器搬数据，CPU 只发指令即可并行做别的事。

5

访问不存在的地址会发生什么？

看答案

总线返回 abort，CPU 触发 data abort 异常，内核判为非法访问。

  1. cat /proc/iomem，列出三块不同性质地址范围。
  2. 算你的 LCD 分辨率下需要的带宽，与 AXI 理论值比。
  3. 用 memcpy 与 DMA 各拷 1MB，比较耗时。
  4. 读手册的总线章节，找出 AXI 与 IPG 的频率。
