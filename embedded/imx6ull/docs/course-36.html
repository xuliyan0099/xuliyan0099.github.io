卷 08·启动链·第 02 篇

启动链

从「按下电源」到「看到 shell 提示符」，中间有四段代码依次接力：片内 Boot ROM、u-boot、内核、init。每一段只做一件事，然后把下一段叫起来。理解这条链，你就能定位「卡在哪一段」。

★ 一读 纯读约 1 小时 左侧是本卷目录 理论为主 · 实作可跳

这一课要回答的问题

① 四段各做什么？② 为什么要分 SPL 与完整 u-boot？③ bootargs 从哪来、传给谁？④ 卡在某一段怎么定位？

1. 各段职责与失败现象

阶段在哪运行关键动作失败现象
Boot ROM片内 SRAM采样启动引脚、读镜像头、校验串口完全无输出
SPL片内 SRAM初始化 DDR、搬完整 u-boot打一两行后停住
u-bootDDR驱动外设、读环境、加载内核与 dtb停在 => 提示符
kernelDDR建页表、初始化子系统、挂 rootfs启动日志停在某一行
init用户态启动服务、开 shell日志完整但没有 shell

这张表就是排障地图：先看串口停在哪，再对照该阶段在做什么，范围立刻缩小到几件事。

2. SPL 为什么必须存在

Boot ROM 只能用片内 SRAM（i.MX6ULL 约 128KB），装不下完整 u-boot（通常几百 KB）。而 u-boot 又要用 DDR 才能跑起来，DDR 却还没初始化——死循环。

解法：把「初始化 DDR」这件最小的事切成 SPL（几十 KB），先在 SRAM 里跑，把 DDR 弄好，再读完整 u-boot 进 DDR。

# 编译产物
u-boot.imx        # 含 IVT/DCD，Boot ROM 直接识别的格式
u-boot-spl.bin    # 早期阶段（部分板子合并进 imx 镜像）
zImage            # 压缩的内核
xxx.dtb           # 设备树（第 37 课）

3. bootargs：内核的命令行

# u-boot 环境变量（printenv 可见）
bootargs=console=ttymxc0,115200 root=/dev/mmcblk1p2 rootwait rw
bootcmd=load mmc 1:1 0x80800000 zImage; load mmc 1:1 0x83000000 dtb; bootz ...

# 关键几项
console=ttymxc0    # 内核往哪个串口打印
root=/dev/mmcblk1p2# 根文件系统在哪个分区
rootwait           # 等设备就绪再挂
rw                 # 可读写挂载
init=/bin/sh       # 应急：不进 init，直接给 shell

init=/bin/sh 是救砖利器：rootfs 坏了但内核能起来时，可以直接进一个最小 shell 去修。这个参数值得记牢。

4. 卡住时的定位方法

# 卡在 Boot ROM 之前
#   → 电源、晶振、启动引脚（第 35 课）

# 卡在 SPL
#   → DDR 参数不对（用错板子的 ddr_init）、DDR 供电

# 停在 u-boot 提示符但 bootcmd 不跑
#   → printenv 看 bootcmd/bootargs 是否被改坏

# 内核日志停在 "Starting kernel ..."
#   → 内核没解压成功、dtb 不匹配、early console 没配

# 内核日志停在 "Waiting for root device"
#   → 根分区名错、驱动没编进去、eMMC 未识别

# 日志完整但没有 shell
#   → init 程序不存在/不可执行，或 inittab 配错

这几条几乎覆盖了 90% 的启动失败。建议抄在纸上贴在工位——每次卡住，先对号入座，别急着改代码。

5. 三条常见误解

6. 自测与动手

1

为什么要两阶段 bootloader？

看答案

片内 SRAM 装不下完整 u-boot；SPL 先初始化 DDR，再搬完整版。

2

init=/bin/sh 有什么用？

看答案

跳过 init 直接给一个 shell，用于 rootfs 异常时的应急修复。

3

日志停在 "Waiting for root device" 通常是什么原因？

看答案

根分区名不对、存储驱动没编进内核、或 eMMC/SD 未被识别。

4

改了设备树要重编内核吗？

看答案

不用。dtb 是独立文件，重新编译并替换即可。

5

卡在 SPL 最可能是哪件事？

看答案

DDR 初始化参数与板上颗粒不匹配；其次是供电或时钟问题。

  1. 上电并完整记录串口输出，标出四段的分界点。
  2. 在 u-boot 里 printenv，抄下 bootargs 与 bootcmd。
  3. 用 init=/bin/sh 启动一次，体验应急 shell。
  4. 故意改坏 root= 参数，观察内核报的错。
