特权级与异常

用户程序写了 1 万行代码，为什么就是改不了内核的一个变量？因为它们在不同的特权级跑，而 CPU 有一套硬件机制保证「低权限的代码无法自己升权」，只能通过一条特殊指令走「正门」。这一课讲这个正门：异常向量与模式切换。

★ 一读 纯读约 1 小时 左侧是本卷目录 理论为主 · 实作可跳

这一课要回答的问题

① 七种模式分别干什么？② SVC 指令执行时硬件做了什么？③ 向量表里八个入口是什么？④ CPSR 与 SPSR 什么关系？⑤ 为什么用户态不能执行特权指令？

1. 一条 svc 的硬件动作

; 向量表（8 个入口，每个 4 字节，通常放一条跳转）
0x00  b  reset          ; 复位
0x04  b  undef_handler  ; 未定义指令
0x08  b  svc_handler    ; 系统调用 ← Linux 的入口
0x0C  b  prefetch_abort ; 取指失败
0x10  b  data_abort     ; 访存失败（缺页在这里）
0x14  b  reserved
0x18  b  irq_handler    ; 普通中断
0x1C  b  fiq_handler    ; 快速中断

Linux 在启动时把向量表放到 0xFFFF0000（高地址）或 0x00000000，由 CP15 的 SCTLR 控制位决定。

2. CPSR 与 SPSR

CPSR 存着：条件标志（N/Z/C/V）、中断使能（I/F）、模式位（低 5 位）。进入异常时，旧的 CPSR 被自动复制到 SPSR_<mode>，返回时用 movs pc, lr 或 rfe 把 SPSR 恢复回 CPSR——一条指令完成「还状态 + 改 PC」。

; 典型的异常返回
    ldmia sp!, {r0-r12, pc}^   ; ^ 表示同时把 SPSR 恢复进 CPSR

注意那个 ^：它是 ARM 汇编里最容易被忽略、也最容易出错的一个符号。忘了它，返回后模式没恢复，程序就会在错误模式里跑。

3. 为什么用户态不能执行特权指令

硬件检查两件事：

  • 模式位：在 User 模式下执行 mcr（访问协处理器）、改 CPSR、关中断等指令，会触发「未定义指令」异常。
  • 页表权限：内核页在页表项里标成「仅特权可访问」，User 模式访问会触发 data abort。

两道锁，一道在指令层、一道在内存层。绕过任何一道都不可能——除非内核有漏洞。

4. 异常与中断、陷阱的区别

类型来源同步性例子
异常（同步）当前指令执行引起与指令同步svc、缺页、未定义指令
中断（异步）外部设备任意时刻定时器、串口、GPIO
陷阱 trap软件主动同步svc、断点指令

区分它们很重要：同步异常可以「修好后重试原指令」（缺页就是这样），异步中断只能「处理完继续下一条」。

5. 实验：看一次 svc 的全过程

# 用户态 strace 看到的是「系统调用」
strace -f ./prog

# 内核侧看入口
# arch/arm/kernel/entry-armv.S 里的 vector_swi
# 它读 r7 作为 syscall 号，查 sys_call_table

# 在板子上看向量表位置
cat /proc/cpuinfo | grep -i "Features"   # 可能显示 vmsa 等
dmesg | grep -i "vector"

# gdb 断在 svc 前后，观察 CPSR 模式位变化
(gdb) info registers cpsr

如果你用 gdb 单步过一条 svc，会看到 PC 突然跳到 0xFFFF0008 附近——那就是向量表在起作用。

6. 三条常见误解

7. 自测与动手

1

svc 执行时硬件自动做了哪四件事？

看答案

保存 CPSR 到 SPSR_svc、切到 SVC 模式、保存返回地址到 lr_svc、跳到向量表 0x08。

2

SPSR 的作用是什么？

看答案

保存进入异常前的 CPSR，返回时用它恢复状态（模式位、中断使能、标志位）。

3

User 模式执行 mcr 会怎样？

看答案

触发未定义指令异常（进入 Undef 模式），内核可据此模拟或杀掉进程。

4

缺页属于哪一类异常？能重试吗？

看答案

同步异常（data abort），可以：补好页表后返回重试原指令。

5

为什么 banked 寄存器让异常进入变快？

看答案

每种模式有自己的 sp/lr/spsr，硬件自动切换，不必用指令保存这些寄存器。

  1. 查 A7 的向量表基址寄存器（VBAR），确认 Linux 把它设在哪。
  2. 用 gdb 单步一条 svc，观察 PC 跳转与 CPSR 变化。
  3. 写一段内联汇编执行 mcr，在用户态跑，观察收到什么信号。
  4. 读 entry-armv.S 的 vector_swi，找出 r7 → 表的索引代码。
