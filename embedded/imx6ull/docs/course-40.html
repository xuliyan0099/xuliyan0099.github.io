存储与外设

前九部的原理在这里落地：eMMC 的块读、NAND 的坏块、LCD 的像素时序、I2C 的两根线、SPI 的四根线。这一课不是教你怎么写每个驱动，而是让你看到每个器件时，能立刻说出它挂在哪个总线、用什么协议、延迟大概是什么量级。

★ 一读 纯读约 1 小时 左侧是本卷目录 理论为主 · 实作可跳

这一课要回答的问题

① eMMC 与 SD 卡的本质区别？② NAND 为什么必须做 ECC 与坏块管理？③ LCD 的像素时钟怎么算？④ I2C 为什么只需要两根线？⑤ 调试外设的第一步该做什么？

1. eMMC 与 SD 卡

eMMCSD 卡
形态焊在板上（BGA）可插拔
接口8 位数据 + 时钟 + 命令4 位数据
可靠性高（工业级可选）较低，接触与供电易出问题
用途量产产品的系统盘开发阶段刷机、临时存储

两者协议同源（都是 MMC/SD 协议），所以内核里常共用一套驱动框架。但 SD 卡的「拔插」会带来一堆问题：挂载中的文件系统突然消失，内核只能报 IO 错误。量产设备几乎都用 eMMC。

2. NAND：便宜但要「养」

NAND 有三个先天缺陷，驱动必须处理：

  • 坏块：出厂就有，且使用中会增加，需要坏块表。
  • 位翻转：读出来偶尔错一位，必须 ECC。
  • 擦除寿命：每块只能擦有限次，需要磨损均衡。

所以 NAND 上不能直接放文件系统，要经过 UBI + UBIFS（或 YAFFS 等）。这也是「为什么嵌入式常用 eMMC 而不是 NAND」——eMMC 内部已经把这三件事做好了。

3. LCD 的像素时钟

像素时钟 = (H 有效 + H 前后肩 + H 同步)
         × (V 有效 + V 前后肩 + V 同步)
         × 刷新率

# 例：800×480 @60Hz，典型时序
H: 800 + 40 + 40 + 48  = 928
V: 480 + 13 + 29 + 3   = 525
928 × 525 × 60 ≈ 29.2 MHz

# 带宽需求（RGB565，每像素 2 字节）
29.2M × 2 ≈ 58 MB/s  ← 这就是第 38 课算总线时要用的数

算错时序的现象很具体：图像偏移、抖动、或者干脆黑屏。屏幕点不亮时，先核对像素时钟与时序参数，再看背光与供电。

5. 调试外设的第一步

# 1) 它有没有被识别？
dmesg | grep -i "i2c\|spi\|mmc\|fb"
ls /sys/bus/i2c/devices/
ls /sys/class/mmc_host/

# 2) 寄存器能不能读？
i2cdetect -y 0            # I2C 扫描
i2cget -y 0 0x50 0x00     # 读一个字节
devmem 0x0209C000         # 直接读物理地址（busybox 常带）

# 3) 时钟与引脚对不对？
cat /sys/kernel/debug/clk/clk_summary
cat /sys/kernel/debug/pinctrl/*/pinmux-pins

这三步几乎能定位 80% 的外设问题：没识别 → 看设备树与时钟；识别了但读写失败 → 看地址与上拉；都正常但数据错 → 看时序与电平。

7. 自测与动手

1

为什么量产设备偏好 eMMC？

看答案

焊接固定、可靠性高、内部已做坏块与磨损管理，不怕振动与拔插。

2

NAND 的三件「必须做的事」？

看答案

坏块管理、ECC 纠错、磨损均衡；通常由 UBI/FTL 层完成。

3

800×480@60Hz 的像素时钟大约多少？

看答案

约 29MHz（含消隐区），带宽约 58MB/s。

4

I2C 为什么需要上拉？

看答案

开漏输出只能拉低，高电平靠上拉电阻；这也是它能「线与」共享的原因。

5

外设没被识别，第一步查什么？

看答案

dmesg 与设备树 status/compatible，再看时钟与引脚复用。

  1. 用 i2cdetect 扫描板上的 I2C 总线，列出地址。
  2. 算你屏幕的像素时钟与带宽需求。
  3. 用 devmem 读一个 GPIO 寄存器，验证地址映射。
  4. 查 /sys/class/mmc_host/，找出 eMMC 与 SD 各自的设备。
