第 07 课 · 补码与减法器：减法根本不需要减法器

CPU 里只有一个加法器，却能做减、乘、除、比较、取负。秘密在于补码：把一个数「取反加一」，它就变成了相反数，于是 A - B 直接变成 A + (-B)。这一课讲透这个技巧，以及它带来的两个后果：为什么 -2147483648 取负还是它自己，为什么有符号溢出要看符号位。

这一课要回答的问题

① 钟表为什么能解释负数？② 补码的定义到底是什么？③ 为什么「取反加一」等于取负？④ 减法指令在硬件上怎么走？⑤ V 标志为什么是「最高进位 XOR 次高进位」？

1. 直觉：钟表倒拨三小时 = 正拨九小时

钟面上没有「-3」，但你可以把指针往前拨 9 小时，效果一样。因为钟面是循环的：12 个小时一圈，12 就是「模」。同理，8 位计数器有 256 个状态，256 就是模：-3 等价于 253（256-3）。

这就是补码：-x 用 2^n - x 表示。它不是一个「符号标记方案」，而是让加法自动完成减法的方案。

失效处：模运算只在「不越界」时成立。一旦越界，就会从最大值瞬间跳到最小值——这就是溢出，也是 C 语言里 INT_MAX + 1 属于未定义行为的物理根源。

2. 硬件上：一个加法器包打天下

减法：A - B  =  A + (-B)
           =  A + (~B + 1)        （取反加一）
           =  A + (~B) + Cin(1)   （Cin 就是那个 +1）

3. 为什么 V 是「最高进位 XOR 次高进位」

有符号溢出只会在一种情况发生：两个同号数相加，结果反号。用进位来描述：

  • 正 + 正 越界 → 进位从 bit30 进到 bit31，但 bit31 没有继续进位 → 两次进位不同 → 符号位被顶成 1（变负）。
  • 负 + 负 越界 → 相反方向 → 符号位被顶成 0（变正）。

所以 V = C31 XOR C30（最高位的进位 与 次高位的进位 异或）。这个公式一行就能实现，代价几乎为零——所以几乎所有的 ALU 都免费提供 V。

7. 自测与动手

1

8 位下 -5 的补码是多少？

看答案

256-5 = 251 = 0xFB = 1111 1011。验证：取反加一 ~5=250，250+1=251。

2

为什么补码没有 -0？

看答案

因为 0 的补码就是 0 本身（取反加一后仍为 0），状态数 2^n 被完整分配：0 一个，负数 2^(n-1) 个，正数 2^(n-1)-1 个。

3

8 位下 -128 的相反数是多少？说明后果。

看答案

还是 -128（+128 超出范围）。后果：abs(INT_MIN) 返回负数，若不判范围会导致后续逻辑错误。

4

一条 sub r0, r1, r2 在硬件上用到几个加法器？

看答案

一个。r2 取反（XOR 门），Cin=1，然后走加法器。

5

为什么两个同号数相加才可能溢出？

看答案

异号相加结果绝对值一定变小，不可能超出范围；只有同号相加才可能越界并翻转符号位。

  1. 跑 Python 脚本，把 -128 ~ 127 全部打印成二进制，找出「突变点」。
  2. 在 Ubuntu 上用 gcc -S 看 a-b 生成的是 sub 还是别的指令。
  3. 写一段代码触发有符号溢出，用 -fsanitize=signed-integer-overflow 看它报什么。
  4. 用 objdump -d 找一条 cmp，确认它其实是 subs。
