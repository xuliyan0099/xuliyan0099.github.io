第 06 课 · 从半加器到全加器：CPU 的心脏

CPU 里最忙的部件是加法器。一条 add 指令、一次地址计算、一次循环变量自增、一次指针偏移，背后都是它。这一课从「两个比特相加」一路搭到 32 位加法器，顺便看清一个关键工程矛盾：进位是串行的，串得越长越慢——这正是主频上限的来源之一。

这一课要回答的问题

① 两个比特相加，为什么需要两个输出？② 全加器比半加器多了什么？③ 8 位加法器最坏延迟是几级？④「超前进位」怎么绕开串联？⑤ CPU 的 C/V/Z/N 标志位是加法器的哪个副产物？

1. 直觉：小学竖式

算 27 + 35：先算个位 7+5=12，写 2 进 1；再算十位 2+3+1=6。这个「进位」就是数字电路的 carry。每一位的运算都需要知道右边传来的进位，所以必须从右往左串行。

失效处：人手算可以跳着来，电路不行。电路里所有位同时工作，但必须「等」进位稳定，这个「等」就是延迟。

2. 硬件上：半加器 → 全加器

半加器（Half Adder）：只加 A、B，不考虑进位输入
  S = A XOR B        （和）
  C = A AND B        （进位）

全加器（Full Adder）：加 A、B、Cin
  S    = A XOR B XOR Cin
  Cout = (A AND B) OR (Cin AND (A XOR B))

全加器可以由「两个半加器 + 一个或门」拼出：第一个半加器算 A+B 得 S1、C1；第二个把 S1 与 Cin 相加得 S、C2；最后 Cout = C1 OR C2。总共约 5 个门、3 级延迟。

32 位加法器就是 32 个全加器串联。最坏情况一次 32 级门延迟——这就是为什么老式 CPU 一条加法指令要花好几个周期。

3. 超前进位：把「等」变成「并行猜」

观察每一位：进位什么时候产生？两种情况——

  • 生成（Generate）：G = A AND B。这一位自己就产生进位，不管输入进位是什么。
  • 传播（Propagate）：P = A XOR B。这一位会把输入进位原样传下去。

于是进位可以写成：C(i+1) = G(i) OR (P(i) AND C(i))。把代入展开，第 4 位进位可以直接用 A3..A0、B3..B0 算出来，不需要等 C3 稳定。4 位一组做 CLA，再组间再 CLA，就成了树形结构——延迟从 O(n) 降到 O(log n)。

代价是门数暴涨（每个进位都要一整套与或树）。所以真实设计在「长度」上折中：通常 4~8 位一组。ARM 的加法器就是这类结构。

4. 一个加法器如何产出五个标志位

ARM 的每条数据处理指令执行完，都会更新 CPSR 里的条件标志。它们全部是加法器的「副产物」：

标志含义从哪里来
N（Negative）结果为负结果最高位（第 31 位）
Z（Zero）结果为零所有结果位 NOR 起来（全 0 则为 1）
C（Carry）无符号进位/借位加法器最高位的进位输出
V（Overflow）有符号溢出最高位进位 XOR 次高位进位（符号位被「顶翻」）
Q（Saturation）饱和（DSP 扩展）饱和运算是否发生

这个表格解释了一个非常实际的调试现象：比较指令 cmp 其实就是 subs（减法并更新标志），分支指令 bne 只是去看 Z 位。CPU 不会「真的比较」，它只是做减法、看标志。第 07 课会把这条链路彻底打通。

5. 实验：用位运算模拟行波加法器

def ripple_add(a, b, bits=8):
    print("a=%s b=%s" % (bin(a), bin(b)))
    carry, out = 0, 0
    for i in range(bits):
        ai = (a >> i) & 1
        bi = (b >> i) & 1
        s = ai ^ bi ^ carry          # 和位
        new_carry = (ai & bi) | (carry & (ai ^ bi))
        print(" bit%d: a=%d b=%d cin=%d -> s=%d cout=%d"
              % (i, ai, bi, carry, s, new_carry))
        out |= s << i
        carry = new_carry
    print("结果=%d 最终进位=%d" % (out, carry))
    return out, carry

ripple_add(0b10110101, 0b01101111)

# 观察：8 位无符号 181+111=292，超出 255 → 结果 36，进位 1
# 这就是 C 标志：无符号溢出

# 再看有符号：-75 + 111 = 36，不溢出，V=0
# 同一个加法，C 和 V 的结论完全不同——这就是「有符号/无符号只看你怎么解释」

跑到这里你应该能自己回答：为什么 181+111 的 C=1 而 V=0？因为无符号视角下 292 超出 8 位；有符号视角下 -75+111=36 完全合法。硬件只管算位，解释权在软件。

6. 三条常见误解

7. 自测与动手

1

半加器为什么不能直接串成多位加法器？

看答案

半加器没有进位输入端口，只能处理最低位；其余位必须能接收低位传来的进位，所以需要全加器。

2

全加器的 Cout 表达式为什么是 (A&B) OR (Cin&(A^B))？

看答案

两种情况会产生进位：A、B 都为 1（自己生成），或者 A、B 只有一个为 1（A^B=1）且 Cin 为 1（把进位传下去）。

3

C 和 V 有什么区别？举一个 C=1、V=0 的例子。

看答案

C 是无符号视角的进位；V 是有符号视角的溢出（符号位被顶翻）。8 位下 181+111：C=1，V=0。

4

超前进位为什么要引入 G 和 P？

看答案

为了把「等进位」变成「用输入直接算出进位」：G 表示本位必然产生进位，P 表示本位会传递进位，于是进位可以由输入并行计算。

5

Z 标志在硬件上怎么算？

看答案

把 32 个结果位全部 NOR（或非）：任一为 1 则输出 0，全为 0 则输出 1。通常用一棵或树 + 取反，比 32 输入或门更快。

  1. 跑上面的 Python，把 181+111 的每一位打印出来，标出进位在哪一位停住。
  2. 用 Python 改 bits=4，试 7+9，观察 C 与 V 的不同结论。
  3. 手画 4 位 CLA 的 G/P 生成逻辑（只看第 3 位）。
  4. 在板子上跑 objdump -d 看一条 add 的机器码，找到它用了哪几个寄存器。
