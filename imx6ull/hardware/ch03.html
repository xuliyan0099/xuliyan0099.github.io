SoC 里面有什么

板子上最贵的那颗 BGA，不是「一个 CPU」，而是「一个 CPU 加一堆控制器」焊在同一块硅片上。这一章把它拆开：谁在执行指令、谁在搬数据、谁在管地址、谁在管引脚、谁在发时钟。后面写驱动，其实就是在跟这里面一个个方块打交道。

读完这一章，你应该能

  1. 说出 Cortex-A7 的核心里有什么（指令流水、Cache、MMU、GIC），以及没有 MMU 为什么跑不了 Linux
  2. 分清「控制器在片内」和「器件在板外」，并能举出三个例子
  3. 知道 IOMUXC 与 CCM 的角色：一个管引脚归谁，一个管时钟给谁
  4. 看到一个外设名（如 enet1），能说出它对应片内哪个模块、板外接了什么、驱动看哪本手册

1.3.1先看全局：三个层次的框图

把芯片想成一座工厂：CPU 是车间（执行指令），总线是传送带（搬数据与地址），控制器是各条生产线（DDR、SD、UART、网口……），CCM 是电闸（谁通电、通多少），IOMUXC 是接线板（把哪条线的信号接到外面哪个脚）。

1.3.2Cortex-A7：这颗核到底强在哪、弱在哪

i.MX6ULL 用的是 ARM Cortex-A7，属于 ARMv7-A 架构、32 位、顺序双发射、8 级流水线。它和同时代的 Cortex-A9 相比少了乱序执行，但功耗低、面积小，正好适合这类工业与教育板。

部件作用去掉它会发生什么
MMU虚拟地址 → 物理地址、页级权限、内存保护跑不了 Linux：内核要靠它做进程隔离、按需分页、mmap
L1 / L2 Cache把常用数据留在离核最近的地方性能断崖；DMA 与 Cache 一致性也需要它（这也是驱动里 dma_sync_* 存在的原因）
NEON / VFP浮点与 SIMD 指令编译器浮点会走软浮点，音视频类运算慢一个数量级
GIC中断排队、优先级、多核分发（本芯片单核）没有任何中断，所有外设只能轮询
TrustZone安全世界与普通世界隔离对日常开发无感，但很多板子用它做安全启动

有个细节值得记住：Cortex-A7 的 L1 Cache 是「VIPT」（虚拟索引物理标记），所以改页表后必须按 ARM 的流程做 Cache 与 TLB 维护，乱序刷新会得到「明明改了映射却还读到旧数据」的怪现象。这类细节在写驱动时才会咬人，先有个印象。

为什么「单核 528MHz」也能跑 Linux

Linux 对主频不挑，对架构能力挑：要有 MMU、要有可编程的定时器（做调度节拍）、要有中断控制器、要有至少几十 MB 内存。i.MX6ULL 这四样齐备，所以能跑完整 Linux；而 Cortex-M 系列缺 MMU，只能跑 RTOS 或 uClinux。这也解释了为什么学嵌入式 Linux 一定要选带 MMU 的片子。

1.3.3控制器与器件：片内片外的分工

新手最容易混淆的一点：「控制器」在芯片里，「器件」在板子上。i.MX6ULL 内部有 DDR 控制器，但 DDR 颗粒是焊在板子上的；有以太网 MAC，但 PHY 在板外；有 UART 控制器，但电平转换/转串口芯片在板外。

片内控制器板外器件连接方式驱动里最先看什么
MMDCDDR3L 颗粒并行 DDR 总线u-boot 的 DDR 配置（校准参数）
uSDHC（SD1/SD2）TF 卡座 / eMMC 芯片SD 总线（CLK/CMD/DAT）设备树里的 bus-width、non-removable
UART1–8USB 转串口芯片 / 排针TX/RX/CTS/RTSpinctrl 分组 + 波特率时钟源
ENET1/2（MAC）KSZ8081 等 PHYRMII（REF_CLK + 数据线）PHY 复位脚、phy-mode、时钟
USB OTG/HostMicroUSB 座 / USB-A 座USB 差分线VBUS 检测、模式脚（ID）
LCDIFRGB 屏 + 背光电路24bit 并口 + PWM 背光时序参数表、背光使能脚

这个表格直接决定排障方向：现象是「全都不能用」→ 查片内共用资源（时钟、电源、总线）；现象是「只有这一个外设不行」→ 先查板外器件与引脚复用。

1.3.4CCM 与 IOMUXC：两个最容易被忽略的闸门

CCM时钟不给，寄存器全是 0

每个外设的寄存器读写都需要时钟。CCM 里为每个模块设了一个 CCGR（Clock Gating Register）门控位，默认多数是关闭的。表现非常像「硬件坏了」：读寄存器返回 0，写进去读不回来，外设毫无反应。所以任何外设调试的第一步，是确认它的 CCGR 已打开、时钟源选对。

IOMUXC引脚不给，信号出不去

芯片的物理引脚数量远少于内部信号数量，所以每个脚都有 8 个候选功能（ALT0–ALT7）。IOMUXC 决定「这个脚此刻听谁的」，PAD_CTL 决定「它的驱动强度、上下拉、开漏、转换速率」。两样都配了，信号才能真正出去。第 6 章专门讲它。

一句话记忆

CPU 算，总线搬，控制器管外设，CCM 供电闸，IOMUXC 接线板，GIC 排队报信。六件事各管一段，出问题时先定位是哪一段沉默。

1.3.5地址空间：为什么寄存器地址长那样

i.MX6ULL 把片内资源映射到固定的物理地址区间，芯片手册的 "Memory Map" 一章会列全。常见几段：

区间（示意）放什么注意
0x0000_0000 起Boot ROM（片内固化的启动代码）上电第一条指令来自这里
0x0090_0000 附近OCRAM（片内小 SRAM）u-boot 早期会借它跑
0x020C_0000 等CCM / IOMUXC / GPIO 等外设寄存器驱动里的 ioremap 目标
0x8000_0000 起DDR（外部内存）内核把自己搬到这里运行

写驱动时看到的「0x020C4068」这类地址，就是这些外设寄存器的物理地址。内核里不能直接解引用，要先 ioremap 成虚拟地址；这也是为什么设备树里写的是「寄存器基址 + 长度」，而不是一段裸指针。

自测

为什么 Cortex-M 能跑 RTOS 却跑不了标准 Linux？
差别不在主频，而在MMU。Linux 依赖虚拟内存做进程隔离、按需分页、文件映射，没有 MMU 就实现不了。Cortex-M 系列通常没有 MMU（只有 MPU），所以只能跑 FreeRTOS 这类系统或 uClinux。
读一个外设寄存器总是 0，写进去也读不回来，最可能是什么原因？
按概率排：① 时钟没开（CCM 的 CCGR）；② 引脚复用没配（信号根本没接到外面，但对寄存器读写不影响，属另一类现象）；③ 复位没释放；④ 地址算错（基址 + 偏移）。寄存器读回全 0 最常见的就是时钟未使能。
「网口不亮」和「整板不启动」，排查方向有什么区别？
整板不启动是共用资源问题：电源、时钟、复位、启动介质。网口不亮是单点问题：先看 PHY 的供电与 50MHz 参考时钟，再看 phy-mode 与 pinctrl，最后才是驱动。判断依据就是「影响面大小」——这决定了先查片内还是先查板外。
