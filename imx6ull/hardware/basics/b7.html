先看电源树，别先看点灯

新手拿到板子第一件事是找 LED；正确顺序是先看电源树——因为所有「时好时坏」的问题，八成在电源。

一块 i.MX6ULL 板子的典型电源轨：

轨电压给谁常见来源
VDD_5V / VIN5V整板入口DC 座 / USB
VDD_3V33.3V外设 IO、大部分芯片降压（buck）
VDD_ARM可调（约 1.2–1.4V）CPU 核降压，可动态调压
VDD_SOC约 1.3–1.4VSoC 内部降压
VDD_DDR1.35V（DDR3L）DDR 颗粒降压/线性
VDD_HIGH / NVCC_*多路模拟、存储接口线性（LDO）

看电源树要读出三件事：

  1. 谁给谁供电（上游是谁）。
  2. 哪几路是「可调」的（CPU 核电压通常随频率变，这就是内核里 DVFS 的物理基础）。
  3. 上电顺序有没有要求（有些芯片要求 core 先于 IO，违反会闩锁）。

这三件事在「硬件设计指南」与 PMIC 手册里，是排查「板子完全不上电」的第一手材料。

晶振与复位：CPU 的「心跳」与「起跑线」

元件参数作用
主晶振24MHz给 SoC 的参考时钟，PLL 从这里倍频出所有频率
RTC 晶振32.768kHz走时，断电也靠纽扣电池维持
复位电路RC + 按键 + 复位芯片保证电源稳定后才放开 CPU

主晶振不起振，整块板子就是「上电无反应」。判断方法：示波器（或高阻探头）量晶振脚，看不到 24MHz 正弦/方波就是它的问题。常见原因：负载电容焊错、晶振虚焊、晶振本身坏。

DDR：最容易「看起来好了其实没配好」的部分

i.MX6ULL 的 DDR 接口要点：

  • DDR3L 常见，1.35V，容量按板子（256MB / 512MB）。
  • 走线等长与端接：数据组内等长、地址/命令组等长，板上常有串联电阻（几十 Ω）。
  • 初始化参数极多：tRCD、tRP、tRAS、刷新周期……这些值来自 DDR 颗粒的 Datasheet，写进 DDR 控制器寄存器。

这就是为什么「裸机点灯」能跑，「裸机用 DDR」几乎必用官方初始化脚本（DCD 或 uboot 的 ddr_init）。自己手算 DDR 参数不是入门任务。

一个诊断技巧：DDR 初始化失败通常表现为「串口完全无输出」或「跑到某处就复位」——因为代码被链接到 DDR 上，DDR 没起来，代码就飞了。

eMMC / TF 卡 / SPI Flash：启动介质三选一

介质接口特点
eMMCSDIO（4/8 线）焊在板上，快，容量大
TF 卡SDIO可换，常用于烧录
SPI FlashSPI小容量，常存 uboot

i.MX6ULL 的 Boot ROM 支持从这些介质启动，由拨码开关或 eFuse 决定顺序。所以「烧了镜像不启动」的第一件事是确认拨码，不是怀疑镜像。

按键与 LED：最简单的两样，坑最多

按键：一端接 GPIO，另一端接 GND，GPIO 侧有上拉（外部或内部）。

  • 没上拉 → 悬空，读数随机。
  • 没有 RC 消抖 → 一次按下被识别成几十次。
  • 判断「按下」要读 PSR（引脚实际电平），不是 DR。

LED：阳极经限流电阻接电源（或接 GPIO），阴极接 GPIO 或地。

  • 极性写反 → 灯常亮或常灭，而不是「不工作」。
  • 多颗 LED 共用一个电阻 → 亮度不均。
  • 直接接 GPIO 不串电阻 → 可能超过 IO 驱动能力。

一张「板子地图」该怎么画

拿原理图，画四层：

① 电源层：入口 → 各路稳压 → 各模块
② 时钟层：晶振 → PLL → 各模块（这层要配合 CCM 章）
③ 接口层：每类总线挂了哪些器件（I2C/SPI/SDIO/ENET）
④ 交互层：按键、LED、串口、USB、网口

画完你会立刻发现两件事：哪些脚被复用冲突、哪些外设你没意识到存在。这张图就是 01 篇「自己的摘要」的物理版。

三个「先量什么」的判断

现象先量
完全不上电入口电压 → 各路稳压输出 → 复位电平
上电但无输出主晶振是否起振 → 启动拨码 → 串口线序
能跑但偶发死机电源纹波 → DDR 参数 → 温度（过热降频）

顺序永远是从「电源」往「信号」推，不要从「我怀疑的芯片」开始。

本篇验收

  • 能画出自己板子的四层地图（电源/时钟/接口/交互）。
  • 能说出 ARM 核电压为什么是可调的，以及它与 DVFS 的关系。
  • 能解释「烧了镜像不启动，先查拨码」。
  • 能说出按键的三个坑（上拉、消抖、读 PSR）。
  • 能说出 LED 极性写反的现象。
