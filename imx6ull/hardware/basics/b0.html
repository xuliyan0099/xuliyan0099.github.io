先修：怎么学才算学会

第 00 章约 12 分钟★ 必读

三条标准：什么算「学会了硬件」

不是「能背出五个元件名」，而是这三条：

  1. 看到一根线，能说出它为什么存在。 比如 DDR 数据线旁边为什么有一串电阻、I2C 的两根线为什么都要上拉。
  2. 看到一个数值，能判断它合不合理。 比如 3.3V 直接接 LED 行不行、上拉用 10k 还是 1k。
  3. 看到一个现象，能提出两个可能原因，并知道先量哪个。 比如「灯不亮」：先量电压还是先量电流？

三条都能做到，你在板子前面就不是瞎猜了。

一条走错的路：从「芯片」开始学

大多数人的路径是：先买板子 → 先跑例程 → 灯亮了 → 觉得自己会了 → 一改外设就崩 → 回头补基础 → 发现基础比想象中简单，只是没人讲过。

正确的顺序反过来：

物理（电是什么）→ 元件（它们各自解决什么问题）→ 电路（连起来干什么）
   → 数字（怎么表示 0/1）→ 时序（为什么要等）→ 总线（怎么传数据）→ 芯片

这个顺序的每一层，都在解释下一层里「看起来玄学」的那部分。跳过任何一层，下一层就只能靠背。

硬件与软件的分界线在哪

很多人以为分界线是「会不会写驱动」。实际的分界线是「你能不能判断问题在软件还是在硬件」。

三个抓手就够区分：

抓手判断
电压对不对该 3.3V 的地方量到 0V → 硬件
时序对不对波形有了但采样点不对 → 硬件/参数
状态对不对寄存器说发了，引脚没波形 → 复用/时钟（软件配错）

绝大多数「硬件坏了」其实是「软件没配对」，而绝大多数「软件有 bug」其实是「电气条件不满足」。这两句是这门课的主线。

你需要的工具，只有三样

  • 万用表（几十块就行）：量电压、量通断、量电阻。这是使用频率最高的工具，占 80% 的诊断工作。
  • 逻辑分析仪（几十到几百块）：看数字波形、解 I2C/SPI/UART。看不到波形时它是唯一证据。
  • 示波器（可选）：看模拟波形、看上升沿、看毛刺。前两样解决不了再上它。

不需要热风枪、不需要显微镜、不需要自己画板。修板子和设计板子是两件事，这门课只做前者。

学完你能做到什么

  • 拿到一块不亮的板子，能按「电源 → 时钟 → 复位 → 引脚 → 通信」的顺序量下去。
  • 看懂原理图上的每一类符号，并知道哪些是「可调」的、哪些是「固定」的。
  • 能读 Datasheet 的电气表，判断「这个器件能不能直接接在这颗芯片上」。
  • 能解释「为什么这里要加个电容」「为什么这里要串个电阻」，而不是照抄参考设计。

本篇验收

  • 能说出三条「学会」的判断标准，并举一个自己的例子。
  • 能画出「物理 → 元件 → 电路 → 数字 → 时序 → 总线 → 芯片」这条路径。
  • 能用三个抓手区分「软件问题」与「硬件问题」。
  • 说清万用表、逻辑分析仪、示波器各自解决什么问题。
