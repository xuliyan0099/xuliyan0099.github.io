三种启动方式

同一块板子，上电时从哪儿读系统是可以被引脚和熔丝决定的。这解释了 90% 的「我烧好了却起不来」：不是你烧错了，是它压根没去读你烧的那块存储。这一章讲清三条路、怎么切、切换失败的排查。

读完这一章，你应该能

  1. 说出 BOOT_MODE 拨码与 eFuse 的关系，以及谁优先级更高
  2. 画出 Boot ROM 的决策流程，知道它为每种介质做了什么准备
  3. 解释「USB 下载模式」为什么能救砖，它绕过了哪一步
  4. 自己完成一次「改拨码 → 从 TF 卡启动」并验证

1.5.1决策发生在毫秒之内

上电后复位释放的那一瞬，Boot ROM 读两个 BOOT_MODE 引脚的电平，决定走哪条路。这就是为什么很多板子的拨码只有 2 位——它只需要表达 4 种组合：内部启动、串行下载、SD 卡、NAND/eMMC（具体映射各家板厂略有差别）。

1.5.2拨码与 eFuse：谁说了算

优先级从高到低：

  1. BOOT_MODE 引脚（拨码）。上电瞬间采样，最高优先级。板子上有两个小开关，通常标 BOOT_MODE0/1 或 1/2。
  2. eFuse（一次性熔丝）。可以用工具烧写，烧了就改不回来，常用于量产时锁定启动介质。
  3. 默认/回退策略。有的板子配置了「主介质失败自动尝试下一个」，具体看参考手册的 Boot chapter。

结论很简单：拨码优先。所以「我明明烧到 eMMC 了怎么起不来」的第一嫌疑永远是拨码位置，而不是烧录工具。

一个三十秒的自检动作

上电前先拍照记下拨码位置；两种位置各上电一次，把串口第一行抄下来对比。i.MX6ULL 的 SPL 通常会打印 Trying to boot from MMC1/MMC2，这一行直接告诉你它认为自己在读哪——比猜快得多。

1.5.3eMMC 启动：日常那一档

Boot ROM 初始化 SD2 控制器，按 eMMC 协议读第一个扇区（通常是 512B 的 MBR 或直接 IVT），找到 IVT，校验，然后把 SPL 搬进 SRAM 执行。这条链路最短、最快，也是日常使用的默认。

注意两个细节：

  • eMMC 有自己的分区结构（boot 区、user 区），有些板厂把 u-boot 写到 boot 区，有些写到 user 区起始位置。烧录时用板厂给的工具或 dd 的确切偏移，别自己估。
  • eMMC 的 VCCQ（IO 电压）常是 3.3V 或 1.8V，配错会识别不到或读错——这就属于第 2 章的「电源脚」检查。

1.5.4TF 卡启动：最安全的试验场

因为 TF 卡可以整机启动，你可以把新系统写到卡上，完全不动 eMMC 里的正式系统；出问题拔卡就行。这是学习阶段最该用的方式。

要让卡能启动，必须满足：

  1. 卡上写入完整的启动镜像（通常包含 SPL、u-boot、内核、设备树、根文件系统，或至少前两段）。
  2. 分区表与偏移符合板厂约定（很多教程用 dd 把 u-boot 写到卡起始几 MB 的裸区）。
  3. 卡本身是 FAT32 或板厂要求的格式，且容量与卡座兼容（老卡座对大容量卡兼容性差）。

失败时的典型串口：Card did not respond to voltage select! 或 MMC: no card present——前者多半是卡不兼容/供电，后者是没识别到卡（卡座、复用、detect 脚）。

1.5.5USB 下载：救砖的最后一道门

当 eMMC 被写坏、系统完全起不来、卡也不灵时，唯一还能救的就是 USB 下载模式。原理是：Boot ROM 不读存储，直接在 USB OTG 上枚举成一个特殊设备，等主机下发镜像。此时 DDR 都还没初始化，所以下发的是「能初始化 DDR 的最小代码 + 后续镜像」。

操作流程（以 uuu 为例）：

# 1. 板上拨到 USB 下载模式（BOOT_MODE 组合）
# 2. 用「数据」线连接 PC 的 USB 口与板的 USB OTG
# 3. 上电，PC 端应出现 NXP/Freescale 设备（Windows 需装驱动）
uuu flash.uuu          # 或 MFG Tool 图形界面

两个常见失败点：线是充电线（没有数据芯），没进下载模式（拨码不对）。这两个占了失败的绝大多数，别一上来怀疑板子。

切换启动方式选一种，看 Boot ROM 与串口的对应行为

1.5.6一次完整的切换练习

  1. 记下当前拨码位置（拍照），确认当前能正常启动，串口第一行是什么。
  2. 拨到 TF 卡模式，插一张做过启动镜像的卡，上电，抄下第一行。
  3. 把卡拔掉再上电，观察它是否报「no card」——这一步能确认拨码真的生效了。
  4. 拨回原位置，确认恢复。整个过程不要动 eMMC。

做完这一次，你对「启动介质」的理解就从文字变成肌肉记忆了。

三个高频误会

「烧录成功」不等于「能启动」。烧录工具常常只写文件，不保证拨码、不保证偏移对。

「从 TF 卡启动」不等于「卡里只要有内核」。卡上必须有第一段（SPL/u-boot），否则 Boot ROM 找不到可执行的镜像。

「USB 模式」下串口可能一句话都没有。因为那时还轮不到串口初始化，主要看 PC 端是否枚举到设备。

自测

拨码与 eFuse 冲突时听谁的？
拨码（BOOT_MODE 引脚）优先。Boot ROM 上电先采样引脚电平；eFuse 是「引脚未明确指定时」才生效的持久配置，且烧写后不可逆，量产时才用。
为什么 USB 下载能救砖，而 TF 卡启动不一定能？
USB 模式完全不依赖任何板上存储：Boot ROM 直接通过 USB 收镜像，连 DDR 初始化代码都是主机下发的。TF 卡启动仍然要读卡、要卡里的镜像正确，卡或卡座有问题就救不了。
串口打印 Trying to boot from MMC1 说明什么？
说明 SPL 已经在跑（电源、时钟、SRAM 都正常），并且它**选择去读 SD1**（通常是 TF 卡）。如果你的系统在 eMMC 上，这一行就暴露了拨码错了；如果卡里没镜像，接下来会卡住或报错。
