上手清单：六件事

理论读到这里就够了，剩下的是手感。这六件事做完，这块板子对你来说就从「一块绿板子」变成「一台我能操作的机器」——而这个感觉，比再读十篇文章都值。

做完这六件事，你会得到

  1. 一套能复现的上电流程和一次完整的串口对话
  2. 两种启动模式的实测差异（不是听别人说）
  3. 一颗能自己控制的灯，和一次真正跑通的网络
  4. 一张写着自己板子参数的记录表，以后排障直接用

1.8.1准备：四样东西

东西要求常见替代没有会怎样
电源5V/2A 独立电源，接口与板匹配质量好的 USB 适配器 + 短粗线启动瞬间掉压，随机重启
USB-TTLCH340/CP2102 均可，3.3V 电平板载 USB 转串口（很多板自带）没有对话通道，全靠猜
TF 卡8–32GB，FAT32U 盘（若板支持）只能玩 eMMC 里的系统
网线普通网线 + 能上网的路由器USB 网卡（不推荐）联网实验做不了

1.8.2六件事，逐条带验收

①认电源：量三个点

  1. 把万用表调到直流 20V 档，黑笔接板子 GND（螺丝孔或排针 GND）。
  2. 红笔量 5V 输入：应 ≥4.9V。低于 4.8V，换电源或换线。
  3. 量 3.3V 测试点（很多板有标注）：应 3.2–3.4V。
  4. 如果板上有 1.35V 测试点，量它：应 1.30–1.40V。
  5. 记下三个数值，写在纸上。

验收：三个数都在范围内，且上电瞬间 5V 不低于 4.5V。

②接串口：看到第一行字

  1. 接线：USB-TTL 的 GND → 板 GND，TXD → 板 RXD，RXD → 板 TXD（交叉！）。
  2. PC 上装驱动，确认出现 /dev/ttyUSB0（Linux）或 COMx（Windows）。
  3. 打开串口终端：picocom -b 115200 /dev/ttyUSB0（或 minicom、PuTTY）。
  4. 上电，观察输出。正常应看到 U-Boot SPL 或板厂 logo。
# 一次完整的记录（Linux）
sudo picocom -b 115200 /dev/ttyUSB0 | tee boot-$(date +%m%d-%H%M).log
# 退出：Ctrl+A 然后 Ctrl+X

验收：串口里出现可读文字，且日志已存成文件。

③玩拨码：两种模式对比

  1. 拍照记下当前拨码位置，上电，抄下第一行（如 Trying to boot from MMC2）。
  2. 断电，拨到另一档（如 TF 卡模式），插一张做过镜像的卡，上电，再抄第一行。
  3. 拔掉卡，保持这一档再上电，看它报什么错（通常会提示找不到卡）。
  4. 拨回原位置，确认系统恢复。

验收：你能说出「两个档位分别打印了哪行字」，并且知道错误长什么样。

④认存储：容量对得上

# 进系统后
lsblk                              # 看 eMMC / TF 的分区
cat /proc/meminfo | head -3        # MemTotal 应接近 512MB（约 490000 kB）
dmesg | grep -i mmc                # 看识别过程与速度模式
cat /sys/block/mmcblk0/size        # 块数 × 512 = 字节

验收：内存、eMMC 容量与丝印一致；dmesg 里能看到卡/芯片的识别记录。

⑤点一个灯：从用户空间控制 GPIO

用 sysfs 最省事（老内核）或 gpioset（新内核 libgpiod）：

# 方式 A：sysfs（内核 < 4.x 常见）
echo 3 > /sys/class/gpio/export          # 假设用 GPIO1_IO03 → 编号 3
echo out > /sys/class/gpio/gpio3/direction
echo 1 > /sys/class/gpio/gpio3/value     # 亮
echo 0 > /sys/class/gpio/gpio3/value     # 灭

# 方式 B：libgpiod（新内核）
gpioinfo | grep -i led
gpioset gpiochip1 3=1                   # 置高

注意：编号不是随便猜的——GPIO1_IO03 在多数 i.MX 内核里是「组内编号」，而 sysfs 的全局编号 = 组基数 + 组内号，先 gpioinfo 或 cat /sys/kernel/debug/gpio 确认。

验收：灯真的亮了/灭了，且用万用表能在排针上量到电平变化。

⑥插一次网线：从 ping 通到能上网

ip link                              # 看 eth0/eth1 是否存在
ip addr add 192.168.1.50/24 dev eth0 # 静态 IP（按你的网段改）
ip link set eth0 up
ping -c 3 192.168.1.1                # 网关通不通
ip route add default via 192.168.1.1
echo "nameserver 223.5.5.5" > /etc/resolv.conf
ping -c 3 www.baidu.com              # 域名能解析才算真通

验收：网关与域名都能 ping 通；ethtool eth0 显示 link detected: yes。

1.8.3做完之后：把结果变成资产

很多人做完就完了，下一次换板子又从零开始。建议把这次的结果整理成一页纸：

  • 板子参数：型号、SoC 丝印、DDR 容量、eMMC 容量、串口位置、拨码组合。
  • 三条命令输出：lsblk、/proc/meminfo、dmesg | grep -i mmc 的首几行。
  • 遇到的坑：例如「USB 线是充电线」「拨码在 TF 档」，一条一句。

这张纸以后会救你很多次——尤其是换板子、换系统、给别人演示的时候。

下一步读哪儿

硬件这层通了，往三个方向走都行：系统层去 卷 00 · 起步与实验台 搭交叉编译环境；原理层去 参考卷 看 T 系列的 Linux 内核机制；动手层去 手写汇编 从 mov 写到点灯，把「寄存器」这件事彻底搞懂。

自测

为什么串口要 TX 接 RX、RX 接 TX？
串口是「单向发送 + 单向接收」的两根线：A 的发送端只输出，必须接到 B 的接收端才能被读到。接成 TX→TX 两边都在说话、没人听，表现就是「完全没输出」或「只有乱码」。
sysfs 的 GPIO 编号为什么不能直接用 GPIO1_IO03 的 3？
因为 sysfs 用的是全局编号：全局号 = 控制器基号 + 组内偏移。GPIO1_IO03 的组内偏移是 3，但基号由内核分配（可能很远）。所以要先 gpioinfo 或 /sys/kernel/debug/gpio 查到真实编号。
ping 通网关但 ping 不通域名，缺什么？
缺 DNS。IP 层已通（网关可达），是域名解析没配：写 /etc/resolv.conf，或用 nslookup 验证解析器。这也说明「能上网」= 链路 + 路由 + DNS 三件事都成立。
