引脚复用：一个脚八个身份

i.MX6ULL 的物理引脚比内部信号少得多，所以几乎每个脚都是「八选一」。这就是为什么「设备树写了、驱动加载了、就是没反应」——信号还堵在芯片里，没接到你焊的那根线上。这一章把 IOMUXC 拆到底。

读完这一章，你应该能

  1. 说清「物理脚」「信号」「ALT 功能」的关系，并画出八选一的开关模型
  2. 读出设备树里 fsl,pins 那串魔数的含义（哪个寄存器、哪几位）
  3. 知道上拉/下拉、开漏、驱动强度分别解决什么电气问题
  4. 按「查表 → MUX → PAD → 时钟 → 外设」的顺序，自己配通一个新引脚

1.6.1八选一的开关模型

每个 PAD（焊盘/物理脚）内部接一个多路选择器，八个输入端分别接着八种功能信号（ALT0–ALT7），一个输出端连着外面的铜箔。写一个 3 位的 MUX_MODE，就等于告诉选择器「听第几路」。

1.6.2MUX_MODE：三位数字的意义

IOMUXC 为每个 PAD 准备一个 32 位寄存器 IOMUXC_SW_MUX_CTL_PAD_xxx，其中只有低 3–4 位有意义，就是 MUX_MODE。写 5 表示 GPIO，写 0 常表示该脚的「第一功能」（各脚不同，必须查手册的 IOMUXC 表）。

概念含义看哪里
PAD 名芯片引脚的名字，如 UART1_TX_DATA、GPIO1_IO03原理图 + 手册 IOMUXC 章节
ALT / MUX_MODE这个脚此刻的功能编号（0–7）手册里每个 PAD 的「Muxing Options」表
寄存器地址控制这个脚的物理地址，如 0x020E_0000 区间手册 Memory Map + IOMUXC 寄存器表
GPIO 编号同一个脚在 GPIO 控制器里的编号，如 GPIO1_IO03手册 GPIO 章节 + 原理图
一个重要的事实

很多脚有三种可查的名字：芯片内部信号名（UART1_TX_DATA）、PAD 名（UART1_TXD）、GPIO 名（GPIO1_IO03）。写设备树时用的是「PAD 名 + 功能编号 + 电气配置」，查表时一定按 PAD 名查，别按信号名猜。

1.6.3PAD_CTL：同一条信号，两种命运

MUX 选对了，信号也只是「接上了」。能不能可靠地跑，取决于电气属性：

位段（示意）作用什么时候必须配配错的后果
PKE / PUE / PUS是否启用内部上拉/下拉、强度I2C（必须上拉）、按键输入（上拉）、片选（下拉）I2C 一直 NACK；按键读到随机值
ODE开漏输出I2C、共享总线总线拉不低，通信失败
DRIVE驱动强度（mA 档）高速信号、长走线、驱动 LED波形边沿变差、误码、带不动负载
SRE压摆率（上升/下降速度）高速接口（SD、以太网 RMII）EMI 变大或时序余量不足
HYS施密特迟滞慢变输入、按键抖动、误触发

这些位合起来就是设备树里那一串十六进制魔数。以 0x10B0 这类值举例：低位是 MUX 设置，高位是 PAD_CTL 配置——具体每位含义手册里有表，但实践中你几乎不需要手算，因为板厂和内核已经给了常用组合：

  • GPIO 输出：常用 0x10B0（大驱动、开漏关、上拉关）
  • I2C：常用带开漏 + 上拉的组合（如 0x4001B8B1 一类）
  • UART：常用 0x1B0B1（带上拉、适中驱动）

这些数字不是背的，是「抄一次、改一位、看现象」练出来的。

1.6.4设备树里的 fsl,pins：一串数字拆开

    
Linux 里不直接写 IOMUXC 寄存器，而是把配置写在设备树的 pinctrl 节点里。典型写法：


&iomuxc {
    pinctrl_uart1: uart1grp {
        fsl,pins = <
            0x020E_0020  0x10B0  /* UART1_TX_DATA */
            0x020E_0024  0x1B0B1 /* UART1_RX_DATA */
        >;
    };
};

    
每一行两个数：第一个是「MUX 寄存器的物理地址」，第二个是「这个寄存器要写的值」（低位选 ALT，高位是 PAD_CTL）。内核的 pinctrl 驱动会把这两个数按手册规则写进 IOMUXC。

    
所以调试时的排查顺序是：

    
    
      
  1. 确认 fsl,pins 里的地址真的是这个 PAD（查手册 IOMUXC 表，别抄错脚）。
    2. 
      
  2. 确认第二个数低 3 位是你要的 ALT（例如 UART 一般是 ALT0，GPIO 常见 ALT5）。
    3. 
      
  3. 确认 pinctrl 组被外设节点引用（pinctrl-0 = &pinctrl_uart1;）。
    4. 
      
  4. 确认外设时钟已开（CCM 的 CCGR）。
    5. 
      
  5. 最后才怀疑外面的器件。
    6. 
    


    

      
四个「配了没反应」的真凶

      
1. pinctrl 组没被引用。写了组，但外设节点没 pinctrl-0，等于没写。

      
2. ALT 号抄错。同一个脚在不同手册版本里 ALT 可能不同，尤其 GPIO 常是 ALT5 而不是 ALT0。

      
3. 两个外设抢一个脚。设备树里同时给了两个节点，内核按顺序生效，后配的覆盖前面的，表现是「配了 A，A 不工作」。

      
4. I2C 忘了开漏与上拉。波形看着像有信号，其实拉不低，永远 NACK。

自测

    
一个脚配成 UART1_TX 后，还能同时当 GPIO 输出吗？
不能。MUX 是八选一的单刀开关，同一时刻只有一个 ALT 生效。想同时做两件事，只能换一个脚，或者分时切换（运行中改 MUX_MODE，但这会打断串口）。

    
fsl,pins 里两个数字分别是什么？
第一个是 MUX 控制寄存器的物理地址（决定哪个 PAD），第二个是 要写进去的值——低几位选 ALT 功能，高位是 PAD_CTL 电气配置（上拉、开漏、驱动强度等）。内核 pinctrl 驱动把它们转成寄存器写操作。

    
I2C 明明接好了却一直 NACK，最该先查什么？
先查 开漏与上拉：I2C 是开漏总线，必须 ODE = 1 且外部（或内部）有上拉电阻，否则线拉不低也拉不高，主机读不到 ACK。再查 ALT 是否选对、时钟是否打开、从机地址是否写错。
