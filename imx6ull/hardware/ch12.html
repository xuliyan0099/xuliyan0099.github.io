接口电路：一根线的电气真相

接口不是「连上就能通」。每一种接口背后都有一套电气约定：谁驱动、空闲是什么电平、要不要上拉、要不要终端匹配、能跑多快、走多长。懂了这套约定，你既能判断一块板为什么不通，也能设计出不会不通的接口。

读完这一章，你应该能

  1. 说出六种常见接口的电气特征，并各举一个「不加就会坏」的器件
  2. 用公式算 I2C 上拉电阻的上下限，判断总线电容超没超
  3. 区分 TTL 串口、RS-232、RS-485 的电平与拓扑差异
  4. 说出 USB 与以太网为什么必须做阻抗控制与 ESD 防护

2.4.2UART：三兄弟别搞混

TTL 串口就是 SoC 引脚直接出来的 3.3V 方波。它只能连同样 3.3V 的对方，线长了会振铃，所以加 22Ω 串阻。接 5V 设备会打坏 IO。

RS-232 用 ±10V 左右电平表示逻辑，抗干扰强、可走十几米，但必须用电荷泵芯片转换（MAX3232 之类），且是「反逻辑」（负电压表示 1）。

RS-485 用一对差分线，多点总线，靠 120Ω 终端吸收反射，靠偏置电阻保证空闲时有确定状态。半双工需要方向控制（DE/RE）。

最常见的三个串口错误

1. 直连 5V 设备。3.3V IO 一般不耐 5V，长期会衰减或直接击穿。

2. RS-485 忘加终端。短距能用，稍长就开始丢包，且现象随线长变化。

3. TX/RX 没交叉。两边都在说话，谁也没在听，现象是「完全没反应」。

2.4.3I2C：上拉电阻是设计出来的，不是抄来的

I2C 的两根线是开漏：器件只能拉低，不能主动拉高。所以「高电平」完全靠上拉电阻把线拉起来。上拉太大 → 上升沿慢，高速时读错；上拉太小 → 灌电流超规格，还可能烧器件。

两个边界公式（标准里就是这么推的）：

\( R_{p(max)} = \dfrac{t_r}{0.8473 \cdot C_b} \)，　\( R_{p(min)} = \dfrac{V_{DD} - V_{OL(max)}}{I_{OL(max)}} \)

其中 \(t_r\) 是该速率允许的最大上升时间（100kHz 时 1000ns，400kHz 时 300ns），\(C_b\) 是整条总线的总电容（线 + 引脚，标准限定 400pF）。

现场判断 I2C 不通的三步

① 断电量 SCL/SDA 对地电阻：正常是几 kΩ（上拉值），接近 0 说明短路。
② 上电量空闲电平：应接近 VDD。若只有 0.8V，通常是上拉太大或某器件在拉低（时钟拉伸/总线卡死）。
③ 用示波器看上升沿：若明显呈圆弧，就是 Cb 太大或 R 太大，降速或减小上拉。

2.4.4USB 与以太网：差分线的规矩

这两种接口的共性是差分传输 + 阻抗控制 + ESD，因为速率高、又常接外部世界（最容易被打静电）。

为什么以太网一定要变压器：隔离两侧地电位差（可能几十伏）、抑制共模、提供阻抗匹配与直流隔离。省掉它，短距也许能通，但一插到长线或不同电位的设备上就烧 PHY。

2.4.5SD 卡：上拉与卡检测

SD 的 CMD 与 DAT 线在初始化阶段是开漏语义，必须上拉（常见 10k–47k）；CLK 是推挽，不需要上拉但要串阻抑制过冲。卡座还要处理两件事：卡检测（CD）与写保护（WP），前者决定「插卡中断」，后者在老卡上有用。

SD 卡「认不到」的电路原因

r 没有上拉，初始化命令发不出去；r CD 脚没接或极性反，系统认为一直没插卡；r 卡座供电没有独立开关，插拔瞬间浪涌把 3.3V 拉塌；r 走线太长没串阻，50MHz 下波形已经不像方波。

自测

100kHz 模式、Cb = 200pF，上拉最大能取多少？
\(R_{max}=1000\mathrm{ns}/(0.8473\times200\mathrm{pF})\approx5.9\,\mathrm{k}\Omega\)。所以 4.7k 可用，10k 就违反了上升时间要求——低速也许能跑，但边沿变缓会引入时序风险。
为什么 I2C 用开漏而 SPI 用推挽？
因为 I2C 是多器件共享两线，必须允许多个器件同时「拉低」而不会互相冲突（线与）；SPI 是每个从机独立片选、点对点信号，推挽能提供更快边沿与更高速度。
以太网不加变压器，最坏会发生什么？
两侧地电位差直接加在 PHY 的差分脚上，轻则通信异常、重则击穿 PHY；同时共模噪声无处泄放，长线时误码率升高。变压器不是「可选的滤波件」，是隔离与安全件。
