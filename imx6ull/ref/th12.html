理论 T12 · 最小系统的必需外设（上）

「最小系统」不是「能亮个灯」，而是能自己跑起来、能对外说话、能按时间做事、能存住数据的那一小撮硬件。这一章逐个拆开 DDR、中断控制器、定时器、引脚复用与 GPIO、串口，每个都给出寄存器级初始化顺序与算例。

本章要解决的问题

① 一块裸板要跑起来，最少需要哪些外设；② DDR 初始化为什么是整板最难的、难在哪；③ 几十路中断怎么收敛到 CPU 的一个引脚上；④ 操作系统的心跳从哪来；⑤ 为什么「点灯」之前必须先配引脚复用；⑥ 串口为什么会乱码。

读完你应该能回答

  • DDR 配置表里那些 tRFC/tRCD 数字到底在约束什么？
  • GIC 的 SGI、PPI、SPI 分别是什么中断，编号范围怎么划？
  • EPIT 与 GPT 有什么区别，定时中断的频率怎么算？
  • GPIO1_IO03 的引脚编号规则是什么，为什么要先写 IOMUXC？
  • UART 初始化的正确顺序是什么，为什么不能先开再配？

1. 最小系统的外设清单

一块 i.MX6ULL 裸板，从「上电什么都不做」到「Linux 能跑起来」，必须凑齐下面这些。少任何一项，系统就停在某个阶段不动：

外设芯片内模块没有它会怎样最小验证方式
时钟CCM + 外部晶振CPU 不执行任何指令量晶振起振、读时钟寄存器
复位SRC上电状态不确定读复位原因寄存器
启动介质SD/eMMC/NAND + BootROMBootROM 找不到代码，卡在下载模式串口看不到任何输出
DRAMMMDC只能跑在内部 128KB SRAM，Linux 起不来写读测 DDR 首地址
串口UART1没有任何输出，等于瞎调试能打印一个字符
中断控制器GIC-400外设中断全部收不到定时器中断能进
定时器GPT / EPIT没有 tick，调度器不工作周期性中断计数
GPIO + IOMUXCGPIO1–5、IOMUXC引脚停在默认功能，点不亮灯拉高一个 LED 引脚
顺序很重要 正确顺序是：时钟 → DDR → 串口 → 其他。因为 DDR 初始化要靠串口打日志，而串口又要靠正确的时钟。这就是为什么几乎所有 SoC 厂商的 BootROM 日志都从「时钟 OK、DDR OK、串口 OK」这三行开始。

2. DDR 控制器：初始化最难的一块

i.MX6ULL 的 DDR 控制器叫 MMDC，基址 0x021B_0000。它之所以是整板最难的部分，是因为 DDR 是高速同步并行总线，几十根线在同一时刻采数据，时序余量只有皮秒级。参数差一点不会「完全不能用」，而是「偶尔出错」——这类问题最难查。

2.1 初始化到底做了什么

上电→颗粒上电复位→配置时序参数→ZQ 校准→写 Leveling→读 DQS 门控训练→正常读写
  • 颗粒上电复位：DDR3 上电后要等电源与时钟稳定，再发 MRS 命令配置模式寄存器，然后等 tXPR（几百 ns）才能访问。
  • 时序参数：把颗粒手册里的 tRCD、tRP、tRAS、tRFC、tWR、CL 换算成控制器时钟周期数写进寄存器。写错一项，表现就是「读写偶发失败」。
  • ZQ 校准：DDR 用外部精密电阻（通常 240Ω）做阻抗校准，抵消工艺与温度漂移——这是 DDR3 比 DDR2 多出来的一步。
  • 写 Leveling：并行总线里每根数据线物理长度略有差异，到达时间不同。写 Leveling 让控制器逐根测量延迟并补偿，保证数据同时到达。
  • 读 DQS 门控：读方向上，控制器要根据 DQS 选通信号找准采样窗口；训练失败就会读出错数据。

关键寄存器（MMDC0）：

寄存器偏移作用
MDMISC0x018杂项控制（burst 长度、DDR 类型选择等）
MDCFG00x02CtRFC、tRAS、tRP 等主要时序
MDCFG10x030tRCD、CL 等
MDRWD0x094读路径延迟与门控训练
MPRDD0x0A0写 Leveling 相关
MDSCR0x01CDDR 初始化与自刷新控制
算一笔：tRCD 该写多少
DDR3L-800 颗粒手册：tRCD = 13.75ns（DDR 时钟 400MHz，即 800MT/s）
换算成控制器时钟周期：13.75ns × 400MHz = 5.5 → 进一取 6
若 MMDC 工作在 528MHz：13.75ns × 528MHz = 7.26 → 取 8（宁可保守）
原则：时序只能取大不能取小；取小会让数据在未就绪时被采样
不要手写 DDR 参数表 U-Boot 里 board/freescale/mx6ull_xxx/ 下的 ddr_init.c 是一整张几百行的配置数组，由 NXP 的 DDR Stress Test 工具在实际板子上跑到稳定后导出。换板、换颗粒必须重新跑工具生成，手改参数几乎不可能一次成功。

2.2 怎么验证 DDR 真的稳

不要只测「能读写一次」。要测三种模式：

  1. 全 0 / 全 1：检查线路是否短路或断路。
  2. 地址走 1 / 数据走 1：检查地址线、数据线有没有接错或串扰。
  3. 长时间随机读写 + 温升：连续跑几十分钟并加热，暴露「冷机正常、热机出错」的时序余量不足。

Linux 起来后可以用 memtester 32M 5 压测，但注意它会占满内存，测试时不要跑关键服务。

3. 中断控制器：几十路中断怎么收敛

i.MX6ULL 有上百个中断源，而 ARM 核只有一个 IRQ 引脚和一个 FIQ 引脚。GIC（Generic Interrupt Controller，型号 GIC-400）的职责是把这些中断排队、分级、送给某一个核。

  • 分发器（Distributor）：基址 0x00A0_1000，负责全局——哪路中断使能、优先级、路由到哪个 CPU、电平还是边沿触发。
  • CPU 接口（CPU Interface）：基址 0x00A0_0000，负责单个核——屏蔽、应答、结束中断。

中断编号（ID）的划分是最需要记住的：

ID 范围类型来源
0–15SGI 软件中断软件写寄存器触发，常用于多核核间通信
16–31PPI 私有外设中断每核独立的定时器、看门狗等
32–1019SPI 共享外设中断GPIO、UART、I2C、DMA、USB 等所有外设
编号不是随便定的 SGI 与 PPI 的编号在 ARM 架构里写死，SPI 的编号由 SoC 手册的「中断表」定义。写驱动时 IRQ_UART1 这类宏就是查表来的，写错编号会出现「中断进了但处理的是别的设备」。

3.1 使能一路中断的完整顺序

  1. 写 ICDICENABLERn（0x0180 + n×4）置位对应 ID 的使能位。GIC 用的是「写 1 生效、读无意义」的寄存器风格。
  2. 写 ICDIPRIORITYR 设优先级，数值越小优先级越高。
  3. 写 ICDICFR 设触发类型：电平还是边沿触发。这一项配错，中断要么丢失、要么无限重复进。
  4. 写 ICDIPTR 指定目标 CPU。
  5. CPU 接口侧：ICCICR（0x100）使能，ICCPMR（0x104）设优先级门限。
  6. 处理器侧 CPSR 的 I 位清零——这一步最容易漏，硬件中断早到了，但 CPU 一直屏蔽，dmesg 里看着「驱动加载成功」却永不进中断。
读 ICCIAR (0x10C) → 得到要处理的 ID（应答，同时抬高同优先级以下的屏蔽） 处理完 → 写 ICCEOIR (0x110) → 写回同一个 ID（结束中断） 不写 ICCEOIR 的后果：该中断永远处于 active，后续同类中断全部收不到

4. 定时器：操作系统的心跳

i.MX6ULL 有两类通用定时器：EPIT（Enhanced Periodic Interrupt Timer，只有周期性中断，基址 0x020D_0000 与 0x020D_4000）和 GPT（General Purpose Timer，能自由计数、能捕获、能比较，基址 0x0209_8000 与 0x020A_0000）。

模块能力典型用途
EPIT单次/周期中断，结构简单裸机节拍、简单延时中断
GPT自由运行计数、输入捕获、输出比较、可级联测脉宽、PWM 辅助、长时间计时
ARM 通用定时器CPU 内部，每核一个，走 CPU 时钟Linux 的 tick 实际用它（CNTP/CNTV）

EPIT 的关键寄存器：

寄存器偏移作用
EPIT_CR0x000使能、计数模式（单次/周期）、分频、中断使能
EPIT_SR0x004状态，溢出标志；必须写 1 清除
EPIT_LR0x008装载值（重装计数值）
EPIT_CMPR0x00C比较值，计到它就触发中断
EPIT_CNR0x010当前计数值（只读）
算一笔：要 1ms 中断一次
EPIT 时钟取 66MHz（IPG 时钟分频而来），先设分频 PRESCALAR=0（1 分频）
1ms 内计数：66,000,000 × 0.001 = 66,000
装载值写 66,000 − 1 = 65,999（计数从 0 开始，数到装载值共装载值+1 个周期）
若分频设 66：装载值 = 66,000/66 − 1 = 999，同样得 1ms
分频的作用：避免装载值超出 32 位，也方便微调
Linux 里的 tick 不是 EPIT 裸机和 RTOS 常用 EPIT 做节拍；Linux 用 ARM 架构自带的通用定时器（每核一个，频率由 CPU 时钟除以固定系数），因为它离 CPU 最近、延迟最低，而且不占 SoC 外设。EPIT/GPT 在 Linux 下留给驱动做精确定时（比如 PWM、输入捕获）。

5. GPIO 与引脚复用：所有外设的公共前提

一个物理引脚（pad）内部是一个多路选择器：既可以做 GPIO，也可以做 UART_TXD、I2C_SCL、PWM 输出……默认状态往往不是你想要的那个功能。所以任何外设的第一步都是写 IOMUXC。

IOMUXC 基址 0x020E_0000，每个 pad 有两个关键寄存器：

寄存器组作用
SW_MUX_CTL_PAD_xxx选择这个 pad 的功能（ALT0–ALT7），如 ALT5 = GPIO
SW_PAD_CTL_PAD_xxx电气属性：上下拉、驱动强度、转换速率、开漏、迟滞

SW_PAD_CTL 的位段（i.MX6 系列通用）：

位字段含义
16HYS迟滞使能，慢速信号抗噪用
15–14PUS上拉/下拉强度（100k/5k 等）
13PUE是否启用内部上/下拉，1 启用
12PKE上下拉/保持器使能
11ODE开漏输出（I2C 用）
10–8SPEED转换速率等级
5–3DSE驱动强度（mA 档位）

GPIO 控制器本身（GPIO1 基址 0x0209_C000，GPIO2–5 依次偏移 0x4000）：

寄存器偏移作用
DR0x000数据寄存器，输出时写它
GDIR0x004方向，1 = 输出，0 = 输入
PSR0x008引脚状态，输入时读它
ICR1/ICR20x00C/0x010中断触发类型（每引脚 2 位：低电平/高电平/上升沿/下降沿）
IMR0x014中断屏蔽，1 = 允许
ISR0x018中断状态，写 1 清除
EDGE_SEL0x01C双沿触发选择，置 1 后忽略 ICR
算一笔：GPIO1_IO03 是第几个引脚
规则：全局编号 = (端口号 − 1) × 32 + 引脚号
GPIO1_IO03 → (1−1)×32 + 3 = 3，即第 3 位
GPIO4_IO17 → (4−1)×32 + 17 = 96 + 17 = 113
写 DR 时：DR |= (1 << 3)；写 GDIR 时同理按位操作

点一个 LED 的完整顺序（少一步就不亮）：

  1. 在 IOMUXC 里找到该 pad 的 SW_MUX_CTL_PAD_xxx，写 ALT5（0x5）切到 GPIO 功能。
  2. 写 SW_PAD_CTL_PAD_xxx，一般给 0x10B0（上拉、驱动强度中等）；I2C 引脚则必须开开漏。
  3. 写 GPIO 的 GDIR 对应位为 1，设为输出。
  4. 写 DR 对应位为 1，输出高电平。
  5. 若要做输入中断：先写 ICR 定触发类型，再写 ISR 清残留标志，最后 IMR 置 1 允许。
顺序反了就白改 如果先把 GDIR 设成输出再配 MUX，中间那一瞬间引脚可能按默认功能输出一个奇怪电平，外部电路会看到毛刺。正确做法：先复用、再电气属性、最后方向与数据。

6. UART：唯一的「眼睛」

UART1 基址 0x0202_0000（UART2–8 依次 +0x4000）。它是整板第一个必须打通的外设，因为其他一切都要靠它输出日志。

寄存器偏移作用
UCR10x080UART 使能、发送/接收使能、各类中断使能
UCR20x084软复位、8/7 位数据、停止位、校验位
UCR30x088RX 采样、DMA 使能、硬件流控
UCR40x08C唤醒、红外、超时中断
UFCR0x090参考时钟分频（RFDIV）
UBIR0x0A4波特率分子
UBMR0x0A8波特率分母
USR10x094状态：发送空、接收有数据、错误标志
UTS0x0B4发送数据寄存器，写它即开始发送
算一笔：80MHz 出 115200
工程公式：分频值 = 参考时钟 / (16 × 波特率)
80,000,000 / (16 × 115,200) = 43.40
取 43：实际 = 80,000,000 / (16 × 43) = 116,279 → 误差 +0.94%
取 44：实际 = 80,000,000 / (16 × 44) = 113,636 → 误差 −1.36%
串口容忍度约 ±2%~3%，两者都可用；优先取落在这条线上的更接近值
// 正确的初始化顺序 1. UCR1 = 0 先关闭 UART，避免配置中误发数据 2. UCR2 |= 0x1 软复位，等它自动清零 3. UFCR 设分频 先定参考时钟 4. UBIR / UBMR 设分频值 再定波特率 5. UCR2 设 8N1 8 位数据、无校验、1 停止位 6. 清 USR1/USR2 残留错误标志 7. UCR1 |= TXEN|RXEN|UARTEN 最后才使能 8. IOMUXC 复用 + 中断使能

漏掉第 6 步的典型现象：第一帧发出去就报 framing error，看起来像「波特率不对」，其实是复位残留的标志位还没清。

7. 常见误解

误解真相
「DDR 参数照抄开发板就行」换颗粒、换 PCB 走线就不是同一组参数，抄来只能「可能能跑」，长期稳定性没保证。
「DDR 能读写就说明没问题」时序余量不足表现为偶发错误，必须长时间加压 + 温升测试才暴露。
「中断号可以随便试」中断号来自 SoC 中断表，写错会进到别人的处理函数，现象极其诡异。
「GIC 使能了就一定能进中断」CPSR 的 I 位不清零，CPU 永远不响应——最典型的「驱动加载成功但没反应」。
「EPIT 是 Linux 的 tick 源」Linux 用 ARM 通用定时器；EPIT/GPT 留给业务驱动做精确定时与捕获。
「GPIO 只要写 DR 就能拉高」必须先切 MUX 到 GPIO 功能，否则写的是 GPIO 模块内部寄存器，引脚上什么都没发生。
「I2C 引脚不用开开漏」I2C 是开漏总线，不开 ODE 总线拉不低，通信直接失败。
「UART 先使能再配波特率也行」中间的半配置状态会发出乱码字节，对端看到一串垃圾。

8. 自检：能答出来才算懂

1

最小系统清单里，哪一项决定「能跑 Linux」而不只是「能跑裸机」？

看答案

DDR。裸机可以只靠片内 128KB SRAM；Linux 内核加根文件系统必须放进 DDR。

2

ZQ 校准和写 Leveling 分别解决什么问题？

看答案

ZQ 校准抵消驱动器阻抗随工艺/温度的漂移；写 Leveling 补偿各数据线长度差造成的到达时间不一致。

3

tRCD = 13.75ns，控制器 528MHz，寄存器该写几？

看答案

13.75 × 528 = 7.26，取 8。时序只能进一，不能向下取整。

4

SGI、PPI、SPI 的 ID 范围各是多少，分别由谁触发？

看答案

SGI 0–15（软件写寄存器触发）；PPI 16–31（每核私有外设）；SPI 32 起（SoC 外设共享）。

5

中断处理返回前必须做什么？漏了会怎样？

看答案

必须往 ICCEOIR 写回中断 ID。漏了则该中断一直 active，同优先级及以下的后续中断全被屏蔽。

6

EPIT 时钟 66MHz、分频 66、要 1ms 中断，装载值多少？

看答案

66,000,000 × 0.001 / 66 = 1000，装载值 = 1000 − 1 = 999。

7

GPIO4_IO17 的全局编号是多少，操作哪个寄存器的第几位？

看答案

全局编号 (4−1)×32 + 17 = 113；但寄存器操作的是 GPIO4 的 DR 第 17 位，端口内按引脚号算。

8

UART 参考 80MHz、要 115200，分频取 43 与 44 的误差各是多少？

看答案

43 → 116,279（+0.94%）；44 → 113,636（−1.36%）。都在容差内，取更接近的 43。

9. 这一章要动手的命令

  1. cat /proc/iomem | head -30 —— 看内核眼里的物理内存与外设地址区间。
  2. cat /proc/interrupts —— 看每路中断的 ID、触发次数、绑定到哪个核。
  3. cat /sys/kernel/debug/gpio —— 看所有 GPIO 的方向与电平。
  4. echo 3 > /sys/class/gpio/export —— 从用户态操作引脚 3，验证第 5 节编号规则。
  5. stty -F /dev/ttyS0 -a —— 看串口实际波特率、数据位、校验位。
  6. dmesg | grep -i -E "mmdc|ddr|gic|uart" —— 看 DDR、中断控制器、串口的初始化日志。
  7. U-Boot 里 md 0x021B0018 1 —— 读 MMDC 的 MDMISC，确认 DDR 已配置。
