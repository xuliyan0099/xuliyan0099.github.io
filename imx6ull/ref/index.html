一、先说结论：学完你能干什么

市面上 Linux 教程的通病是「命令大全 + 一堆原理」，学完还是不会用。这份手册只围绕一件事：让你能独立维护一台 Linux 机器，并且能在 i.MX6ULL 这类 ARM 板子上把程序、系统、驱动跑起来。

全部走完后，你应该能做到下面 6 件事，这也是本书的最终验收标准：

1. 纯命令行生存

不用鼠标完成文件管理、查找、批量处理、权限调整；看到报错能自己定位，而不是截图问人。

2. 搭环境

从零装一台 Ubuntu，配好国内源、SSH、NFS、TFTP、交叉编译工具链，让别人能远程连上你的机器编译代码。

3. 写工程代码

能写 Shell 脚本做自动化，能写 Makefile / CMake 管理多文件 C 工程，能用 gdb 定位段错误。

4. 读懂启动过程

能讲清楚从通电到出现 shell 提示符之间，BootROM、SPL、U-Boot、内核、设备树、根文件系统各干了什么。

5. 改系统

能裁剪内核、改设备树点亮一个 LED、用 Buildroot 做出自己的根文件系统并烧进板子。

6. 写驱动

能写字符设备驱动 + GPIO 驱动，通过设备树匹配硬件，用 insmod 加载并用应用程序验证。

注意这里没有「精通内核」「看懂调度算法」。那是第 14 章之后的事，先能干活，再谈深挖。新手最大的时间浪费，就是在还没跑通过一次编译链的情况下，去啃《深入理解 Linux 内核》。

三、理论卷：17 章，完全可以脱离开发板

实践卷解决「怎么做」，理论卷解决「为什么是这样」。两者独立成册，互不依赖：没有板子、不想动手，只读理论卷也能从头读到尾；只想快点上板子，可以先跳实践卷，回头再补理论。

理论卷沿一条主线走：CPU 与操作系统原理 → 从上电第一个字节到内核启动 → 总线与时钟 → 最小系统必需外设逐个讲 → 内存管理与内核子系统 → BSP 与设备树 → 工具链。

本版已按「细节级」重写完毕（17 章全部） 初版每章只有概念与结论，零基础读完只知道「大概是什么」。现在每章都拆到寄存器位、算例、完整流程、带答案自检：看完一章你应该能算出具体数值、能指出某一位写错会导致什么现象，而不是背名词。17 章合计约 12 万字。

每一章都固定是这套骨架，所以你可以放心跳着读：

  1. 本章要解决的问题 / 读完你应该能回答 —— 两张卡先告诉你「这一章要拿下什么」，读完再回头自测。

  5. 这一章要动手的命令 —— 7 条左右，全是在真板子或 QEMU 上能直接敲的，用来验证本章结论。

六、每一章怎么学：读 → 敲 → 造

每章固定三步，缺一步这一章就等于没学：

  • 读（30%）：先通读本章，只求看懂「为什么需要这个东西」。看不懂的名词先记在便签上，不要停下来查，读完再回头。
  • 敲（50%）：把本章所有命令、代码手打一遍，不许复制粘贴。打错、报错、修好，这个过程才长肌肉记忆。看到的报错信息记进笔记。
  • 造（20%）：做本章「动手任务」，并且故意改坏一次——改错一个参数、删错一个文件、拔掉网线，看系统怎么反应，再修回来。会修，才算会。
只读不敲 = 白学 Linux 是操作型技能，和游泳一样。看 100 小时教程的旱鸭子，下水还是沉。本手册每章都设了「动手任务」，那是作业，不是选读。

八、四个阶段的验收标准

每到一个阶段结束，拿这张清单自测。有一条做不到，就回头补，别往下走。

7.1第一阶段（第 1–5 章）· 地基

  • 能说出 Linux 内核、发行版、GNU 工具三者关系
  • 不查资料，30 秒内完成：找到 /home 下所有大于 10MB 的文件
  • 能解释 -rw-r--r-- 的含义，并把它改成 755
  • 能说清楚软链接和硬链接的区别，并各建一个
  • 能用 ps aux | grep xxx 找到进程并杀掉
  • 能写一个 for 循环脚本批量改文件名
  • 全程 Vim 编辑，不碰鼠标、不碰记事本

7.2第二阶段（第 6–7 章）· 开发

  • 两台机器 ping 通、ssh 免密登录成功
  • 板子（或第二台 VM）能通过 NFS 挂载 PC 目录，并直接运行里面的程序
  • 能写出一个三文件 C 工程的 Makefile，含 clean 目标
  • 能用 arm-linux-gnueabihf-gcc -v 确认工具链正常，并编出一个 ARM 可执行文件
  • 能用一个 gdb 会话定位一次数组越界导致的段错误

7.3第三阶段（第 8–11 章）· 系统

  • 能画出 BootROM → SPL → U-Boot → 内核 → 根文件系统 的完整链路，并标出各阶段加载地址
  • 会改 bootargs 让内核从 NFS 启动，从 eMMC 启动
  • 能独立完成一次系统烧写，并在串口看到完整启动日志
  • 能改设备树，让板子上的 LED 在系统启动后处于你想要的状态
  • 能用 Buildroot 生成自己的根文件系统并启动成功

7.4第四阶段（第 12–14 章）· 驱动与实战

  • 能写一个字符设备驱动，insmod 后 /dev 下出现对应节点

  • 能说出 register_chrdev 老接口和 cdev/misc 新接口的差别
  • 驱动出错时，能靠 dmesg + 串口日志定位到具体文件行
  • 脱离教程，从零做出「内核 + 设备树 + 根文件系统 + 一个驱动」四件套

九、小白最容易踩的 8 个坑

坑 1：版本不对

教程用的是 4.1.15 内核 + 2016.03 U-Boot，你装了 5.15。命令、目录、配置项全不一样。跟板卡厂商的版本来，别自己升级。

坑 2：地址乱抄

0x87800000、0x80800000 这些是特定板卡特定配置下的加载地址。DDR 大小变了、U-Boot 配置变了，地址就可能变。

坑 3：忽视串口

板子起不来时，SSH 是连不上的，唯一的信息源就是串口。先把串口调通，再谈其他。

坑 4：中文路径 / 空格路径

编译工具链、内核源码放在含中文或空格的路径上，make 会报各种莫名其妙找不到文件的错误。

坑 5：直接 root 干活

sudo rm -rf 一次失误就重装系统。日常用普通用户 + sudo，权限问题才用 root。

坑 6：网线没通就烧写

NFS 挂载失败、TFTP 超时，先 ping、再看防火墙、最后看服务是否真的起来了。

坑 7：只看不动手

把教程当小说看，看到第 12 章发现自己连 chmod 都敲不利索。这行没有「看会」这回事。

坑 8：报错就换方案

一个报错卡三天很正常。先把报错的第一个错误（不是最后一个）读完，再搜索。90% 的答案就在第一行错误里。

十、全书书写约定

约定含义
$ 命令普通用户在 PC / 板子终端执行
# 命令root 身份执行（提示符为 #）
[pc] / [board]标明命令在哪台机器上跑，这是新手最常混的地方
地址、引脚、分区名除特别说明外，均以正点原子 i.MX6ULL 阿尔法/迷你板为准，你的板子不同就必须对照原理图和厂商文档
灰色段落补充说明，可跳过
关于硬件差异 本手册里出现的 GPIO 编号、I2C 地址、分区名、DDR 容量都是示例。i.MX6ULL 有几十种封装与板型，唯一权威是你的原理图和厂商提供的 DTS 文件。看书时养成「先核对原理图」的习惯，比背任何代码都有用。

十一、开始吧

读完这一页就可以开始了。只想懂原理：从 T01 一路读到 T17，不碰板子也能读通；想快点上板子：从实践卷 01 开始，遇到「为什么」再回理论卷查。两条路都不需要等「准备好」。
