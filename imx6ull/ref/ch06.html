06 · 网络与远程开发

嵌入式开发的黄金组合是：内核和根文件系统放在 PC 上，板子通过网络去取。改一行代码不用重新烧写整块板子——这就是 NFS 存在的意义。

本章目标

① 理解 IP、掩码、网关、端口；② 给 Ubuntu 配静态 IP；③ 配通 SSH / NFS / TFTP 三个服务；④ 板子能挂载 PC 目录直接跑程序；⑤ 网络不通时有一套排查顺序。

6.1 四个概念，一张表

概念是什么举例
IP 地址机器在网络里的门牌号192.168.1.100
子网掩码说明哪几位是网络号，同网络号才算同网段255.255.255.0 = /24
网关出本网段时找谁转发192.168.1.1
端口一台机器上不同服务的编号SSH 22、TFTP 69、NFS 2049、HTTP 80

怎么判断两台机器同网段？ 看掩码为 1 的那些位是否相同。192.168.1.100 和 192.168.1.101 前 24 位都是 192.168.1，同网段，网线直连就能通；192.168.2.5 不同网段，必须过网关，网关没配对，ping 一定不通——这和「网线通不通」是两回事。

嵌入式最常用的拓扑 PC 或虚拟机 192.168.1.100 ←→ 板子 192.168.1.101，同网段、网线直连。不需要路由器，两边都配静态 IP 即可。速度最快，也最少受公司网络策略干扰。

6.2 必备网络命令

# 看 IP、网卡状态、路由表
$ ip addr
$ ip link
$ ip route

# 临时改 IP（重启失效，正式配置见 6.3）
$ sudo ip addr add 192.168.1.100/24 dev ens33
$ sudo ip link set ens33 up

# 测连通性
$ ping -c 4 192.168.1.101

# 看端口是否在监听、被谁监听
$ ss -lntp
$ ss -lntp | grep 2049

# 测端口通不通（比 ping 更准，能测到服务层）
$ nc -zv 192.168.1.100 2049
ping 通不等于服务能用 ping 走 ICMP，服务走 TCP/UDP 端口。ping 通但 SSH 连不上，问题一定在端口、防火墙或服务本身，不在网线。

6.3 配静态 IP（Ubuntu 22.04 的 netplan）

Ubuntu 17 以后网络配置统一交给 netplan，配置文件在 /etc/netplan/ 下，YAML 格式，缩进必须用空格，不能用 Tab。

$ sudo vim /etc/netplan/01-network-manager-all.yaml
network:
  version: 2
  ethernets:
    ens33:
      dhcp4: no
      addresses: [192.168.1.100/24]
      routes:
        - to: default
          via: 192.168.1.1
      nameservers:
        addresses: [8.8.8.8, 114.114.114.114]
$ sudo netplan try      # 试应用，120 秒内不确认会自动回滚（推荐）
$ sudo netplan apply
$ ip addr show ens33
网卡名不是 ens33？ 用 ip link 看真实名字（可能是 ens160、eth0、enp3s0）。写错名字，netplan 会直接报错或配置无效。另外 22.04 已弃用 gateway4 写法，用上面的 routes。

6.4 SSH：远程操作的基础

$ sudo apt install -y openssh-server
$ sudo systemctl enable --now ssh
$ sudo systemctl status ssh

# 从另一台机器登录
$ ssh ubuntu@192.168.1.100
# 传文件
$ scp app ubuntu@192.168.1.101:/home/ubuntu/
$ scp ubuntu@192.168.1.101:/home/ubuntu/app ./
# 传整个目录
$ scp -r work/ ubuntu@192.168.1.101:/home/ubuntu/

免密登录（省事，也让脚本能自动跑）

$ ssh-keygen -t rsa -b 4096       # 一路回车
$ ssh-copy-id ubuntu@192.168.1.101
$ ssh ubuntu@192.168.1.101        # 不再问密码

常用服务端配置（可选）

$ sudo vim /etc/ssh/sshd_config
# 改端口（降低扫描风险）
Port 2222
# 允许密码登录（调试期建议开着，免密配好后再关）
PasswordAuthentication yes
$ sudo systemctl restart ssh
改完必须 restart 且改端口后旧连接不会自动断开，新连接要用 ssh -p 2222。关掉密码登录前，先确认密钥登录真的能进，否则会把自己锁在外面。

6.5 NFS：板子直接跑 PC 上的程序

NFS 让板子把 PC 的一个目录「挂」成自己的目录。好处是：你在 PC 上用交叉编译器编出新程序，板子上立刻就能跑，不用 scp、不用重烧。这是嵌入式开发效率的关键。

PC 端（服务端）

$ sudo apt install -y nfs-kernel-server
$ sudo mkdir -p /home/ubuntu/nfsroot
$ sudo chmod 777 /home/ubuntu/nfsroot

$ sudo vim /etc/exports
# 追加一行：允许 192.168.1.0/24 网段读写
/home/ubuntu/nfsroot 192.168.1.0/24(rw,sync,no_subtree_check,no_root_squash)

$ sudo exportfs -ra                  # 重新加载导出表
$ sudo systemctl restart nfs-kernel-server
$ showmount -e localhost             # 确认导出生效
参数含义
rw读写（只读用 ro）
sync写入即同步落盘，更安全
no_subtree_check不检查子目录，性能更好
no_root_squash板子上的 root 保留 root 权限（调试期需要）

客户端（板子或另一台虚拟机）

# 手动挂载测试
$ mkdir -p /mnt/nfs
$ mount -t nfs -o nfsvers=3 192.168.1.100:/home/ubuntu/nfsroot /mnt/nfs
$ ls /mnt/nfs
$ df -h | grep nfs

# 卸载
$ umount /mnt/nfs
用 NFS 当根文件系统（第 8 章会用到） U-Boot 的 bootargs 里这样写，板子就直接从 PC 启动，根目录全是 PC 上的文件： 
root=/dev/nfs rw nfsroot=192.168.1.100:/home/ubuntu/nfsroot,nfsvers=3 \
ip=192.168.1.101:192.168.1.100:192.168.1.1:255.255.255.0::eth0:off
含义依次是：板子 IP : 服务器 IP : 网关 : 掩码 : 主机名 : 网卡 : 关闭自动配置。
NFS 挂载失败的排查顺序 ① ping 192.168.1.100 通不通 ② showmount -e 192.168.1.100 能不能列出来 ③ /etc/exports 里的网段写对没 ④ 防火墙 111/2049 端口放行了没 ⑤ sudo systemctl status nfs-kernel-server 是否真在跑。顺序别乱，从下往上查会浪费很久。

6.6 TFTP：给 U-Boot 下载文件

U-Boot 阶段网络协议栈很简单，只支持 TFTP。所以「用 U-Boot 从 PC 下载内核或设备树」这条调试路径，必须配 TFTP。

$ sudo apt install -y tftpd-hpa
$ sudo mkdir -p /home/ubuntu/tftpboot
$ sudo chmod 777 /home/ubuntu/tftpboot

$ sudo vim /etc/default/tftpd-hpa
TFTP_USERNAME="tftp"
TFTP_DIRECTORY="/home/ubuntu/tftpboot"
TFTP_ADDRESS=":69"
TFTP_OPTIONS="--secure --create"

$ sudo systemctl restart tftpd-hpa
$ echo test > /home/ubuntu/tftpboot/t.txt
$ tftp 192.168.1.100 -c get t.txt     # 本机自测

板子 U-Boot 里这样下载（第 9 章细讲）：

=> setenv serverip 192.168.1.100
=> setenv ipaddr 192.168.1.101
=> ping 192.168.1.100
=> tftp 80800000 zImage
=> tftp 83000000 imx6ull-14x14-evk.dtb
为什么是 TFTP 不是 FTP/HTTP U-Boot 的 NET 栈体积受限，只实现了最精简的 UDP + TFTP。用对协议，别硬上。

6.7 防火墙：先把门打开再谈连通

$ sudo ufw status                 # 看状态
$ sudo ufw allow 22/tcp
$ sudo ufw allow 2049
$ sudo ufw allow 69/udp
$ sudo ufw allow from 192.168.1.0/24
$ sudo ufw enable
远程操作时开防火墙要小心 先 allow 22 再 enable，顺序反了会把自己 SSH 踢下线。云主机上尤其注意。

6.8 不通？按这个顺序查

  1. 物理层：网线插好没、网口灯亮不亮、交换机通电没。
  2. IP 层：ip addr 两边是否同网段、有没有 IP 冲突。
  3. 路由：ip route 有没有本网段的路由。
  4. 连通：ping 对方 IP。不通就是上面三步的问题。
  5. 端口：nc -zv IP 端口。ping 通但端口不通 → 防火墙或服务没起。
  6. 服务：systemctl status 服务名 + journalctl -u 服务名。
  7. 配置：服务端配置文件的网段、路径、权限是否有误。

6.9 动手任务

  • 给虚拟机配静态 IP，重启后用 ip addr 确认仍然是那个地址。
  • 复制一份虚拟机（或开第二台），两台互相 ping 通、ssh 免密登录成功。
  • 在 PC 上导出 /home/ubuntu/nfsroot，在第二台机器上挂载，新建一个文件，回到服务端确认能看到。
  • 配好 TFTP，用 tftp 客户端从本机取一个文件；如果板子在手，进 U-Boot 用 tftp 下载一次 zImage。
  • 故意把 /etc/exports 的网段写错，体验一次 mount 失败，再用 exportfs -ra 修好。
  • 用 ss -lntp 找出本机所有监听端口，说出 22、2049、69 分别是哪个服务。

6.10 验收标准

  • 能解释 IP、掩码、网关三者的作用，并判断两个地址是否同网段
  • 会 netplan 配静态 IP，且配置能持久生效
  • 能配好 SSH 免密，并用 scp 双向传文件
  • 能配 NFS 并在客户端挂载成功，能写对 /etc/exports 的权限参数
  • 能说出 bootargs 里 nfsroot 那串参数每一段的含义
  • 网络问题能按「物理 → IP → 路由 → ping → 端口 → 服务 → 配置」顺序排查
