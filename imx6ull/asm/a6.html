位操作：配置一个寄存器的标准三行

第 06 章约 26 分钟★ 必读

七条指令覆盖外设配置的 90%

指令语义配置寄存器时对应什么
and按位与取出某几位、判断某位
orr按位或置位（其他位不动）
eor按位异或翻转某位、交换两个寄存器
bic位清零（and 的补码形式）清位，比「先 mvn 再 and」少一条
mvn取反搬移造 ~mask、得到 -1
lsl/lsr/asr/ror移位造掩码、取位域、对齐
bfi/bfc/ubfx/sbfx位域插入/清除/取出一条指令改一段位（ARMv7 新增）

bic 是这套里最容易被忽略、又最该用的：bic r1, r1, r2 等价于 r1 = r1 & ~r2，专为「清位」而生。内核里 regmap_update_bits 的掩码取反就靠它。

移位量的两种形态

    lsl  r0, r1, #3        @ 立即数移位：0–31
    lsl  r0, r1, r2        @ 寄存器移位：用 r2 的低 8 位（0–255）

立即数移位只能 0–31，这是硬限制。需要移 32 位以上时，要么用寄存器形式的移位量，要么拆两次。

另一个细节：ror（循环右移）在普通数据处理里用得少，但配合 and 取位域时很有用——ror r0, r0, #8 可以把某个字节转到最低位再 and #0xFF。

位域三件套

    bfi  r0, r1, #3, #3    @ 把 r1 的低 3 位 → 放进 r0 的 bit[5:3]，其他位不动
    bfc  r0, #3, #3        @ 把 r0 的 bit[5:3] 清 0
    ubfx r2, r0, #3, #3    @ 从 r0 的 bit[5:3] 取出，零扩展到 32 位
    sbfx r2, r0, #3, #3    @ 同上，但符号扩展

bfi 的参数顺序容易记错：bfi 目标, 源, lsb, 宽度——lsb 在前、宽度在后，不是「起始位，结束位」。

还有一条坑：bfi 取源的低 n 位，超出宽度的高位被忽略（不是截断报错）。如果源值本身超范围，结果不会错，但可能不是你想要的。

标准三行：配置一个寄存器的正确姿势

真实场景：把 IOMUXC_SW_MUX_CTL_PAD_GPIO1_IO03 的 MUX_MODE（bit[2:0]）改成 5（ALT5 = GPIO），其余位原样保留。

    ldr  r0, =0x020E0068       @ 寄存器地址
    ldr  r1, [r0]              @ ① 读：拿到当前值
    bic  r1, r1, #0x7          @ ② 清：低 3 位归零，其他位一个不动
    orr  r1, r1, #0x5          @ ③ 置：写入 5
    str  r1, [r0]              @ ④ 写回

四步里最容易被省掉的是①②，直接 str #5 一次覆盖。后果：SION（bit4）、保留位、以及同一寄存器里别人的位全部归零。在 i.MX6 的 IOMUXC 上，写错 SION 会让输入回读失效；在 CCM 上误写别人那两位，会关掉别的外设时钟。

掩码编不进怎么办：造出来

掩码 0x38（bit[5:3]）能编，但 0x1C0（bit[8:6]）、0x7<<26（时钟门控位）编不进。标准造法：

    mov  r2, #0x7
    lsl  r2, r2, #6            @ r2 = 0x1C0
    bic  r1, r1, r2            @ 清 bit[8:6]
    orr  r1, r1, #0x80         @ 置 bit7（0x80 能编）

这就是内核里满地 #define MASK(x) + 运行时移位的由来：编译期常量在 C 里能算，写进指令时却编不过。

真实寄存器实战四例

① 时钟门控（CCM_CCGRx）——每 2 位管一个模块：

    ldr  r0, =0x020C406C       @ CCM_CCGR1
    ldr  r1, [r0]
    mov  r2, #3
    lsl  r2, r2, #26           @ 3 << 26 → bit[27:26]
    bic  r1, r1, r2            @ 先清
    orr  r1, r1, r2            @ 再置（00 关 / 11 开）
    str  r1, [r0]

注意这里 bic 和 orr 用的是同一个 r2：先清再置，写法最省。顺序反了（先 orr 后 bic）就等于全清 0，模块时钟永远开不起来。

② 引脚电气属性（SW_PAD_CTL）——驱动强度、上下拉、速率，多位域：

    ldr  r0, =0x020E02F4
    ldr  r1, [r0]
    mov  r2, #0x3F
    lsl  r2, r2, #3            @ 清 bit[8:3] 这几位域
    bic  r1, r1, r2
    orr  r1, r1, #0x30         @ 置需要的组合
    str  r1, [r0]

③ GPIO 方向（GDIR）——一位一个脚：

    ldr  r0, =0x0209C004
    ldr  r1, [r0]
    orr  r1, r1, #0x8          @ bit3 = 1 → 输出
    str  r1, [r0]

④ 状态判断（PSR）——只读位、W1C 位：

    ldr  r0, =0x0209C008
    ldr  r1, [r0]              @ 读 PSR（只读）
    tst  r1, #0x8              @ 测 bit3
    beq  is_low                @ 为 0 就跳

两个必须知道的边界

  • bfi/ubfx 不是所有核都有。它们是 ARMv6T2/ARMv7 引入的，Cortex-A7 有；老的 ARMv5（比如某些 ARM9）没有，写进去直接非法指令。跨核移植代码时要小心。
  • 位带（bit-band）在 Cortex-A 上不存在。那是 Cortex-M3/M4 的特性（把某段别名区的一个字映射到一位）。你在 A7 上找不到 0x22000000 那块别名区，别照着 M 系列的资料配。

本篇验收

  • 能默写「读—清—置—写回」四步，并解释为什么不能直接赋值。
  • 给定掩码 0x1C0 与 0x7<<26，能写出「先 mov 再 lsl」的造法。
  • 能说出 bic 与 and + mvn 的关系，并说明为什么 bic 更好。
  • 能写出 bfi 的参数顺序（目标、源、lsb、宽度）。
  • 能解释「先 orr 后 bic」为什么会把时钟门控写成 0。
