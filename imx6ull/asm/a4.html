函数调用与 AAPCS：lr 为什么必须保

第 04 章约 28 分钟★ 必读含互动工具

一条 bl 只够一层

bl label 做两件事：把「下一条指令的地址」写进 lr，然后跳到 label。函数末尾 bx lr 跳回来。

问题在「只有一个 lr」。你在函数 A 里 bl B，lr = A 的返回点；B 里又 bl C，lr 被覆盖成 B 的返回点——A 的返回点永久丢了。这就是「跑飞」：bx lr 跳到某个随机地址，取到随机指令，然后 HardFault 或者死循环。

解决办法只有一条：进函数时把 lr 存到栈上。

@ 叶子函数：自己不再调别人，lr 没人踩 —— 不存也行
add3:
    add  r0, r0, r1
    add  r0, r0, r2
    bx   lr

@ 非叶子函数：内部还有 bl —— 必须存
blink:
    push {r4, lr}        @ ← 这一条是命
    mov  r4, r0
    bl   delay
    mov  r0, r4
    pop  {r4, lr}
    bx   lr

判断标准很简单：这个函数体里有没有第二条 bl？有就必须 push。 更稳妥的做法是「只要不是明显的叶子就一律 push {lr}」，多两条指令换成不会跑飞，划算。

AAPCS：ARM 的函数调用约定

AAPCS（ARM Architecture Procedure Call Standard）就六条，背下来就能读所有反汇编：

规矩内容
传参第 1–4 个参数放 r0–r3；第 5 个起放栈上（调用者准备）
返回返回值在 r0；64 位返回值用 r0:r1
调用者保存r0–r3、r12：被调函数可以随便毁，调用者自己负责
被调用者保存r4–r11、sp：被调函数要用就先 push，退出前恢复
栈对齐公开接口处 sp 必须 8 字节对齐
结构体返回调用者传一块内存指针在 r0（隐藏参数），函数把结果写进去

「调用者保存」这四个字最容易误读：它说的是责任在被调函数那边——r4–r11 被调函数不许乱改；r0–r3 被调函数不用负责，返回时里面是什么垃圾都行。所以你在调用前放在 r0–r3 里的值，调用后不要指望还在。

为什么 push {r4, lr} 常常写成 push {r4-r6, lr}

因为这涉及 8 字节对齐。算一下：

  • push {lr} = 4 字节 → sp 变 4 mod 8，破了对齐。
  • push {r4, lr} = 8 字节 → 保持对齐 ✓
  • push {r4-r6, lr} = 16 字节 → 保持对齐 ✓
  • push {r4-r5, lr} = 12 字节 → 破了 ✗

所以编译器会凑成偶数个寄存器（必要时塞一个没用的 r7 进来当填充）。你在反汇编里看到「为什么莫名其妙 push 了 r7」——那就是对齐填充。

超过 4 个参数怎么取

@ void f(int a, int b, int c, int d, int e)
@ 调用者：a→r0, b→r1, c→r2, d→r3, e→[sp]
caller:
    push {r4, lr}        @ 16 字节对齐
    mov  r0, #1
    mov  r1, #2
    mov  r2, #3
    mov  r3, #4
    mov  r4, #5
    push {r4}            @ e 放栈上（注意：这里会破坏对齐，实际编译器会凑两次 push）
    bl   f

被调函数里怎么取 e？关键在「我自己 push 了多少」：

f:
    push {r4, lr}        @ sp -= 8
    ldr  r0, [sp, #8]    @ 第 5 个参数：8（我 push 的）+ 0（调用者放的位置）

如果函数体里又 push 了 3 个寄存器（12 字节），偏移就变成 12 + 0。每次改 push 的数量，所有 [sp, #N] 都要重算——这是手写汇编里最容易出错的一处，编译器则完全不会错。

返回值：不只是 r0

  • 32 位：r0
  • 64 位（long long）：r0 低、r1 高
  • 小结构体（≤ 4 字节）：r0
  • 大结构体：隐藏参数——调用者在 r0 里传目标地址，函数把结果写到那块内存，返回时 r0 再带回这个地址（方便链式）

反汇编里看到「函数一进来就 str r1, [r0]，然后各种往 [r0+4] 写」，那基本就是在构造一个返回值结构体。

可变参数：va_list 就是「栈上指针 + 偏移」

int printf(const char *fmt, ...);

实现细节：r0 是 fmt，r1–r3 是前三个可变参数，第 4 个起在栈上。va_start 大概做两件事：把 r1–r3 先「倒」进一块连续内存（因为它们在寄存器里，不连续），再记下栈上参数的起始地址。之后 va_arg 就是「按类型宽度往后挪指针」。

所以 printf 用错格式符（%d 却传了 long long）会读到错位的数据——不是玄学，而是指针挪错了宽度。

工具：把调用过程一步步走完

单步台 · 选 C「函数调用与栈」，专门盯 lr 和 sp

选 C 段程序，点单步：注意 bl 把 lr 写成 0x0000000C，push 把 lr 存到栈上（sp 变 0x1FFC），pop 恢复，bx lr 跳回去。

看三件事：

  1. bl add3 执行后，lr 变成 0x0000000C（第 4 条指令的地址）——这就是返回点。
  2. push {lr} 执行后，sp 从 0x2000 变 0x1FFC，mem[0x1FFC] 出现 0x0000000C。
  3. 走完全程，sp 回到 0x2000（栈必须平衡），r0 = 7。

如果这个函数里没有 push {lr}，那么第二次 bl 会把 lr 覆盖，最后 bx lr 跳到别处——模拟器里你能直接看到 pc 跑到一个没有指令的位置。

本篇验收

  • 能判断任意一段汇编「这个函数必须 push lr 吗」，并说明理由。
  • 能解释 push {r4, lr} 为什么常被写成 8 或 16 字节（对齐）。
  • 能算出「函数 push 了 3 个寄存器时，第 5 个参数在 [sp, #12]」。
  • 能说出结构体返回值走隐藏指针，r0 一进来里装的是什么。
  • 单步台里 C 程序跑完，sp 必须回到起始值、r0 必须是 7。
