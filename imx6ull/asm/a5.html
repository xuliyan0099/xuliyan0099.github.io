条件码与分支：两套门，别走错

第 05 章约 28 分钟★ 必读含互动工具

cmp 不是「比较」，是「减法丢掉结果」

    cmp  r0, r1        @ 等价于 subs r2, r0, r1（但结果不写回，只更新标志）

它从不产生寄存器结果，只更新 N/Z/C/V 四位。所以后面跟什么条件码，取决于这四位怎么组合。

同理还有三个只看标志的指令：

指令做的事常用条件
cmp r0, r1r0 - r1，丢结果eq/ne/lt/gt/hi/ls
cmn r0, r1r0 + r1，丢结果判断「负数加正数」、cmn r0,#1 实现「r0 == -1」
tst r0, r1r0 & r1，丢结果测某位是否为 0（tst r0,#0x8; beq）
teq r0, r1r0 ^ r1，丢结果测「是否相同」（异或为 0）

14 个条件码，两张表就够

第一张：纯标志位

后缀成立条件用途
eqZ=1相等
neZ=0不等
cs / hsC=1无符号「有进位/无借位」，即 ≥
cc / loC=0无符号 <
miN=1结果为负
plN=0结果非负
vsV=1有符号溢出
vcV=0无溢出

第二张：比较结论（最常用）

后缀成立条件语义
hiC=1 且 Z=0无符号大于
lsC=0 或 Z=1无符号小于等于
geN=V有符号大于等于
ltN≠V有符号小于
gtZ=0 且 N=V有符号大于
leZ=1 或 N≠V有符号小于等于

最大的坑：有符号与无符号是两套门

看这个例子：r0 = 0xFFFFFFFF（有符号是 -1），r1 = 1。

    mvn  r0, #0        @ r0 = 0xFFFFFFFF = -1
    mov  r1, #1
    cmp  r0, r1
    blt  signed_less   @ ✓ 成立：有符号 -1 < 1
    blo  unsigned_less @ ✗ 不成立：无符号 0xFFFFFFFF > 1

同一对操作数、同一条 cmp，blt 跳、blo 不跳。这就是为什么「数组下标用 blt 判越界」是漏洞：

/* 危险写法 */
if (i < len) buf[i] = 0;      /* i 是 int，len 是 unsigned → 混合比较 */

编译器会怎么编？如果 len 是 unsigned，i 被提升成 unsigned，i = -1 变成 0xFFFFFFFF，比较变成 bhi 形式——结果「超大下标」通过了检查。

判断口诀：变量是无符号的（size_t、uint32_t、指针长度、数组下标）→ 用 hi/ls；变量是有符号的（int、int32_t、差值）→ 用 gt/lt/ge/le。混用时以「提升后的类型」为准，int 与 unsigned 混比会被提升成无符号，这是 C 语言埋的坑，汇编层面才看得见。

工具：14 个条件一次算给你看

条件码判断器 · 给两个数，逐个标成立/落空

试三组，把结论记住：

  • -1 与 1：lt 成立、lo 不成立 —— 有符号与无符号分道扬镳。
  • 1 与 -1：gt 成立、hi 不成立 —— 反过来也一样。
  • 5 与 5：eq/ge/le/hs/ls 全成立，ne/lt/gt/hi/lo 全不成立 —— 相等时「大于」「小于」都不成立，但「大于等于」「小于等于」成立。

条件执行：不跳也能选

ARM 态几乎每条指令都能带条件后缀，省掉跳转和流水线冲刷：

    cmp  r0, #5
    movgt r1, #1        @ r0>5 才执行，否则这条相当于 nop
    movle r1, #0

Thumb 态没这么自由：只有 b 系列能带条件，其余条件指令必须包在 IT 块里：

    cmp  r0, #5
    ite  gt             @ t: 紧跟 1 条(then)；e: 再跟 1 条(else)
    movgt r1, #1
    movle r1, #0

IT 的字母含义：IT 后面最多 4 个字母，T 表示该位指令按条件执行，E 表示按「条件取反」执行。IT = 1 条 then；ITT = 2 条 then；ITE = then + else；ITTEE = 2 then + 2 else。

写错 IT 块的表现是汇编器报 Thumb IT block error，或者更糟：编过了但行为不对（比如把 E 写成 T，条件反了）。

循环的三种标准形态

计数循环（最常用）：

    mov  r0, #0            @ sum
    mov  r1, #1            @ i
loop:
    add  r0, r0, r1
    add  r1, r1, #1
    cmp  r1, #6
    blt  loop              @ 有符号小于则回跳（i 是 1..5）

指针遍历（找字符串结尾）：

strlen:
    mov  r1, r0            @ 保存起点
1:  ldrb r2, [r0], #1      @ 取一个字节并后索引 +1
    cmp  r2, #0
    bne  1b                @ 非 0 继续（1b 是「向后找最近的局部标号 1」）
    sub  r0, r0, r1
    sub  r0, r0, #1        @ 减掉多走的那一步
    bx   lr

局部标号 1: / 1b（backward）/ 1f（forward）是 GNU as 的写法，适合短距离跳转，不会污染符号表。

先减后判（do-while，省一条指令）：

    mov  r1, #10
1:  subs r1, r1, #1
    bne  1b                @ 减到 0 之前一直回跳，天然执行 10 次

注意 subs 带 s 才会更新标志——sub 不带 s 不改标志，bne 就会用到上一次的旧标志。这是新手最常见的「循环次数不对」原因：忘了 s。

跳转表：adr + ldr pc

多分支（switch）不该写成 cmp 链：

    cmp  r0, #3
    bhi  default
    adr  r1, table          @ r1 = table 的地址（位置无关）
    ldr  pc, [r1, r0, lsl #2]   @ pc = *(table + r0*4)，直接跳
table:
    .word case0
    .word case1
    .word case2
    .word case3

adr 是伪指令：汇编器算成 add/sub pc, #偏移，所以拿到的是「运行地址」而不是「链接地址」，位置无关代码也能用。enable_mmu 前后跳转表必须用 adr，用绝对地址就会崩——这是开启 MMU 阶段最典型的坑之一。

本篇验收

  • 能解释 cmp 为什么没有结果寄存器，以及 N/Z/C/V 各自怎么来。
  • 能给一个具体数值对，说出 hi 与 gt 哪个成立、为什么。
  • 能指出「数组越界漏洞」在汇编层面长什么样（blt 换成 bhi 就修了）。
  • 能写出 Thumb 态下的 IT 块，并说清 IT 后面字母的含义。
  • 能解释 subs 与 sub 的差别，以及它为什么会让循环多跑或少跑一次。
  • 能写出跳转表，并说清 adr 与绝对地址的差别。
