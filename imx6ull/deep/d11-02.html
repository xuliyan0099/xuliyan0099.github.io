JTAG 与 Ozone：停核、看页表、单步走启动链

串口只能告诉你「到哪了」，JTAG 能让你在任意一条指令上把 CPU 按停，然后翻它的寄存器、页表和内存。

串口只能告诉你「跑到哪了」，而且只有你打了 printk 的地方才说。JTAG 不一样：它能让 CPU 在任意一条指令上停下来，然后把寄存器、内存、页表全翻给你看。

对 i.MX6ULL 这种「从 BootROM 开始就只有几行串口」的芯片，JTAG 是唯一能看到启动早期真相的工具。

先玩一下：停核、看寄存器、单步

这就是 Ozone/J-Link 的基本操作循环。注意第 3 步：停核读到的是「此刻真正在执行的指令」，不是日志。

这三件事——停核、读寄存器、单步——构成了 JTAG 的全部价值。剩下的功能（Flash 烧写、trace）都是它们的组合。

一、i.MX6ULL 上的三个关键状态

阶段PC 大致在哪MMU你能看到什么
复位瞬间BootROM（内部 ROM 区）关物理地址；串口未初始化
SPL / U-Boot 早期OCR RAM / DDR通常关或刚开DDR 初始化结果、时钟寄存器
内核运行中内核代码段开虚拟地址；要看物理地址得手动走页表

最容易踩的坑是「地址对不上」：U-Boot 里你看到 0x8000_0000 是 DDR 起始，内核里同一个物理地址可能映射在 0xC000_0000 的虚拟地址上。判断方法就是读 SCTLR 的 M 位：MMU 关了，地址即物理；开了，就要查页表或让调试器做地址翻译。

这张表的价值在于「预期」：单步时你心里有一个 PC 应该在哪，一旦偏离，问题就出在上一步。

二、硬件断点、观察点与它们的限制

  • 硬件断点：靠 CPU 内的地址比较器，数量有限（Cortex-A7 通常 6 个）。软件断点（改指令为 BKPT）在 Flash/ROM 上不可用，所以早期启动只能靠硬件断点。
  • 观察点（watchpoint）：监视某个地址的读/写，命中即停。查「谁把这个变量改坏了」时无可替代。
  • 单步：每次只执行一条指令，慢但准确；配合 step over 跳过函数调用。
误解：接上 JTAG 就能随便停停核会让看门狗继续计数，停太久板子会被复位；某些外设（DMA、eMMC）在 CPU 停住时仍在动，读到的状态可能已经变了。调试早期启动时，先确认看门狗已关或已喂。
Ozone 的三个实用动作1）加载 ELF 后按符号下断点，比记地址可靠；2）用 Memory 窗口看外设寄存器，配合手册的 offset；3）用 Timeline/Trace（若支持）看中断进出，比 printk 精确。

三、什么时候必须上 JTAG

动手（可选）：停住刚上电的 CPU

只在 🔧 实作模式展开需要 J-Link 与板子；本站在根目录另有 J-Link 连接笔记可对照。
  1. Ozone 新建工程，选 i.MX6ULL（Cortex-A7），连接方式 JTAG，复位策略选 Reset and halt。
  2. 连上后先读 PC 与 CPSR，确认停在复位向量。
  3. 加载 U-Boot 的 ELF（带符号），在 board_init_f 或 dram_init 下硬件断点。
  4. 命中后读 DDR 控制器寄存器与串口寄存器，对照手册确认初始化是否真的生效。

离开这一篇，你应该能

  • 说出停核时该看哪四个寄存器，以及 SCTLR.M 为什么关键。
  • 解释硬件断点与软件断点的区别，以及为什么早期启动只能用前者。
  • 按「四段假设」定位一块完全没输出的板子。

JTAG 是「手动挡」。日常排障更需要「自动挡」：不加 printk 也能知道谁慢、谁在频繁分配。下一篇讲 ftrace、perf 与 eBPF。
