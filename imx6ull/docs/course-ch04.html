系统管理四件事

装软件、看进程、管服务、查日志——这四件事占了日常 Linux 操作的 80%。板子上调不通的时候，你靠的也是这四件事。

★ 一读 纯读约 16 小时 左侧是本卷目录 理论为主 · 实作可跳

本章目标

① 理解 root / sudo / 用户组的权限模型；② 会用 apt 装软件，也会源码编译装；③ 能找到并杀掉卡死的进程；④ 会写 systemd 服务让程序开机自启；⑤ 会写 crontab 定时任务；⑥ 知道日志去哪找。

4.1 用户、组与 sudo

Linux 里所有进程都带着「我是谁」的身份运行。root（UID 0）拥有一切权限，普通用户只有自己范围内的权限。日常千万别用 root 登录，需要时用 sudo 临时提权——这样每条危险命令都必须显式加 sudo，等于强制你多想一秒。

文件内容看什么
/etc/passwd所有用户的基本信息用户名、UID、家目录、登录 shell
/etc/shadow密码哈希（普通用户读不了）只有 root 能看
/etc/group组与成员看自己是否在 dialout、sudo 组里
/etc/sudoers谁能用 sudo只能用 visudo 改，改坏会锁死权限
 
# 我是谁
$ whoami
$ id                    # 输出 uid/gid 和所属组

# 建用户（会交互式建家目录，推荐）
$ sudo adduser dev1
# 加入附加组（如串口 dialout）
$ sudo usermod -aG dialout dev1
$ groups dev1

# 提权执行单条命令
$ sudo systemctl restart ssh

# 切到 root（不推荐长期使用）
$ sudo -i
改 sudoers 一定用 sudo visudo 直接 vim /etc/sudoers 写错一个字符，sudo 就彻底不可用，只能进恢复模式救。visudo 会在保存时做语法检查。

4.2 装软件的三种方式

方式一：apt（99% 的场景用它）

$ sudo apt update              # 刷新软件列表（先做这个）
$ sudo apt search nfs          # 搜包
$ sudo apt install -y nfs-kernel-server
$ sudo apt remove nfs-kernel-server
$ sudo apt purge nfs-kernel-server   # 连配置一起删
$ dpkg -l | grep nfs           # 看装了哪些包
$ apt show vim                 # 看包信息、版本、依赖
apt update 和 apt upgrade 别搞混 update 是刷新「有哪些包可以装」，upgrade 才是真正升级已装的包。不 update 就 install，可能装到旧版本或报找不到。

方式二：源码编译（板卡工具链、老版本软件常用）

三步曲：配置 → 编译 → 安装。缺依赖时第一步就会报错，报错信息通常会告诉你缺哪个包。

$ tar -zxvf xxx-1.0.tar.gz
$ cd xxx-1.0
$ ./configure --prefix=/opt/xxx      # 检查环境、生成 Makefile
$ make -j4                            # 编译，-j4 用 4 核并行
$ sudo make install                   # 装到 prefix 指定的目录

--prefix 很重要：不指定就装进 /usr/local，容易和 apt 装的版本打架。板卡厂商的交叉工具链最好统一装到 /opt 下。

装完如果命令找不到，是 PATH 没生效：

# 临时生效
$ export PATH=/opt/xxx/bin:$PATH
# 永久生效（写进 ~/.bashrc，只对自己的账户）
$ echo 'export PATH=/opt/xxx/bin:$PATH' >> ~/.bashrc
$ source ~/.bashrc
# 全局生效（写 /etc/profile.d/，所有用户）

4.3 进程管理

进程就是正在跑的程序。你要会做三件事：看它在不在、它吃了多少资源、怎么让它停。

$ ps aux                  # 所有进程快照
$ ps aux | grep nginx     # 找特定程序
$ top                     # 实时看 CPU/内存，q 退出
$ htop                    # 更好看的版本，需 apt 装
$ pstree -p               # 看进程父子关系

# 按 CPU 排序取前 10
$ ps aux --sort=-%cpu | head -11

# 看某个程序的详细信息
$ ls -l /proc/$(pgrep nginx | head -1)/   # cwd exe fd 都在这

结束进程：信号是关键

信号编号含义用法
SIGTERM15请你退出（可被程序捕获做清理）kill <pid> 默认就是它
SIGKILL9立刻杀死，无法捕获kill -9 <pid>，最后手段
SIGINT2中断（等于 Ctrl+C）前台程序
SIGHUP1挂断，很多服务用它重读配置kill -1 <pid>
SIGSTOP19暂停kill -19 <pid>
先 15 再 9 直接 kill -9 会让程序没机会保存数据、释放设备，网络文件可能写坏。正确姿势：先 kill（15），等 3–5 秒还在，再 -9。

前台 / 后台

$ ./long_task &        # 后台运行
$ jobs                 # 看后台任务
$ fg %1                # 把 1 号任务调回前台
$ bg %1                # 让暂停的任务在后台继续
$ Ctrl+Z               # 暂停当前前台程序

# 关掉终端也不退出（板子上跑测试常这么干）
$ nohup ./test > run.log 2>&1 &

4.4 systemd：让程序开机自启

现代 Linux 用它管服务。systemctl 是最常用的命令，四个动作覆盖全部：

$ sudo systemctl start  ssh        # 启动
$ sudo systemctl stop   ssh        # 停止
$ sudo systemctl restart ssh       # 重启（改了配置后）
$ sudo systemctl status ssh        # 看状态 + 最近日志
$ sudo systemctl enable ssh        # 开机自启
$ sudo systemctl disable ssh
$ systemctl list-units --type=service --state=running
改配置必 restart 改了 /etc/ssh/sshd_config、NFS 的 /etc/exports、TFTP 配置之后，不执行 restart，新配置完全不生效。这是新手最常见的「我明明改了却不生效」。

写自己的服务

假设你有一个脚本 /home/ubuntu/lab/hello.sh，想让板子/PC 开机自动运行，新建一个 unit 文件：

$ sudo vim /etc/systemd/system/hello.service
[Unit]
Description=My hello service
After=network.target

[Service]
Type=simple
ExecStart=/home/ubuntu/lab/hello.sh
Restart=on-failure
RestartSec=3
User=ubuntu

[Install]
WantedBy=multi-user.target
$ sudo systemctl daemon-reload      # 新增 unit 必须重新加载
$ sudo systemctl enable --now hello
$ sudo systemctl status hello
$ journalctl -u hello -f             # 实时看这个服务的日志

4.5 crontab：定时任务

五个字段 + 一条命令，顺序是分 时 日 月 周：

写法含义
* * * * *每分钟
*/5 * * * *每 5 分钟
0 * * * *每小时整点
30 2 * * *每天 2:30
0 3 * * 1每周一 3:00
0 0 1 * *每月 1 号 0:00
@reboot开机时（比 systemd 弱，简单场景可用）
 
$ crontab -e       # 编辑当前用户的定时任务
$ crontab -l       # 列出
$ sudo crontab -e  # 编辑 root 的

# 内容示例：每分钟把时间写进日志
*/1 * * * * date "+\%Y-\%m-\%d \%H:\%M:\%S" >> /tmp/time.log 2>&1
cron 不执行的三个原因 ① 环境变量不同（脚本里用绝对路径，别依赖 ~）② 没执行权限 ③ % 在 crontab 里是特殊字符，需要转义成 \%。日志看 /var/log/syslog 里 CRON 开头的行。

4.6 日志：出问题先看这里

位置 / 命令内容什么时候看
/var/log/syslog系统综合日志（Debian/Ubuntu）服务启动失败、cron 执行、网络事件
/var/log/auth.log登录、sudo 记录SSH 连不上、被拒绝登录
dmesg内核环形缓冲区驱动打印、硬件识别、内核崩溃——第 12 章主力
journalctlsystemd 统一日志服务日志、按时间/单元过滤
 
$ tail -f /var/log/syslog        # 实时跟踪
$ journalctl -u ssh -n 50        # 某服务最近 50 行
$ journalctl --since "10 min ago"
$ dmesg | tail -30               # 内核最近输出
$ dmesg -w                        # 实时跟随内核日志（插拔 USB 时用）
$ dmesg | grep -i error
排障四连 服务起不来 → systemctl status → journalctl -u 服务名 → /var/log/syslog → 内核问题看 dmesg。这四步能解决绝大多数「为什么没反应」。

4.7 动手任务

  • 新建用户 dev1，把它加入 dialout 和 sudo 组，切换到该用户执行一次 sudo ls /root。
  • 用 apt 装 htop，用 top 和 htop 各看一次系统负载。
  • 跑一个死循环 while true; do :; done &，用 ps 找到它，先用 kill（15）再用 kill -9，记录两次结果差异。
  • 写一个 hello.service，让 /home/ubuntu/lab/hello.sh 开机自启（脚本内容：往 /tmp/hello.log 追加一行时间）。用 journalctl -u hello 验证。
  • 写一条 crontab，每分钟记录一次时间到你自己的日志文件，观察 3 分钟确认生效。
  • 故意启动一个不存在的服务 systemctl start nosuch，看报错；再写一个 ExecStart 路径错误的 unit，用 status 和 journalctl 找出原因。

4.8 验收标准

  • 能解释为什么日常不用 root 登录，而用 sudo
  • 能独立 apt 装包、卸载、查询版本
  • 能源码编译装一个软件并让它全局可用（PATH 配置正确）
  • 能 30 秒内找到占用 CPU 最高的进程并安全结束它
  • 能自己写一个 systemd 服务并让它开机自启
  • 能写出「每 5 分钟执行一次」的 crontab
  • 看到服务异常，第一反应是 systemctl status + journalctl
