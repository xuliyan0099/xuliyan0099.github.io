从按键到屏幕

你按下键盘上的「A」，屏幕上出现一个「A」，感觉是瞬时的。但这一瞬间里，信号穿过了机械触点、GPIO、中断控制器、驱动、输入子系统、终端行规程、你的程序、显示控制器，至少六次内存拷贝、两次特权级切换。这一课把这条链子走一遍——不是为了背流程，而是为了建立一个以后天天要用的直觉：任何一次「用户看到的结

这一课要回答的问题

① 按一下键，硬件怎么把「按下」变成数字？② 为什么键盘需要「去抖」？③ 内核里那条数据经历了几个缓冲区？④ 为什么有时候输入会「延迟一下才出现」？⑤ 我怎么测量每一段花了多久？

1. 直觉：一次跨省快递

你在网上下单（按键），包裹经过卖家仓库（驱动）、区域分拣中心（输入子系统）、城市配送站（终端/图形栈）、快递员（你的程序），最后到你手上（屏幕）。每一站都有「卸货—扫描—装车」，也就是内存拷贝与状态更新。

类比的失效处：快递每一站都可能丢件、需要签收确认；而计算机这条链路是流式的——不会等上一段完全签收才发下一段，中断可以在任何时刻插入，多个输入可以并发排队。所以链路更像「传送带 + 分流器」，不是「接力棒」。

2. 硬件上：一个按键就是一个开关

键盘按键本质是一个机械触点：按下时两个金属片接触。问题在于金属有弹性，闭合瞬间会在几毫秒内反复弹跳十几次——如果直接读电平，你会看到「按下、松开、按下、松开」的抖动。

现象硬件处理软件处理
触点抖动 1–5msRC 滤波（电容 + 电阻）去抖：连续两次采样间隔 ≥ 5ms 且状态一致才算有效
空闲电平不确定上拉电阻把线拉高；按下接地变低配置 GPIO 内部上拉
多个键同时按矩阵扫描（行列扫描）扫描周期决定最大同时按键数
USB 键盘主机每 1ms 轮询一次（全速）HID 报告描述符解析

「GPIO 按键 + 中断」在嵌入式里最常见的配置是：按键接 GPIO，配置为双边沿中断，驱动里起一个定时器做 5–20ms 去抖，超时后再确认状态。你在开发板上点一个键没反应，八成是这两步之一没做对。

3. 软件上：数据被搬了几次

为什么这么多层？因为每一层解决一个问题：驱动管硬件差异，输入子系统管设备抽象，终端管「行编辑/回显/信号」，应用只管拿到字符。分层的代价是拷贝，收益是每一层都能独立替换——换成 USB 键盘、串口终端、触摸屏，上层代码一行不改。

5. 实验：把这条链路看穿

# ① 看输入设备与事件（板子或带 X 的虚拟机上）
ls /dev/input/
[board] evtest /dev/input/event0        # 按键时能看到 event: type 1 code 30 value 1

# ② 看一次程序到底调了哪些系统调用
strace -e trace=read,write,ioctl cat   # 敲键盘，看 read 的返回与内容

# ③ 看内核给这个输入设备的抽象
cat /proc/bus/input/devices

# ④ 量化：用 evtest 时间戳算「按下到事件」的间隔
[board] evtest /dev/input/event0 | ts '%.s'

第 ② 条命令的输出最能建立直觉：你敲一个字符，cat 那边的 read() 就返回一次，返回值的字节数就是这次读到的长度。「输入」在程序眼里就是「read 有返回值了」，没有任何魔法。

7. 自测与动手

1

为什么按键需要去抖？不去抖会看到什么现象？

看答案

机械触点在闭合瞬间会弹跳多次（1–5ms 内十几次），不去抖会读成「按了很多次」，表现为一次按键输入多个字符。

2

从内核缓冲到用户空间，数据为什么要复制一次？能不能不复制？

看答案

因为用户进程不能直接访问内核地址空间（页表里那块标了仅内核可访问）。可以不复制，但要改映射（如 mmap 环形缓冲、零拷贝方案），代价是复杂性与安全边界。

3

体感「输入延迟半秒」，你会先查哪一段？为什么？

看答案

先查「等」：CPU 占用、锁竞争、驱动里的忙等、显示 vsync。因为按量级算，正常链路只有几十毫秒，半秒的差值不可能来自正常的拷贝与计算。

4

evtest 里的 type/code/value 分别是什么？

看答案

type 是事件类别（1=按键，2=相对移动，3=绝对坐标），code 是具体键码（30 对应 KEY_A），value 是状态（1 按下，0 松开，2 重复）。

5

为什么显示要等 vsync，而不是写完立刻刷？

看答案

面板按固定帧率逐行扫描，非同步写入会造成撕裂（上半屏新帧、下半屏旧帧）。等 vsync 是把「什么时候写」对齐到面板的刷新节拍。

  1. 在虚拟机上跑 strace -e read,write cat，敲几个字符，观察 read 的返回。
  2. 板子上 evtest 看按键事件，记录按下到事件打印的间隔。
  3. 画一张自己的链路图，标出每一段的「缓冲区」在哪。
  4. 估一下你手机上一次点击的总延迟，指出最可能的两段。
