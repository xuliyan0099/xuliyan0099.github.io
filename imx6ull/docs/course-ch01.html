卷 00·起步 · Linux 与实验台·第 01 篇

Linux 全景认知

这一章不敲命令，只解决一个问题：你接下来要学的这一堆东西，各自在哪一层、为什么存在。概念不清就开始敲命令，等于背电话号码。

★ 一读 纯读约 4 小时 左侧是本卷目录 理论为主 · 实作可跳

本章目标

① 能画出「硬件 → 内核 → 系统调用 → 应用」的层次图；② 能区分内核、发行版、GNU 工具；③ 知道嵌入式 Linux 和服务器 Linux 的六大差别；④ 知道 i.MX6ULL 是什么定位的芯片；⑤ 知道板子上要跑的四件套是什么。

1.1 操作系统到底在管什么

把电脑想成一栋楼。硬件是钢筋水泥，应用程序是住户，内核就是物业：谁用电梯（CPU 时间片）、谁分到房间（内存）、谁能进仓库（磁盘）、谁能打电话（网络），全归它调度。住户不能直接去配电房拉闸，只能填单子——这张单子就叫系统调用。

应用程序你的 C 程序 / shell / nginx
↓
库 / C 库glibc、musl：把系统调用包装成函数
↓
系统调用接口open / read / write / ioctl
↓
内核进程·内存·文件系统·驱动·网络
↓
硬件CPU / DDR / eMMC / 网卡 / GPIO

关键点：应用程序永远不直接操作寄存器。你想点亮一个 LED，代码最终是 write() 到一个设备文件，由内核里的驱动去写 GPIO 寄存器。这条链路就是本书第 12 章要打通的东西。

一句话记住 内核是唯一能碰硬件的代码。用户程序想碰硬件，必须通过内核提供的接口。所以「学 Linux」的本质是：学怎么用这些接口，以及怎么在内核里加新的接口。

1.2 内核、发行版、GNU 工具，别再混为一谈

名词是什么谁做的你可以怎么改
内核（kernel）真正管硬件的那坨代码，一个 zImage / uImage 文件Linus 及全球社区，版本如 4.1.15、5.15配置裁剪、改驱动、打补丁、加自己的模块
GNU 工具shell、编译器 gcc、调试器 gdb、各种命令行工具GNU 计划换版本、换实现（如 BusyBox）
发行版内核 + 工具 + 包管理器 + 默认配置，打包成一个能装的系统Ubuntu、Debian、Fedora、Yocto、Buildroot整包替换，或自己用 Buildroot 造一个
根文件系统挂载成 / 的那套目录和文件，里面装着 shell、库、配置你（用 BusyBox / Buildroot 做）随便改，是自己做的就完全可控

新手最常见的误解是「Linux 就是一个系统」。严格讲，Linux 只是内核；你平时说的「装个 Linux」其实装的是发行版；板子上跑的往往是「内核 + 一个自己做的根文件系统」，根本没有发行版的概念。

1.3 嵌入式 Linux 和服务器 Linux，差在哪

命令是同一套，但工程约束完全不同。这张表决定了你后面为什么会被一些「服务器上很正常的操作」坑到：

维度服务器 / 桌面 Linux嵌入式 Linux（i.MX6ULL）
CPUx86_64，多核，几 GHzARM Cortex-A7，单核，528 MHz
内存32–512 GB256 MB / 512 MB DDR
存储SSD / 云盘，几百 GB8–16 GB eMMC，或 8 GB SD 卡
编译本机 gcc 直接编交叉编译：PC 上编，板子上跑
启动BIOS/UEFI → GRUB → 内核BootROM → SPL → U-Boot → 内核
显示桌面环境随便装可能只有一个串口终端，没有屏幕
调试ssh 上去，随便装工具串口是最后的生命线，SSH 挂了只能靠它
升级apt upgrade重新烧写整机镜像，或做 OTA
最要命的一条 板子内存只有 256MB 时，你在 PC 上编译一个「随便就吃 2GB」的程序，板子上根本跑不起来。交叉编译出来的文件还要考虑体积、依赖库、ABI，这些都是服务器开发不需要操心的。

1.4 为什么选 i.MX6ULL

i.MX6ULL（全称 i.MX 6UltraLite）是 NXP 的单核 Cortex-A7 应用处理器，主频 528MHz，主打低功耗、工业级、长供货周期。它不是性能怪兽，但作为「第一块能跑完整 Linux 的板子」，性价比极高：

芯片 / 平台定位跑 Linux 的难度适合谁
STM32F103MCU，无 MMU跑不了标准 Linux，只能跑 RTOS / uClinux学裸机、RTOS
i.MX6ULL低端 MPU，单核 A7难度低，资料极多，板子便宜第一次学嵌入式 Linux
RK3588 / i.MX8M高端 MPU，多核 A76/A55难度中，BSP 庞大，编译慢做产品、跑 AI
树莓派 5消费级 SBC几乎零难度（官方镜像开箱即用）应用层验证，但学不到启动链

选它的真正理由：它的启动链你能完整走一遍。树莓派给你一个装好的系统，你碰不到 U-Boot、碰不到 DTS、也看不到 BootROM 怎么加载。而 i.MX6ULL 从烧写、U-Boot 命令行、内核编译、设备树、根文件系统，每一环都暴露在你面前——这才是「学嵌入式 Linux」而不是「用一个 Linux 小电脑」。

它有什么外设 双路 10/100M 以太网（ENET1/2）、2 路 CAN、多路 UART、I2C、SPI、LCD 控制器、ADC、SD/eMMC、NAND、USB OTG/Host、GPIO 若干组。做工业网关、车载终端、HMI 面板的经典选择，你后面点 LED、接传感器都够用。

1.5 板子里跑的是「四件套」

一块能启动的 i.MX6ULL 板子，存储介质里一定躺着这四个东西。后面第 8–11 章就是把它们逐个拆开讲：

U-Boot引导程序
负责初始化 DDR、加载内核
+
zImage内核镜像
真正管硬件的那坨代码
+
.dtb设备树
告诉内核这块板子有什么硬件
+
rootfs根文件系统
shell、库、你的程序

少任何一个都起不来：没有 U-Boot 芯片不知道从哪加载；没有 dtb 内核不知道 LED 接在哪个引脚；没有 rootfs 内核最后一步会报 Kernel panic - not syncing: No working init found——这个报错你以后一定会见到，现在先记住它长什么样。

1.6 三个心理陷阱，提前拆掉

陷阱一：追新版本

看到教程用 4.1.15，自己去找 6.x 版内核，然后配置项全对不上。跟着板卡厂商的版本走，这是唯一正确姿势。

陷阱二：先啃内核源码

没跑通过一次编译链就去读 kernel/sched/core.c，只会死在里面。先会用，再会改，最后才谈懂。

陷阱三：怕命令行

板子上没有鼠标，所有操作都是敲命令。第 3 章必须练到盲打级别，否则后面寸步难行。

1.7 动手任务

  • 拿一张纸，默画「应用 → 库 → 系统调用 → 内核 → 硬件」五层图，标出 LED 点亮时数据走的路径。
  • 查你手上（或打算买的）板子的资料：确认 SoC 型号、DDR 容量、eMMC/SD 容量、串口是哪个 UART、调试串口波特率。
  • 把板卡厂商提供的资料包目录列一遍，找出这四样文件：U-Boot 镜像、内核镜像（zImage）、设备树（.dtb）、根文件系统镜像。找不到就说明你的资料不完整，这会直接影响第 8 章之后的进度。
  • 用一句话向自己解释：为什么板子上的程序要在 PC 上编译？

1.8 验收标准

  • 能说出内核和发行版的区别，并举一个例子说明「板子上没有发行版」
  • 能列出嵌入式 Linux 与服务器 Linux 至少 5 个差别
  • 能解释为什么 i.MX6ULL 适合作为第一块学习板
  • 能说出四件套各是什么、缺了会怎样
  • 知道自己板子的 SoC 型号、内存大小、调试串口编号
