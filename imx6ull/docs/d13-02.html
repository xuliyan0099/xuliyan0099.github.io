卷 13·拔高·第 03 篇

xv6 或自制一个最小 OS：把操作系统造一遍

● 一读 纯读约 8 小时 左侧是本卷目录 理论为主 · 实作可跳

读一百篇讲调度的文章，不如自己写一次 swtch。xv6 只有几千行，却把进程、页表、中断、系统调用全串起来了。

它是 MIT 的教学 OS，现在的主流版本跑在 RISC-V 上。你不需要板子，QEMU 里就能把它跑起来、改坏、再修好。

先玩一下：xv6 的进程状态

xv6 的 struct proc 里有一个 state 字段。点事件，看它怎么转——和 Linux 的 task_struct 是同一套逻辑，只是字段少得多。

一、swtch：上下文切换的全部秘密

切换不是「保存所有寄存器」，而是只保存调用者保存寄存器（callee-saved）。因为切换发生在函数调用语境里，调用者保存寄存器已经由编译器负责了。

注意最后一行：swtch 返回时，CPU 已经在另一个栈上、跳到另一个函数的「返回点」。这正是「上下文切换」最反直觉的地方——它不需要特殊的硬件指令，靠的就是保存/恢复栈指针与返回地址。

二、内核地址空间与 trampoline

xv6 的页表里还有一个特殊的 trampoline 页：它同时映射在用户页表和内核页表的同一个虚拟地址，且可执行。这样在切换页表（satp）的那一瞬间，代码还在原地，不会因为「换了页表就找不到下一条指令」而崩。这个技巧在所有 OS 里都有，名字不同而已。

三、和你手里的 i.MX6ULL 怎么对上

xv6（RISC-V）i.MX6ULL（ARMv7 + Linux）共同点
entry.S 设栈、跳 start()BootROM → SPL → U-Boot → head.S都要先有栈、先有关掉 MMU 的物理地址阶段
start() 配时钟中断、开页表start_kernel() 里的 paging_init「开 MMU」是内核真正变成内核的那一刻
main() 初始化各子系统，userinit()kernel_init → init 进程第一个用户进程由内核亲手造出来
usertrap() 处理 ecall/中断异常向量表 + do_IRQ用户态进内核的唯一入口是异常
swtch 协作式切换context_switch + 抢占都是保存 callee-saved + 换栈
最高效的学法不要通读。选一条路径走完：initcode 怎么执行第一条指令 → 怎么进 exec → 怎么跑到 shell。走通这一条，整本书就活了。
误解：xv6 太简单，学了没用它省掉的是「性能与兼容性」，保留的是「机制」。你在这几千行里看到的每个结构，Linux 里都有对应物，只是多了锁、RCU、cgroup、namespace 这些工程复杂度。

动手（可选）：在 QEMU 里跑起来并改坏它

只在 🔧 实作模式展开PC 上即可，10 分钟。
  1. git clone xv6-riscv，make qemu，看到 xv6 kernel is booting 与 shell。
  2. 在 sys_write 里加一句 printf，观察每次 echo 都打印——你就摸到了系统调用入口。
  3. 把 NPROC 改成 8，跑并发程序，看 fork 何时返回 -1。
  4. 在 swtch 里故意不保存 s0，观察程序出现随机错误——这就是「上下文没保存全」的后果。

离开这一篇，你应该能

  • 解释 swtch 为什么只保存 callee-saved 寄存器，以及「切换像函数返回」是什么意思。
  • 说出 trampoline 页的作用，以及不用它会怎样。
  • 把 xv6 的启动路径与 i.MX6ULL 的五级启动链一一对应。

最后一步往外走：如果一台机器要同时跑多个操作系统，硬件需要多给什么？那就是虚拟化与 KVM。
