GIC 与定时器

上百个中断源不可能各占一个 CPU 引脚。它们汇到一个「中断调度中心」——GIC，由它排队、定优先级、再向 CPU 报一个中断号。而「时间」这件事，也靠一个定时器不停打断来实现。这两个东西合起来，构成了内核的「心跳」。

这一课要回答的问题

① GIC 内部有哪两部分？② SPI / PPI / SGI 差在哪？③ 中断优先级怎么生效？④ 内核里 tick 从哪个定时器来？⑤ 高精度定时器怎么做到微秒级？

1. GIC 的两部分

  • Distributor：管所有中断源——使能、优先级、分组、目标 CPU。
  • CPU Interface：每核一个，向 CPU 报中断（IRQ/FIQ）、应答（IAR）、结束（EOIR）。

典型流程：外设拉线 → Distributor 记录 pending → 按优先级选一个 → 通过 CPU Interface 发给某个核 → 内核读 IAR 拿到中断号 → 处理完写 EOIR。

只读 IAR 而不写 EOIR，会导致这个中断永远不再触发——这是新手写裸机中断最常见的坑。

2. 三类中断号

类型编号来源用途
SGI0~15软件写寄存器触发核间唤醒、IPI（如 TLB shootdown）
PPI16~31每核私有时钟/定时器本地 tick、性能计数器
SPI32~255外部设备UART、GPIO、DMA、网卡

PPI 是「每核私有」：同一个中断号在每个核上各有一份，适合本地定时器。SPI 可以路由到指定核，也可以广播。

3. 定时器：内核的心跳

# i.MX6ULL 上可用的几类
# 1) GPT（通用定时器）：可做 PWM、输入捕获、周期中断
# 2) EPIT：增强型周期中断定时器，专为 tick 设计
# 3) ARM Generic Timer：A7 内置，每核一个，精度高

# 内核里的层次
clocksource   # 提供「现在几点」（读计数器）
clockevent    # 提供「N 纳秒后叫我」（编程比较值）
tick          # 周期性调度时机（可配置 NO_HZ 关掉）
hrtimer       # 高精度定时器，微秒级

你会发现内核把「计时」拆成两件事：一个是「读时间」，一个是「定闹钟」。前者要稳定（clocksource 打分选最优），后者要精确（clockevent 用硬件比较寄存器）。

4. 与 Linux 的接缝

# 看中断分布与定时器
cat /proc/interrupts | head -20
cat /sys/devices/system/clocksource/clocksource0/current_clocksource
grep CONFIG_HZ /boot/config-$(uname -r)

5. 三条常见误解

6. 自测与动手

1

GIC 的 Distributor 与 CPU Interface 各管什么？

看答案

Distributor 管所有源的使能/优先级/路由；CPU Interface 负责向某个核报中断、应答与结束。

2

SGI 用来做什么？

看答案

核间中断（IPI），如唤醒其它核、请求 TLB 刷新、调度 IPI。

3

clocksource 与 clockevent 的区别？

看答案

clocksource 用来「读现在的时间」；clockevent 用来「设定下一次中断时刻」。

4

为什么必须写 EOIR？

看答案

通知 GIC「这个中断处理完了」，否则它保持 active 状态，后续同源中断不再投递。

5

NO_HZ 省电的原理？

看答案

空闲时停掉周期 tick，让 CPU 真正进入低功耗；有任务时再按需编程定时器。

  1. 查手册找到 UART1 的 GIC 中断号，与设备树里的对照。
  2. 在 /proc/interrupts 里找到它并观察计数增长。
  3. 用 cat /sys/devices/system/clocksource/.../current_clocksource 看当前时钟源。
  4. 写裸机代码：使能一个 GPT 中断，验证「不写 EOIR 就不再触发」。
