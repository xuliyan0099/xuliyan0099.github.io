卷 03·存储与地址·03.07

缺页与换页

你 malloc 了 100MB，程序立刻返回，物理内存却只多了一点。真相是：malloc 只给了一段虚拟地址，物理页要等第一次访问才分配。这个「等」由一个异常完成——缺页异常。它同时是 SIGSEGV 的来源，也是 fork 能廉价的原因。

★ 一读 纯读约 1 小时 左侧是本卷目录 理论为主 · 实作可跳

这一课要回答的问题

① malloc 为什么立刻返回？② 缺页异常怎么区分「补页」与「SIGSEGV」？③ 写时复制（COW）怎么省内存？④ minor fault 与 major fault 差别？⑤ 没有 swap 的板子内存不够会怎样？

1. malloc 的真相

char *p = malloc(100 * 1024 * 1024);   // 立刻返回，不占物理内存
// 此时 p 指向一段虚拟地址，页表项全部「无效」
// 内核只在 VMA 里记了一笔「这 100MB 是堆，可读写」

p[0] = 1;      // 第一次写 → 缺页 → 分配 1 页（4KB）
// 之后每跨过 4KB 边界写一次，才再多分配一页

// 所以「malloc 成功但 OOM」是很常见的现象：
// 分配时没花钱，真正花钱是在访问时

Linux 默认开启 overcommit，所以 malloc 几乎不会失败；OOM 发生在访问阶段，由内核的 OOM killer 选一个进程杀掉。这就是「为什么程序跑着跑着被 killed」的常见原因。

2. 判断合法与非法的依据：VMA

内核为每个进程维护一张 VMA（虚拟内存区域）表，就是 /proc/<pid>/maps 的内容。缺页时它做三件事：

  1. 地址落在某个 VMA 里吗？不在 → SIGSEGV。
  2. 访问类型与 VMA 权限匹配吗？（写一个 r-- 的段）→ SIGSEGV。
  3. 都在 → 分配页、填 PTE、返回重试。

3. 写时复制：fork 为什么这么快

fork 要复制整个地址空间？如果真复制，一个 100MB 的进程 fork 一次要拷 100MB。实际做法是：

  • 子进程的页表指向同一批物理页，但全部标成「只读」。
  • 任何一方写入 → 触发「写保护」缺页 → 内核此时才复制那一页，并各自改成可写。

于是 fork 的代价是「复制页表」，与内存大小近似无关。这也是 exec 前的 fork 几乎不花钱的原因——exec 会立刻把地址空间整个换掉，那些 COW 页从来没被复制过。

4. minor 与 major fault

# 观察两类缺页
/usr/bin/time -v ./prog        # 输出里有 minor/major page faults
perf stat -e page-faults,minor-faults,major-faults ./prog
cat /proc//stat | awk '{print "minflt="$10, "majflt="$12}'

一个健康的长期运行程序，启动时 major fault 多、之后应该几乎为 0。如果持续有 major fault，说明它在不断「换入换出」或反复读文件——这就是性能问题的信号。

5. 没有 swap 的嵌入式

板子上通常不配 swap（Flash 写寿命有限、SD 卡太慢）。所以内存压力只能靠：

  • 回收页缓存：丢弃可再生的文件缓存（drop_caches）。
  • 压缩内存：zram（用 CPU 换内存）。
  • 杀掉进程：OOM killer。
# 看内存压力
cat /proc/meminfo | head -8
cat /proc/pressure/memory      # PSI：内存压力指标（新版内核）
dmesg | grep -i "oom\|killed process"

嵌入式里最实用的三条经验：别 malloc 大块、注意页缓存占用（它算在 available 里但可回收）、以及给关键进程设 oom_score_adj。

6. 三条常见误解

7. 自测与动手

1

malloc 100MB 成功，物理内存会立刻少 100MB 吗？

看答案

不会。只建立了虚拟映射（VMA），物理页在首次访问时才分配。

2

内核怎么判断一个缺页该补页还是该杀进程？

看答案

查 VMA：地址是否在区域内、访问类型是否匹配权限。合法就补页，否则投递 SIGSEGV。

3

COW 为什么让 fork 变快？

看答案

子进程共享物理页并标只读，只有真正写入时才复制单页；fork 成本因此与内存大小近似无关。

4

major fault 与 minor fault 的本质区别？

看答案

minor 只需分配物理页（或 COW 复制）；major 还要从磁盘/Flash 读入数据，慢得多。

5

嵌入式为什么常不配 swap？

看答案

Flash/SD 写入慢且寿命有限，频繁换页会拖垮性能并磨损存储；改用 zram 或直接控内存。

  1. 写一个 malloc 100MB 但不访问的程序，看 RSS 是否几乎不变。
  2. 访问它，每跨 4KB 写一次，用 /proc/pid/stat 观察 minflt 增长。
  3. fork 一个大内存进程，测耗时，验证 COW 的效果。
  4. 在板子上看 /proc/pressure/memory，制造内存压力观察变化。
