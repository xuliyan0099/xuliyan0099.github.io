PC 与指令寄存器

CPU 里最忙的两个小寄存器：一个叫 PC，永远指着「下一条要执行的指令」；一个叫 IR，装着「正在被解释的那条指令」。这一课讲清它们怎么配合，以及 ARM 里一个让无数新手困惑的现象——读 PC 得到的不是当前指令地址，而是「当前 + 8」。

★ 一读 纯读约 1 小时 左侧是本卷目录 理论为主 · 实作可跳

这一课要回答的问题

① PC 到底是什么，为什么它决定了「执行顺序」？② IR 和译码器怎么把 32 位变成控制信号？③ 为什么「改 PC」就等于跳转？④ ARM 的 b 指令偏移量怎么算？⑤ 为什么读 PC 得到的是 PC+8？

1. 直觉：书页上的手指

把内存想成一本书，指令是一行一行。PC 就是你手指按住的那一行。执行一行，手指往下挪一行；想跳读，就直接把手指按到别处。整台机器的「顺序执行」和「跳转」，都是这一根手指的动作。

失效处：书是线性的，但手指可以随便按。所以顺序执行是最省事的默认，而跳转要额外付出代价——流水线里已经预取进来的指令要作废，这就是第 13 课分支惩罚的根源。

2. 硬件上：PC、IR 与译码器

寄存器位宽作用ARM 里
PC32下一条指令地址R15（可被读写，但读到的值特殊）
IR32当前指令的机器码无编号，软件不可见
CPSR32标志位 + 模式位软件可见（第 29 课）
LR32函数返回地址R14，bl 自动写入

译码器做的事，就是把 IR 里的 32 位按固定位段切开：哪些位是操作码、哪个是目标寄存器、哪些是立即数/偏移。第 14 课会把 A32 的位段逐位拆开。

3. 跳转的本质：给 PC 赋值

; ARM 汇编
    b   label        ; 无条件跳转
    bl  func         ; 跳转并把返回地址存到 LR (r14)
    bx  lr           ; 跳回 LR 指向的地址（函数返回）
    mov pc, r0       ; 直接把 PC 赋成 r0 —— 这也是跳转
    ldr pc, [sp], #4 ; 从栈里弹出返回地址 —— 函数返回的经典写法

所有跳转指令，最终都落到一件事：修改 PC。ARM 的 b 指令编码里没有绝对地址，只有一个 24 位有符号偏移（单位是指令，即 4 字节）：

目标地址 = 当前指令地址 + 8 + (偏移 × 4)

那个 +8 就是本课标题里的怪现象：因为译码/执行时 PC 已经前进了两条指令的距离（三级流水）。所以汇编器算偏移时，减的是「当前 + 8」。

4. 为什么读 PC 得到 PC+8

经典 ARM（ARM7/9）三级流水：取指、译码、执行。当一条指令处于「执行」阶段时，流水线里已经有两条更年轻的指令处于「译码」和「取指」——它们的地址分别是 PC+4 和 PC+8。为了让「读 PC」在流水线里有一致的语义，ARM 规定：读 PC 得到的是「当前指令地址 + 8」。

这个设计的实际后果：位置无关代码（PIC）可以用 adr 指令基于 PC 取地址，这样同一段代码加载到任何地址都能跑。Linux 内核与库大量依赖这个特性。

5. 实验：从机器码里读出跳转偏移

// 示例 C
int f(int x) { if (x > 0) return 1; return -1; }

// gcc -O2 -S 会生成类似：
//   cmp r0, #0
//   ble .L2
//   mov r0, #1
//   bx  lr
// .L2:
//   mvn r0, #0
//   bx  lr

objdump -d a.out | grep -A6 "<f>:"

然后手工验证：把 ble 那行的机器码取出来，低 24 位是偏移，按「当前 + 8 + 偏移×4」算一遍，看是否正好等于 .L2 的地址。算对一次，你对「跳转」的理解就永久固化了。

# 快速验证（Bash / Ubuntu）
objdump -d a.out | sed -n '/<f>:/,/^$/p'

6. 三条常见误解

7. 自测与动手

1

PC 自增发生在取指后还是执行后？为什么重要？

看答案

取指后（每条指令取完就 +4）。这决定了「执行阶段读 PC」得到的是超前值，也是 +8 现象的由来。

2

ARM 的 b 指令偏移为何以 4 字节为单位？

看答案

指令 4 字节对齐，地址低 2 位永远为 0，省掉这两位可以把 24 位偏移撑到 ±32MB 范围。

3

bl 与 b 的区别？返回怎么实现？

看答案

bl 额外把「下一条指令地址」写入 LR（r14）；返回用 bx lr 或 mov pc, lr。

4

为什么位置无关代码能加载到任意地址？

看答案

因为它用 PC 相对寻址（adr、PC-relative ldr）而不是绝对地址，代码与数据的相对距离不变，整体平移不影响。

5

中断发生时，硬件保存的「返回地址」是什么？

看答案

被中断指令之后的那条（有些架构是当前指令，ARM 需要在处理里 sub lr, lr, #4 修正）——这是第 30 课的重点细节。

  1. 写一个带 if 的小函数，gcc -O2 -S 看生成的跳转。
  2. objdump -d 取一条 b 的机器码，手工算偏移并验证。
  3. 写汇编用 adr r0, label 取地址，打印出来，确认它是 PC 相对。
  4. 故意在函数里 mov pc, lr 返回，观察与 bx lr 的区别（Thumb 模式下会出错）。
