存储层次

CPU 跑一条指令 1 纳秒，去 DDR 取一次数据要几十纳秒。如果每次都等 DDR，528MHz 的 CPU 实际效率只剩几十兆。解法是「阶梯」：越快越小越贵，层层缓存。这一课的数字，你以后调性能时会反复用到。

★ 一读 纯读约 1 小时 左侧是本卷目录 理论为主 · 实作可跳

这一课要回答的问题

① 为什么不能只用寄存器？② 为什么不能只用 DRAM？③ SRAM 与 DRAM 差在哪？④ i.MX6ULL 的层次具体是什么？⑤ 一次 Cache 未命中到底损失多少？

1. 五种存储的物理差异

类型单元结构延迟成本/bit用途
寄存器触发器，6 个管子1 拍极高CPU 内部
SRAM6 管锁存2~10 拍高Cache、片上 OCRAM
DRAM1 管 + 电容，需刷新30~100 拍低主存
NOR Flash浮栅，可随机读微秒中代码存储（XIP）
NAND / eMMC / SD块访问毫秒最低大容量存储

关键差异是「每 bit 用几个管子」：SRAM 6 个，DRAM 1 个 + 一个电容。同样面积 DRAM 能装 6 倍以上。这就是「内存大但慢」的物理解释，不是工程偷懒。

2. i.MX6ULL 的具体层次

层规格组织
L1 D-Cache32KB4 路组相联，32 字节/行
L1 I-Cache32KB与 D 分离（改良哈佛）
L2 Cache128KB8 路，统一（I 与 D 共享）
片上 OCRAM128KB物理连续，常做 DMA 缓冲
DDR3512MB经 DDR 控制器，支持突发传输

OCRAM 这块 128KB 值得记住：物理上离 CPU 近，延迟远低于 DDR。很多驱动把 DMA 缓冲区、启动阶段的栈放这里，为的就是避开 DDR 的延迟与缓存一致性麻烦。

3. 为什么按「行」搬，不按字节搬

Cache 一次搬 32 或 64 字节，因为 DRAM 打开一行之后，连续读很多列几乎不额外花时间（突发传输）。一次搬 32 字节，比搬 1 字节 × 32 次便宜得多。

直接推出一个工程事实：顺序访问数组远快于随机访问。你读 a[0] 时，a[0..7] 已经全进了 Cache（int 4 字节、行 32 字节）。这就是第 22 课「局部性」的物理基础。

4. 未命中的代价：算一次

# 528MHz，一周期 1.89ns；DDR 延迟 80 周期 = 151ns
# 一次未命中相当于浪费多少条指令机会？
151 / 1.89 ≈ 80 条

# 若一个循环每 10 条指令就有一次未命中：
# 有效 CPI = (10 + 80) / 10 = 9
# 也就是 90% 的时间在等内存

这个粗算就是「内存墙」：过去三十年，CPU 与内存的速度差距拉大了上千倍，Cache 是唯一有效的缓解手段。也解释了为什么「局部性好」常比「指令少」更影响实测性能。

5. 实验：量出你自己机器的台阶

lscpu | grep -i cache
getconf -a | grep CACHE

# 访问不同大小的数组，测每次访问的平均耗时
# 固定访问次数，数组从小到大（4KB → 64MB）
# 超过 L1 会跳一次，超过 L2 再跳，超过 L3 再跳
# 那些台阶的位置就是各级容量

# 板子上：
cat /proc/cpuinfo | grep -i cache
dmesg | grep -i "cache\|ocram"

把这条曲线画出来，你会看到明显的台阶。台阶的位置，就是这台机器的 L1/L2/L3 容量。这是理解 Cache 最直观的实验，比背参数表有效得多。

6. 三条常见误解

7. 自测与动手

1

为什么寄存器不能做很大？

看答案

6 管/bit 的面积极高，且译码与布线复杂度随数量超线性上升；指令里也没有足够位宽去编码几百个寄存器。

2

SRAM 与 DRAM 的本质差别？

看答案

SRAM 用 6 管锁存、不需刷新、快但贵；DRAM 用 1 管 + 电容、需定时刷新、慢但便宜得多。

3

为什么 Cache 按行搬？

看答案

利用 DRAM 突发传输：一次打开行，连续列几乎免费；按行搬摊薄了开销。

4

一次 DDR 未命中在 528MHz 下约等于多少条指令？

看答案

按 80 周期、CPI≈1 算，约 80 条指令的执行机会。

5

OCRAM 什么时候比 DDR 更合适？

看答案

需要低延迟、确定性、或避开 Cache 一致性时：DMA 缓冲、中断上下文、启动早期 DDR 未初始化时。

  1. 在 Ubuntu 上用大小递增的数组做访问测试，画出台阶曲线。
  2. 在板子上查 L1/L2 参数，与你测出的台阶核对。
  3. 写两段代码：一段顺序遍历、一段跨步 32 字节，比较耗时。
  4. 算一下你的程序里「一次未命中」在业务上意味着多少延迟。
