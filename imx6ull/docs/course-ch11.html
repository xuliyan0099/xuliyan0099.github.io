根文件系统构建

内核本身不会给你一个 shell。它做完初始化后会去执行根文件系统里的 /sbin/init，没有这个文件就直接 panic。这一章教你把「/」造出来。

★ 一读 纯读约 14 小时 左侧是本卷目录 理论为主 · 实作可跳

本章目标

① 知道根文件系统里最少要有哪些目录；② 用 BusyBox 手工做一个能启动的根文件系统；③ 会打包成 ext4 镜像；④ 会用 Buildroot 一键构建；⑤ 能看懂 No working init found 这类报错。

11.1 最小根文件系统长什么样

目录必须吗放什么
/bin /sbin必须命令与 init（BusyBox 的软链接）
/etc必须inittab、fstab、启动脚本
/dev必须console、null 两个节点，少了就 panic
/proc /sys必须（空目录即可）内核运行时挂载点
/lib动态链接时必须libc、ld-linux
/usr建议更多程序与库
/tmp /var /root建议临时文件、日志、root 家目录
内核最后一步 挂载根文件系统 → 执行 /sbin/init（或 /etc/init.d/rcS）→ 这个进程成为 1 号进程，再由它启动 shell 和其他服务。根文件系统的作用就是提供这个「起点程序」和它需要的所有东西。

11.2 用 BusyBox 手工搭一套

BusyBox 把几百个命令塞进一个可执行文件，通过软链接扮演 ls、cp、sh……体积只有几百 KB，是嵌入式根文件系统的标准件。

$ wget https://busybox.net/downloads/busybox-1.36.1.tar.bz2
$ tar -xjf busybox-1.36.1.tar.bz2 && cd busybox-1.36.1

# 配置：交叉编译 + 静态链接
$ make ARCH=arm CROSS_COMPILE=arm-linux-gnueabihf- menuconfig
# Settings → Build Options → [*] Build static binary (no shared libs)
# Installation Options → 确认安装路径

$ make -j4
$ make CONFIG_PREFIX=/home/ubuntu/rootfs install

装完 /home/ubuntu/rootfs 下会得到 bin、sbin、usr 三个目录和一堆软链接。

补齐 /dev 下的两个节点

$ sudo mknod /home/ubuntu/rootfs/dev/console c 5 1
$ sudo mknod /home/ubuntu/rootfs/dev/null    c 1 3
$ sudo chmod 666 /home/ubuntu/rootfs/dev/console /home/ubuntu/rootfs/dev/null

这两个设备节点是手工建的，因为此时还没有 udev 帮你自动创建。缺了它们，内核打印完 Freeing unused kernel memory 就会 panic。

三个配置文件

/etc/inittab（BusyBox 的 init 靠它决定启动流程）：

::sysinit:/etc/init.d/rcS
::askfirst:-/bin/sh
::ctrlaltdel:/sbin/reboot
::restart:/sbin/init

/etc/init.d/rcS（开机脚本，必须可执行）：

#!/bin/sh
mount -a
mkdir -p /tmp /var
echo "rootfs ready"

/etc/fstab（配合 mount -a）：

proc   /proc  proc   defaults 0 0
sysfs  /sys   sysfs  defaults 0 0
tmpfs  /tmp   tmpfs  defaults 0 0
$ chmod +x /home/ubuntu/rootfs/etc/init.d/rcS

11.3 打包成镜像

# 方法一：做成 ext4 镜像文件（大小按需，示例 512MB）
$ dd if=/dev/zero of=rootfs.ext4 bs=1M count=512
$ mkfs.ext4 rootfs.ext4
$ mkdir -p /mnt/rootfs && sudo mount rootfs.ext4 /mnt/rootfs
$ sudo cp -a /home/ubuntu/rootfs/* /mnt/rootfs/
$ sudo umount /mnt/rootfs

# 方法二：直接写进 SD 卡的某个分区
$ sudo dd if=rootfs.ext4 of=/dev/sdb2 bs=1M status=progress
dd 的目标设备千万别写错 /dev/sdb 是你的 U 盘还是系统盘，写错就是整机数据没了。执行前先 lsblk 看清楚，确认容量对得上。

11.4 Buildroot：一键构建整套系统

手工做根文件系统能让你理解每个文件为什么存在，但做产品时没人这么干。Buildroot 用一份配置，自动帮你编工具链、内核、BusyBox、各种库，最后吐出完整镜像。

$ wget https://buildroot.org/downloads/buildroot-2024.02.tar.gz
$ tar -zxf buildroot-2024.02.tar.gz && cd buildroot-2024.02

$ make menuconfig
# Target Architecture → ARM (little endian)
# Target CPU → cortex-A7, 浮点 VFPv4 / hard
# Toolchain → 用 Buildroot 自己编 or 外部工具链
# System configuration → 主机名、root 密码、串口 console
# Target packages → 勾选你要的库（如 openssh、gdb server）

$ make -j8

产物在 output/images/：zImage、*.dtb、rootfs.ext4、rootfs.tar。三件套一次齐全。

先跑通默认配置 不要一上来就改一百个选项。make menuconfig 里先选一个和你板子接近的 defconfig（如 freescale_imx6ullevk_defconfig 一类），编出能跑的系统，再逐个改。一次改一个变量，出问题才知道是谁的问题。

11.5 用 NFS 根文件系统（开发期标配）

# PC 上导出
$ sudo vim /etc/exports
/home/ubuntu/rootfs 192.168.1.0/24(rw,sync,no_subtree_check,no_root_squash)
$ sudo exportfs -ra

# U-Boot 里改 bootargs
=> setenv bootargs console=ttymxc0,115200 root=/dev/nfs rw \
nfsroot=192.168.1.100:/home/ubuntu/rootfs,nfsvers=3 \
ip=192.168.1.101:192.168.1.100:192.168.1.1:255.255.255.0::eth0:off
=> saveenv

此后在 PC 上改根文件系统里的任何文件，板子重启就生效，不用重新打包。写驱动、调应用时全靠这个。

11.6 三种典型 panic 怎么修

报错原因修法
No working init found根分区没挂上，或里面没有 /sbin/init检查 bootargs 的 root=、分区格式、init 是否存在且可执行
VFS: Unable to mount root fs内核没编进对应文件系统驱动，或设备名写错menuconfig 里确认 ext4/nfs 已编入内核；核对 mmcblkXpY
卡在 Freeing unused kernel memory 后无输出/dev/console 缺失，或 inittab 写错补 console 节点，检查 inittab 语法

11.7 动手任务

  • 用 BusyBox 手工做一套根文件系统，补齐 /dev 两个节点与三个配置文件。
  • 打包成 ext4 镜像，烧到 SD 卡或 eMMC，让板子从它启动，看到 shell 提示符。
  • 用 NFS 方式再启动一次，对比「改文件是否要重新烧写」的差别。
  • 故意删掉 /sbin/init，看 panic 报错原文；再删 /dev/console 重复一次。
  • 用 Buildroot 编一套，记录产物清单和总耗时。
  • 在根文件系统里加一个自己的 hello 程序，开机自动运行。

11.8 验收标准

  • 能说出根文件系统里至少 6 个目录的作用
  • 能独立用 BusyBox 做出可启动的根文件系统
  • 知道 console/null 两个设备节点为什么要手工建
  • 会写 inittab、rcS、fstab 三个文件
  • 能打包 ext4 镜像并用 dd 写入存储设备
  • 会用 Buildroot 出一套完整镜像
  • 看到 No working init found 能立刻定位方向
