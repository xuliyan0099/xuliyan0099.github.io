搭好实验台

这一章结束时，你会有一台能远程登录的 Ubuntu，一个能看板子日志的串口，和一套能编译 ARM 代码的工具链。这是后面所有实验的地基。

★ 一读 纯读约 10 小时 左侧是本卷目录 理论为主 · 实作可跳

本章目标

① 装好 Ubuntu 22.04 虚拟机并换国内源；② 一次装齐后续 14 章要用到的工具；③ 从 Windows 用 SSH 登进虚拟机；④ 串口能收到板子（或任意串口设备）的打印；⑤ 学会打快照，敢折腾。

2.1 为什么一定要用虚拟机

你也可以装双系统，但对新手来说虚拟机有三个无法替代的好处：

弄坏能回滚

一条 rm -rf 敲错，双系统就重装。虚拟机拍个快照，30 秒回到昨天。

环境可复制

配好一台，复制三台。学 NFS、SSH 时正好需要「两台机器」。

不污染 Windows

交叉编译工具链、老版本 gcc、一堆依赖，全塞在虚拟磁盘里。

2.2 安装 Ubuntu 22.04

  • 装 VMware Workstation Player（免费）或 VirtualBox。
  • 下载 ubuntu-22.04-desktop-amd64.iso（约 4GB）。一定选 22.04 LTS，不要 24.04：很多板卡 BSP 和教程仍以 22.04/20.04 为准，老工具链在新系统上容易出兼容问题。
  • 新建虚拟机，分配 4 核 CPU、4–8GB 内存、50GB 磁盘（磁盘选「拆分成多个文件」）。内存 8GB 时编译内核更舒服；只有 8GB 物理内存就分 4GB，别让宿主机开始换页。
  • 安装时选「最小安装」也可以，但新手建议保留默认桌面，方便第一次熟悉系统；键盘布局、时区选上海。
  • 装完第一件事：打开终端，确认能联网。
$ ping -c 3 mirrors.tuna.tsinghua.edu.cn
装完先拍快照 VMware：虚拟机 → 快照 → 拍摄快照，命名「干净系统」。以后搞崩了直接回滚，比重装省两小时。

2.3 换国内源（必做，否则装包慢到怀疑人生）

Ubuntu 22.04 的代号是 jammy。官方源在国外，apt update 可能要十分钟。换成清华源：

# 备份原文件
$ sudo cp /etc/apt/sources.list /etc/apt/sources.list.bak

# 一键替换域名（保留原有路径结构）
$ sudo sed -i 's|http://.*archive.ubuntu.com|https://mirrors.tuna.tsinghua.edu.cn|g' /etc/apt/sources.list
$ sudo sed -i 's|http://.*security.ubuntu.com|https://mirrors.tuna.tsinghua.edu.cn|g' /etc/apt/sources.list

$ sudo apt update
$ sudo apt upgrade -y

如果你的 sources.list 里是 cn.archive.ubuntu.com 这种带地区前缀的写法，sed 可能替换不到，直接手动编辑更稳：

$ sudo vim /etc/apt/sources.list
# 把每行 http://xx.archive.ubuntu.com/ubuntu/ 改成：
# https://mirrors.tuna.tsinghua.edu.cn/ubuntu/
# 保存后执行：
$ sudo apt update
怎么判断换源成功 apt update 输出的 Get:1 行里出现 mirrors.tuna.tsinghua.edu.cn 就对了。如果报 404 Not Found，多半是版本代号写错（22.04 必须是 jammy）。

2.4 一次装齐 14 章要用的工具

别等用到再装。下面这条命令覆盖了后文的编译、串口、NFS、TFTP、设备树、内核配置：

$ sudo apt install -y \
    build-essential vim git curl wget \
    net-tools iproute2 openssh-server \
    nfs-kernel-server tftpd-hpa minicom \
    device-tree-compiler u-boot-tools \
    libncurses5-dev libncursesw5-dev bison flex libssl-dev bc \
    gdb-multiarch gcc-arm-linux-gnueabihf
包干什么用哪章用到
build-essentialgcc、make、libc 头文件，本地编译基础03 / 07
openssh-server让 Windows 能 ssh 进虚拟机02 / 06
nfs-kernel-server把 PC 目录共享给板子挂载06 / 08
tftpd-hpa板子从 PC 下载内核/设备树06 / 09
minicom命令行串口工具（Windows 侧用 MobaXterm）02 / 08
device-tree-compilerdtc，把 .dts 编译成 .dtb，也能反编译 .dtb10
u-boot-toolsmkimage，给内核加 U-Boot 头09
libncurses5-dev bison flex libssl-dev bc内核 menuconfig 与编译的依赖10
gdb-multiarch调试 ARM 程序 / 内核07 / 13
gcc-arm-linux-gnueabihfARM 交叉编译器（也可换成厂商自带工具链）07
关于交叉编译器版本 板卡厂商一般会提供配套工具链（如 gcc-linaro-4.9.4-arm-linux-gnueabihf）。编译 U-Boot 和内核时优先用厂商那一套，因为老版本内核源码对新版 gcc 常有报错。本章装的 apt 版只用来做第 7 章的入门练习。

2.5 网络模式：NAT 还是桥接

虚拟机要跟板子通信，这个选择很关键，选错了后面 NFS 一定连不上：

模式行为适合坑
NAT虚拟机借宿主机上网，IP 是 192.168.x.y 内网段只上网、只 ssh板子若直连 PC 网口，访问不到虚拟机
桥接虚拟机像一台独立设备接在同一个交换机上板子 + 虚拟机 + PC 同网段互访公司/校园网可能禁止，或 IP 冲突
仅主机只与宿主机通信做隔离实验上不了网

推荐做法：给虚拟机加两块网卡——网卡 1 用 NAT 专门上网，网卡 2 用桥接（或直接连着板子的那个物理网口）专门跟板子通信。这样能上网，也能连板子。

# 看 IP 与网卡名
$ ip addr
$ ip route

# 临时配静态 IP（重启失效，第 6 章讲永久配置）
$ sudo ip addr add 192.168.1.100/24 dev ens33
$ sudo ip link set ens33 up

2.6 从 Windows 登进虚拟机

为什么不直接在虚拟机窗口里敲？因为窗口里复制粘贴别扭、字体小、切换麻烦。SSH 上去之后，Windows Terminal 全屏，体验完全不一样。

# 虚拟机内：确认 ssh 服务在跑
$ sudo systemctl status ssh
$ ip addr show | grep "inet "

# Windows 端（Win10 以上自带 ssh 客户端）
# 假设虚拟机 IP 是 192.168.1.100
C:\> ssh ubuntu@192.168.1.100

每次输密码很烦，配免密（后面写脚本、scp 传文件都靠它）：

# Windows 端生成密钥（一路回车）
C:\> ssh-keygen -t rsa -b 4096

# 把公钥推到虚拟机
C:\> type %USERPROFILE%\.ssh\id_rsa.pub | ssh ubuntu@192.168.1.100 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"

# 之后免密登录
C:\> ssh ubuntu@192.168.1.100
虚拟机 IP 老是变？ 第 6 章会给它配静态 IP。临时办法：在 VMware 里把虚拟网络编辑器中的 DHCP 租约时间调长，或在 Ubuntu 里用 nmcli 固定地址。

2.7 串口：板子唯一的生命线

板子启动到一半挂掉，网还没起来，SSH 是连不上的。这时唯一能告诉你「死在哪一步」的，就是串口打印。

接线（三根线，接错就收不到数据）

板子USB 转串口模块说明
GNDGND必须接，信号才有共同参考电平
TX（板子发）RX交叉接：发对收
RX（板子收）TX交叉接

板子的调试串口一般是 UART1，参数 115200、8 数据位、无校验、1 停止位、无流控（记作 115200 8N1）。这是 i.MX 系列 BSP 默认值，改过的话以厂商文档为准。

Windows 端用 MobaXterm

  1. 设备管理器里确认 USB 转串口对应哪个 COM 口（如 COM3）。
  2. MobaXterm → Session → Serial → 选 COM3，波特率 115200，8N1，无流控。
  3. 打开会话，板子上电，应该能看到一堆启动日志刷出来。看不到就换 TX/RX，或换个 USB 口。

Linux 端用 minicom

# 插入 USB 转串口后查看设备名
$ dmesg | tail -20
$ ls -l /dev/ttyUSB*

# 把自己加进 dialout 组，否则没权限打开串口
$ sudo usermod -aG dialout $USER
# 重新登录生效

# 直接指定参数打开
$ minicom -D /dev/ttyUSB0 -b 115200
串口打不出东西的排查顺序 ① 线是不是交叉接的 ② GND 接了吗 ③ 波特率对不对（试 115200 / 57600 / 38400）④ COM 口选错没 ⑤ 板子到底上电没（灯亮不亮）。这五步能解决 90% 的「串口没输出」。

2.8 动手任务

  • 装完 Ubuntu，拍一张快照，命名为「干净系统 + 换源完成」。
  • 从 Windows 用 SSH 免密登录进虚拟机，并执行 htop 或 top 看资源占用。
  • 执行 arm-linux-gnueabihf-gcc -v，把输出的 gcc 版本记进笔记。
  • 插上 USB 转串口，在 Windows 和 Ubuntu 各打开一次串口（Ubuntu 侧把 /dev/ttyUSB0 打开后敲回车，看有没有回显）。
  • 故意做坏一次：把 sources.list 改乱，执行 apt update 看报错长什么样，再从备份恢复。

2.9 验收标准

  • apt update 走的是国内源，输出里没有超时
  • Windows 能免密 ssh 进虚拟机，且能在里面正常跑 ls、vim
  • 能说出 NAT 和桥接的区别，以及为什么板子实验需要桥接或独立网口
  • 串口工具能打开设备，参数是 115200 8N1
  • 有至少一张可用快照，知道怎么回滚
