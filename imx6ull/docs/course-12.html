卷 01·机器与指令·第 13 篇

一条指令的完整旅程

这一课只做一件事：把 ldr r0, [r1, #4] 这一条指令，从内存里的 4 个字节，走到 r0 里的 4 个字节，逐拍拆开。你会看清每个阶段谁在动作、哪些控制信号被拉高、数据走了哪几条总线。看完这一课，反汇编不再是天书，而是一串你能复述的动作。

★ 一读 纯读约 1 小时 左侧是本卷目录 理论为主 · 实作可跳

这一课要回答的问题

① 五个阶段分别做什么？② 控制信号是谁发的，什么时候发？③ 为什么 ldr 的 EX 阶段只是算地址？④ 单周期、多周期、流水线三种组织方式差在哪？⑤ 一条指令在真实 CPU 里到底花几个周期？

1. 具体走一遍：给它填上真实数字

假设：r1 = 0x8000_1000，内存 0x8000_1004 处存着 0x1234_5678，指令本身在 0x8000_2000。

拍阶段动作此刻的值
T1IF读 0x8000_2000 的 32 位到 IR；PC → 0x8000_2004IR = E5910004
T2ID拆位段：opcode=load、Rn=r1、Rd=r0、imm=4；读 r1r1 = 0x8000_1000
T3EXALU 做 r1 + 4地址 = 0x8000_1004
T4MEM按地址读 4 字节（小端：低字节在前）数据 = 0x1234_5678
T5WB写入 r0（受 RegWrite 控制）r0 = 0x1234_5678

把 E5910004 拆开：1110 0101 1001 0001 0000 0000 0000 0100。cond=1110（无条件执行）、bits27:26=01（单数据传送类）、bits25:20 = 1 1 0 1 0 1 依次是 P=1（前索引）、U=1（加偏移）、B=0（按字访问）、W=0（不写回基址）、L=1（load，读内存）、I 的位在 bit25=0（偏移是立即数，来自索引寄存器，不是移位寄存器）。Rn=0001（r1）、Rd=0000（r0）、offset=0x004。第 14 课会把这 32 位完整拆给你看。

关键洞察：CPU 没有「理解」这条指令，它只是照着控制表把一堆开关拨到某个组合。所谓「指令集」，就是这张表的全部行。

3. 三种组织方式：单周期 / 多周期 / 流水线

方式做法一条指令耗时问题
单周期一拍走完五个阶段1 个长周期周期必须按最慢指令（如访存）定，其它指令都在浪费
多周期每个阶段一拍3~5 拍硬件复用省面积，但吞吐低
流水线五条指令各占一个阶段，同时推进理想 1 拍/条有冒险（数据、控制、结构），要旁路与预测

Cortex-A7 是 8~10 级流水、双发射（一个周期可以启动两条指令）。i.MX6ULL 上跑 Linux 时，你看到的「528MHz」就是流水线节拍的频率。

4. 与 Linux 的接缝：readl 就是一条 ldr

// 内核里的 readl() 最终就是一条 ldr（或 ldr + 屏障）
static inline u32 readl(const volatile void __iomem *addr) {
    u32 v;
    __asm__ volatile("ldr %0, [%1]" : "=r"(v) : "r"(addr) : "memory");
    return v;
}

// 你写的驱动：
val = readl(base + 0x04);   // 读 GPIO1_DR 寄存器
// 硬件上发生的事情，与上面表格里的五拍完全一致
// 唯一区别：地址落在「设备区」而不是 DDR，
// 所以总线会把它路由到 GPIO 控制器，而不是内存控制器

这条链路解释了嵌入式开发的很多现象：为什么 readl 比读普通变量慢（设备区通常不可缓存、要等外设响应）、为什么必须加 memory 屏障（防止编译器重排或 CPU 乱序）、为什么外设寄存器常要求「先写后读回」来保证生效。

5. 实验：数清一条指令的周期

// 在 Ubuntu 上，用 perf 看指令与周期
perf stat -e instructions,cycles ./a.out

// 在板子上（需要内核开启 perf）
perf stat -e cycles,instructions,branch-misses ./your_prog

// 用 objdump 找一条 ldr，确认它的偏移字段
arm-linux-gnueabihf-objdump -d your.o | grep ldr

如果 instructions / cycles 接近 1.0，说明流水线吃得比较饱；如果远小于 1，说明大量时间在等（缓存未命中或分支预测失败）。这个比值是理解「CPU 到底在忙什么」的第一个量化指标。

6. 三条常见误解

7. 自测与动手

1

ldr 的哪一阶段真正访问内存？为什么不是 EX？

看答案

MEM 阶段。EX 只做「基址 + 偏移」的地址计算，访存要单独一个阶段（因为存储器慢，需要独立时序）。

2

单周期设计最大的浪费是什么？

看答案

周期长度由最慢指令（通常是访存）决定，所有算逻指令都在等一个它们用不完的长周期。

3

译码器输出的是什么？

看答案

一组控制信号（RegWrite、MemRead、ALUSrc、ALUOp、MemWrite、Branch 等）的 0/1 组合，本质是查找表。

4

为什么 readl() 比读普通变量慢？

看答案

地址在设备区，不可缓存、需经过总线到外设、外设响应有等待周期；且限制编译器优化，必须真读。

5

CPI 大于 1 意味着什么？

看答案

平均每条指令花了多于一个周期，通常因为缓存未命中、分支惩罚、依赖停顿——是性能优化的主要靶点。

  1. 把 E5910004 按位段自己拆一遍，与第 14 课的对照表核验。
  2. 在板子上跑 perf stat，记录 CPI，换一个访存密集的程序再对比。
  3. 写一段 C，编译后找出其中的 ldr，标注它是「取变量」还是「取外设」。
  4. 把同一条指令写成单周期/多周期/流水的表格，自己画一遍时序。
