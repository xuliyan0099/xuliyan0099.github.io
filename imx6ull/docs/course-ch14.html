综合实战项目

前面 13 章的知识点，在这一章被拧成一个能演示的东西。目标不是做出多高级的产品，而是证明你能独立闭环：从改设备树到应用跑起来。

★ 一读 纯读约 16 小时 左侧是本卷目录 理论为主 · 实作可跳

项目：一块能自检、能上报的板子

板子上电后自动启动自己的服务，LED 按心跳闪烁；按键按下时记录事件并改变 LED 状态；程序把运行日志写进文件；网络通则定时把状态发到 PC，网络断则本地缓存。

14.2 八个步骤，按顺序做

  1. 画硬件连接图：哪个 GPIO 接 LED、哪个接按键、有效电平是什么。翻原理图，别猜。把引脚号、bank、offset 写在纸上。
  2. 先不写驱动，用 sysfs 验证硬件：如果内核已有 gpio-leds 节点，直接 echo 1 > /sys/class/leds/xxx/brightness。灯亮 = 硬件和引脚配置都对，这一步排除了 50% 的变量。
  3. 改设备树：加 pinctrl 组、加自己的节点、compatible 取一个独一无二的名字。编 dtbs，启动确认 /proc/device-tree 里能看到你的节点。
  4. 写驱动：platform_driver + probe，先只打印一行 dev_info(&pdev->dev, "probed\n")，确认能匹配上，再往里加 GPIO 和字符设备。
  5. 写应用：先跑通 open → write → LED 变化，再加按键读取和心跳逻辑。每加一个功能就测一次，别一次写完再调。
  6. 做开机自启：systemd unit 指向你的应用，enable --now，重启验证。日志用 journalctl -u 看。
  7. 加网络上报：PC 上开一个 TCP 服务端（或用 nc -l），板子上定时发一行状态。断网时缓存到本地文件，恢复后补发。
  8. 做一次全流程复现：清空环境，从烧写开始，不看教程，把整套重新做一遍。做不出来的地方，就是你没真掌握的地方。

14.3 每一环的验证方法

阶段怎么算通过
设备树cat /proc/device-tree/你的节点/compatible 能看到字符串
驱动匹配dmesg 里有 probe 打印；/sys/bus/platform/drivers/名字/ 下有设备
设备节点ls -l /dev/yourdev 出现 c 开头的节点
GPIO 输出LED 实际亮灭，或万用表量到电平翻转
按键输入cat /dev/yourdev 能看到键值；/proc/interrupts 计数增长
开机自启断电重启后不登录也能跑；systemctl status 是 active
网络上报PC 端能收到；拔网线后本地日志继续增长

14.4 最容易翻车的五个点

引脚被占用

设备树里原生 gpio-leds 已经用了同一个脚，你的 gpio_request 必然失败。先 disable 原生节点。

compatible 写错

大小写、厂商前缀、逗号，差一个字符就不匹配，且没有任何报错。

pinctrl 没配

寄存器写了，但引脚还复用成别的功能，电平根本不出去。

开机时序

服务在网络起来之前启动，连不上对端。unit 里加 After=network-online.target 并重试。

日志写满存储

eMMC 只有几 GB，日志无轮转会写死系统。按大小或按天轮转。

只看软件不看电

怀疑代码之前，先用万用表量引脚。硬件问题代码永远修不好。

14.5 交付物清单

  • 一份 dts 修改前后对比（哪几行加了什么）
  • 驱动源码 + Makefile，能一条 make 编出来
  • 应用源码 + Makefile，交叉编译产物能在板子上跑
  • systemd unit 文件或启动脚本
  • 一份可复现的操作笔记：从烧写到验证的命令序列
  • 一份踩坑记录：每个问题、报错原文、最终解法

14.6 做完之后往哪走

这套东西做完，你已经具备了「能独立开发一个嵌入式 Linux 小项目」的完整能力。往下走有三个方向，选一个深入，别同时开三条线：

方向下一步学什么
驱动深入中断与并发（自旋锁/互斥量）、I2C/SPI 子系统、input 子系统、DMA、电源管理
系统深入内核启动流程源码、内存管理、设备模型（bus/device/driver）、Yocto/Buildroot 定制、OTA 升级
应用与产品网络编程与协议、Qt/LVGL 界面、多线程、看门狗、可靠性设计、量产测试
最后一条建议 不要等「学完」再动手做东西。你现在就可以拿一块板子，从点亮一个 LED 开始，一路上把每次卡住的地方记下来。那些卡点，才是你真正学到的东西；顺利跑通的部分，只是验证了教程没写错。
