复盘的四个问题

① 一条 C 语句怎么变成电平变化？② 一次按键怎么变成屏幕上的字符？③ 一个进程切换时到底发生了什么？④ 板子不启动你会按什么顺序查？

1. 十条一句话结论

  1. 一切从开关开始：CPU 是几亿个可控开关的组合，没有魔法，只有门与线。
  2. 反相是免费的：所以 NAND 比 AND 便宜，所以「用与非门搭出一切」成立。
  3. 加法器是心脏：减法是加补码，比较是做减法看标志，地址计算也是加法。
  4. 记忆需要时钟：没有触发器就没有状态；时序违例会随机出错，而不是稳定错。
  5. PC 就是手指：顺序执行是默认，跳转就是给 PC 赋值，函数调用额外存 LR。
  6. 流水线换吞吐：五条指令同时在路上，代价是三个冒险；load-use 只能停。
  7. 内存墙是主矛盾：一次未命中等于几十条指令的时间，Cache 与局部性是唯一杠杆。
  8. 地址是翻译出来的：虚拟地址只是编号，MMU 决定它落到哪、能不能写、能不能执行。
  9. 内核就在管四件事：谁用 CPU（调度）、谁能用哪块内存（页表）、谁在打断（中断）、怎么访问设备（驱动）。
  10. 一切皆文件：把设备、管道、网络都做成 file_operations，是 Linux 最成功的抽象。

IF 取指 → ID 译码读寄存器 → EX 算 → MEM（无）→ WB 写回；有 S 位时顺带更新 N/Z/C/V。

2

为什么 load-use 冒险必须停一拍？

参考

load 的数据在 MEM 末才拿到，紧跟的指令此时已进 EX，时间上倒挂，旁路无法解决。

3

进程切换的大头开销在哪？

参考

换页表后的 TLB 与 Cache 冷启动，而不是寄存器保存本身。

4

板子「完全无输出」，你的前五步？

参考

电源电压 → 晶振 → 复位电平 → 启动引脚 → 串口接线，最后才怀疑镜像。

5

用一句话说明「为什么 Cache 有效」。

参考

因为程序的访问有时间和空间局部性，把常用的搬到近处，绝大部分访问就不必等远内存。

  1. 把上面「按键到字符」的十一层，自己画一遍并标出每层的关键接口。
  2. 挑一条后续路线，写出两周的具体计划。
  3. 在板子上跑一次 perf stat，把 CPI 与未命中率记下来。

课程结束 这套课的价值不在「读完」，而在「能对上」。当你在某天调试一个 bug 时，脑子里能自动浮现「这是 Cache 冲突」「这是 load-use」「这是 TLB 没刷」——那这门课就真正生效了。
