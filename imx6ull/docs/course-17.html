函数调用与 ABI

函数调用看起来是「跳过去再跳回来」，但参数怎么传、返回地址存哪、哪些寄存器能随便改、局部变量放哪——这些都要有一份约定。ARM Linux 用 AAPCS，同一套规则贯穿用户态程序、内核、汇编代码。这一课讲清它，你就能看懂任何一份崩溃栈。

★ 一读 纯读约 1 小时 左侧是本卷目录 理论为主 · 实作可跳

2. 一次调用的完整动作

; caller: 调用 func(a, b, c, d, e)
    mov  r0, a
    mov  r1, b
    mov  r2, c
    mov  r3, d
    push {r0-r3}        ; 也可只压 e（第 5 个参数），保持 8 字节对齐
    str  e, [sp, #-4]!  ; 第 5 个参数入栈
    bl   func           ; 跳并保存返回地址到 lr
    add  sp, sp, #8     ; 回收参数空间

; callee: func 开头
func:
    push {r4-r11, lr}   ; 保存 callee-saved 与返回地址
    sub  sp, sp, #32    ; 腾出局部变量空间
    ...                 ; 函数体
    mov  r0, result     ; 返回值放 r0
    add  sp, sp, #32
    pop  {r4-r11, pc}   ; 恢复并把返回地址直接装回 PC

注意最后一行：pop {..., pc} —— 把返回地址直接弹进 PC，等价于「恢复 + 返回」，一条指令完成两件事。这是 ARM 汇编里非常经典的收尾写法。

3. 叶子函数优化：不建帧

如果一个函数不再调用别人（叶子函数）、且局部变量少，它完全可以不建栈帧：

int add3(int a, int b, int c) { return a + b + c; }

; 编译结果（无栈操作！）
add3:
    add r0, r0, r1
    add r0, r0, r2
    bx  lr

三条指令、零内存访问。这是编译器最有效的优化之一。反过来说：如果你在崩溃栈里看到一个函数没有帧，不代表它没执行，只是它太简单。

4. 崩溃栈是怎么回溯的

两种方式：

  • 帧指针回溯：每个帧开头存着「上一帧的 fp」和「返回地址」，沿着 fp 链一路往上走。gcc -fno-omit-frame-pointer 保证这一点，代价是占一个寄存器、多几条指令。
  • 展开表（unwind table）：编译器生成 .ARM.exidx 段，记录「在某个 PC 处，栈上哪些位置存着哪些寄存器」。gcc -funwind-tables（默认开启）。这种方式不占寄存器，但需要额外查表。

内核的 panic() 打印调用栈、perf 采样火焰图，用的都是第二种。你在嵌入式里看到「栈回溯只有两级就断了」，通常是因为编译时去掉了 unwind 信息。

5. 与 Linux 的接缝：内核栈只有 8KB

// 内核栈很小（ARM 上通常 8KB，THREAD_SIZE）
// 所以内核代码绝不能放大数组：
void bad(void) {
    char buf[4096];   // 危险！加上调用链很容易栈溢出
}

// 正确做法：用 kmalloc / vmalloc
void good(void) {
    char *buf = kmalloc(4096, GFP_KERNEL);
    ...
    kfree(buf);
}

// 查看当前栈使用：
cat /proc//stack        // 内核栈回溯
echo t > /proc/sysrq-trigger // 打印所有任务栈

这个限制解释了内核编程里一个反复出现的规范：大缓冲区一律动态分配。用户态进程的栈有 8MB（可调），内核栈只有 8KB——600 倍的差距。

6. 实验：看清一次调用的栈

// gdb 里最实用的三条
// 1) 看帧
(gdb) bt
(gdb) info frame
// 2) 看参数寄存器
(gdb) info registers r0 r1 r2 r3 sp lr pc
// 3) 断在函数入口，看栈刚建好时的样子
(gdb) break func
(gdb) run
(gdb) x/16wx $sp

在板子上可以用 gdb-multiarch + gdbserver 做同样的事。看一次真实的栈内容，比读十页文档有用。

8. 自测与动手

1

第 5 个参数怎么传？为什么？

看答案

压栈。因为只有 r0-r3 四个参数寄存器，多出的按顺序放栈上，且要保持 8 字节对齐。

2

callee-saved 有哪几个？为什么必须保存？

看答案

r4-r11（以及 sp）。调用者可能正用它们存着重要值，callee 若要用必须先存、返回前恢复。

3

为什么函数开头要 push {lr}？

看答案

bl 会覆盖 lr；若本函数还要调用别人，就必须先把 lr 存起来，返回前恢复。

4

pop {..., pc} 为什么能返回？

看答案

它把栈里的返回地址直接装进 PC，等于「恢复现场 + 跳回」，一条指令完成。

5

内核栈为什么不能放大数组？

看答案

内核栈通常只有 8KB，一个 4KB 数组加调用链就会溢出；应使用 kmalloc 等动态分配。

  1. 写一个 5 参数的函数，-O2 -S 看第 5 个参数是否在栈上。
  2. 用 gdb 断在函数入口，x/16wx $sp 找出保存的 lr。
  3. 编译时加 -fno-omit-frame-pointer，对比帧指针链。
  4. 写一个内核模块，故意用大数组，观察栈溢出或警告。
