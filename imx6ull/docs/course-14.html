机器码的位段

一条 ARM 指令永远是 32 位——不多不少。这 32 位里要塞进「什么操作、哪个寄存器、什么操作数、什么条件下执行」。这一课把 mov r0, #1 的机器码 E3A00001 逐位拆开，再讲那个让所有人第一次都看不懂的设计：立即数为什么只有 12 位，却要能表示 0xFF000000。

这一课要回答的问题

① 为什么 ARM 指令固定 32 位？② cond 字段为什么放在最高 4 位？③ 立即数只有 8 位，怎么表示 0xFF000000？④ load/store 与分支的位段长什么样？⑤ 为什么会有 movw/movt 这两条「补充」指令？

1. 固定长度：一个大胆的取舍

x86 的指令长度从 1 字节到 15 字节不等，译码器要靠「前缀 + 变长解码」一点点啃。ARM 选择固定 32 位（Thumb 是 16 位混合），好处：

  • 取指简单：地址永远 4 字节对齐，PC+4 就是下一条。
  • 译码快：所有字段位置固定，组合逻辑直接切。
  • 流水线友好：不用等「解码出长度」才知道下一条在哪。

代价：表达力不足。塞不进一个完整 32 位立即数、也塞不进一个完整 32 位地址——于是必须用「相对偏移」和「旋转编码」来补救。这两个补救方案，就是本课后半段的全部内容。

2. 立即数的旋转编码：8 位数据 + 4 位旋转

规则：立即数 = 8 位值，循环右移 (rot × 2) 位。rot 只有 4 位（0~15），所以移位量是 0,2,4,…,30。

试着手算：0xFF000000 能不能编码？0xFF 是 8 位值，循环右移 8 位 → 0xFF000000。可以！rot=4。所以 mov r0, #0xFF000000 是一条合法指令。

而 0x12345678 不行——它的比特分布不满足「8 位连续段 + 循环移位」的形式。这就是为什么编译器会生成：

movw r0, #0x5678      ; 低 16 位
movt r0, #0x1234      ; 高 16 位
; 两条指令拼出完整 32 位常量（movw/movt 是 ARMv6T2 起的新指令）

3. load/store 与分支的位段

; ldr r0, [r1, #4]  =  0xE5910004
; cond 1110 | 01 | I=0 P=1 U=1 B=0 W=0 L=1 | Rn=0001 | Rd=0000 | offset=0x004
;  └ 条件    └类 └───────────────┘  └基址┘  └目标┘  └偏移┘

; b label  =  0xEAxxxxxx
; cond 1110 | 1010 | 24 位有符号偏移（单位 4 字节）

; bl func  =  0xEBxxxxxx
; cond 1110 | 1011 | 24 位有符号偏移，同时写 LR

4. Thumb 与 Thumb-2：为什么还要 16 位

32 位指令虽然整齐，但代码密度差——同样的功能，x86 可能只占 3 字节，ARM 要 4 字节。对 Flash 只有几百 KB 的 MCU，这是真金白银的成本。

于是 ARM 推出 Thumb：16 位指令子集，只保留最常用的操作与寄存器（r0~r7）。代码密度提升约 30%，代价是指令能力受限。Thumb-2 再进一步，允许 16 位与 32 位混排。

i.MX6ULL 上跑 Linux 通常是 ARM 模式（性能优先），但很多 MCU（如 STM32）默认 Thumb。你在反汇编里看到 movs r0, #1（带 s、寄存器少）就可能是 Thumb。

5. 实验：手工拆一条指令

# 把机器码拆成位段（Python）
def split(w):
    print("cond  = %X" % ((w >> 28) & 0xF))
    print("27:26 = %X" % ((w >> 26) & 0x3))
    print("I     = %d" % ((w >> 25) & 1))
    print("opcode= %X" % ((w >> 21) & 0xF))
    print("S     = %d" % ((w >> 20) & 1))
    print("Rn    = r%d" % ((w >> 16) & 0xF))
    print("Rd    = r%d" % ((w >> 12) & 0xF))
    rot = (w >> 8) & 0xF
    imm = w & 0xFF
    val = ((imm >> (rot*2)) | (imm << (32 - rot*2))) & 0xFFFFFFFF if rot else imm
    print("rot=%d imm=%02X -> 立即数 0x%X" % (rot, imm, val))

split(0xE3A00001)   # mov r0, #1
split(0xE3A004FF)   # mov r0, #0xFF000000（rot=4, imm=0xFF）
split(0xE5910004)   # ldr r0, [r1, #4]（注意这条不是数据处理类，字段含义不同）

跑一遍，把输出与第 12 课的表格对照。能手工拆一条指令，你就有资格读 ARM 手册的指令编码章节了——那里全是这种表格。

6. 三条常见误解

7. 自测与动手

1

cond 字段为什么放在最高 4 位？

看答案

让所有指令（不管哪一类）都能用同一套条件执行机制——只要 cond 在固定位置，译码器不必先判断指令类型就能读到条件。

2

立即数能编码的最大范围是什么？举一个能编、一个不能编的值。

看答案

8 位值 × 16 种偶数位移。能编：0xFF000000（0xFF 移 8 位）；不能编：0x12345678（需 movw/movt）。

3

E3A00001 里哪一位决定「这是 mov 而不是 add」？

看答案

bits 24:21 的 opcode=1101 表示 MOV（ADD 是 0100）。

4

为什么 Thumb 在 MCU 上流行？

看答案

代码密度高约 30%，省 Flash 与带宽；代价是寄存器受限、部分操作要拆成两条。

5

为什么 b 用相对偏移而不是绝对地址？

看答案

24 位装不下 32 位地址；相对偏移让代码位置无关，且 24 位即可覆盖 ±32MB，对单文件足够。

  1. 跑 Python 拆分三个机器码，手工核对每一位。
  2. 自己写 mov r0, #0xFF000000 汇编，编译后看它是否只有一条指令。
  3. 写 r0 = 0x12345678，看编译器生成 movw/movt 还是常量池 ldr。
  4. 用 arm-linux-gnueabihf-objdump -d -M reg-names-std 反汇编一个小程序，标注每条的类别。
