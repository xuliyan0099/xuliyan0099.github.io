块设备与 eMMC：gendisk、请求队列与分区

◆ 一读 纯读约 4 小时 左侧是本卷目录 理论为主 · 实作可跳

字符设备是「一次搬一点」，块设备是「一次搬一块，而且要排队」。dd 之所以快，不是因为它聪明，而是因为它把请求交给了会合并、会排序的那一层。

这一篇从 gendisk 往下走到 eMMC 的 CMD17，顺便说清「分区」到底是谁的概念。

先玩一下：请求队列不是先进先出

下面是一个环形队列。点「写入一块」放请求进去，点「取出一块」模拟被驱动取走。真实的 blk-mq 还会在取出前做合并与排序，但先看清「环」这个结构。

队列满时上层会被阻塞（或返回 EAGAIN），这就是「磁盘忙」在软件侧的样子。SSD/eMMC 内部还有自己的队列，两层队列叠加，才出现「iostat 里 await 很高但 %util 不满」的现象。

一、从 bio 到硬件命令

这里的关键抽象是「扇区」：块设备的最小寻址单位通常是 512 字节，而文件系统的块是 4 KB。一个文件系统块 = 8 个扇区，所以一次读盘往往会看到「多块读」命令。

二、gendisk、分区与设备节点

对象代表什么你能看到
gendisk一整块磁盘（eMMC 的一个硬件分区也算一个）/dev/mmcblk0、/sys/block/mmcblk0
block_device / hd_struct分区/dev/mmcblk0p1
request_queue该盘的请求队列与调度参数/sys/block/mmcblk0/queue/
bio一次块 IO 的描述（运行时对象）只能在内核里看到

gendisk 里最重要的一张表是 fops（block_device_operations）：open、release、ioctl。注意没有 read/write——块设备的读写不走 file_operations 的常规路径，而是走 submit_bio。

注意 Boot0/Boot1 与 p1/p2 的区别：前两个是 eMMC 规范里的硬件分区（有自己的地址空间，用 mmcblk0boot0 访问），后面的分区是分区表里划出来的逻辑分区。把这两者混在一起，是量产时「刷了没起来」的常见原因。

三、eMMC 在底下发生了什么

eMMC 不是「一个会自己管理的闪存」，它是一颗带控制器的芯片。Linux 侧看到的是 mmc_host + mmc_card；驱动把块请求翻译成 MMC 命令：

  • CMD17 读单块、CMD18 读多块、CMD24/25 写单/多块；CMD12 停止多块传输。
  • 数据阶段由 DMA 搬运，命令与响应走命令线。i.MX6ULL 的 uSDHC 控制器同时支持 SD 与 eMMC。
  • 速度模式：默认 26 MHz 左右，高速 52 MHz，HS200/HS400 需要板级与时序支持；不确定就用 mmc extcsd read /dev/mmcblk0 看实际协商结果，别照抄别人的 dts。
误解：块设备自己有缓存，所以 read 不会真的读盘缓存主要在上面的页缓存（由文件系统管理）。O_DIRECT 绕过的是页缓存，不是设备缓存；eMMC 内部还有自己的缓存，你控制不了它。
误解：分区是硬件划的分区表只是磁盘开头的一段字节。改分区表（fdisk/parted）本质是改数据，之后内核重读（partprobe 或重启）才出现新节点。所以「分区表改了但设备节点没变」不是 bug。

动手（可选）：看清一次 IO 的形状

只在 🔧 实作模式展开PC 或板子均可。
  1. lsblk -o NAME,SIZE,TYPE,MOUNTPOINT 认磁盘、分区、挂载点三层。
  2. cat /sys/block/mmcblk0/queue/scheduler 看当前调度器；cat .../rotational 判断是否被当成机械盘。
  3. dd if=/dev/zero of=/tmp/t.bin bs=4k count=256 oflag=direct 与不加 oflag=direct 对比，看时间差。
  4. iostat -x 1 看 r/s、w/s、await、%util，再回到上面的队列图对照。

离开这一篇，你应该能

  • 说清 bio → request → 硬件命令这条链，以及页缓存在哪一层。
  • 区分 gendisk、分区、硬件 boot 分区三者。
  • 解释「队列满」在软件侧的表现，以及 O_DIRECT 到底绕过了什么。
