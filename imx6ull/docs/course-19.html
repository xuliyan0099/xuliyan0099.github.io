从源码到可执行

上一课停在 .o 文件。它是一个「还没定地址的机器码盒子」：里面的 call printf 不知道该跳哪，只能留个坑。链接器的工作就是把这些坑填上，再把散落的盒子拼成一块能装进内存的东西。这一课讲段、符号、重定位，以及嵌入式里那个绕不开的文件——链接脚本。

★ 一读 纯读约 1 小时 左侧是本卷目录 理论为主 · 实作可跳

这一课要回答的问题

① 段是什么，为什么代码和常量要分开？② 符号是什么，重定位在填什么？③ 静态库与动态库差在哪？④ 链接脚本在嵌入式里干什么？⑤ 为什么嵌入式常推荐 -static？

1. 段：不只是「分类」，是权限

段不是随便分的：它对应 MMU 的页权限（第 25 课）。.text 只读可执行，防止代码被改写（这也是 W^X 安全策略的基础）；.rodata 只读，防止常量被偷偷修改；.data/.bss 可读写但不可执行。

你在内核里看到的 __init 段（启动后内存被回收）、__user 标记，都是「段」这个概念在软件层的延伸。

2. 符号与重定位：先留坑，后填坑

; t.o 里的一段机器码
    bl  printf        ; 此时 printf 地址未知 → 留坑 + 重定位项

; readelf -r t.o 能看到：
;   偏移      类型            符号
;   0x00000008  R_ARM_CALL    printf

; 链接后（a.out）：
;   printf 被填成真实地址（静态链接）
;   或填成 PLT 表项（动态链接，第一次调用才解析）

3. PLT / GOT：动态库怎么「延迟绑定」

动态库的地址在编译时不知道。于是链接器造了两张表：

  • GOT（全局偏移表）：存放「真实函数地址」的数组，位于数据段，可写。
  • PLT（过程链接表）：每个外部函数一小段跳板，第一次调用时去查 GOT，若未解析就触发动态链接器填好。

这解释了「第一次调用慢一点」的现象，也解释了为什么攻击者喜欢改 GOT（GOT 覆写攻击），以及为什么现代系统开启 RELRO 把 GOT 变只读。

4. 链接脚本：嵌入式的地基

PC 上链接脚本由发行版管，你从不用看。但在嵌入式里，你必须自己写——因为你要决定「哪段代码放在 SRAM、哪段放在 DDR、栈顶在哪」。

/* 一个典型的 i.MX6ULL 裸机链接脚本片段 */
MEMORY
{
    DDR   (rwx) : ORIGIN = 0x80000000, LENGTH = 512M
    OCRAM (rwx) : ORIGIN = 0x00900000, LENGTH = 128K
}

SECTIONS
{
    .text : { *(.text*) } > DDR
    .rodata : { *(.rodata*) } > DDR
    .data : { *(.data*) } > DDR
    .bss : { *(.bss*) *(COMMON) } > DDR
    _stack_top = ORIGIN(DDR) + LENGTH(DDR);   /* 栈顶放最高地址 */
}

Uboot 的 u-boot.lds、内核的 vmlinux.lds 都是这个套路。看懂它们，你就知道「为什么内核启动代码必须放在最前面」——因为复位向量跳到的就是那儿。

5. 实验：读懂一个 ELF

readelf -h a.out        # 文件头：入口地址、架构、类型
readelf -S a.out        # 段表：每段的地址、大小、权限
readelf -l a.out        # 加载视图：怎么装进内存
readelf -s a.out        # 符号表
readelf -r a.out        # 重定位（.o 才有意义）
ldd a.out               # 依赖哪些动态库
size a.out              # text/data/bss 各多大

# 在板子上看内核：
readelf -h vmlinux | head
arm-linux-gnueabihf-objdump -d vmlinux | head -40

先看 size：它会给你 text、data、bss 三个数字。嵌入式里「Flash 够不够」看 text+data，「内存够不够」看 data+bss——这两个判断几乎每天都要做。

7. 自测与动手

1

为什么 .text 必须只读？

看答案

防止代码被意外或恶意改写（如缓冲区溢出改返回地址），MMU 页权限提供硬件级保护。

2

.bss 为什么不占文件体积？

看答案

它的初值全是 0，文件里只需记录长度；加载时由 loader（或启动代码）把这块内存清零。

3

动态链接的「延迟绑定」是什么意思？

看答案

第一次调用外部函数时才去解析真实地址并写入 GOT，避免启动时解析所有符号。

4

链接脚本里的 _stack_top 有什么用？

看答案

给启动代码一个符号，用来初始化 SP；栈从高地址向低地址长，所以取可用内存的最高地址。

5

嵌入式为什么常用 -static？

看答案

避免依赖目标机的 .so 与 glibc 版本，程序可独立运行、启动快，适合精简根文件系统。

  1. 对一个 C 程序跑 readelf -h/-S/-l，画出它的段布局。
  2. 用 size 比较 -static 与动态版本的三段大小。
  3. 写一个最小链接脚本，把程序放到指定地址，用 objdump 验证。
  4. 在板子上 ldd busybox，看它是静态还是动态。
