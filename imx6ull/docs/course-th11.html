0. 为什么需要时钟：从一根导线讲起

先把结论放这儿：时钟不是「给 CPU 供能」，而是给整个芯片一个统一节拍。没有节拍，几十亿个晶体管各按各的速度跑，谁也不知道别人算完了没有，结果就是一团随机错误。下面从最小的一块电路开始，一步一步讲到你熟悉的「528MHz」。

0.1 先看一个开关

芯片里最基本的元件是 MOS 管，它干的事只有一件：当开关。栅极给高电平，源漏导通；给低电平，断开。用几个这样的开关组合，就能做出「与门」「或门」「非门」：

门符号含义行为
非门（NOT）输入取反输入 1 出 0，输入 0 出 1
与门（AND）两个都 1 才出 1像两个串联的开关，都闭合才通电
或门（OR）有一个 1 就出 1像两个并联的开关，一个闭合就通电
异或（XOR）不同出 1，相同出 0加法器的核心，一位加法的「和」就是它

把这些门连起来，就能做加法器、比较器、译码器——也就是 CPU 里那些「运算」。

0.2 关键问题：信号不是瞬间到达的

假设你要算 (A AND B) OR (C AND D)。电路上电流要从输入端流到输出端，中间经过晶体管、导线，每一段都要花时间。这个时间叫传播延迟，单位是皮秒到纳秒。

环节典型延迟（40nm/28nm 工艺）
一个反相器约 20–40 ps
一个两输入与非门约 30–60 ps
一段片上导线（1mm）约 50–100 ps
一个 32 位加法器约 1–2 ns
一次 L1 cache 访问约 1–4 个周期

问题就在这儿：同一个信号，经过不同的路径，到达终点的时间不同。你算 (A AND B) OR (C AND D)，上面那路经过 2 个门，下面那路也 2 个门，还好；但如果写成 A OR (B AND (C OR D))，两条路径的门数就不一样了，一长一短，短的那路早就稳定了，长的那路还在变。此时你去读输出，读到的到底是什么？

算一笔：等多久才算「算完了」
假设最长路径 12 个门，每门 50ps → 600ps
最短路径 4 个门 → 200ps
在 200–600ps 之间去读结果：可能对，可能错，取决于温度、电压、工艺偏差
只有等到 600ps 之后再读，结果才确定正确
「600ps 之后」这个时刻，需要一个全芯片统一的计时方式来规定 —— 这就是时钟

0.3 时钟就是全队的鼓点

想象一百个人一起划船。如果各划各的，船原地打转；只要有一个人敲鼓，所有人「听到鼓点就一起划」，船才往前走。时钟就是这个鼓：它是一条不断在 0 和 1 之间翻转的信号，全芯片所有寄存器都盯着它的同一个沿。

时钟低→上升沿→时钟高→下降沿→再上升沿

为什么用「沿」而不是「高电平」？因为沿是一个瞬间，高电平是一段时间。用瞬间做「采纳」的动作，所有器件才可能对齐到同一个时刻；用一段时间做动作，谁先谁后又说不清了。

一个时钟周期里发生的事，固定成三段：

  1. 沿到来：所有寄存器同时把「此刻的输入」锁进来（这一瞬间叫采样）。
  2. 沿之后：组合逻辑开始算，信号在电路里传播、稳定。这段时间叫逻辑延迟。
  3. 下一个沿到来前：结果必须已经稳定，并且保持了足够长的时间，等着被下一个沿采走。

所以「时钟频率」的真正含义是：我给了组合逻辑多长时间去算完。频率 528MHz，周期就是 1.89ns；这 1.89ns 里，最慢的那条路径必须走完。

0.4 触发器：只在沿上「看一眼」

能实现「沿到来才采样」的电路叫触发器（flip-flop），最常见的是 D 触发器：一个数据输入 D、一个时钟输入 CLK、一个输出 Q。它的规则只有一句：时钟上升沿到来的一瞬间，把 D 的值抄到 Q；其他时间 Q 不动。

// D 触发器的行为（伪代码） on rising_edge(CLK): Q = D // 只在沿上抄一次 其余时间: 保持 Q 不变 // 输入怎么变都不影响输出

这条规则带来两个必须遵守的时间窗口，它们是数字电路里最重要的两个参数：

参数含义违例后果
建立时间 tsetup沿到来之前，D 必须已经稳定这么久采到正在变化的值 → 亚稳态
保持时间 thold沿到来之后，D 还要保持这么久不变采到的值被后一级抢走/改写 → 亚稳态

违例会怎样？触发器进入亚稳态：输出既不是 0 也不是 1，而是在中间电压上晃，晃多久不确定（可能几纳秒，也可能几毫秒）。后面接的逻辑看到这个「半高不高」的电平，可能这级判成 1、那级判成 0，整个系统进入不可预测状态。这就是为什么「时序不满足」不能靠重试解决——它是物理层面的不确定。

一句话记住 时钟的作用不是「让电跑起来」，而是规定「什么时候可以认为信号已经算完」。所有数字电路的可靠性，都建立在这条约定上。

0.5 为什么频率不能无限提高

既然周期越短算得越快，那把 24MHz 直接翻到 5GHz 不就行了？不行，有三个硬约束，一个比一个狠。

约束一：最慢那条路径就那么多延迟。

算一笔：一条关键路径决定最高频率
某段逻辑（例如一次 32 位加法 + 选择器）最长路径 = 3.0ns
触发器开销（建立时间 + 时钟到输出）≈ 0.3ns
所以周期下限 ≈ 3.3ns → 最高频率 ≈ 300MHz
想跑到 528MHz（周期 1.89ns），就必须把这段逻辑拆成两级流水线，每级 1.6ns 左右
这就是「流水线」存在的唯一理由：不是为了炫技，是为了把长路径切短

约束二：频率越高，功耗越大，而且是超线性。数字电路动态功耗的公式是

P = C × V2 × f × α（C 是节点电容、V 是电压、f 是频率、α 是每周期翻转概率）

其中 C 是节点电容、V 是电压、f 是频率、α 是翻转率。频率翻倍，功耗就翻倍；更麻烦的是，频率高了电压还得往上提（否则电路跑不动），电压又进平方项——528MHz 的功耗可能是一个 264MHz 系统的三倍以上。

约束三：热量出不去。功耗变成热，封装散热能力有限。温度一高，晶体管更慢、漏电更大，形成恶性循环（热失控）。所以嵌入式芯片的「标称主频」往往是在某个温度与散热条件下的承诺，不是物理极限。

这三条约束解释了 i.MX6ULL 为什么是 528MHz 它是 28nm 工艺、面向工业级温度范围（−40~105℃）、无风扇被动散热。厂商要保证在最坏工艺角、最高温度下仍然满足时序，所以频率不能定得太激进。同一颗芯片换到消费级温度范围，往往能跑更高。

0.6 为什么一个芯片需要几十路时钟

如果全芯片只有一个时钟，会发生两件荒唐事：

  1. 浪费：I2C 只需要 100kHz，你却给它 528MHz，它的分频器要数 5280 次才出一个周期，功耗白白烧掉。
  2. 做不到：USB 要求 480MHz 且精度 ±500ppm，音频要求低抖动，DDR 要求与数据同步的专用时钟——一个频率满足不了所有需求。

所以芯片被切成多个时钟域，每个域有自己的频率与来源：

时钟域典型频率为什么是这个值
ARM 核528MHz（可调）性能与功耗折中，可随负载调频
AXI 总线264MHz通常取核频率的 1/2，保证带宽够用又不过快
AHB / IPG132MHz / 66MHz外设寄存器访问不需要太快，降频省电
UART80MHz要能分出 115200 等标准波特率且误差小
USB PHY480MHzUSB 2.0 高速的物理层要求
以太网50MHz（RMII 参考）100Mbps ÷ 2bit = 50M 组/秒
DDR400MHz（800MT/s）颗粒速率决定
RTC32.768kHz2^15 分频得 1Hz

不同时钟域之间传数据，叫跨时钟域。这是数字设计里最容易出错的地方：A 域的信号在 B 域看来，可能正好在跳变，直接采就会亚稳态。工程上的解法是加两级同步器（连续两个触发器串联）或异步 FIFO。这部分在 T15 讲中断与并发时会再遇到。

0.7 为什么用 PLL，不直接把晶振做成 528MHz

晶振是靠石英片的机械共振产生频率的，它有一个致命特点：频率由晶片尺寸决定，做不了太高。常见的基频晶振集中在 8–50MHz，再高就要用「泛音」模式，成本与稳定性都变差。所以板上只会焊 24MHz，不可能焊 528MHz。

把 24MHz 变成 528MHz 的电路叫 PLL（锁相环）。它的原理可以这样理解：

24MHz 参考→鉴相器（比相位）→滤波器→压控振荡器 VCO→分频后反馈

通俗说：它内部有一个能自由跑的振荡器，PLL 不断比较「它的相位」和「参考时钟的相位」，跑快了就压慢一点、跑慢了就推快一点，最后锁在参考频率的整数倍上。24MHz × 22 = 528MHz，这个 22 就是倍频系数。

算一笔：为什么倍频系数不能随便取
24MHz × 22 = 528MHz ✔（这是硬件支持的组合）
想直接要 400MHz：400 / 24 = 16.67 —— 不是整数，PLL 做不出
只能 528 再分频：528 / 1 = 528、/2 = 264、/4 = 132 …… 得到的是 528 的约数
所以「i.MX6ULL 的主频只能是 528、396(24×16.5 不支持)、264…」这类限制，根源在「PLL 只能整数倍频」

PLL 还有一个隐藏本领：它能输出多路不同相位的时钟。同频但相位差 90°、180° 的时钟，在 DDR 接口里用来对齐数据与选通信号——这是纯晶振永远做不到的。第 9 章讲 DDR 时会用到。

0.8 为什么要分频：不是所有模块都需要快

PLL 出来的是高频，但绝大多数模块用不上。给它高速时钟有两个害处：功耗高、时序更难满足。所以每个模块前面都有分频器，把频率降到刚好够用的档位。

模块需要多少降频的收益
UART80MHz（分出 115200）再高也没有意义，反而分频误差更难凑
I2C几 MHz 即可总线本来就只有 100k/400kHz
GPIO66MHz（IPG）翻转速率远超人手感知
定时器66MHz 或 32.768kHz够做微秒级计时

分频本身很简单：一个计数器数 N 个周期翻转一次，就是 N 分频。但它有个陷阱——分频值改变时，输出会有一个不完整的周期。所以改分频必须先把模块停掉（关时钟门控），改完再开，否则可能发出一个「半个脉冲」，被外设当成有效沿。

0.9 为什么要门控：不用的模块直接断时钟

数字电路的动态功耗与「有没有在翻转」直接相关。一个模块即使不工作，只要时钟还在给它，内部的触发器就一直在翻转、一直在耗电。所以每个模块前面还有一个与门（叫时钟门控）：

// 门控的本质就是一个与门 module_clk = pll_clk AND gate_enable gate_enable = 0 → module_clk 恒为 0，模块内部完全不翻转，功耗接近 0 gate_enable = 1 → module_clk 跟着 pll_clk 跑

i.MX6ULL 里这个开关就是 CCGR0–CCGR6 七个寄存器，每个外设占 2 位。这就是为什么「外设寄存器写不进去」的第一嫌疑永远是门控没开——时钟没到，寄存器里的触发器根本不会响应。

门控的两个副作用 ① 关掉时钟后再去读该模块的寄存器，可能返回全 0 或直接挂死总线（因为模块内部状态机停了）；② 重新打开后，模块往往需要重新初始化，不能假设它记得之前的状态。「先关时钟再配置」是标准做法，「配置到一半关时钟」是事故。

0.10 为什么时钟要画成「树」

一颗 24MHz 晶振要驱动全芯片几万个触发器，直接连是不行的：驱动能力不够、走线太长、到达时间差太多。所以时钟是一层层缓冲放大、分叉传递的，形状像树：

晶振→PLL→根缓冲→一级缓冲→二级缓冲→各模块

树形带来两个专业名词，它们直接决定芯片能跑多快：

  • 时钟偏斜：同一个沿到达不同触发器的时间差。偏斜太大，等于某些触发器「提前」看到了沿，建立时间就不够了。
  • 时钟抖动：同一个触发器，这个周期的沿比上个周期早/晚了一点（由电源噪声、PLL 噪声引起）。抖动会吃掉时序余量。
算一笔：抖动吃掉多少余量
周期 1.89ns（528MHz），关键路径 1.6ns，理论上余量 0.29ns
时钟抖动 ±100ps（±0.1ns）、偏斜 80ps → 实际余量只剩 0.29 − 0.1 − 0.08 ≈ 0.11ns
所以「标称 528MHz」必须按最坏抖动与偏斜留够余量，不能按理想值设计
这也是为什么超频会「看起来能跑、偶尔算错」：余量被吃光了
回到你最初的疑问 「为什么需要时钟」的完整答案是三层：① 组合逻辑有传播延迟，需要一个统一时刻来判断「算完了」；② 触发器靠时钟沿采样，才能让全芯片同步推进；③ 不同模块对频率、精度、相位的需求不同，所以要用 PLL 生成、分频裁剪、门控开关，最终形成一棵树。

1. 时钟树：从一颗晶振到几十路时钟

i.MX6ULL 板上通常只有一颗 24MHz 晶振（外加一颗 32.768kHz 给 RTC）。所有其他频率都从它派生。路径是固定的四段：

晶振 24MHz→PLL（倍频）→选择器（多路选一）→分频器（PODF）→门控（CCGR）→外设
PLL典型频率主要去向
PLL1（ARM PLL）528MHz（24 × 22）CPU 核（再经 CACRR 分频）
PLL2（System PLL）528MHz，带 4 路 PFDAHB、IPG、UART、eMMC、I2C 等大部分外设
PLL3（USB PLL）480MHzUSB PHY（必须精确 480M）
PLL4音频用SAI/I2S
PLL5视频用LCD/CSI
PLL6网络用ENET 的 25/50/125MHz 参考
PLL7USB OTG另一路 USB

为什么要这么多 PLL 而不是一个高频再分频？因为某些外设对频率精度和抖动极其敏感：USB 必须精确 480MHz（否则枚举失败）、音频必须低抖动（否则有噪声）、以太网 RMII 需要精确的 50MHz。用同一个 PLL 分出所有频率，无法同时满足这些约束。

1.1 三个关键环节的寄存器

CCM（Clock Controller Module）基址 0x020C_4000。你只需要认识下面几个：

寄存器偏移管什么
CCM_CCR0x00各 PLL 的使能与锁定状态
CCM_CACRR0x10ARM 核分频（1/2/4/8）
CCM_CBCDR0x14AHB / IPG / PERCLK 分频与选择
CCM_CSCDR10x24UART 时钟的选择与分频
CCM_CCGR0–60x68–0x80外设时钟门控，每个寄存器管 16 个外设

CCGR 的编码规则必须记住：每个外设占 2 位，取值含义：

00 = 时钟关闭（最省电） 01 = 仅运行模式开（保留） 10 = 仅等待模式开（保留） 11 = 全开（除停止模式外都开） ← 绝大多数情况写这个

所以「打开 GPIO1 时钟」就是在对应 CCGR 的对应 2 位上写 0b11。这也是 T10 强调的「先开时钟再碰寄存器」的具体操作。

算一笔：528MHz 怎么一路分到 IPG 132MHz
PLL1 = 24MHz × 22 = 528MHz（ARM PLL）
CACRR = 1（不分频）→ ARM 核 = 528MHz
CBCDR 的 AHB_PODF = 2 → AHB = 528/2 = 264MHz
CBCDR 的 IPG_PODF = 2 → IPG = 264/2 = 132MHz
IPG 是大部分 APB 外设的基准（GPIO、I2C 等都靠它）

2. 波特率：为什么改主频会让串口乱码

UART 的波特率不是「设一个数就完事」，它是由输入时钟分频得来的。i.MX6ULL 的 UART 时钟通常来自 PLL2 的 PFD，配到 80MHz，然后：

divisor = UART_CLK / (16 × baudrate) 波特率误差 = |实际 - 目标| / 目标 （一般要求 < 2%）
算一笔：80MHz 出 115200
divisor = 80,000,000 / (16 × 115,200) = 80,000,000 / 1,843,200 = 43.40
取整 43：实际波特率 = 80,000,000 / (16 × 43) = 116,279 → 误差 +0.94%
取整 44：实际 = 113,636 → 误差 −1.36%
两者都在 ±2% 内，可通；但若时钟被改到 66MHz，误差会放大到 4% 以上，开始丢字节
这就是「改了主频，串口突然乱码」的根因：时钟变了，分频值没跟着重算

所以改时钟树时有一条铁律：凡是从被改动的 PLL 派生的外设，都要重新核对分频。串口、SD 卡、I2C 速率、LCD 像素时钟全在内。这也是为什么 Linux 用 clock framework 统一管理——驱动通过 clk_get_rate() 动态算分频，而不是写死。

3. RTC：断电之后时间靠什么走

i.MX6ULL 的实时时钟在 SNVS（Secure Non-Volatile Storage）模块里，基址 0x020C_C000。它有三个特殊之处：

  • 用独立的 32.768kHz 晶振。这个数字不是随便选的：32768 = 215，用 15 级二分频就能得到精确 1Hz，硬件实现最省。
  • 有独立的电源域（VDD_SNVS，通常接纽扣电池或超级电容）。主电源断了，它继续走。
  • 有独立的「防拆」逻辑（tamper），一旦检测到入侵就清掉密钥——这也是它叫 Secure 的原因。

关键寄存器：

寄存器偏移作用
HPCR0x00高功率域配置（含 RTC 时钟源选择、日历使能）
LPCR0x04低功率域配置（闹钟使能、RTC 使能）
LPSRTCMR0x10RTC 计数器高位
LPSRTCLR0x14RTC 计数器低位

计数器按 32.768kHz 递增，所以读出来的原始值要换算成秒：

秒数 = ((MR << 15) | (LR >> 17)) 原理：MR 存的是「已经满 2^15 个 tick 的次数」，LR 的低 15 位是「不满一秒的剩余 tick」

这个换算最容易出错的地方是移位方向。写错就是时间差几百倍。实际项目里不要手算，用驱动或 hwclock。

Linux 里 RTC 是标准设备类：/dev/rtc0 提供 RTC_RD_TIME 等 ioctl，hwclock -r 从 RTC 读、hwclock -w 把系统时间写回 RTC。开机时通常是 init 脚本调 hwclock -s 把 RTC 时间同步给系统。

RTC 也会走不准的两个真实原因 ① 晶振负载电容选错，频率偏几十 ppm，一天差几秒；② 电池电压不足时进入「低电压检测」，计数器行为异常。遇到「每次断电后时间都回到 1970」，先量电池电压，再查驱动有没有真的读到 SNVS 而不是某个假 RTC。

4. 看门狗：专门用来对付「程序卡死」

看门狗（WDOG）本质是一个只减不增的计数器：启动后它从设定值往下数，数到 0 就拉复位。软件必须定期「喂」它（把计数器重置回满值），喂得不够快就重启。它的设计意图很明确：软件如果失去「定期执行」的能力，硬件就替你重启。

i.MX6ULL 有 WDOG1/2/3，WDOG1 基址 0x020B_C000。关键寄存器：

寄存器偏移作用
WCR0x00控制：使能、时钟源、分频、是否允许关闭
WSR0x02服务（喂狗），必须写序列 0x5555 → 0xAAAA
WRSR0x08复位状态：记录上次是不是看门狗导致的复位

超时时间由三个量决定：

算一笔：超时时间怎么算
超时 = (计数器初值 + 1) × 分频系数 / 时钟频率
例：时钟 32.768kHz、分频 256、初值 0x0FFF（4095）
= 4096 × 256 / 32768 = 32 秒
若把分频改成 1024：= 4096 × 1024 / 32768 = 128 秒
工程取值原则：超时 > 最长一次正常任务耗时 × 2，否则会误复位

为什么喂狗要写两个特定值？ 因为「写一个值就能喂狗」太容易被误触发：任何一次野指针写到这个地址都会意外喂狗，看门狗就形同虚设。要求连续写 0x5555 与 0xAAAA，把误触发概率降到极低。这是硬件层面的防误操作设计，和 T10 讲的寄存器语义一脉相承。

还有两条工程经验：

  • 不要在中断里喂狗。主循环已经卡死、只剩中断还在跑时，中断里喂狗会让看门狗完全失效。正确做法是在主循环里喂，让「活着」和「在干正事」等价。
  • 一旦启动往往不能关。很多 SoC 的看门狗一旦使能就无法用软件关闭（WCR 的 WDA 位控制），这是故意的——防止程序「为了不出问题先把狗关了」。

5. 复位与电源域：上电那几百毫秒

「复位」不只是「按一下复位键」。i.MX6ULL 的复位源有多种，它们都会把系统拉回初始状态，但留下的线索不同：

复位源触发怎么判断
POR（上电复位）电源上电、电压跌到阈值以下复位状态寄存器里无其他标志
外部复位RESET 引脚被拉低（复位键 / 外部芯片）同上，通常难以区分
看门狗复位WDOG 超时WRSR 里有 WDOG 标志
软件复位写 SRC 的复位控制位SRC 的复位状态位
温度/电压异常复位内部保护触发相关状态寄存器

排查「设备老是莫名重启」时，先读复位原因寄存器，能省掉大量猜测。如果每次都是看门狗复位，说明软件有卡死；如果是 POR，则查电源（纹波、跌落、上电斜率）。

电源域管理（PMU）解决的是另一个问题：不用的部分要断电。i.MX6ULL 支持运行、待机、暂停、断电等模式，各模式下不同电源域的状态不同。做低功耗产品时，你要知道自己关掉的是哪个域、唤醒源是什么（GPIO、RTC 闹钟、USB 等）。这部分细节多、和具体板子强相关，实操时对照手册的 PMU 章节逐项验证。

6. 八个常见误解

误解真相
「CPU 主频就是 PLL 频率」PLL 之后还有 CACRR 分频，ARM 核拿到的是分频后的频率。
「改了 PLL 只影响 CPU」同一 PLL 派生的外设全部受影响，串口/SD/I2C 都要重算分频。
「CCGR 写 1 就开」每个外设占 2 位，要写 0b11 才是全开。
「波特率设个数字就行」是由输入时钟分频得来的，时钟变了必须重算，误差要控制在 2% 内。
「RTC 靠主电源供电」靠独立电源域（纽扣电池/超级电容），否则断电就不走时。
「32.768kHz 是随便选的」是 215，便于精确二分频到 1Hz，且功耗低。
「看门狗喂得越勤越好」喂得太勤会掩盖「任务没跑完」的问题；应该在主循环按周期喂，且超时要大于最长任务耗时。
「看门狗可以在中断里喂」那样主循环死了照样被喂，看门狗失去意义。

7. 自检：能答出来才算懂

1

24MHz 晶振到 ARM 528MHz，中间经过哪些环节？

看答案

晶振 → PLL1 倍频（×22 得 528MHz）→ CACRR 分频（1/2/4/8）→ 门控 → CPU。ARM 核拿的是最后一级的产物。

2

为什么需要多个 PLL，而不是一个高频再分频？

看答案

因为 USB（480MHz 精确）、音频（低抖动）、以太网（50MHz 精确）对频率精度与抖动要求各不相同，单一 PLL 分频无法同时满足。

3

CCGR 里一个外设占几位？写什么值表示开？

看答案

2 位，0b11 表示除停止模式外全开（最常用）；00 关闭。

4

UART 时钟 80MHz 要 115200，分频值多少、误差多少？

看答案

divisor = 80,000,000/(16×115,200) = 43.40；取 43 得 116,279（+0.94%），取 44 得 113,636（−1.36%），都在 ±2% 内。

5

改了 CPU 主频后串口乱码，原因是什么？怎么避免？

看答案

UART 的输入时钟跟着变了，但分频值没重算，实际波特率偏离超限。避免方式：用 clock framework 动态取频率算分频，不要写死。

6

RTC 计数器怎么换算成秒？为什么要独立供电？

看答案

秒 = ((MR << 15) | (LR >> 17))，因为计数按 32.768kHz 走。独立供电（纽扣电池/超级电容）是为了主电源断开后仍继续计时。

7

看门狗超时时间怎么算？取值的工程原则是什么？

看答案

超时 = (初值+1) × 分频 / 时钟频率。原则：超时大于「最长一次正常任务耗时」的 2 倍，既不误复位，也不让故障拖太久。

8

为什么喂狗要写 0x5555 再写 0xAAAA？为什么不能在中断里喂？

看答案

双写序列防止野指针误喂狗。不能在中断里喂，是因为主循环卡死时中断可能还在跑，看门狗就检测不到「主程序已死」。

8. 这一章要动手的命令

  1. cat /sys/kernel/debug/clk/clk_summary —— 看整棵时钟树的频率与使能状态。
  2. cat /proc/interrupts | grep -i rtc —— 确认 RTC 闹钟中断是否注册。
  3. hwclock -r 与 date —— 对比 RTC 与系统时间，判断谁不准。
  4. cat /sys/class/rtc/rtc0/since_epoch —— 直接读 RTC 的秒值，验证第 3 节的换算。
  5. dmesg | grep -i -E "rtc|snvs|wdog" —— 看 RTC 与看门狗驱动的加载情况。
  6. U-Boot 里 md 0x020BC000 4 —— 读 WDOG 寄存器，看它是否已启动。
  7. 故意死循环并停止喂狗，复位后读 WRSR，确认看门狗标志。
