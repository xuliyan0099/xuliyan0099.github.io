虚拟化与 KVM：ARM 上的 EL2 与 stage-2 页表

● 一读 纯读约 4 小时 左侧是本卷目录 理论为主 · 实作可跳

虚拟机不是软件模拟出来的假机器，而是硬件多给了一个特权级和一层页表。ARM 上这个特权级叫 EL2，这层页表叫 stage-2。

理解了这两样东西，「VM exit 为什么贵」「MMIO 怎么被拦截」「KVM 为什么比纯软件模拟快一个数量级」就都有答案了。

先玩一下：两级地址翻译

guest 里的虚拟地址要经过两次翻译：stage-1 是 guest OS 自己的页表，stage-2 是 hypervisor 的页表。拖动地址，看两次查表。

stage-2 的价值在于：hypervisor 可以给每个 VM 一张「IPA → 真实 PA」的表，于是两个 VM 都认为自己从 0 开始用内存，却互不重叠。guest 完全不知道自己被翻译了两次。

一、EL2 与 HCR_EL2：多出来的那个开关

EL0guest 的用户态应用。
EL1guest 的内核。它以为自己在管硬件，其实关键操作会被截住。
EL2hypervisor（KVM）。决定哪些操作允许、哪些触发异常到 EL2。
EL3安全监控（TrustZone），通常与虚拟化正交。

HCR_EL2 是这套机制的总开关。几个关键位：VM（开启 stage-2）、IMO/FMO/AMO（把中断路由到 EL2）、TGE（让 EL1 的系统调用/异常也陷入 EL2，便于全虚拟化）。改一位，guest 的行为就变一套。

二、VM exit：什么情况下会「被踢出来」

VM exit 之所以贵，是因为它要保存/恢复大量状态、切换栈、可能还要进出用户态（QEMU 在后端）。所以高性能虚拟化的核心是减少 exit：virtio 批量队列、posted interrupt、硬件嵌套页表（stage-2 由硬件走，不用 hypervisor 介入）。

三、i.MX6ULL 能不能跑 KVM

Cortex-A7 带虚拟化扩展（VE）与 LPAE，理论上支持 32 位 ARM KVM。但实际能不能用，还取决于：内核是否开了 CONFIG_KVM、内存是否够（每个 VM 都要独立内核与 rootfs）、以及你有没有第二套 rootfs。建议先在 QEMU 上练：qemu-system-aarch64 -M virt, virtualization=on 起一个 guest，再在 guest 里跑 KVM，成本最低。

方案成本能学到什么
QEMU 纯模拟最低，PC 上跑guest 启动、virtio、镜像制作
QEMU + KVM（同架构）低硬件加速、stage-2、exit 路径
i.MX6ULL 上 KVM中（内存与 rootfs 吃紧）真实硬件上的 VE 行为
Xen / Jailhouse高静态分区、实时性隔离
误解：容器就是轻量虚拟机容器共享宿主内核，靠 namespace + cgroup 隔离；虚拟机有自己的内核，靠 EL2 + stage-2 隔离。前者隔离的是「视图」，后者隔离的是「特权」。安全边界完全不同。
一句话记住三层stage-1 是「进程 → guest 物理」，stage-2 是「guest 物理 → 真实物理」。两次翻译，两次 TLB，两次缺页可能——这就是虚拟化性能损耗的主要来源。

动手（可选）：在 QEMU 里起一个 guest

只在 🔧 实作模式展开PC 上即可，不需要板子。
  1. 装 qemu-system-aarch64，用 -M virt,virtualization=on 起一个最小 guest（可用 Buildroot 的 qemu_aarch64_virt_defconfig）。
  2. guest 里 dmesg | grep -i kvm，确认 /dev/kvm 存在。
  3. 在 guest 里再起一个小 VM（嵌套），观察 dmesg 里的 stage-2 相关日志。
  4. 用 perf kvm stat（若支持）看 exit 原因分布：MMIO、WFI、中断，各占多少。

  • 区分容器与虚拟机的隔离边界。
