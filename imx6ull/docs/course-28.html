fork 与 exec

Linux 创建进程的方式很怪：没有「创建一个新程序」的系统调用。只有 fork（复制一个自己）和 exec（把自己的身体换掉）。要启动一个新程序，必须先复制自己，再换掉身体——这就是 shell 每次执行命令时做的两件事。

★ 一读 纯读约 1 小时 左侧是本卷目录 理论为主 · 实作可跳

这一课要回答的问题

① fork 到底复制了什么？② 为什么 fork 有两次返回？③ exec 保留了哪些东西？④ 僵尸进程是什么，怎么回收？⑤ 孤儿进程谁来管？

1. fork：复制「身份证」，共享「身体」

复制共享（COW）保留
task_struct、内核栈物理内存页（只读，写入时复制）打开的文件（引用计数 +1）
页表（新的一份）文件内容（页缓存）工作目录、信号处理设置
fd 表（新的一份）——
 
pid_t pid = fork();
if (pid == 0) {
    // 子进程：这里是新任务，跑自己的逻辑
    execvp("ls", argv);       // 通常立刻 exec
} else if (pid > 0) {
    // 父进程：pid 是子进程号，用 wait 等它
    waitpid(pid, &status, 0);
} else {
    // fork 失败（内存/进程数限制）
    perror("fork");
}

「两次返回」不是魔法：fork 之后有两个 task 从同一个返回点继续执行，各自拿到不同的返回值（子得 0，父得 pid）。

2. exec：不换身份，只换身体

// 一个真实的技巧：进程自我重启（热升级）
// 重新 exec 自身，PID 不变，fd 保留
execv("/proc/self/exe", argv);

// fd 泄漏的常见坑：exec 前要关闭不需要的 fd
// 或者创建时加 O_CLOEXEC
int fd = open(path, O_RDONLY | O_CLOEXEC);

3. 僵尸与孤儿

类型成因现象处理
僵尸 Z子进程退出，父进程没 waitps 里一堆 Z，占 PID 但不占内存父进程 wait；或父进程退出后由 init 收养
孤儿父进程先死被 init（PID 1）收养并 wait通常自动解决

僵尸不占内存却占 PID。PID 上限通常 32768，僵尸堆积到上限后就无法创建新进程——这是「系统突然不能 fork」的经典原因。

# 找僵尸
ps -eo pid,ppid,stat,comm | awk '$3 ~ /Z/'
# 找它们的父进程，看为什么没 wait
ps -eo pid,ppid,stat,comm | grep -w Z

4. vfork 与 posix_spawn

vfork 是老优化：父子共享地址空间，子进程必须立刻 exec（否则会破坏父进程）。现代系统上性能优势已不明显，且危险，能不使用就不用。

posix_spawn 是把 fork+exec 打包成一个系统调用，内部可能用 vfork 或 clone 优化。glibc 的 system() 最终也是走这条路。

5. 实验：自己实现一个 mini shell

// 最简 shell（200 行内可写完）
while (1) {
    printf("$ ");
    fflush(stdout);
    char line[256];
    if (!fgets(line, sizeof(line), stdin)) break;

    pid_t pid = fork();
    if (pid == 0) {
        execlp("/bin/sh", "sh", "-c", line, NULL);
        _exit(127);                 // exec 失败
    }
    int st;
    waitpid(pid, &st, 0);
    printf("[exit %d]\n", WEXITSTATUS(st));
}

写完这个，你就真正理解 shell 了：它不过是一个「fork + exec + wait」的循环，再加上一些管道与重定向的处理。

6. 三条常见误解

7. 自测与动手

1

fork 返回 0 和返回正数分别代表什么？

看答案

0 = 当前是子进程；正数 = 当前是父进程，值是子进程 PID；负数 = 失败。

2

exec 之后 PID 会变吗？fd 会关吗？

看答案

PID 不变；fd 默认保留（带 CLOEXEC 的会被关闭）。

3

僵尸进程占什么资源？有什么危害？

看答案

占 PID 和一个 task_struct；堆积会导致无法创建新进程（PID 耗尽）。

4

孤儿进程会被谁收养？

看答案

由 init（PID 1，现代系统可能是 systemd）收养并最终 wait。

5

为什么「fork 大进程」并不慢？

看答案

COW：物理页共享且只读，只复制页表；真正复制只在某一方写入时按页发生。

  1. 写一个 fork 后打印 PID 的程序，验证两次返回。
  2. 写 mini shell，执行 ls 与 sleep 2。
  3. 故意不 wait，制造僵尸并用 ps 找出它。
  4. 用 strace -f 跟一个 shell 命令，看到 clone/execve/wait4 序列。
