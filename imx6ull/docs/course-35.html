i.MX6ULL 最小系统

软件讲完了，回到硬件。一块 SoC 不是插上电就能跑：需要多路电源按正确顺序上电、一颗晶振提供时钟、复位信号保持足够长、启动模式引脚选对启动源、串口能输出第一行字。这五件事任何一件不对，板子就是「死的」——而且往往没有任何提示。

★ 一读 纯读约 1 小时 左侧是本卷目录 理论为主 · 实作可跳

这一课要回答的问题

① 电源为什么分多路、按序上电？② 晶振坏了有什么现象？③ 复位要多久？④ 启动模式引脚怎么选启动源？⑤ DDR 为什么必须由软件初始化？

1. 电源：不只是「3.3V」

电源域典型电压供给注意
VDD_SNVS3.0~3.6VRTC、唤醒逻辑必须常供，主电源断开也要在
NVCC_ARM1.2~1.3VCPU 内核降频时要同步降压（DVFS）
NVCC_DDR1.35V（DDR3L）DDR IO与颗粒规格严格匹配
NVCC_IO3.3V / 1.8VGPIO、外设 IO决定 IO 电平，接错会烧外设

上电有顺序要求（通常 SNVS → 内核 → DDR → IO），否则可能闩锁或初始化失败。查数据手册的 Power-Up Sequence，不要凭经验猜。

2. 时钟与复位

# 时钟
24MHz 主晶振 → 内部 PLL → 528MHz 内核 / 各外设时钟
32.768kHz    → RTC（走时、低功耗唤醒）

# 现象对照
# 晶振不起振：完全无输出，或串口乱码
# 晶振频率偏：波特率偏差，通讯不稳

# 复位
POR 需保持毫秒级，让电源稳定；
外部复位芯片（如 MAX809）比 RC 电路可靠得多

「串口乱码」几乎总是时钟或波特率问题。先确认晶振频率与 PLL 配置，再怀疑串口线。

3. 启动模式：最容易被忽略的「不启动」原因

4. DDR 为什么必须由软件初始化

DDR3 颗粒上电后处于未知状态，必须先配置控制器（时序参数、刷新率、ODT、驱动强度），再做一次「训练」（写入读回校准）。这个流程只能是软件做，而且必须在 Boot ROM 之后的 bootloader 里完成。

所以 i.MX6ULL 的启动链是：Boot ROM（在片内 SRAM 跑）→ 读 bootloader 到 OCRAM → bootloader 初始化 DDR → 搬自己到 DDR → 继续。

不同板子的 DDR 参数不同，所以 uboot 的 board/freescale/mx6ull_xxx/ 目录里会有一个 ddr_init.c 或 MX6ULL_xxx_ddr3_*.inc。用错了别人的 DDR 参数，板子会在 DDR 初始化阶段静默挂死。

5. 实验：接上第一根线

# 硬件侧
# 1) 万用表量各路电源（尤其 NVCC_ARM 是否 1.2~1.3V）
# 2) 示波器看 24MHz 晶振是否起振
# 3) 确认复位引脚在启动后为高

# 软件侧（USB-TTL 转串口，接 UART1）
picocom -b 115200 /dev/ttyUSB0
# 或
minicom -D /dev/ttyUSB0 -b 115200

# 上电瞬间应看到 Boot ROM 的打印（若 uboot 未烧写，可能只有一行乱码）

第一次上板，建议顺序是：先只供电、不接任何外设 → 量电压 → 接串口 → 上电看是否有输出。每加一步都确认，比一次接齐后排查快得多。

6. 三条常见误解

7. 自测与动手

1

VDD_SNVS 为什么必须常供？

看答案

它供 RTC 与唤醒逻辑，主电源断开后仍需走时与保存状态。

2

串口乱码最可能的原因？

看答案

时钟频率不对（晶振或 PLL 配置错）导致波特率偏差；其次是接线/电平不匹配。

3

启动模式引脚什么时候被采样？

看答案

上电复位时由 Boot ROM 采样一次，之后运行期改变无效。

4

DDR 初始化为什么不能省？

看答案

颗粒上电状态未知，必须配置时序、刷新并做训练，否则读写全错。

5

板子「完全没反应」时的排查顺序？

看答案

电源电压 → 晶振起振 → 复位电平 → 启动模式引脚 → 调试串口接线 → 最后才怀疑镜像。

  1. 用万用表量你板子的各路电源，记录实测值。
  2. 用示波器（或逻辑分析仪）看 24MHz 晶振波形。
  3. 找到启动模式拨码开关，改成 SD 卡启动并验证。
  4. 接串口，上电，记录第一屏输出。
