文件与设备

Linux 最成功的一个抽象是：把磁盘文件、串口、GPIO、管道、socket 全都做成「文件」。于是用户程序只需要 5 个系统调用就能操作万物。这一课讲 VFS 怎么实现这个统一，以及你写驱动时到底在填哪几个坑。

★ 一读 纯读约 1 小时 左侧是本卷目录 理论为主 · 实作可跳

这一课要回答的问题

① inode、dentry、file 各是什么？② 字符设备与块设备差在哪？③ 写一个字符设备驱动需要哪几步？④ /dev 与 /sys 有什么区别？⑤ 为什么 read 有时会立刻返回、有时会阻塞？

1. 三个核心对象

对象描述什么生命周期举例
inode一个文件的「元数据 + 数据位置」与文件同寿大小、权限、时间戳、数据块指针
dentry一个「名字 → inode」的目录项缓存，可回收/dev/ttyS0 这条路径的每一段
file一次 open 产生的「打开实例」close 即销毁读写位置、访问模式、f_op 指针

注意「一个文件可以有多个 file」：两次 open 同一个路径，得到两个独立的读写位置。这就是为什么两个进程能各自读到文件的不同部分。

2. 字符设备与块设备

3. 写一个字符设备：最少五步

#include <linux/cdev.h>

static int my_open(struct inode *i, struct file *f) { return 0; }
static ssize_t my_read(struct file *f, char __user *buf, size_t n, loff_t *off) {
    return simple_read_from_buffer(buf, n, off, "hello\n", 6);
}

static const struct file_operations my_fops = {
    .owner = THIS_MODULE,
    .open  = my_open,
    .read  = my_read,
};

static int __init my_init(void) {
    alloc_chrdev_region(&devid, 0, 1, "mychar");   // 1) 申请设备号
    cdev_init(&my_cdev, &my_fops);                 // 2) 初始化 cdev
    cdev_add(&my_cdev, devid, 1);                   // 3) 注册
    device_create(my_class, NULL, devid, NULL, "mychar"); // 4) 创建 /dev 节点
    return 0;
}

五步：申请设备号 → 填 file_operations → cdev_add → 创建设备节点 → 在 exit 里逆序释放。更简单的方式是用 misc_register()，一行搞定（次设备号自动分配）。

4. /dev 与 /sys 的分工

  • /dev：设备节点，用来 open/read/write。mknod 或 udev 生成。
  • /sys：设备模型，用来查看/配置属性（读写文本文件）。echo 1 > /sys/class/leds/...
  • /proc：内核状态与统计，历史遗留但极实用。

嵌入式调试最常用的三条：ls /sys/class/、cat /sys/kernel/debug/gpio、cat /proc/interrupts。它们不需要写任何代码，就能看到驱动与硬件的真实状态。

5. 阻塞与非阻塞

read() 的行为由 open 时的 O_NONBLOCK 与驱动的实现决定：

  • 阻塞：没数据就睡，直到有数据或被信号打断。适合串口、按键。
  • 非阻塞：没数据立刻返回 -EAGAIN。适合 poll/epoll 循环。

驱动里通常用等待队列实现：wait_event_interruptible() 与 wake_up_interruptible()。这也是「中断里唤醒等待队列」的标准配合（第 30 课的下半部）。

6. 实验：从 /dev 看内核

ls -l /dev | head            # 看主次设备号
cat /proc/devices            # 已注册的主设备号清单
ls /sys/class/               # 设备类
cat /sys/class/net/eth0/address   # 网卡 MAC（若存在）

# 读一个字符设备
cat /dev/urandom | head -c 16 | xxd

# 看某个设备的驱动与总线
readlink -f /sys/class/tty/ttyS0/device/driver

这三条命令能回答「这个设备是谁在管、用了哪个驱动、挂在哪个总线」——排查「设备不工作」时的第一步。

7. 三条常见误解

8. 自测与动手

1

inode 与 file 的区别？

看答案

inode 描述「文件本身」（元数据与数据位置），file 描述「一次打开」（读写位置与访问模式）。

2

块设备为什么不能直接 read 字节？

看答案

它按块访问、经页缓存与 IO 调度；要么挂载成文件系统，要么按块（dd）访问。

3

字符设备驱动最少要填哪几个回调？

看答案

至少 open/read/write 之一 + owner；其余可留空由内核默认处理。

4

/sys 与 /dev 的根本区别？

看答案

/dev 是数据通道（open/read/write）；/sys 是属性视图（读写文本文件配置设备）。

5

O_NONBLOCK 对 read 的影响？

看答案

无数据时立即返回 -EAGAIN 而不是睡眠等待。

  1. 写一个 misc 设备驱动，注册 /dev/mychar 并能读出一句话。
  2. 用 cat /proc/devices 找到它的主设备号。
  3. 把 read 改成阻塞版（等待队列），用两个终端观察阻塞行为。
  4. 用 strace 跟一次 open/read/close，看到实际系统调用序列。
