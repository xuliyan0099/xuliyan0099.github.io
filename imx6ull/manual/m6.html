从板子上的一个脚，查到 dts 一行

第 06 章约 24 分钟★★ 核心

从一根线到一行 dts：五个节点

原理图网络名 → 球号 → 引脚名 → 功能名 → dts 里的节点与属性
    UART_RX     A15    GPIO1_IO03   UART1_RX_DATA   &uart1 { pinctrl-... }

每一步都有具体材料可查，缺一步就会猜：

步骤查什么产出
1 网络名原理图 PDF，搜网络名它连到哪个球
2 球号 → 引脚名Datasheet 的 ball mapGPIO1_IO03
3 引脚名 → 功能RM 的 Signal Multiplexing 表ALT5 = GPIO、ALT0 = UART1_RX_DATA
4 功能 → 引脚组同表，看这个功能属于哪个 pinctrl 组uart1grp
5 组 → dtsdtsi 里 &iomuxc 下的子节点一组 fsl,pins

dts 里那行长什么样

&iomuxc {
    pinctrl_uart1: uart1grp {
        fsl,pins = <
            MX6UL_PAD_UART1_RX_DATA__UART1_RX_DATA  0x1b0b1
            MX6UL_PAD_UART1_TX_DATA__UART1_TX_DATA  0x1b0b1
        >;
    };
};

&uart1 {
    pinctrl-names = "default";
    pinctrl-0 = <&pinctrl_uart1>;
    status = "okay";
};

三个要点：

① 宏的名字就是「引脚 + 功能」的组合。 MX6UL_PAD_UART1_RX_DATA__UART1_RX_DATA 拆开读是「引脚 UART1_RX_DATA 复用成功能 UART1_RX_DATA」。宏里第二个 __ 之后的部分就是 MUX_MODE 的语义名，编译后变成一个 mux + config 的 32 位数。

② 后面那个十六进制数不是地址，是 PAD_CTL 值。 它编码驱动强度、速率、上下拉。这个值来自「参考板实测 + 数据手册位域」，抄了能用，改了要知道自己在改什么。

③ status = "okay" 才是「打开这个设备」。 很多新手配了半天 pins，忘了改 status（或改错了节点），现象是「设备树里明明写了，驱动却没跑」。

宏怎么查出来的

MX6UL_PAD_* 系列宏定义在内核头文件里（形如 arch/arm/boot/dts/imx6ul-pinfunc.h）。它本质是四个数：

<mux_reg  mux_val  config_reg  config_val>

其中 mux_reg 就是 SW_MUX_CTL_PAD_* 的偏移，mux_val 就是 ALT 号。所以你在手册里查到的「偏移 + ALT 号」，就是内核宏里那两个数。 对不上时，一眼就能看出是「引脚选错」还是「ALT 号选错」。

查法：直接在内核源码里 grep 引脚名：

grep -rn "UART1_RX_DATA" arch/arm/boot/dts/imx6ul-pinfunc.h

三个常见断点及现象

断在哪现象
pins 没配（或组没引用）设备能注册，但收发全无；读引脚电平是悬空值
status 没开/proc/device-tree 里能看到节点，但驱动不 probe
引脚被别的设备抢了（两个节点引用同一个脚）后 probe 的那个报 -EBUSY，前一个突然失灵

第三种最难查，因为两个驱动各自都「看起来对」。排查办法：cat /sys/kernel/debug/pinctrl/*/pinmux-pins 看每个脚归谁。

用 pinctrl 调试的三个命令

cat /sys/kernel/debug/pinctrl/<控制器>/pinmux-pins   # 谁占了这个脚
cat /sys/kernel/debug/pinctrl/<控制器>/pinconf-pins  # 电气配置生效了没
grep -n "" /proc/device-tree/soc/.../pinctrl-0       # 确认引用链

第一条给你「归属」，第二条给你「参数」。大多数「引脚配了但不工作」在这两条里就能定位：要么归属不对（被别的设备拿了），要么参数不对（驱动太弱/上拉类型错）。

一个完整的例子：把一个 LED 接上

  1. 原理图：LED_RED → 球 A15。
  2. Datasheet ball map：A15 = GPIO1_IO03。
  3. RM 复用表：GPIO1_IO03 的 ALT5 = GPIO1_IO03（GPIO 功能）。
  4. 内核宏：MX6UL_PAD_GPIO1_IO03__GPIO1_IO03。
  5. dts：
&iomuxc {
    pinctrl_led: ledgrp {
        fsl,pins = < MX6UL_PAD_GPIO1_IO03__GPIO1_IO03 0x10B0 >;
    };
};

leds {
    compatible = "gpio-leds";
    led-red {
        gpios = <&gpio1 3 GPIO_ACTIVE_LOW>;
        pinctrl-0 = <&pinctrl_led>;
        linux,default-trigger = "heartbeat";
    };
};

GPIO_ACTIVE_LOW 表示「拉低才亮」——这来自硬件（LED 阳极接 3.3V、阴极接引脚）。这个极性写反，灯会常亮或常灭，而不是不工作，很容易被误判成「代码没跑」。

本篇验收

  • 能默写「一根线到一行 dts」的五步，并说出每步查什么材料。
  • 能解释 MX6UL_PAD_A__B 宏的名字含义，以及它编译后是哪四个数。
  • 能说出 status = "okay" 漏写、pins 漏配、引脚被抢三种情况各自的现象。
  • 能用 pinmux-pins 判断某个脚归谁。
  • 能解释 GPIO_ACTIVE_LOW 来自硬件的哪一部分。
