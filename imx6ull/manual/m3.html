Reference Manual 一章的固定骨架

第 03 章约 20 分钟★ 必读

每一章都是同一个骨架

NXP 的 RM 写得很「工业」：几十个外设章，全都按同一个顺序排。认清这个顺序，你读任何一章都不需要从头读，直接跳到你要的那一节。

序号小节里面有什么你要不要读
1Overview / Features这个模块能做什么，支持什么模式快速扫，确认「它有没有我要的功能」
2Block Diagram框图：数据从哪进、存哪、出哪必看，尤其 FIFO 在哪一级
3Signal Descriptions外部信号表：这个模块有哪些引脚做引脚复用时看
4Functional Description工作模式、状态机、协议流程必看，理解行为
5Register Definition基地址 + 每个寄存器的表写代码时查
6Initialization / Application Info官方给的初始化步骤必看，顺序都在这儿

一句话：1、2、4、6 是「读懂」，3 是「接线」，5 是「写代码」。

② Block Diagram：看图比看字快

框图的用处只有一个：搞清楚「这个模块的数据经过了哪些级，哪里会丢、哪里会卡」。

以 UART 为例，框图里能看到：

引脚 RX → 采样逻辑 → 接收 FIFO → 数据寄存器 URXD
引脚 TX ← 移位寄存器 ← 发送 FIFO ← 数据寄存器 UTXD
                    ↑ 波特率发生器 ← 时钟源

看懂这一条链，你就能回答三个实际问题：

  • 为什么收数据会丢？ FIFO 满了没读，后来的就覆盖/丢弃。
  • 为什么有接收超时/空闲中断？ 因为一次只来几个字节时，FIFO 水位永远不够。
  • 波特率误差从哪来？ 发生器是「源时钟分频」，分不尽就有误差。

图里没画的东西也很重要：如果没有 DMA 请求线，说明这个模块不能直接喂 DMA（或需要外部的 DMA 复用器参与）。

③ Signal Descriptions：模块与板子之间那一层

这一节列出该模块对外的所有信号名（有的芯片叫 i.MX6 内部信号名）。注意这些名字不是引脚名，而是「模块端口名」，比如 UART1_RXD。引脚名（UART1_RX_DATA、GPIO1_IO03）在 IOMUXC 的复用表里。

两层的区别值得弄清楚，因为排查问题时常在两层之间来回：

模块端口（UART1_RXD）  ←复用→  引脚（GPIO1_IO03）  ←焊接→  板上网络（UART_RX）

「串口收不到数据」可能断在任意一层：模块没使能（第一层）、MUX 配错（第二层）、排线没接（第三层）。

④ Functional Description：真正决定行为的部分

这是最长的一节，也是最该花时间的一节。典型子小节：

  • Clock gating / Power management：什么时候模块「看起来配了但不工作」——因为门控关着。
  • Reset：哪些复位会清哪些寄存器。关键：不是所有复位都清所有东西。
  • Operating modes：主从、单次/连续、轮询/中断/DMA。
  • Protocol / data flow：比如 SPI 的四种 CPOL/CPHA 组合，各自长什么样。
  • Error handling / status flags：溢出、校验错、仲裁丢失，以及「怎么清」。

这一节里藏着最容易被忽略的一句话：很多模块会在某段写「写这个位会清掉那个状态」，这种跨字段的联动只在这节里有，寄存器表里看不到。

⑤ Register Definition：结构永远是三段

每章的这一节都长这样：

  1. 一张 Memory map 表：这个模块所有寄存器的偏移、名字、宽度。先看这张，它给你全景。
  2. 每个寄存器一张位域表：偏移、位、字段名、访问类型、复位值。
  3. 有时在末尾给「保留寄存器不要写」的警告。

读法在 04 篇详细讲，这里只需记住：先看 map，再看具体表的位域。

⑥ Initialization：照抄顺序，别自己发明

这一小节存在感最低，价值最高。典型内容：

1. 使能模块时钟
2. 复位模块（写某位，等它自清）
3. 配置模式与参数
4. 使能模块
5. 使能中断

顺序几乎是不可交换的。比如 UART：要先清 FIFO 再使能，反过来会带着一团旧数据启动；SD/eMMC 要先给时钟再发命令，反过来命令发不出去。

如果你写的驱动「怎么调都不对」，八成是把这里的顺序改了。

一个真实的读法示例

任务：给 UART1 加一个「接收超时」功能。

  1. Overview：确认这个 UART 支持 idle-line detect（有的老 UART 不支持）。
  2. Block Diagram：确认接收 FIFO 的深度，决定水位怎么设。
  3. Functional：找到 idle detect 那一小节，看它是「总线空闲多久触发」以及「清标志的正确方式」。
  4. Register：找控制位（使能位）、状态位（标志）、以及它们的 W1C 特性。
  5. Initialization：确认这个功能要不要在使能 UART 之前配。

五步走完，你手里有一份「改哪几个寄存器、按什么顺序」的清单——而不是拿着寄存器表一个个试。

本篇验收

  • 能默写一章的六个小节顺序，并说出哪几节必读。
  • 能解释 Block Diagram 为什么比 Functional Description 更快让你理解 FIFO 行为。
  • 能说清「模块端口名」与「引脚名」是两层，并给出一个排查例子。
  • 能举出一个「只在 Functional 小节里、寄存器表里没有」的联动行为。
