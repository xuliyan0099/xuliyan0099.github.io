八个坑，和一张速查

第 07 章约 20 分钟★ 必读

八个坑，每一个都真实发生过

坑 1：页码对不上。 你按 AN 笔记里的「第 1234 页」翻，结果那一页是别的模块。原因：不同版本的 RM 页码会变（勘误、增补）。对策：只记「章名 + 表名 + 寄存器名」，不记页码。

坑 2：把 Reserved 写 1。 手册说「Reserved」，你整写寄存器时把它写成了 1。轻则被忽略，重则触发未公开行为。对策：只在需要的字段上读改写。

坑 3：以为复位值是 0。 表里 Reset value 有具体数值，你假设 0 直接整写。对策：初始化时把「你关心的每一位」显式写一遍，别依赖默认值。

坑 4：W1C 上做读改写。 读—清位—写回，标志清不掉。对策：W1C 只能写掩码，writel(mask, ISR)。

坑 5：模块名对，实例号错。 你调 UART3，dts 里是 uart2。现象：完全没输出，代码看起来全对。对策：dmesg | grep -i uart 看实际注册了哪几个。

坑 6：MUX 配了，PAD 没配。 引脚通了但驱动太弱/输入悬空。现象：输出波形幅度不够、输入偶发误触发。对策：两组寄存器一起配，别只写 MUX。

坑 7：DR 当 PSR 用。 输入模式下读 DR 永远是旧值。现象：按键永远「按着」或永远「没按」。对策：输入读 PSR，只在输出时用 DR。

坑 8：把手册读成小说。 从第 1 页开始读，三天读到第 200 页，遇到问题还是不会查。对策：只查不读。问题驱动，查完立刻合上。

三种「看起来是软件问题，其实是手册没读对」

  1. 「寄存器读回全 0」：时钟没开（坑 3 的变体）。手册在 CCM 章写着「未开时钟时访问返回 0」。
  2. 「偶发数据错」：时序参数超了（Datasheet AC 表）。软件层看是「偶发」，硬件层是「建立时间不够」。
  3. 「第一次能跑，重启不行」：依赖了复位默认值（坑 3）。第一次是上电冷启动，第二次是 warm reset 留下的旧状态。

读手册的三条习惯

  • 边读边抄：每查一次，往自己的摘要里加一行（「模块 / 基址 / 关键位 / 坑」）。三次之后你就不需要手册了。
  • 对照源码：手册里的「Recommended initialization」与内核驱动的 probe 顺序对照着看，能发现官方 BSP 为什么那么写。
  • 留疑点清单：读不懂的位、看不懂的联动，写进一张「疑点」表。等真正调试到它时再回来——带着问题回读，效率是通读的十倍。

本篇验收

  • 能说出「页码对不上」的原因，并给出对策。
  • 能列举三个「把寄存器读成 0」的原因。
  • 能解释「第一次能跑重启不行」背后的复位类型问题。
  • 手上有一份自己的摘要（至少十行），每行都注了出处。
