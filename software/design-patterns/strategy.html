策略模式STRATEGY

同一个 drain()，队列一样、帧一样，只是“下一帧发谁”的规则不同。策略模式只做一件事：把这条规则从调用点搬到一个可替换的值上，让上下文从此只认一个签名。

运行时可换 C 版少一级间接 C++ 版 unique_ptr 持有

01问题：三种规则堆进同一个循环

先看没上模式的写法：drain() 里先 if (mode == FIFO) 取队首，else if (mode == EDF) 扫一遍最小截止，else 再扫一遍最小 ID。三段代码各自维护一个小循环，看起来也能跑。

问题在第二次、第三次改动时出现：新加一种“按信号优先级 + 老化”的调度，要动 drain()；测试要覆盖 mode 的组合；某个策略的临时状态（比如老化计数）只能挂在上下文里，越挂越乱。这就是“算法”和“调用流程”被焊死在同一段代码里的典型症状。

  • 症状一：同一段流程里出现按类型分支的算法选择；
  • 症状二：加一种实现，要改调用方；
  • 症状三：算法本身想单独测，却要先把整个上下文搭起来。

02结构：上下文只持有一个“会算下一步”的东西

点方框看职责。注意箭头的方向：上下文指向策略，而不是反过来——策略不知道谁在用它。

上下文 / 策略接口 / 三个具体策略structure
职责点方框：上下文 / 接口 / 三个具体策略，各自只知道什么、不知道什么。

03两份实现

C 版把接口做成 {name, fn} 常量，C++ 版做成纯虚基类。两边都保留同一份队列和同一套输出，便于逐行对照。

Cstrategy.c
/* 策略模式 · C 实现：CAN 发送队列的调度策略
 * 编译：gcc -std=c11 -Wall -Wextra strategy.c -o strategy
 * 策略接口只有一个函数指针，上下文不关心是谁实现。
 */
#include <stdio.h>

typedef struct { int id; int due_ms; } frame_t;

/* 策略 = 一个签名固定的函数指针 */
typedef int (*pick_fn)(const frame_t *q, int n);

typedef struct {
    const char *name;
    pick_fn    pick;
} sched_t;

/* 三个具体策略：都返回「下一个该发哪一帧」的下标 */
static int pick_fifo(const frame_t *q, int n)
{
    (void)q;
    return n > 0 ? 0 : -1;
}

static int pick_edf(const frame_t *q, int n)          /* 最早截止优先 */
{
    int best = -1;
    for (int i = 0; i < n; i++)
        if (best < 0 || q[i].due_ms < q[best].due_ms)
            best = i;
    return best;
}

static int pick_prio(const frame_t *q, int n)         /* CAN ID 越小越优先 */
{
    int best = -1;
    for (int i = 0; i < n; i++)
        if (best < 0 || q[i].id < q[best].id)
            best = i;
    return best;
}

static const sched_t FIFO = { "FIFO", pick_fifo };
static const sched_t EDF  = { "EDF",  pick_edf  };
static const sched_t PRIO = { "PRIO", pick_prio };

/* 上下文：只持有 sched_t 的指针，换策略就是换指针 */
static void drain(const sched_t *s, frame_t *q, int n)
{
    printf("%-5s ->", s->name);
    int left = n;
    while (left > 0) {
        int i = s->pick(q, left);
        if (i < 0) break;
        printf(" %03X", q[i].id);
        for (int k = i; k < left - 1; k++)
            q[k] = q[k + 1];
        left--;
    }
    printf("\n");
}

int main(void)
{
    static const frame_t seed[5] = {
        { 0x210, 10 }, { 0x120, 4 }, { 0x305, 2 }, { 0x180, 8 }, { 0x0A0, 6 }
    };
    frame_t q[5];

    for (int i = 0; i < 5; i++) q[i] = seed[i];
    drain(&FIFO, q, 5);
    for (int i = 0; i < 5; i++) q[i] = seed[i];
    drain(&EDF, q, 5);
    for (int i = 0; i < 5; i++) q[i] = seed[i];
    drain(&PRIO, q, 5);

    printf("sizeof(sched_t)=%u  sizeof(pick_fn)=%u\n",
           (unsigned)sizeof(sched_t), (unsigned)sizeof(pick_fn));
    return 0;
}
C++strategy.cpp
// 策略模式 · C++ 实现：同一场景，改用抽象基类 + 虚函数
// 编译：g++ -std=c++17 -Wall -Wextra strategy.cpp -o strategy_cpp
#include <cstdio>
#include <memory>
#include <vector>

struct Frame { int id; int due_ms; };

class IScheduler {
public:
    virtual ~IScheduler() = default;
    virtual const char* name() const = 0;
    virtual int pick(const std::vector<Frame>& q) const = 0;
};

class Fifo final : public IScheduler {
public:
    const char* name() const override { return "FIFO"; }
    int pick(const std::vector<Frame>& q) const override { return q.empty() ? -1 : 0; }
};

class Edf final : public IScheduler {
public:
    const char* name() const override { return "EDF"; }
    int pick(const std::vector<Frame>& q) const override {
        int best = -1;
        for (int i = 0; i < static_cast<int>(q.size()); ++i)
            if (best < 0 || q[i].due_ms < q[best].due_ms) best = i;
        return best;
    }
};

class PriorityId final : public IScheduler {
public:
    const char* name() const override { return "PRIO"; }
    int pick(const std::vector<Frame>& q) const override {
        int best = -1;
        for (int i = 0; i < static_cast<int>(q.size()); ++i)
            if (best < 0 || q[i].id < q[best].id) best = i;
        return best;
    }
};

// 上下文持有策略的所有权；换策略即换对象
class TxQueue {
public:
    void set(std::unique_ptr<IScheduler> s) { sched_ = std::move(s); }

    void drain() {
        std::printf("%-5s ->", sched_->name());
        while (!q_.empty()) {
            int i = sched_->pick(q_);
            if (i < 0) break;
            std::printf(" %03X", q_[static_cast<std::size_t>(i)].id);
            q_.erase(q_.begin() + i);
        }
        std::printf("\n");
    }

    void reset(const std::vector<Frame>& seed) { q_ = seed; }

private:
    std::vector<Frame> q_;
    std::unique_ptr<IScheduler> sched_;
};

int main() {
    const std::vector<Frame> seed = {
        { 0x210, 10 }, { 0x120, 4 }, { 0x305, 2 }, { 0x180, 8 }, { 0x0A0, 6 }
    };
    TxQueue q;

    q.reset(seed);   q.set(std::make_unique<Fifo>());       q.drain();
    q.reset(seed);   q.set(std::make_unique<Edf>());        q.drain();
    q.reset(seed);   q.set(std::make_unique<PriorityId>()); q.drain();
    return 0;
}

RUN./strategy_cpp.exe
FIFO  -> 210 120 305 180 0A0
EDF   -> 305 120 0A0 180 210
PRIO  -> 0A0 120 180 210 305

05同一组角色，两种写法

角色职责C 的落地C++ 的落地
上下文保存业务数据，调用策略，不判断具体策略const sched_t * 字段unique_ptr<IScheduler>
策略接口固定一个签名，让实现可替换typedef int (*pick_fn)(...)纯虚函数 pick()
具体策略只实现算法，不碰队列生命周期三个 static 函数 + 三个 const 描述符三个 final 类
切换运行中换算法，不需要重建上下文换一个指针，零分配move 一个新对象（或换引用）
开销一次间接调用函数指针：1 次取地址虚调用：取 vptr + 取槽 + 跳转
值得注意的一处差别。C 版把策略直接做成函数指针，比“对象 + 虚表”少一级间接；代价是没有地方挂策略自己的状态。如果某个策略真需要状态（比如老化计数），C 版就得多传一个 void *self，或者干脆为策略建一个结构体——那时它才真正变成“对象”。

06代价与坑

1. 策略和状态别混。策略由外部注入（“用哪种算法”是调用方的决定）；状态由对象自己迁移（“我现在处于哪个状态”是对象内部的事实）。判断标准：谁有权改它。
2. 无状态策略才能共享。三个策略对象被多个上下文共用时，千万别在策略里写可变成员；C 版的函数指针天然无状态，一旦加了 self 就要考虑每个上下文一份。
3. 策略不该知道上下文的细节。如果实现里开始读 ctx->queue_len、改上下文状态，它就不再是策略，而是在偷偷做状态机或模板方法。
4. 两个分支不值得。只有 A/B 两种、且以后也不会加时，if 比一个接口更便宜、更好读。模式的价值在“会持续增加第三种、第四种”。
