    享元模式FLYWEIGHT

    整车上千个信号，每个都要带单位、缩放、偏移。若每个信号各存一份字符串和系数，光描述就占掉可观内存，缓存命中也会变差。享元把“不随信号变化的部分”抽出来共享，每个信号只留一个指向描述的句柄。

    1000 个信号 8 份描述内部状态共享外部状态随信号走

    01问题：一千个信号，一千份单位描述

    坏写法是每个信号自带一份描述：

    typedef struct {
    char unit[8];      /* "kPa" 重复一千次 */
    double scale;
    int raw;           /* 这个才是变的 */
} signal_t;

    问题不在“能不能跑”，而在放大之后：

    • 内存翻倍。8 字节单位 × 1000 个信号，加上对齐填充，描述比数据还大。
    • 改一处要改一千处。单位从 kPa 改成 bar，所有信号的副本都要遍历修改。
    • 比较变慢。判断“两个信号同单位”要逐字符比较，而不是比较一个指针。

    享元把描述拆成“内部状态”（单位、缩放，可共享）与“外部状态”（raw 值，随信号走）。内部状态进池，外部状态留在信号对象里。

    02结构：内部状态共享，外部状态随行

    左边是信号句柄，中间是工厂，右边是共享描述池；一千个句柄只指向八份描述。

    信号句柄与共享描述flyweight
    职责点方框：共享的是描述，不是数值。

    03两份实现

    C 版用静态池 + 指针数组；C++ 版用 shared_ptr，引用计数就是“还有多少信号在用”。

    Cflyweight.c
    /* 享元：1000 个信号共用 8 份单位描述，只存指针 */
#include <stdio.h>
#include <string.h>
#include <stddef.h>

typedef struct {
    const char *unit;
    double scale;
} sig_t;

typedef struct {
    sig_t pool[8];
    int n;
} registry_t;

static const sig_t *intern(registry_t *r, const char *unit, double scale)
{
    for (int i = 0; i < r->n; i++)
        if (strcmp(r->pool[i].unit, unit) == 0) return &r->pool[i];
    if (r->n >= 8) return NULL;
    r->pool[r->n].unit = unit;
    r->pool[r->n].scale = scale;
    return &r->pool[r->n++];
}

int main(void)
{
    static const char *UNITS[] = { "C", "kPa", "rpm", "%", "V", "A", "km/h", "deg" };
    registry_t reg = { .n = 0 };
    const sig_t *signals[1000];

    size_t nu = sizeof UNITS / sizeof UNITS[0];
    for (size_t i = 0; i < 1000; i++)
        signals[i] = intern(&reg, UNITS[i % nu], 1.0 + (double)(i % nu) / 10.0);

    printf("信号 1000 个，描述池 %d 份\n", reg.n);
    printf("sig[0]   unit=%-4s scale=%.1f\n", signals[0]->unit, signals[0]->scale);
    printf("sig[7]   unit=%-4s scale=%.1f\n", signals[7]->unit, signals[7]->scale);
    printf("sig[999] unit=%-4s scale=%.1f\n", signals[999]->unit, signals[999]->scale);
    printf("指针相同：sig[0]==sig[8] -> %s\n", signals[0] == signals[8] ? "yes" : "no");
    return 0;
}
    RUN./flyweight.exe
    信号 1000 个，描述池 8 份

sig[7]   unit=deg  scale=1.7

指针相同：sig[0]==sig[8] -> yes
    C++flyweight.cpp
    // 享元 · C++：工厂缓存 shared_ptr，1000 个句柄只留 8 份对象
// 编译：g++ -std=c++17 -Wall -Wextra flyweight.cpp -o flyweight_cpp
#include <cstdio>
#include <map>
#include <memory>
#include <string>
#include <vector>

struct Signal {
    std::string unit;
    double scale;
};

class SignalFactory {
public:
    std::shared_ptr<const Signal> intern(const std::string &unit, double scale)
    {
        auto it = pool_.find(unit);
        if (it != pool_.end()) return it->second;
        auto s = std::make_shared<const Signal>(Signal{ unit, scale });
        pool_.emplace(unit, s);
        return s;
    }
    std::size_t size() const { return pool_.size(); }
private:
    std::map<std::string, std::shared_ptr<const Signal>> pool_;
};

int main()
{
    const std::string units[] = { "C", "kPa", "rpm", "%", "V", "A", "km/h", "deg" };
    SignalFactory f;
    std::vector<std::shared_ptr<const Signal>> signals;
    signals.reserve(1000);
    for (int i = 0; i < 1000; i++)
        signals.push_back(f.intern(units[static_cast<size_t>(i) % 8], 1.0 + (i % 8) / 10.0));

    std::printf("信号 1000 个，描述池 %zu 份\n", f.size());
    std::printf("sig[0]   unit=%-4s scale=%.1f use_count=%ld\n",
                signals[0]->unit.c_str(), signals[0]->scale, signals[0].use_count());
    std::printf("sig[999] unit=%-4s scale=%.1f\n",
                signals[999]->unit.c_str(), signals[999]->scale);
    std::printf("指针相同：sig[0]==sig[8] -> %s\n", signals[0] == signals[8] ? "yes" : "no");
    return 0;
}
    RUN./flyweight_cpp.exe
    信号 1000 个，描述池 8 份

sig[999] unit=deg  scale=1.7
指针相同：sig[0]==sig[8] -> yes

    05C 与 C++：共享的寿命

    角色C 版C++ 版差别意味着什么
    共享对象静态 sig_t pool[8]shared_ptr<const Signal>C 固定上限；C++ 可扩容且自动释放
    查重strcmp 线性扫描map 查找池小的时候线性也够；大了换哈希
    句柄const sig_t *shared_ptr 拷贝C 要保证池不重排；C++ 引用计数托管
    外部状态信号结构里的 raw调用时传入的 raw两者都不能塞进共享对象
    释放进程生命周期最后一个句柄释放时C 版通常不释放；C++ 版可能提前回收

    06代价与坑

    • 不要把 raw 放进享元。一旦把当前值塞进共享描述，两个信号就互相串数据；共享对象必须不可变。
    • 池不能边用边扩容重排。C 版用数组存池，扩容后旧指针全部失效；要么预分配上限，要么存索引不存指针。
    • 字符串比较不是免费的。一千个信号逐个 strcmp 也会慢；单位数量固定时，先做一次映射再按 id 取。
    • 共享对象的生命周期。C++ 的 shared_ptr 会让描述活得比预期久；确认没有长生命周期句柄时再指望回收。
    • 别为省内存牺牲可读性。只有描述确实重复且量大时才值得；十个信号用享元，收益不如直接写清楚。
