    享元模式FLYWEIGHT

    一片森林要画一千棵树。每棵树如果都存名字、叶色、纹理，内存很快见底。但这些字段大多数树是一样的。享元把可共享的内部状态抽出来共用，只把坐标这类外部状态留在每棵树上。

    内部状态共享外部状态随行C 用静态表 · C++ 用工厂缓存

    01问题：坏代码长什么样

    坏写法是每棵树复制一份描述：

    typedef struct { char name[16]; int color; int x, y; } tree_t;
/* 1000 棵树 → 1000 份 name 和 color */

    名字和颜色只有两种，却存了一千遍；真正每棵不同的是坐标。

    享元把 tree_type_t 抽出来，按名字查表共享；tree_t 只留一个类型指针和 x/y。一千棵树 → 两份描述 + 一千组坐标。

    02结构：共享内部状态，外部状态随行

    左边是森林，中间是共享类型表，右边是每棵树的外部状态。

    共享不变的部分，随行变化的部分structure
    职责享元省的是“重复的相同数据”，不是“对象本身”。

    03两份实现：C 与 C++

    C 版类型池是静态数组，按名字线性查；C++ 版用 map 缓存 shared_ptr。

    Cflyweight.c
    /* 享元 · 森林共享树型
 * gcc -std=c11 -Wall -Wextra flyweight.c -o flyweight
 */
#include <stdio.h>
#include <string.h>

typedef struct {
    char name[16];
    int  leaf_color;
} tree_type_t;

typedef struct {
    const tree_type_t *type;   /* 共享内部状态 */
    int x, y;                  /* 外部状态 */
} tree_t;

static tree_type_t TYPES[2] = {
    { "橡树", 0x2E7D32 },
    { "松树", 0x1B5E20 },
};

static const tree_type_t *get_type(const char *name)
{
    for (unsigned i = 0; i < 2; i++)
        if (strcmp(TYPES[i].name, name) == 0) return &TYPES[i];
    return NULL;
}

int main(void)
{
    tree_t forest[1000];
    int n = 0;
    for (int i = 0; i < 1000; i++) {
        forest[n].type = get_type(i % 2 ? "松树" : "橡树");
        forest[n].x = i * 3;
        forest[n].y = i * 5;
        n++;
    }

    printf("1000 棵树，共享 %d 份树型描述\n", 2);
    printf("%s x=%d y=%d color=0x%06X\n",
           forest[0].type->name, forest[0].x, forest[0].y, forest[0].type->leaf_color);
    printf("%s x=%d y=%d color=0x%06X\n",
           forest[999].type->name, forest[999].x, forest[999].y, forest[999].type->leaf_color);
    printf("每棵树只多存 2 个坐标，不复制颜色和名字\n");
    return 0;
}
    RUN./flyweight.exe
    1000 棵树，共享 2 份树型描述
橡树 x=0 y=0 color=0x2E7D32
松树 x=2997 y=4995 color=0x1B5E20
每棵树只多存 2 个坐标，不复制颜色和名字
    C++flyweight.cpp
    // 享元 · 森林共享树型
// g++ -std=c++17 -Wall -Wextra flyweight.cpp -o flyweight_cpp
#include <cstdio>
#include <memory>
#include <string>
#include <unordered_map>
#include <vector>

struct TreeType {
    std::string name;
    int leafColor;
};

class TreeFactory {
public:
    const TreeType& get(const std::string& name, int color) {
        auto it = pool_.find(name);
        if (it == pool_.end())
            it = pool_.emplace(name, TreeType{name, color}).first;
        return it->second;
    }
private:
    std::unordered_map<std::string, TreeType> pool_;
};

struct Tree {
    const TreeType* type;
    int x, y;
};

int main()
{
    TreeFactory factory;
    std::vector<Tree> forest;
    forest.reserve(1000);
    for (int i = 0; i < 1000; i++) {
        const auto& type = i % 2 ? factory.get("松树", 0x1B5E20)
                                 : factory.get("橡树", 0x2E7D32);
        forest.push_back(Tree{&type, i * 3, i * 5});
    }

    std::printf("1000 棵树，共享 2 份树型描述\n");
    std::printf("%s x=%d y=%d color=0x%06X\n",
                forest[0].type->name.c_str(), forest[0].x, forest[0].y, forest[0].type->leafColor);
    std::printf("%s x=%d y=%d color=0x%06X\n",
                forest[999].type->name.c_str(), forest[999].x, forest[999].y, forest[999].type->leafColor);
    std::puts("每棵树只多存 2 个坐标，不复制颜色和名字");
    return 0;
}
    RUN./flyweight_cpp.exe
    1000 棵树，共享 2 份树型描述
橡树 x=0 y=0 color=0x2E7D32
松树 x=2997 y=4995 color=0x1B5E20
每棵树只多存 2 个坐标，不复制颜色和名字

    05C 与 C++ 对照

    角色C 版C++ 版差别意味着什么
    共享池静态数组 + 线性查名map<string, shared_ptr>C 版简单，C++ 版查找更快
    内部状态tree_type_t 值TreeType 共享对象必须不可变
    外部状态每棵树的 x/y每棵树的 x/y随实例走，不进池
    省了多少1000 份描述 → 2 份同左省的是重复数据，不是全部内存

    06代价与坑

    参考教程：refactoringguru.cn

    • 共享对象被修改内部状态一旦可变，所有树一起变；共享对象必须只读。
    • 池无上限按用户输入无限建类型会泄漏；类型集合应是有限、可枚举的。
    • 把外部状态也塞进共享对象坐标、时间戳这类每实例不同的字段不能进池。
