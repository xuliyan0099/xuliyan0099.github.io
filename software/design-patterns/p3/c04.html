    装饰器模式DECORATOR

    一段文本要支持加粗、斜体、下划线，未来还可能有删除线。每加一种就复制一遍渲染函数，组合顺序也说不清。装饰器把每种效果做成一层：持有一个内层文本，输出时在自己的前后加标记。

    一层一件事顺序可见C 用值传递 · C++ 用包装对象

    01问题：坏代码长什么样

    坏写法是给每个组合写一个函数：

    render_bold(t);
render_bold_italic(t);
render_italic_bold_underline(t);   /* 组合越来越多 */

    N 种效果就有 2^N 种组合，函数名先爆炸。

    装饰器只做单层：bold(t) 返回 <b>…</b>，italic(t) 返回 <i>…</i>。叠加就是函数套函数，顺序直接写在调用里。

    02结构：一层只包一对标签

    左边是原始文本，中间两层装饰，右边是最终输出。

    每层只负责一对标签structure
    职责装饰层不改变文本内容，只改变表示。

    03两份实现：C 与 C++

    C 版装饰是“文本进、文本出”的纯函数，靠值拷贝避免别名；C++ 版装饰对象持有内层文本。

    Cdecorator.c
    /* 装饰器 · 给文本加粗、加斜体
 * gcc -std=c11 -Wall -Wextra decorator.c -o decorator
 */
#include <stdio.h>
#include <string.h>

typedef struct { char text[96]; } text_t;

static text_t bold(text_t t)
{
    text_t out;
    snprintf(out.text, sizeof out.text, "<b>%.*s</b>", (int)(sizeof out.text - 9), t.text);
    return out;
}

static text_t italic(text_t t)
{
    text_t out;
    snprintf(out.text, sizeof out.text, "<i>%.*s</i>", (int)(sizeof out.text - 9), t.text);
    return out;
}

int main(void)
{
    text_t t = { "hello" };
    printf("原始：%s\n", t.text);

    text_t b = bold(t);
    printf("加粗：%s\n", b.text);

    text_t bi = italic(b);
    printf("加粗+斜体：%s\n", bi.text);

    text_t ib = bold(italic(t));
    printf("顺序反过来：%s\n", ib.text);
    return 0;
}
    RUN./decorator.exe
    原始：hello
加粗：<b>hello</b>
加粗+斜体：<i><b>hello</b></i>
顺序反过来：<b><i>hello</i></b>
    C++decorator.cpp
    // 装饰器 · 给文本加粗、加斜体
// g++ -std=c++17 -Wall -Wextra decorator.cpp -o decorator_cpp
#include <cstdio>
#include <memory>
#include <string>

class Text {
public:
    virtual ~Text() = default;
    virtual std::string render() const = 0;
};

class Plain final : public Text {
public:
    explicit Plain(std::string s) : s_(std::move(s)) {}
    std::string render() const override { return s_; }
private:
    std::string s_;
};

class Bold final : public Text {
public:
    explicit Bold(std::unique_ptr<Text> inner) : inner_(std::move(inner)) {}
    std::string render() const override { return "<b>" + inner_->render() + "</b>"; }
private:
    std::unique_ptr<Text> inner_;
};

class Italic final : public Text {
public:
    explicit Italic(std::unique_ptr<Text> inner) : inner_(std::move(inner)) {}
    std::string render() const override { return "<i>" + inner_->render() + "</i>"; }
private:
    std::unique_ptr<Text> inner_;
};

int main()
{
    std::printf("原始：%s\n", Plain("hello").render().c_str());
    std::printf("加粗：%s\n", Bold(std::make_unique<Plain>("hello")).render().c_str());
    std::printf("加粗+斜体：%s\n",
                Italic(std::make_unique<Bold>(std::make_unique<Plain>("hello"))).render().c_str());
    std::printf("顺序反过来：%s\n",
                Bold(std::make_unique<Italic>(std::make_unique<Plain>("hello"))).render().c_str());
    return 0;
}
    RUN./decorator_cpp.exe
    原始：hello
加粗：<b>hello</b>
加粗+斜体：<i><b>hello</b></i>
顺序反过来：<b><i>hello</i></b>

    05C 与 C++ 对照

    角色C 版C++ 版差别意味着什么
    装饰怎么实现文本值进、文本值出装饰对象持有内层C 无对象层次，C++ 可动态组合
    顺序调用顺序即嵌套顺序构造顺序即嵌套顺序顺序由调用方负责
    拷贝成本每次复制整个结构体指针/引用传递C 版示例文本短，长文本要注意
    扩展新效果加一个函数加一个装饰子类都不改已有层

    06代价与坑

    参考教程：refactoringguru.cn

    • 装饰层里做业务装饰只改表示；加日志、鉴权会让组合语义混乱。
    • 顺序被隐式固定如果构造函数里自动排序，调用方就失去控制；顺序应显式。
    • C 版缓冲区不够拼接后长度会增加，必须按目标容量截断或动态分配。
