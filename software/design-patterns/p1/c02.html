    C 也能面向对象VTABLE

    后面 8 个模式的 C 版，全部建立在这一页的三件东西上：结构体首成员放函数表指针、派生类首成员嵌基类、把基类指针还原成派生类指针。看懂这三步，C 里的“多态”就不再是玄学，而是一次普通的间接跳转。

    C / C++ 输出一致 sizeof 实测：24 / 16 无堆分配

    01问题：同一段代码，两种形状

    没有多态时，调用方只有两个选择：要么写 switch (kind)，要么为每种形状复制一份同样的循环。加第三种形状，就得到处补分支——这就是“结构病”的起点。

    C++ 的答案你知道：virtual double area()。C 没有这个关键字，但虚函数在机器层面并不神秘：对象里存一个指针，指向一张全是函数指针的表；调用时先取表，再按固定偏移取函数地址，最后把对象自己当第一个参数传进去。这三步手工写出来，就是 C 的多态。

    02结构：对象里只有一个指针是真的“类型信息”

    点方框看每个角色负责什么。注意偏移：vptr 在 0，派生类的 base 也在 0——这就是为什么可以把 rect_t* 直接当 shape_t* 用。

    对象 → 虚表 → 代码：一次分派的三个落脚点layout
    职责点上面的方框（对象 / 虚表 / 函数），这里会说明它在这一跳里干什么。

    03两份实现：C 的手工虚表 vs C++ 的 virtual

    同一件事写两遍，第二遍只看编译器替你做了哪些事。源码在 src/coop.c 与 src/coop.cpp。

    Ccoop.c
    /* C 的面向对象地基：vtable + 结构体内嵌 + 指针还原
 * 编译：gcc -std=c11 -Wall -Wextra coop.c -o coop
 * 这段是所有 C 版设计模式的地基。
 */
#include <stddef.h>
#include <stdio.h>

typedef struct shape shape_t;

/* 虚函数表：一个结构体，里面全是函数指针 */
typedef struct {
    double      (*area)(const shape_t *self);
    const char *(*name)(const shape_t *self);
} shape_ops_t;

/* 基类：只有一个 vptr，布局与 C++ 的「有虚函数的类」一致 */
struct shape { const shape_ops_t *vptr; };

typedef struct { shape_t base; double w, h; } rect_t;
typedef struct { shape_t base; double r; }     circle_t;

static double rect_area(const shape_t *s) { const rect_t *r = (const rect_t *)s; return r->w * r->h; }
static const char *rect_name(const shape_t *s) { (void)s; return "rect"; }
static double circle_area(const shape_t *s) { const circle_t *c = (const circle_t *)s; return 3.14159 * c->r * c->r; }
static const char *circle_name(const shape_t *s) { (void)s; return "circle"; }

static const shape_ops_t RECT_OPS   = { rect_area, rect_name };
static const shape_ops_t CIRCLE_OPS = { circle_area, circle_name };

int main(void)
{
    rect_t   r = { { &RECT_OPS }, 3.0, 4.0 };   /* base 必须是第一个成员 */
    circle_t c = { { &CIRCLE_OPS }, 1.0 };

    /* 同一个接口，两种实现：动态分派发生在 vptr->area 这一跳 */
    const shape_t *shapes[] = { (const shape_t *)&r, (const shape_t *)&c };
    for (int i = 0; i < 2; i++) {
        const shape_t *s = shapes[i];
        printf("%-6s area=%6.2f  vptr=%s\n", s->vptr->name(s), s->vptr->area(s),
               s->vptr == &RECT_OPS ? "RECT_OPS" : "CIRCLE_OPS");
    }

    printf("offsetof(shape_t,vptr)=%u  sizeof(shape_t)=%u\n",
           (unsigned)offsetof(shape_t, vptr), (unsigned)sizeof(shape_t));
    printf("sizeof(rect_t)=%u  sizeof(circle_t)=%u\n",
           (unsigned)sizeof(rect_t), (unsigned)sizeof(circle_t));
    printf("把 rect_t* 当 shape_t* 用是合法的：base 在偏移 0\n");
    return 0;
}
    C++coop.cpp
    // C++ 的对应写法：虚函数由编译器生成 vptr + vtable
// 编译：g++ -std=c++17 -Wall -Wextra coop.cpp -o coop_cpp
#include <cstdio>

class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
    virtual const char* name() const = 0;
};

class Rect final : public Shape {
public:
    Rect(double w, double h) : w_(w), h_(h) {}
    double area() const override { return w_ * h_; }
    const char* name() const override { return "rect"; }
private:
    double w_, h_;
};

class Circle final : public Shape {
public:
    explicit Circle(double r) : r_(r) {}
    double area() const override { return 3.14159 * r_ * r_; }
    const char* name() const override { return "circle"; }
private:
    double r_;
};

int main() {
    Rect   r(3.0, 4.0);
    Circle c(1.0);

    Shape* shapes[] = { &r, &c };
    for (Shape* s : shapes)
        std::printf("%-6s area=%6.2f\n", s->name(), s->area());

    std::printf("sizeof(Rect)=%d  sizeof(Circle)=%d  sizeof(void*)=%d\n",
                static_cast<int>(sizeof(Rect)), static_cast<int>(sizeof(Circle)),
                static_cast<int>(sizeof(void*)));
    std::printf("单继承下 vptr 也在偏移 0：把 Rect* 转 Shape* 不用调整地址\n");
    return 0;
}

    05四个零件，两种语言

    把“面向对象”拆成四件事看，就很容易判断 C 版缺了什么。

    零件C 的做法C++ 的对应C 要自己保证的事
    封装头文件只放不完整类型 typedef struct cfg cfg_t;，成员留在 .cprivate没有访问控制，只能靠不透明指针 + 约定
    继承派生结构体第一个成员是基类: public Base必须偏移 0；多继承要手工算偏移
    多态s->vptr->area(s)virtual 调用（隐式 this）函数表放 const；self 不能漏传
    销毁函数表里加 void (*destroy)(shape_t*)virtual ~Shape()没有虚析构，忘了就漏资源
    一句话。C 的“对象”就是一个结构体 + 一张函数表 + 一群第一个参数叫 self 的普通函数。C++ 把这三样藏进了语法，代价是你要理解它藏了什么；C 把它摊在桌面上，代价是每一处都得自己写对。

    06代价与坑

    1. base 不在偏移 0，强转就是未定义行为。不要为了“省几个字节”把 base 放到中间；需要多重继承的布局时，老老实实算偏移或改用接口表 + 独立字段。
    2. 没有虚析构，基类指针 destroy 会漏资源。C 版必须在 ops 里放 destroy，并且所有释放都走它；不要出现 free(shape) 这种绕过表的写法。
    3. 函数表被写坏，整类对象一起崩。ops 表声明成 static const，放在只读段；初始化后不要再去改它。表里少一个槽位，所有派生类都会按错偏移调用。
    4. 间接调用挡不住内联。热路径上（比如每帧都跑的插值）用表调用会失去内联机会。C 可以保留一个“已知类型”的直调分支，C++ 可以靠 final / 具体对象让编译器去虚化。
