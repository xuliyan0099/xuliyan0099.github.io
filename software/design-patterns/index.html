地基 · 不是模式C 也能面向对象COOP首成员嵌基类、函数指针表、指针还原，看懂这一页，后面 8 页的 C 版都不再陌生。 行为型策略STRATEGY同一段调度代码，换算法不换调用点。CAN 发送队列的 FIFO / EDF / 优先级三种策略。 行为型观察者OBSERVER一处采样，仪表、记录仪、诊断各自收通知；重点演示“回调里退订”为什么会漏发。 行为型状态STATEECU 的 OFF / ACC / ON / RUN / FAULT：表驱动与状态类两种写法，非法转移统一拒绝。 行为型命令COMMAND诊断参数写入排队、执行、撤销：命令对象自己记住旧值，历史栈只认接口。 行为型责任链CHAIN报文过滤：长度 → CRC → 白名单 → 业务，每一环都能就地终止，并说明是谁丢的。 结构型适配器ADAPTER两种温湿度传感器、两套厂商 API，上层只写一段 report()；顺带分清装饰器和代理。 创建型工厂 + 注册表FACTORY按名字创建驱动，新增型号只加一行注册；未注册时明确返回空，让上层降级。 创建型单例SINGLETON唯一配置对象怎么保证；更要看清它的代价：全局可变状态、测试污染、线程安全。

04三条读法

从地基开始（推荐给写 C 的人）。先看 C 也能面向对象，弄清“vptr 在第 0 字节”这件事，再按顺序读策略 → 观察者 → 状态。C 版的每个模式，本质都是这一页的排列组合。

按症状查。用上面第 01 节。选中之后先看“代价/坑”，再看代码：模式真正的成本，通常不在写法，而在它引入的间接层。

按分类通读。创建型看工厂与单例；结构型看适配器（装饰器、代理的差别在页末对照）；行为型五页连起来看，会发现它们都在回答同一个问题：把“谁在什么时候做什么”从调用链里拆出来，放到一个可替换、可观察、可测试的结构里。

看图的约定。实线箭头 = 调用或持有；虚线箭头 = 实现或订阅关系；方框里第一行是类型名，第二行斜体是它的角色，第三行等宽字体是它暴露的方法。点任意方框，图下方的说明栏会换成那个角色的职责。

05经典出处与本节的取舍

目录结构和“意图 / 问题 / 结构 / 代价”的讲法，沿用 Refactoring.Guru 的设计模式目录；C++ 全 23 个模式的可运行示例在 GitHub：RefactoringGuru/design-patterns-cpp（每个模式都有 Conceptual 与 RealWorld 两套）。C 侧“用结构体 + 函数指针表实现封装、继承、多态”的原典是 Axel-Tobias Schreiner 的《Object-Oriented Programming with ANSI-C》，有 中文社区译本。

本节的代码没有抄这些示例：场景换成了车载/嵌入式语境（CAN 调度、ECU 状态机、报文过滤、驱动注册），每份源码都保留在 src/ 目录，页面里的“运行结果”是实际跑出来的输出。C 版统一用静态存储 + 函数指针表，避免在示例里引入堆分配；C++ 版统一用 unique_ptr / shared_ptr 表达所有权。

一点提醒：模式是事后命名，不是事前套用。先写出能跑的直白版本，等第二、第三个调用方出现、结构开始重复时，再回来找名字。
