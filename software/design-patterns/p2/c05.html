    单例模式SINGLETON

    主题、字号、语言这些配置每个模块都要读。到处传参太啰嗦，到处复制又会改出多份。单例把“唯一实例”收在一个入口后面：谁调都拿到同一个地址，初始化只发生一次。

    一个入口初始化一次C 用函数内静态 · C++ 用 Meyers 单例

    01问题：坏代码长什么样

    坏写法是每个模块自己存一份：

    config_t cfg_a = { "light", 12 };
config_t cfg_b = { "light", 12 };   /* 改 a，b 不知道 */

    两份初始值一样，运行一会儿就分叉：设置页改了主题，主窗口还是旧的。

    单例只留一个入口 instance()：第一次调用时初始化，之后都返回同一个对象。它不是“全局变量换皮”，而是把初始化时机和唯一性一起管住。

    02结构：唯一入口与唯一实例

    左边三个模块，中间是唯一入口，右边是同一份配置。

    三个调用点，一个地址structure
    职责入口负责“有没有”；实例负责“是什么”。

    03两份实现：C 与 C++

    C 版用函数内 static，初始化天然只跑一次；C++ 版用函数内静态对象（Meyers singleton），C++11 起线程安全。

    Csingleton.c
    /* 单例 · 全局配置
 * gcc -std=c11 -Wall -Wextra singleton.c -o singleton
 */
#include <stdio.h>
#include <string.h>

typedef struct {
    char theme[16];
    int  font_size;
} config_t;

static config_t *instance(void)
{
    static config_t cfg = { "light", 12 };
    static int inited = 0;
    if (!inited) {
        inited = 1;
        printf("  初始化配置（只发生一次）\n");
    }
    return &cfg;
}

int main(void)
{
    config_t *a = instance();
    config_t *b = instance();
    config_t *c = instance();

    printf("取三次实例：%p %p %p（同一个地址）\n", (void *)a, (void *)b, (void *)c);

    strcpy(a->theme, "dark");
    a->font_size = 16;
    printf("通过 a 改成 %s/%d，通过 c 读：%s/%d\n",
           a->theme, a->font_size, c->theme, c->font_size);
    return 0;
}

通过 a 改成 dark/16，通过 c 读：dark/16
    C++singleton.cpp
    // 单例 · 全局配置
// g++ -std=c++17 -Wall -Wextra singleton.cpp -o singleton_cpp
#include <cstdio>
#include <string>

class Config {
public:
    static Config& instance() {
        static Config cfg;
        return cfg;
    }

    std::string theme = "light";
    int font_size = 12;

    Config(const Config&) = delete;
    Config& operator=(const Config&) = delete;

private:
    Config() { std::puts("  初始化配置（只发生一次）"); }
};

int main()
{
    Config& a = Config::instance();
    Config& b = Config::instance();
    Config& c = Config::instance();

    std::printf("取三次实例：%p %p %p（同一个地址）\n",
                static_cast<void*>(&a), static_cast<void*>(&b), static_cast<void*>(&c));

    a.theme = "dark";
    a.font_size = 16;
    std::printf("通过 a 改成 %s/%d，通过 c 读：%s/%d\n",
                a.theme.c_str(), a.font_size, c.theme.c_str(), c.font_size);
    return 0;
}

    05C 与 C++ 对照

    角色C 版C++ 版差别意味着什么
    唯一性怎么保证函数内 static函数内静态对象都靠语言级静态存储
    初始化时机首次调用首次调用懒初始化，不增加启动成本
    线程安全C11 起静态初始化有保证C++11 起局部静态初始化线程安全旧编译器要自己加锁
    销毁进程结束时释放进程结束时析构一般不需要手动 delete

    06代价与坑

    参考教程：refactoringguru.cn

    • 把单例当全局变量单例适合“确实唯一且到处要读”的配置；普通共享数据用依赖注入更可测。
    • 在单例里做重活构造函数里读文件、连网络会让首次调用变慢且难测。
    • 多线程下双重检查写错C++ 直接用局部静态；C 用 pthread_once，不要手写裸双检。
