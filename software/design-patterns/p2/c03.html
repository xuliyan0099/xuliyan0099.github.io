    建造者模式BUILDER

    盖房子不是一次 malloc 就能完事：墙、门、窗、屋顶有先后，少一步就是半成品。建造者把“怎么一步步拼”收进流程，每一步都可检查，最后只交付一次成品。

    步骤显式交付前校验C 用函数参数 · C++ 用链式调用

    01问题：坏代码长什么样

    坏写法是一个巨大的初始化函数，参数排成一串：

    house_t h = { 4, 1, 2, 1 };  /* 墙、门、窗、屋顶？顺序错了也编译过 */

    位置参数没有名字，调用方靠记忆；漏一个字段就是“能住但漏雨”的半成品，而且没有任何地方能拦住。

    建造者把每个步骤变成一次具名调用，最后 build() 统一校验。顺序、缺项、成品完整度都摆在代码里。

    02结构：步骤显式、交付前校验

    左边是施工队，中间是建造者，右边是成品房子。

    四步施工，最后校验一次structure
    职责建造者持有“正在盖的房子”；校验通过才允许拿走。

    03两份实现：C 与 C++

    C 版每一步都是 house_t* 上的函数，最后由 build 返回成败；C++ 版用引用串联步骤，build() 返回值对象。

    Cbuilder.c
    /* 建造者 · 一步步盖房子
 * gcc -std=c11 -Wall -Wextra builder.c -o builder
 */
#include <stdio.h>

typedef struct {
    int walls, doors, windows;
    int has_roof;
} house_t;

static void add_walls(house_t *h, int n)   { h->walls = n;   printf("  砌 %d 面墙\n", n); }
static void add_doors(house_t *h, int n)   { h->doors = n;   printf("  装 %d 扇门\n", n); }
static void add_windows(house_t *h, int n) { h->windows = n; printf("  装 %d 扇窗\n", n); }
static void add_roof(house_t *h)           { h->has_roof = 1; printf("  封顶\n"); }

static int build(const house_t *h)
{
    if (h->walls < 4 || h->doors < 1 || h->windows < 1 || !h->has_roof) {
        printf("  校验失败：房子还不完整\n");
        return -1;
    }
    printf("  交付：%d 墙 / %d 门 / %d 窗 / 有屋顶\n",
           h->walls, h->doors, h->windows);
    return 0;
}

int main(void)
{
    house_t h = { 0, 0, 0, 0 };
    printf("普通小屋：\n");
    add_walls(&h, 4); add_doors(&h, 1); add_windows(&h, 2); add_roof(&h);
    build(&h);

    house_t v = { 0, 0, 0, 0 };
    printf("缺步骤的房子：\n");
    add_walls(&v, 4); add_doors(&v, 1);
    build(&v);
    return 0;
}
    RUN./builder.exe

  装 1 扇门
  装 2 扇窗
  封顶
  交付：4 墙 / 1 门 / 2 窗 / 有屋顶

  砌 4 面墙

    C++builder.cpp
    // 建造者 · 一步步盖房子
// g++ -std=c++17 -Wall -Wextra builder.cpp -o builder_cpp
#include <cstdio>
#include <string>

class House {
public:
    std::string walls, doors, windows;
    bool roof = false;
};

class HouseBuilder {
public:
    HouseBuilder& addWalls(int n)   { h_.walls   = std::to_string(n) + " 面墙"; std::printf("  砌 %d 面墙\n", n); return *this; }
    HouseBuilder& addDoors(int n)   { h_.doors   = std::to_string(n) + " 扇门"; std::printf("  装 %d 扇门\n", n); return *this; }
    HouseBuilder& addWindows(int n) { h_.windows = std::to_string(n) + " 扇窗"; std::printf("  装 %d 扇窗\n", n); return *this; }
    HouseBuilder& addRoof()         { h_.roof = true; std::puts("  封顶"); return *this; }

    bool build() const {
        if (h_.walls.empty() || h_.doors.empty() || h_.windows.empty() || !h_.roof) {
            std::puts("  校验失败：房子还不完整");
            return false;
        }
        std::printf("  交付：%s / %s / %s / 有屋顶\n",
                    h_.walls.c_str(), h_.doors.c_str(), h_.windows.c_str());
        return true;
    }

private:
    House h_;
};

int main()
{
    std::puts("普通小屋：");
    HouseBuilder{}.addWalls(4).addDoors(1).addWindows(2).addRoof().build();

    std::puts("缺步骤的房子：");
    HouseBuilder{}.addWalls(4).addDoors(1).build();
    return 0;
}
    RUN./builder_cpp.exe

  封顶

    05C 与 C++ 对照

    角色C 版C++ 版差别意味着什么
    步骤怎么表达具名函数 add_walls(h, 4)链式 w(4).d(1).win(2).roof()C 显式传对象，C++ 可连写
    中间状态放哪调用方栈上的 house_t建造者对象内部C 版无隐藏状态，C++ 版封装更好
    校验时机build() 返回 -1build() 返回 optional/抛错都必须在交付前
    成品归属值拷贝或指针值返回，移动语义C 版注意别把栈地址带出去

    06代价与坑

    参考教程：refactoringguru.cn

    • 步骤可以任意跳过建造者要能表达“缺项”，并在 build 时拒绝；不要默认补全。
    • build 之后还能改成品交付后应视为不可变；否则校验结果立刻失效。
    • 把所有业务都塞进建造者建造者只管拼装与完整性，不要在里面发网络请求、写数据库。
