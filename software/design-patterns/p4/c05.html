    中介者模式MEDIATOR

    三个模块两两直连是 3 条线，五个模块是 10 条线，十个模块是 45 条。中介者让每个模块只认识总线，消息由总线决定投给谁；新增模块只加一个连接，不改其他人的代码。

    N² 条线收成 N 条发送方不认识接收方路由规则集中一处

    01问题：N 个模块两两直连，N² 条线

    两两直连的代码通常长这样：

    engine.brake = &brake;
engine.dash  = &dash;
brake.dash   = &dash;
    • 依赖网越织越密。每加一个模块，都要改已有模块的初始化，漏一条就收不到消息。
    • 路由规则散落。“BRAKE 要广播、TEMP 只给仪表”写在各个发送方里，改规则要翻遍代码。
    • 无法统一审计。想知道谁发了什么，只能逐模块加日志。

    中介者把所有发送改成“发给总线”，总线按主题路由。发送方只认识 bus，接收方只认识自己的处理函数；路由规则只有一份。

    02结构：所有消息过总线

    三个节点围着总线；点方框看一条消息会被投给谁。

    总线式中介者：三个节点，一个路由中心mediator
    职责点方框：发送方只认总线，路由规则只在总线里。

    03两份实现

    C 版用节点数组 + 一个 bus_publish()；C++ 版用 Mediator 类持有 Colleague*。

    Cmediator.c
    /* 中介者：三个 ECU 不互相认识，所有转发走同一条总线 */
#include <stdio.h>
#include <string.h>

typedef struct mediator mediator_t;
typedef struct ecu ecu_t;

struct ecu { const char *name; mediator_t *bus; };
struct mediator { ecu_t *nodes[3]; int n; };

static void bus_publish(mediator_t *m, ecu_t *from, const char *topic)
{
    printf("[BUS] %s -> %s\n", from->name, topic);
    for (int i = 0; i < m->n; i++) {
        ecu_t *to = m->nodes[i];
        if (to == from) continue;
        int want = strcmp(topic, "BRAKE") == 0 || strcmp(to->name, "DASH") == 0;
        if (want) printf("      %s handles %s\n", to->name, topic);
    }
}

int main(void)
{
    ecu_t engine = { "ENGINE", NULL };
    ecu_t dash   = { "DASH",   NULL };
    ecu_t brake  = { "BRAKE",  NULL };
    mediator_t bus = { .nodes = { &engine, &dash, &brake }, .n = 3 };

    engine.bus = &bus; dash.bus = &bus; brake.bus = &bus;

    bus_publish(&bus, &engine, "BRAKE");
    bus_publish(&bus, &engine, "TEMP");
    bus_publish(&bus, &brake,  "WHEEL_SPEED");
    printf("发送方只认识 bus，不认识另外两个节点\n");
    return 0;
}

    C++mediator.cpp
    // 中介者 · C++：Colleague 只持 Mediator&，路由规则集中在一处
// 编译：g++ -std=c++17 -Wall -Wextra mediator.cpp -o mediator_cpp
#include <cstdio>
#include <string>
#include <vector>

class Mediator;

class Colleague {
public:
    explicit Colleague(std::string name) : name_(std::move(name)) {}
    virtual ~Colleague() = default;
    const std::string &name() const { return name_; }
    void join(Mediator *m) { bus_ = m; }
    void publish(const std::string &topic);   /* 定义放在 Mediator 之后 */
protected:
    Mediator *bus_ = nullptr;
private:
    std::string name_;
};

class Mediator {
public:
    void add(Colleague *c) { nodes_.push_back(c); c->join(this); }
    void route(Colleague *from, const std::string &topic)
    {
        std::printf("[BUS] %s -> %s\n", from->name().c_str(), topic.c_str());
        for (auto *to : nodes_) {
            if (to == from) continue;
            bool want = topic == "BRAKE" || to->name() == "DASH";
            if (want) std::printf("      %s handles %s\n", to->name().c_str(), topic.c_str());
        }
    }
private:
    std::vector<Colleague *> nodes_;
};

inline void Colleague::publish(const std::string &topic)
{
    if (bus_) bus_->route(this, topic);
}

int main()
{
    Mediator bus;
    Colleague engine("ENGINE"), dash("DASH"), brake("BRAKE");
    bus.add(&engine); bus.add(&dash); bus.add(&brake);

    engine.publish("BRAKE");
    engine.publish("TEMP");
    brake.publish("WHEEL_SPEED");
    std::printf("发送方只认识 bus，不认识另外两个节点\n");
    return 0;
}

    05C 与 C++：谁持有谁

    角色C 版C++ 版差别意味着什么
    中心mediator_t + 节点数组Mediator + vector<Colleague*>C 固定上限；C++ 动态加入
    发送bus_publish(bus, from, topic)from->publish(topic)C 要显式传总线；C++ 节点持有总线指针
    路由总线内 strcmp 判断总线内 topic == 判断规则集中，但仍是硬编码字符串
    回环跳过 from跳过 from不跳会自己通知自己，递归爆栈
    新增节点加进数组 + 设 bus构造 + add()两边都不改已有节点

    06代价与坑

    • 中介者会变成上帝对象。所有路由都塞进去，最后它知道每个模块的业务细节；路由规则要按主题分层，必要时拆多个总线。
    • 别忘跳过发送方。广播时把自己也通知一遍，轻则重复处理，重则递归。
    • 同步调用会放大延迟。一个 publish 里同步跑完所有接收方，慢的接收方拖住发送方；实时总线要考虑队列或异步。
    • C 版字符串主题易拼错。用枚举或常量表，别让 "BRAKE" 和 "BRAKE " 成为两个主题。
    • 死锁风险。接收方在回调里再 publish，可能形成环；路由要检测重入或限制深度。
