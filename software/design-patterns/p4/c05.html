    中介者模式MEDIATOR

    三个用户两两直连是 3 条线，十个用户就是 45 条。每加一个人，所有人都要认识他。中介者把连线收到中间：用户只认识房间，房间负责转发。

    N² 降到 N用户互不持有C 用房间数组 · C++ 用类

    01问题：坏代码长什么样

    坏写法是用户互相保存指针：

    alice.to[0] = &bob; alice.to[1] = &carol;
bob.to[0] = &alice; /* 每加一个人，所有人都要改 */

    连线数量随人数平方增长，而且“谁在线、谁能收”这类规则散落在每个用户里。

    中介者让用户只持有 room：发消息调 send(from, msg)，房间遍历名单转发。加人只改房间名单。

    02结构：所有消息穿过房间

    左边是三个用户，中间是聊天室，右边是转发目标。

    所有线穿过房间，用户之间不直连structure
    职责中介者知道“谁在名单里”，用户只知道“往哪发”。

    03两份实现：C 与 C++

    C 版房间是用户指针数组；C++ 版房间是类，用户持有房间指针。

    Cmediator.c
    /* 中介者 · 聊天室转发
 * gcc -std=c11 -Wall -Wextra mediator.c -o mediator
 */
#include <stdio.h>
#include <string.h>

typedef struct chat chat_t;
typedef struct { const char *name; chat_t *room; } user_t;

struct chat { user_t *users[4]; int n; };

static void join(chat_t *c, user_t *u) { u->room = c; c->users[c->n++] = u; }

static void send(user_t *from, const char *msg)
{
    printf("%s: %s\n", from->name, msg);
    for (int i = 0; i < from->room->n; i++) {
        user_t *u = from->room->users[i];
        if (u != from) printf("  -> %s 收到\n", u->name);
    }
}

int main(void)
{
    chat_t room = { { 0 }, 0 };
    user_t alice = { "Alice", NULL };
    user_t bob   = { "Bob", NULL };
    user_t carol = { "Carol", NULL };
    join(&room, &alice); join(&room, &bob); join(&room, &carol);

    send(&alice, "晚上好");
    send(&bob, "在的");
    printf("三个用户互不知道对方地址，只认识 room\n");
    return 0;
}

  -> Carol 收到
Bob: 在的
  -> Alice 收到
  -> Carol 收到
三个用户互不知道对方地址，只认识 room
    C++mediator.cpp
    // 中介者 · 聊天室转发
// g++ -std=c++17 -Wall -Wextra mediator.cpp -o mediator_cpp
#include <cstdio>
#include <string>
#include <vector>

class ChatRoom;

class User {
public:
    User(std::string name) : name_(std::move(name)) {}
    void join(ChatRoom* room);
    void send(const std::string& msg);
    const std::string& name() const { return name_; }
private:
    std::string name_;
    ChatRoom* room_ = nullptr;
};

class ChatRoom {
public:
    void add(User* u) { users_.push_back(u); }
    void broadcast(User* from, const std::string& msg) {
        std::printf("%s: %s\n", from->name().c_str(), msg.c_str());
        for (auto u : users_)
            if (u != from) std::printf("  -> %s 收到\n", u->name().c_str());
    }
private:
    std::vector<User*> users_;
};

void User::join(ChatRoom* room) { room_ = room; room->add(this); }

void User::send(const std::string& msg) {
    if (room_) room_->broadcast(this, msg);
}

int main()
{
    ChatRoom room;
    User alice("Alice"), bob("Bob"), carol("Carol");
    alice.join(&room); bob.join(&room); carol.join(&room);

    alice.send("晚上好");
    bob.send("在的");
    std::puts("三个用户互不知道对方地址，只认识 room");
    return 0;
}
    RUN./mediator_cpp.exe
    Alice: 晚上好
  -> Bob 收到
  -> Carol 收到
Bob: 在的
  -> Alice 收到
  -> Carol 收到

    05C 与 C++ 对照

    角色C 版C++ 版差别意味着什么
    中介者形态chat_t + 用户数组ChatRoom 类C 用数组，C++ 用容器
    用户持有什么chat_t*ChatRoom*都只有一条反向引用
    广播规则遍历 users[]遍历 users_规则只在中介者里
    扩展加人进数组加人进容器用户代码不改

    06代价与坑

    参考教程：refactoringguru.cn

    • 中介者变成上帝对象所有业务都塞进房间，它会长成第二个“万能模块”；只做路由和名单。
    • 用户和中介者互相持有又销毁C++ 用裸指针要约定谁先死；必要时用弱引用。
    • 广播包含发送者自己收到自己的消息，通常要显式排除。
