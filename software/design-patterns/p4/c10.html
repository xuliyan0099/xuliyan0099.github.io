    模板方法模式TEMPLATE METHOD

    台架自检和现场自检的步骤完全一样：电源、通信、传感器，任何一步失败就中止。差别只在每步的具体实现。模板方法把顺序写在一个 run() 里，把每步留成可覆写的钩子，两个变体共用同一套日志和短路规则。

    骨架只写一遍步骤可替换失败立即中止

    01问题：自检流程抄了四遍，顺序还不一致

    复制流程的写法：

    int bench_test(void) { power(); comm(); sensor(); ... }
int field_test(void) { power(); comm(); sensor(); ... }

    两份代码看起来一样，实际已经开始漂移：

    • 顺序不一致。现场版为了快，把传感器挪到通信前面，失败日志就对不上。
    • 短路规则不同。台架版继续跑完，现场版第一步失败就退出，统计口径不同。
    • 加一步要改多处。新增“绝缘检查”，两份都要改，第三份测试桩又漏了。

    模板方法只保留一个 run()：顺序、日志、短路都在骨架里；子类只实现 power()/comm()/sensor()。新增步骤只改骨架一处。

    02结构：骨架固定，步骤可换

    骨架在左，两个变体在右；点方框看失败如何中止后续步骤。

    自检骨架与两个变体template method
    职责点方框：骨架不关心步骤怎么实现，只关心顺序与失败。

    03两份实现

    C 版用函数指针表；C++ 版 run() 非虚、三个步骤虚函数。

    Ctemplate_method.c
    /* 模板方法：自检顺序固定，每一步换成具体实现 */
#include <stdio.h>

typedef struct {
    const char *name;
    int (*power)(void);
    int (*comm)(void);
    int (*sensor)(void);
} selftest_t;

/* 骨架：顺序不可改，任何一步失败立即中止 */
static int run(const selftest_t *t)
{
    printf("== %s ==\n", t->name);
    printf("step1 power  ... ");
    if (!t->power())  { printf("FAIL\n"); return 0; }
    printf("OK\n");

    printf("step2 comm   ... ");
    if (!t->comm())   { printf("FAIL\n"); return 0; }
    printf("OK\n");

    printf("step3 sensor ... ");
    if (!t->sensor()) { printf("FAIL\n"); return 0; }
    printf("OK\n");

    printf("result PASS\n");
    return 1;
}

static int p_ok(void)  { return 1; }
static int c_ok(void)  { return 1; }
static int s_ok(void)  { return 1; }
static int s_bad(void) { return 0; }

int main(void)
{
    const selftest_t bench = { "bench",  p_ok, c_ok, s_ok };
    const selftest_t field = { "field",  p_ok, c_ok, s_bad };

    run(&bench);
    run(&field);
    printf("两个变体共用同一套顺序与日志\n");
    return 0;
}

    C++template_method.cpp
    // 模板方法 · C++：run() 非虚，步骤虚函数，子类只覆写细节
// 编译：g++ -std=c++17 -Wall -Wextra template_method.cpp -o template_method_cpp
#include <cstdio>
#include <string>

class SelfTest {
public:
    explicit SelfTest(std::string name) : name_(std::move(name)) {}
    virtual ~SelfTest() = default;

    // 模板：不打算被覆写
    bool run() const
    {
        std::printf("== %s ==\n", name_.c_str());
        std::printf("step1 power  ... ");
        if (!power())  { std::printf("FAIL\n"); return false; }
        std::printf("OK\n");
        std::printf("step2 comm   ... ");
        if (!comm())   { std::printf("FAIL\n"); return false; }
        std::printf("OK\n");
        std::printf("step3 sensor ... ");
        if (!sensor()) { std::printf("FAIL\n"); return false; }
        std::printf("OK\n");
        std::printf("result PASS\n");
        return true;
    }
protected:
    virtual bool power() const = 0;
    virtual bool comm() const = 0;
    virtual bool sensor() const = 0;
private:
    std::string name_;
};

class BenchTest : public SelfTest {
public:
    BenchTest() : SelfTest("bench") {}
protected:
    bool power() const override { return true; }
    bool comm() const override { return true; }
    bool sensor() const override { return true; }
};

class FieldTest : public SelfTest {
public:
    FieldTest() : SelfTest("field") {}
protected:
    bool power() const override { return true; }
    bool comm() const override { return true; }
    bool sensor() const override { return false; }
};

int main()
{
    BenchTest b;
    FieldTest f;
    b.run();
    f.run();
    std::printf("两个变体共用同一套顺序与日志\n");
    return 0;
}

    05C 与 C++：谁定义骨架

    角色C 版C++ 版差别意味着什么
    骨架run(const selftest_t*)SelfTest::run()（非虚）顺序只写一份
    步骤三个函数指针三个纯虚函数C 换表项；C++ 换派生类
    失败返回 0 并立即 return返回 false 并立即 return短路规则一致
    日志骨架里统一打印骨架里统一打印变体不再各自打日志
    新增步骤改结构体 + 骨架加虚函数 + 骨架只改骨架一处，变体补实现

    06代价与坑

    • 骨架不能太胖。把业务判断塞进 run()，子类就失去意义；骨架只该管顺序、日志、短路。
    • 虚函数别在构造/析构里调。构造时派生类还没建好，调用会分派到基类版本。
    • C 版函数指针要判空。表项漏填就是空指针调用，直接崩；初始化时统一校验。
    • 失败要带步骤。只返回 false，现场不知道是哪步；骨架应输出步骤名或错误码。
    • 别把模板方法当“万能流程”。步骤之间若有复杂条件分支，硬套骨架会让每个钩子都带一堆参数，反而更难读。
