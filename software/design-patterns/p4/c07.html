    观察者模式OBSERVER

    气温变化时，手机 App 要刷新，客厅大屏也要刷新。如果采样函数里直接调这两个界面，采样就被界面绑架了。观察者把“发布”和“订阅”分开：发布者只遍历名单，订阅者各自处理。

    发布订阅解耦名单可增删C 用回调数组 · C++ 用虚接口

    01问题：坏代码长什么样

    坏写法是采样函数里写死通知：

    void on_temp(int t) {
    phone_update(t);
    screen_update(t);   /* 加一个界面就要改这里 */
}

    每加一个展示端就改采样；某个端暂时不想收，也只能改代码。

    观察者让发布者持有一份订阅名单：subscribe(o) 加入，set_temp() 遍历调用 update。采样不再认识具体界面。

    02结构：发布者只发事件

    左边是天气站，中间是订阅名单，右边是两个订阅者。

    发布者只发事件，订阅者各自处理structure
    职责发布者不知道订阅者是谁；订阅者不知道还有谁订阅。

    03两份实现：C 与 C++

    C 版订阅者是 {name, callback} 结构；C++ 版是抽象 Observer，发布者存指针。

    Cobserver.c
    /* 观察者 · 天气站订阅
 * gcc -std=c11 -Wall -Wextra observer.c -o observer
 */
#include <stdio.h>

typedef struct { const char *name; void (*update)(const char *, int); } observer_t;

typedef struct {
    observer_t *subs[4];
    int n;
} station_t;

static void subscribe(station_t *s, observer_t *o) { s->subs[s->n++] = o; }

static void set_temp(station_t *s, int t)
{
    printf("气温 -> %d℃\n", t);
    for (int i = 0; i < s->n; i++)
        s->subs[i]->update(s->subs[i]->name, t);
}

static void phone(const char *name, int t)   { printf("  %s：显示 %d℃\n", name, t); }
static void display(const char *name, int t) { printf("  %s：大屏刷新 %d℃\n", name, t); }

int main(void)
{
    station_t s = { { 0 }, 0 };
    observer_t a = { "手机 App", phone };
    observer_t b = { "客厅大屏", display };
    subscribe(&s, &a); subscribe(&s, &b);

    set_temp(&s, 21);
    set_temp(&s, 24);
    printf("发布者不认识订阅者，只遍历名单\n");
    return 0;
}
    RUN./observer.exe
    气温 -> 21℃
  手机 App：显示 21℃
  客厅大屏：大屏刷新 21℃
气温 -> 24℃
  手机 App：显示 24℃
  客厅大屏：大屏刷新 24℃
发布者不认识订阅者，只遍历名单
    C++observer.cpp
    // 观察者 · 天气站订阅
// g++ -std=c++17 -Wall -Wextra observer.cpp -o observer_cpp
#include <cstdio>
#include <string>
#include <vector>

class Observer {
public:
    virtual ~Observer() = default;
    virtual void update(int temp) = 0;
};

class WeatherStation {
public:
    void subscribe(Observer* o) { subs_.push_back(o); }
    void setTemp(int t) {
        std::printf("气温 -> %d℃\n", t);
        for (auto o : subs_) o->update(t);
    }
private:
    std::vector<Observer*> subs_;
};

class PhoneApp final : public Observer {
public:
    void update(int t) override { std::printf("  手机 App：显示 %d℃\n", t); }
};

class BigScreen final : public Observer {
public:
    void update(int t) override { std::printf("  客厅大屏：大屏刷新 %d℃\n", t); }
};

int main()
{
    WeatherStation s;
    PhoneApp a;
    BigScreen b;
    s.subscribe(&a);
    s.subscribe(&b);

    s.setTemp(21);
    s.setTemp(24);
    std::puts("发布者不认识订阅者，只遍历名单");
    return 0;
}
    RUN./observer_cpp.exe
    气温 -> 21℃
  手机 App：显示 21℃
  客厅大屏：大屏刷新 21℃
气温 -> 24℃
  手机 App：显示 24℃
  客厅大屏：大屏刷新 24℃
发布者不认识订阅者，只遍历名单

    05C 与 C++ 对照

    角色C 版C++ 版差别意味着什么
    订阅者形态{name, update}Observer 虚接口C 用回调，C++ 用多态
    名单固定数组vector<Observer*>真实实现要支持退订
    通知遍历数组调用遍历容器调用发布者不判断类型
    退订示例未做示例未做生产实现必须支持“通知中退订”

    06代价与坑

    参考教程：refactoringguru.cn

    • 通知中退订遍历时删除元素会让迭代器失效；先拷贝名单或延迟删除。
    • 订阅者比发布者先死C++ 裸指针会悬空；需要弱引用或显式退订。
    • 更新顺序有依赖订阅者互相依赖时，观察者顺序会变成隐式契约；尽量不要让订阅者互相调用。
