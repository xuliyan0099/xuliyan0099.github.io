    策略模式STRATEGY

    排序算法有好几种，选哪种取决于数据规模和是否近乎有序。如果把算法名写死在调用处，换算法就要改调用方。策略模式把算法变成参数：上下文只持有一个“会排序”的函数/对象。

    算法即参数调用方不选分支C 用函数指针 · C++ 用策略对象

    01问题：坏代码长什么样

    坏写法是一个函数里堆所有算法：

    if (mode == BUBBLE) bubble(a, n);
else if (mode == INSERT) insertion(a, n);
else if (mode == QUICK) quick(a, n);

    算法越多分支越长；每个调用方都要知道 mode 的取值，测试也要覆盖所有分支。

    策略把算法抽成可传递的依赖：sort(a, n, bubble)。调用方只提供数据，选哪个算法由上层决定。

    02结构：上下文只持有策略

    左边是调用方，中间是策略参数，右边是两种排序实现。

    同一份数据，换一个排序函数structure
    职责上下文不认识具体算法；算法也不认识业务。

    03两份实现：C 与 C++

    C 版策略是函数指针，直接传函数名；C++ 版策略是对象，用 unique_ptr 注入。

    Cstrategy.c
    /* 策略 · 排序策略
 * gcc -std=c11 -Wall -Wextra strategy.c -o strategy
 */
#include <stdio.h>

typedef void (*sort_fn)(int *, int);

static void bubble(int *a, int n)
{
    for (int i = 0; i < n; i++)
        for (int j = 0; j + 1 < n - i; j++)
            if (a[j] > a[j + 1]) { int t = a[j]; a[j] = a[j + 1]; a[j + 1] = t; }
}

static void insertion(int *a, int n)
{
    for (int i = 1; i < n; i++) {
        int key = a[i], j = i - 1;
        while (j >= 0 && a[j] > key) { a[j + 1] = a[j]; j--; }
        a[j + 1] = key;
    }
}

static void run(const char *name, sort_fn fn, int *src, int n)
{
    int a[8];
    for (int i = 0; i < n; i++) a[i] = src[i];
    fn(a, n);
    printf("%s：", name);
    for (int i = 0; i < n; i++) printf(" %d", a[i]);
    printf("\n");
}

int main(void)
{
    int src[] = { 5, 1, 4, 2, 3 };
    run("冒泡", bubble, src, 5);
    run("插入", insertion, src, 5);
    printf("排序函数是参数，换策略不改调用方\n");
    return 0;
}
    RUN./strategy.exe
    冒泡： 1 2 3 4 5
插入： 1 2 3 4 5
排序函数是参数，换策略不改调用方
    C++strategy.cpp
    // 策略 · 排序策略
// g++ -std=c++17 -Wall -Wextra strategy.cpp -o strategy_cpp
#include <cstdio>
#include <memory>
#include <vector>

class SortStrategy {
public:
    virtual ~SortStrategy() = default;
    virtual const char* name() const = 0;
    virtual void sort(std::vector<int>& v) const = 0;
};

class Bubble final : public SortStrategy {
public:
    const char* name() const override { return "冒泡"; }
    void sort(std::vector<int>& v) const override {
        for (size_t i = 0; i < v.size(); i++)
            for (size_t j = 0; j + 1 < v.size() - i; j++)
                if (v[j] > v[j + 1]) std::swap(v[j], v[j + 1]);
    }
};

class Insertion final : public SortStrategy {
public:
    const char* name() const override { return "插入"; }
    void sort(std::vector<int>& v) const override {
        for (size_t i = 1; i < v.size(); i++) {
            int key = v[i], j = static_cast<int>(i) - 1;
            while (j >= 0 && v[j] > key) { v[j + 1] = v[j]; j--; }
            v[j + 1] = key;
        }
    }
};

class Sorter {
public:
    explicit Sorter(std::unique_ptr<SortStrategy> s) : s_(std::move(s)) {}
    void run(std::vector<int> v) {
        s_->sort(v);
        std::printf("%s：", s_->name());
        for (int x : v) std::printf(" %d", x);
        std::printf("\n");
    }
private:
    std::unique_ptr<SortStrategy> s_;
};

int main()
{
    std::vector<int> src = { 5, 1, 4, 2, 3 };
    Sorter(std::make_unique<Bubble>()).run(src);
    Sorter(std::make_unique<Insertion>()).run(src);
    std::puts("排序函数是参数，换策略不改调用方");
    return 0;
}
    RUN./strategy_cpp.exe

    05C 与 C++ 对照

    角色C 版C++ 版差别意味着什么
    策略形态函数指针策略对象C 最轻，C++ 可带状态
    注入方式参数传入构造/Setter 注入都在运行时决定
    调用方只给数据和策略只给数据和策略不写算法分支
    扩展算法加一个函数加一个策略子类都不改上下文

    06代价与坑

    参考教程：refactoringguru.cn

    • 策略里藏业务规则策略只做算法；折扣、权限这类规则放别处。
    • 策略对象有状态还共享C++ 策略若被多个上下文共用，内部计数会互相干扰。
    • 为两个分支硬抽策略只有算法会独立演化、或需要运行时切换时才值得。
